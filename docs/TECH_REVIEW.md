# 기술 검토 및 적정 기술 제안

> 2026-10-18 조사 기준. 요청서 7장의 검토 사항 8가지에 답한다. 확인하지 못한 내용은 **[미확인]**으로 표시했다.

## 0. 한 장 요약

| 질문 | 답 |
|---|---|
| B1을 PC에서 직접 제어? | **가능.** 크롬/엣지의 Web Bluetooth(또는 USB Web Serial) + 오픈소스 `niimbluelib`로 브라우저에서 바로 출력. 설치·드라이버가 필요 없다 |
| 직접 제어가 안 되면? | 아이폰 등은 라벨 PNG를 공식 NIIMBOT 앱으로 공유해 출력. 라벨 크기 PDF·A4 PDF도 제공 |
| 유튜브 채팅·감사 메시지 | 공식 API. 수집은 **`streamList`(스트리밍)** 필수. 폴링은 3시간 방송 하나로 하루 할당량을 다 쓴다. 감사 글 1건 = 20 units |
| 음성 인식을 PC에서? | 가능. MVP는 크롬 내장 Web Speech(무료). 정확도는 후처리(한글 금액 파서 + 품종 사전)로 확보. 필요하면 Deepgram·리턴제로로 교체 |
| PC+휴대폰 구조 | **웹 서비스(PWA)** 하나. 서버가 상태를 갖고 모든 기기가 실시간 구독. 휴대폰은 문자찜·포장·프린트 스테이션 |
| 안전한 저장 | PostgreSQL + 이벤트 로그(입력 우선 기록) + 매일 백업. 판정은 로그 재생으로 언제든 검증 |
| 기간·비용 | 스프린트 14개(S00~S13). 운영비는 소규모 서버+DB 수준. 경쟁사 대비 가격 여지가 크다(§7) |
| 확장성 | 프린터·채팅·STT를 어댑터로 분리. 다중 판매자는 구조상 지원. 진짜 병목은 **유튜브 API 할당량**(§2.4) |

## 1. NIIMBOT B1 출력

### 1.1 직접 제어 — 가능
- **niimbluelib** (`@mmote/niimbluelib`, MIT, v0.47.1 / 2026-10-14 배포, 활발히 유지보수).
  - B1을 지원한다: 203dpi, 인쇄 헤드 384px(48mm), 농도 1~5(기본 3), "B1" 인쇄 방식. B1 펌웨어 3.03·3.07·5.14·5.18에서 동작 보고.
  - 연결 방식
    - **Web Bluetooth**: Windows·macOS·안드로이드의 크롬/엣지
    - **Web Serial(USB)**: Windows·macOS 크롬만. 안드로이드는 USB 시리얼 미지원
- 같은 저자의 웹앱 **NiimBlue**(niim.blue, MIT)가 실제로 B1에 출력하는 검증된 구현이다. CSV 일괄 출력도 지원한다.
- **50×30mm 라벨 = 384×240px 이미지**. 우리가 캔버스에 한글 글꼴로 그린 뒤 1비트로 바꿔 보낸다. 프린터 글꼴을 쓰지 않으니 한글이 깨질 일이 없다.

### 1.2 알려진 함정
| 문제 | 대응 |
|---|---|
| 마지막 1픽셀 줄이 안 찍힘(펌웨어 버그, 공식 앱도 동일) | 페이지 높이를 1줄 크게 선언 |
| **정품 RFID 라벨이 아니면 농도가 거의 0** | 사용자 안내: 정품 롤 사용 (도움봇처럼 판매사 전용 라벨에 묶이는 건 아니고, 제조사 정품이면 됨) |
| Windows에서 USB 포트를 NIIMBOT 드라이버가 잡고 있으면 Web Serial 실패 | 블루투스를 기본으로, USB는 고급 옵션 + 안내 |
| 브라우저 보안상 **세션마다 첫 연결은 사용자가 클릭**해야 함 | 방송 시작 화면에 "프린터 연결" 버튼. 연결 후엔 탭이 열려 있는 동안 자동 출력 |
| 아이폰 사파리는 Web Bluetooth 없음. 우회 앱은 불안정(2026-10-16 보고: 일부 앱만 성공) | 아이폰은 PNG 공유 → 공식 앱 출력. 또는 안드로이드 폰/PC를 프린트 스테이션으로 |

### 1.3 공식 프로그램
- NIIMBOT 공식 PC 앱(Windows/Mac)이 있고 B1과 동작한다. niimbluelib 저자가 공식 Windows 앱에서 B1 버그를 재현했다. 일괄 출력도 지원한다.
- OS 인쇄 대화상자로 임의 PDF를 B1에 보내는 드라이버 경로는 **[미확인]**.
- 공식 모바일 앱은 흑백 이미지 삽입을 지원한다. 엑셀 가져오기는 판매처 주장뿐이라 **[미확인]**.

### 1.4 제안
1. **기본**: Web Bluetooth + niimbluelib (PC·안드로이드 크롬). 코드 경로 하나, 드라이버 없음.
2. **대체 1**: PC USB(Web Serial). 대량 연속 출력에 유리하다.
3. **대체 2**: 라벨 PNG → 공식 앱(아이폰 포함 모든 기기). 라벨 크기 PDF / A4 모아찍기 PDF.
4. **나중에(선택)**: 로컬 출력 브리지(`niimblue-node` REST 서버). 탭을 안 열어 둬도 되는 무인 출력, 아이폰 지원용.

### 1.5 ⚠ 사업 위험
niimbluelib 코드는 MIT지만, README에 "교육용, **상업적 사용은 제조사 동의 필요**"라는 문구가 있다. 프로토콜을 역분석한 구현이기 때문이다.
- 대응
  1. 출시 전 NIIMBOT(국내 총판)에 문의해 동의나 공식 SDK를 받는다.
  2. 프린터 어댑터를 분리해 교체 가능하게 둔다.
  3. PNG/PDF 대체 경로를 항상 제공한다.
- **→ 결정 D-009**

## 2. 유튜브 API

### 2.1 채팅 읽기
| 방법 | 비용 | 비고 |
|---|---|---|
| `liveChatMessages.list` 폴링 | 호출당 5 units, 응답이 정하는 간격(약 5초) | 3시간 ≈ 2,160회 = **10,800 units → 하루 기본 할당량 10,000 초과** |
| **`liveChatMessages.streamList`** | 연결(호출)당 5 units | gRPC 서버 스트리밍. 끊기면 `nextPageToken`으로 이어받기. 3시간 내내 재연결해도 수백 units. 2025-07 문서 갱신, 베타 표기 없음 |
| 비공식(내부 웹 엔드포인트 스크래핑) | 할당량 없음 | 유튜브 약관이 자동 수집을 금지한다. 차단·깨짐 위험, API 접근권 상실 위험. **사용하지 않음** |

- 채팅방 ID: `liveBroadcasts.list`(OAuth, 1 unit, 내 방송 목록) 또는 `videos.list`(API 키, 1 unit, 영상 ID 필요).
- 메시지 필드
  - `id`: 중복 제거 키
  - `snippet.publishedAt`: 실제 샘플은 마이크로초 정밀도
  - `authorDetails.channelId`: 구매자 고유 키
  - `displayName`: 바뀔 수 있음
  - `isChatOwner`: 방송자 본인 여부
  - 삭제된 메시지는 `tombstone` 이벤트로 온다 → 주문을 자동 취소하지는 말고 방송자에게 알림.

### 2.2 감사 메시지 쓰기
| 위치 | API | 비용 | 권한 |
|---|---|---|---|
| 실시간 채팅 | `liveChatMessages.insert` | **20 units** | `youtube.force-ssl` (판매자 채널로 게시) |
| 영상 댓글 | `commentThreads.insert` | 50 units | `youtube.force-ssl` |

- 방송 중 영상 댓글 게시 가능 여부는 문서에 없다 **[미확인]** → HG-3에서 실측한다. 기본은 "방송 종료 후 요약 1건" 권장.
- 채팅 게시 횟수 제한·글자 수 제한은 문서에 숫자가 없다 **[미확인]** → 묶음 감사로 줄이고, 200자 기준으로 나눈다(실측 후 조정).
- 정책상 **자동 게시는 판매자의 명시적 사전 동의**가 필요하다 → 설정 화면 동의 체크(SPEC YT-04 AC2).

### 2.3 3시간 방송 할당량 예산
| 항목 | units |
|---|---|
| streamList (재연결 포함) | ~200 |
| 감사 메시지 100건 × 20 | 2,000 |
| 방송 조회 등 | ~10 |
| **합계** | **~2,200** |

### 2.4 ⚠ 다중 판매자의 진짜 병목: 할당량은 "프로젝트 단위"
- 하루 10,000 units는 **구글 클라우드 프로젝트 하나**의 몫이다. 우리 서비스의 모든 판매자가 나눠 쓴다.
- 정책상 서비스 하나에 프로젝트 하나만 쓸 수 있고, 할당량을 우회하려고 쪼개는 것도 금지다.
- 기본 할당량으로는 하루 3시간 방송 약 4회분(감사 메시지 포함)이다.
- 판매자 1명이 쓰는 초기 단계엔 충분하다. 다중 판매자 출시 전엔 **할당량 증설 신청(준수 감사)**이 필수다. 소요 기간은 공개되지 않았다.
- 판매자가 각자 자기 프로젝트를 만드는 방식은 정책상 회색지대이고 비전문가에게 너무 어렵다.

### 2.5 계정 연결(OAuth) 준비물
- 유튜브 권한은 "민감" 등급으로 분류된다(제3자 자료 기준, 콘솔에서 확인 필요). 검증을 받으려면 아래가 필요하다(검토 3~5영업일).
  - 공개 홈페이지
  - 같은 도메인의 개인정보처리방침(구글 개인정보처리방침 링크 포함)
  - 서치 콘솔 도메인 소유 확인
  - 권한 사용 설명
  - 영어 데모 영상
- 검증 전 제약
  - 경고 화면이 뜨고 신규 사용자 100명 상한이 있다.
  - "테스트" 상태에선 갱신 토큰이 7일마다 만료된다. 판매자 본인만 쓰는 초기엔 감수 가능하지만, 매주 재연결이 필요하다.

### 2.6 ⚠ 데이터 보관 규정과 장부 보관의 충돌
- 유튜브 개발자 정책
  - API로 받은 데이터는 **30일 안에 갱신하거나 삭제**해야 한다.
  - 사용자가 연결을 끊으면 7일(앱에서 끊은 경우) 또는 30일(구글 설정에서 끊은 경우) 안에 삭제해야 한다.
  - 삭제 요청은 7일 안에 처리해야 한다.
- 반면 판매 장부(누가 무엇을 얼마에 샀는지)는 판매자의 거래 기록이라 세법상 장기 보관이 필요하다.
- 제안: 데이터를 둘로 나눈다. 법률 검토가 필요하다 → **결정 D-012**.
  - **유튜브 원본 캐시**(채팅 원문, API 닉네임): 30일 정책을 적용한다.
  - **판매자 장부**(판매자가 확정한 구매자 표시명, 거래 내역): 판매자 소유 기록으로 둔다.

## 3. 음성 인식

| 방식 | 한국어 | 지연 | 시간당 비용 | 사용자 단어 등록 | 비고 |
|---|---|---|---|---|---|
| **크롬 Web Speech** | 일반 대화 양호(판단) | 낮음, 중간 결과 제공 | **무료** | 크롬 지원 [미확인] | 음성이 구글 서버로 전송. 자동 정지 → 재시작 처리 필요 |
| Deepgram Nova-3 | 2026-08 한국어 스트리밍 개선 | 300ms 이하 주장 | 약 $0.29~0.35 | keyterm(500토큰) | 서버 중계 필요 |
| 리턴제로(RTZR) | 한국어 특화 | 미공개 | ₩1,000 (월 10시간 무료) | 키워드 100개 | 서버 연동 권장 |
| Google Chirp 3 | ko-KR 스트리밍 GA | — | 약 $0.96 (2차 출처) | 1,000구문 | |
| OpenAI 실시간 전사 | 한국어 품질 [미확인] | 조절 가능 | $0.36~1.02 | keywords/prompt | |
| 브라우저 내 Whisper(WebGPU) | CER 5~6% (공개 벤치) | 청크 단위, 실시간 아님 | 무료 | — | 모델 0.5~1.6GB 다운로드 |

**제안**
- MVP: Web Speech(무료, 서버 없음).
- 정확도는 **후처리**에서 확보한다.
  - "N번"·"만오천 원"은 한글 수사 파서로 읽는다(골든 `parser/amount.yaml` 공용).
  - 품종명은 판매자 판매 이력 + 기본 다육 사전에서 자모 단위 유사도로 맞춘다.
  - 결과는 항상 "제안 카드"로 보여주고 Enter로 확정한다.
- 정확도가 모자라면 서버 중계로 Deepgram 또는 리턴제로를 붙이고, 품종 사전을 키워드 부스팅에 넣는다.
- 고르기 전에 실제 판매자 방송 음성 30~60분으로 비교 측정한다(HG-4).

**마이크 문제**
- OBS로 같은 PC에서 방송하면 공유 모드 마이크를 OBS와 브라우저가 함께 쓸 수 있다(독점 모드면 충돌).
- **휴대폰으로 방송하면** PC 브라우저가 그 마이크를 들을 수 없다. 대안은 셋이다.
  - 휴대폰 브라우저에서 음성 기능 실행
  - PC에서 방송 탭 오디오 캡처
  - 가상 오디오 케이블

## 4. PC + 휴대폰 구조 → 웹 서비스(PWA)

데스크톱 설치형(Electron/Tauri) 대신 웹을 고른 이유는 넷이다.
1. "복잡한 설치 없이"라는 요구사항.
2. PC·휴대폰이 같은 데이터를 실시간으로 봐야 한다.
3. 향후 다중 판매자.
4. Web Bluetooth 덕분에 웹에서도 B1에 직접 출력할 수 있다. 데스크톱 앱을 만들 결정적 이유가 사라졌다.

| 기기 | 역할 |
|---|---|
| PC 크롬 | 라이브 콘솔(빠른 입력·상품 보드·채팅·알림), 정산, B1 연결 |
| 안드로이드 크롬 | 문자찜 입력, 포장 모드, **프린트 스테이션**(B1 블루투스) |
| 아이폰 사파리 | 문자찜 입력, 포장 모드, 조회, 라벨 PNG 공유 |

## 5. 데이터 저장

- **PostgreSQL** (관리형: Neon/Supabase 등). 테스트는 PGlite(내장 Postgres)로 도커 없이 돌린다.
- **입력 우선 기록**: 채팅·문자찜·조작은 판정 전에 `events` 테이블에 저장한다. (방송, 출처, 외부 ID)에 유일 제약을 걸어 재수신을 DB 단계에서 막는다.
- **방송별 직렬 처리**: 같은 방송의 이벤트는 한 줄로 처리한다(어드바이저리 락 또는 방송별 큐). 동시에 들어와도 중복 판매가 날 수 없다.
- **프로젝션**: 상품·찜·구매자·정산 테이블은 이벤트에서 만든 조회용 사본이다. 재생 검사 명령으로 언제든 일치를 확인한다(INV-4).
- **백업**: 관리형 DB의 시점 복구 + 매일 논리 백업 30일 보관. 판매자 단위 전체 내보내기(엑셀+JSON)·가져오기.
- **암호화**: 전화번호·유튜브 토큰은 앱 단에서 암호화(AES-GCM, 키는 환경변수/KMS). 로그에서는 가린다.
- **시간**: UTC 저장, 화면과 정산 날짜는 KST.

```
 PC 크롬 ─┐                         ┌──── YouTube API
 안드로이드 ┼── HTTPS + 실시간 푸시 ──┤  apps/server (Node LTS, TypeScript)
 아이폰  ─┘                         │   ├ 이벤트 저장 → 판정(packages/core) → 프로젝션 → 푸시
                                   │   ├ 채팅 수집 워커 (방송별 streamList 연결)
                                   │   ├ outbox 워커 (감사 메시지·재시도)
                                   │   └ 백업·정리 작업
                                   └──── PostgreSQL
 B1 ◀── Web Bluetooth/Serial ── 브라우저 (packages/label: 캔버스 렌더 + niimbluelib)
```

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript (전 구간) | 엔진을 서버·브라우저가 공유. 에이전트 바이브코딩에 유리 |
| 저장소 구조 | pnpm 모노레포: `packages/core`, `packages/label`, `apps/server`, `apps/web` | 순수 엔진을 격리해 테스트 집중 |
| 엔진 테스트 | Vitest + fast-check + 골든 러너 | 판정·금액을 예시와 속성으로 이중 고정 |
| 서버 | Fastify 또는 Hono, Drizzle ORM, `@grpc/grpc-js`(streamList), `googleapis`(OAuth·insert) | 장시간 연결 워커가 필요해 서버리스(Vercel 함수)는 부적합 |
| 웹 | React + Vite, TanStack Query, Tailwind, PWA | 빠른 개발, 휴대폰 설치 |
| 라벨·문서 | Canvas + Pretendard/Noto Sans KR(OFL), `pdf-lib`, `exceljs` | 미리보기 = 출력 이미지 |
| E2E | Playwright | ux-reviewer·qa-breaker가 사용 |
| 배포 | 컨테이너 1개(Fly.io/Railway/Render 등) + 관리형 Postgres | 단순, 저렴 |

## 8. 확장성

- **프린터**: `PrinterAdapter` 인터페이스. niimbluelib이 지원하는 다른 NIIMBOT 모델(B21, D110 등)은 설정만으로 추가한다. 타사 프린터는 PDF·OS 인쇄로 연결한다. 단 B1 Pro는 300dpi·576px로 다르니 별도 프로필이 필요하다.
- **채팅 플랫폼**: `ChatSource` 인터페이스(유튜브 / 시뮬레이터 / 향후 다른 플랫폼).
- **STT**: `SpeechEngine` 인터페이스(Web Speech / Deepgram / 리턴제로).
- **다중 판매자**: 모든 테이블에 판매자 ID, 쿼리 계층에서 격리 강제. 판매자별 할당량 사용량을 계량해 공정 배분한다.
