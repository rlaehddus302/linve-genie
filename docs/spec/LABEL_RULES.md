# 라벨·출력 규칙서 (LABEL_RULES)

> 버전 v0.1.0 · 2026-10-20 (P1: D-P1-01~D-P1-10) · 소유자: spec-keeper
> 라벨 패키지(`packages/label`)와 프린터 패키지(`packages/printer`)의 "법전". SPEC §5.4 LBL-01~08·11·12의 세부 규칙이다.
> 라벨에 찍히는 글(값·쪽 나누기)과 라벨 크기는 `tests/golden/label/*.json` 골든으로 고정한다(형식: `tests/golden/README.md` "라벨 골든").
> 규칙을 바꾸려면 DECISIONS.md 결정 → 이 문서 수정 → 골든 수정 순서를 지킨다. 판정·정산 규칙은 DOMAIN_RULES가 정하고, 이 문서는 그 결과를 라벨에 옮기는 법만 정한다.

## L-0. 기본 원칙

1. **미리보기 = PNG = PDF = 프린터로 보내는 그림** (LBL-03). 라벨 하나는 렌더 함수 하나가 만든 1비트 그림 하나다. 미리보기·PNG·PDF·프린터는 모두 그 그림을 그대로 쓴다(다시 그리지 않는다).
2. 렌더는 두 단계다. **글 계산**(템플릿 + 라벨 데이터 → 항목마다 찍을 글, 포장 라벨의 쪽 나누기)은 캔버스 없이 도는 순수 함수이고 골든으로 고정한다. **그리기**(글 계산 결과 → 1비트 그림)는 글 계산 결과만 그린다 — 그리기 단계가 글을 새로 만들거나 바꾸지 않는다(줄이기·두 줄·말줄임표는 L-5).
3. 같은 라벨 데이터·템플릿·글꼴이면 같은 그림이다. 시각·난수·실행 환경의 언어·시간대·시스템 글꼴을 쓰지 않는다(NFR-02). 브라우저와 Node 시험은 같은 렌더 함수를 쓰고 캔버스만 바꿔 끼운다.
4. 라벨에는 판매자에게 필요한 글만 찍는다. 문자찜의 메모·전화번호·뒤 4자리는 어떤 라벨에도 찍지 않는다(DOMAIN_RULES R-11 "효과(감사 문구·라벨)", YT-04 AC1) — 라벨 데이터 형식에 그 칸이 아예 없다(L-3, L-4).

## L-1. 라벨 크기와 점 (LBL-04, D-P1-02)

| 크기(폭×높이 mm) | 그림(점) | 기본 | A4 한 장에 |
|---|---|---|---|
| 50×30 | 384×240 | **기본** | 24 (3열×8줄) |
| 50×20 | 384×160 | | 36 (3열×12줄) |
| 50×40 | 384×320 | | 18 (3열×6줄) |

- B1은 203dpi = 1mm에 8점으로 본다. 그림 높이 = 높이mm × 8. 그림 폭 = min(폭mm × 8, 384) — B1 인쇄 헤드는 384점(48mm)이라 50mm 라벨의 가운데 48mm에 찍힌다.
- 이 목록 밖의 크기는 쓰지 않는다(템플릿 검사 오류). 크기를 더하려면 기본 템플릿 두 벌(상품·포장)과 골든 한 줄을 함께 더한다.
- **1비트**: 그린 뒤 흰 바탕에 합친 밝기(R·G·B 평균, 0~255)가 128 미만인 점은 검정, 나머지는 흰색이다. 회색·디더링은 없다.
- **1비트 그림 형식**(라벨 → 프린터·내보내기 공용): `{ width, height, data }` — `data`는 줄 순서(위→아래), 한 줄은 `ceil(width/8)` 바이트, 바이트 안은 왼쪽 점이 높은 비트, 1 = 검정.
- B1 마지막 줄 미출력(TECH_REVIEW §1.2)은 프린터 어댑터가 맡는다(L-7). 라벨 그림의 높이는 위 표 그대로다.

## L-2. 글 다듬기와 글꼴 (LBL-05, D-P1-04)

**글 다듬기** — 가게 이름, 품종, 유튜브 닉네임, 방송 제목에 쓴다. 차례대로:
1. 유니코드 NFC로 합친다(맥에서 복사한 풀어 쓴 한글 → 한 글자).
2. 줄바꿈·탭 같은 제어 문자(`\p{Cc}`)와 줄·문단 구분자(U+2028·U+2029)는 공백으로 바꾼다.
3. 보이지 않는 서식 문자(`\p{Cf}` — 폭 없는 공백·방향 바꾸기 문자·BOM·이음 문자 등)는 지운다. 라벨의 글 순서가 기기마다 뒤집히지 않게 한다.
4. 이어진 공백(`\p{Zs}` — 전각 공백·줄바꿈 없는 공백 포함)은 보통 공백 하나로 줄이고, 앞뒤 공백은 지운다.
- 다듬은 결과가 빈 글이면: 유튜브 닉네임은 `이름 없음`, 방송 제목은 `제목 없음`, 가게 이름은 머리글을 찍지 않는다, 품종은 빈 값으로 둔다(L-3).
- 이모지 같은 글자는 다듬기에서 지우지 않는다(아래 글꼴 규칙이 그리는 법을 정한다).

**글꼴**
- 한글 글꼴 하나(Pretendard 또는 Noto Sans KR, SIL OFL 1.1)를 패키지에 넣고 그 글꼴로만 그린다. 실행 중 인터넷에서 글꼴을 받지 않고, 시스템 글꼴로 대신 그리지 않는다 — 어느 기기에서 그려도 같은 라벨이다. 열 감지 인쇄에서 잘 보이도록 굵은 굵기를 권한다.
- 글꼴은 적어도 다음을 모두 가진다: 한글 음절 11,172자(U+AC00~U+D7A3), 호환 자모 51자(U+3131~U+3163 — `ㅋㅋ`·`ㅠㅠ`), ASCII 출력 글자(U+0020~U+007E). 글꼴 라이선스 파일을 글꼴 옆에 둔다.
- 내장 글꼴에 없는 글자(이모지 등)는 다른 글꼴로 대신 그리지 않고 **빈 네모 하나**로 그린다. 서로 다른 없는 글자도 같은 네모다. 이모지 하나가 네모 몇 개가 되는지는 정하지 않는다. 그리기 결과는 항목마다 네모로 그린 글자를 알려 준다(L-5 배치 결과의 `missing`).

## L-3. 상품 라벨 (LBL-01, D-P1-03)

판매자 샘플 형식:
```
        -가게이름-
번호: 194   가격: 8 천원        26.10.08
품종:   왕비뇌신금
닉네임: 우주천사
```

**라벨 데이터** (이 밖의 칸이 있으면 입력 오류 `INVALID_DATA` — 라벨을 만들지 않는다)

| 칸 | 값 |
|---|---|
| `no` | 상품 번호, 정수 1~9999 |
| `name` | 품종(문자열, 비어도 된다) |
| `price` | 가격, 0 이상 안전한 정수 원 |
| `date` | 방송 날짜 `YYYY-MM-DD`(있는 날짜) |
| `buyer` | `{ kind: "youtube", name: <닉네임> }` 또는 `{ kind: "sms" }` — 문자찜은 다른 칸을 가질 수 없다 |

**항목** (템플릿 항목 ID · 찍는 글 · 끌 수 있나)

| 항목 | 찍는 글 | 값(골든이 보는 것) | 끄기 |
|---|---|---|---|
| `shop` | `-{값}-` (가운데 머리글) | 템플릿의 가게 이름을 다듬은 것. 비면 항목을 찍지 않는다 | 된다 |
| `number` | `번호: {값}` | 번호 그대로(앞에 0을 붙이지 않는다) | **안 된다** |
| `price` | `가격: {값}` | 아래 "가격 표기" | 된다 |
| `date` | `{값}` | 방송 날짜를 `YY.MM.DD`(`2026-10-08` → `26.10.08`) | 된다 |
| `name` | `품종: {값}` | 다듬은 품종. 비었으면 빈 값(`품종:`만 찍는다 — "품종 미입력" 같은 글을 라벨에 찍지 않는다) | 된다 |
| `buyer` | `닉네임: {값}` | 유튜브 = 다듬은 닉네임(비면 `이름 없음`), 문자찜 = 언제나 `문자찜` | **안 된다** |

**가격 표기** (템플릿 `priceStyle`, 기본 `THOUSAND` — D-007)
- `THOUSAND`: 가격이 1,000의 배수이고 0보다 크면 `{가격 ÷ 1000을 세 자리 쉼표} 천원`(`8000` → `8 천원`, `150000` → `150 천원`, `1234000` → `1,234 천원`). 아니면 원 표기(`8500` → `8,500원`, `500` → `500원`, `0` → `0원`). 소수점(`8.5 천원`)은 쓰지 않는다.
- `WON`: 언제나 원 표기 — 세 자리 쉼표 + `원`(`8000` → `8,000원`). 코어 `formatWon`과 같다.

## L-4. 포장 라벨 (LBL-02, D-P1-05)

구매자 한 명의 정산 묶음(DOMAIN_RULES R-12 — 같은 날의 모든 방송) 하나를 라벨 한 장 이상으로 찍는다.

**라벨 데이터** (이 밖의 칸이 있으면 `INVALID_DATA`)

| 칸 | 값 |
|---|---|
| `date` | 묶음 날짜 `YYYY-MM-DD` |
| `buyer` | L-3과 같다 |
| `broadcasts` | 1개 이상. 방송 순서(그날 선언한 순서)대로 `{ title, numbers }` — `numbers`는 그 방송에서 이 구매자가 1등인 상품 번호(정수 1~9999, 1개 이상, 같은 방송 안에서 겹치지 않는다) |
| `subtotal` | 상품 합계, 0 이상 안전한 정수 원 — 코어 정산 결과의 값을 그대로 받는다. 라벨 패키지는 금액을 다시 계산하지 않는다 |

**항목**

| 항목 | 찍는 글 | 값 | 끄기 |
|---|---|---|---|
| `shop` | `-{값}-` | L-3과 같다 | 된다 |
| `date` | `{값}` | 묶음 날짜 `YY.MM.DD` | 된다 |
| `buyer` | `{값}` | L-3과 같다(문자찜은 `문자찜`) | **안 된다** |
| `page` | `{값}` | 쪽 `k/n` — 한 장이어도 `1/1` | **안 된다** |
| `broadcast` | `{값}` | 그 쪽 번호들의 방송 제목(다듬은 것, 비면 `제목 없음`). 묶음에 방송이 둘 이상일 때만 찍는다 | **안 된다** |
| `count` | `상품 {값}개` | 묶음 전체 번호 개수 | 된다 |
| `subtotal` | `상품 합계 {값}` | `subtotal`을 원 표기(`30,000원`). 템플릿의 가격 표기와 상관없이 늘 원 표기다 | 된다 |
| `numbers` | 번호를 `, `로 이어 찍는다 | 그 쪽의 번호들 | **안 된다** |

**쪽 나누기**
1. 방송마다 따로 쪽을 만든다(한 쪽에는 한 방송의 번호만). 방송 순서는 받은 순서 그대로(제목으로 다시 줄 세우지 않는다), 한 방송 안의 번호는 작은 것부터.
2. 한 쪽에 번호를 템플릿 `perPage`개까지 앞에서부터 채운다(기본: 50×30은 10). 남으면 다음 쪽.
3. 쪽 `k/n`의 n은 모든 방송의 쪽을 더한 수다.
- `count`·`subtotal`·`buyer`·`date`·`shop`은 모든 쪽에 같은 값이다.

## L-5. 템플릿과 글 맞추기 (LBL-04, D-P1-06)

**템플릿** — 판매자 단위로 저장할 수 있는 JSON. `format: 1`, `kind`(`product`/`packing`), `size`(L-1 목록), `shopName`, `priceStyle`(상품), `perPage`(포장, 1~40), 항목마다 `{ visible, x, y, width, height, fontSize, minFontSize }`(점 단위, 상자 왼쪽 위 기준).
- 검사(`validateTemplate`)는 모르는 칸, 목록 밖의 크기, 끌 수 없는 항목을 끈 것, 라벨 밖으로 나간 상자, 글자 크기 16~120점 밖, `minFontSize > fontSize`를 오류(`INVALID_TEMPLATE`)로 알린다. 문제마다 쉬운 한국어 한 문장이 있다(UX-03). 상자가 겹치는 것은 오류가 아니라 경고다.
- 기본 템플릿: 크기마다 상품·포장 한 벌씩 패키지가 준다. 기본 상품 라벨의 배치는 판매자 샘플을 따른다 — 맨 위 가운데 가게 이름, 둘째 줄 왼쪽부터 번호·가격·날짜, 셋째 줄 품종, 넷째 줄 닉네임. 기본 템플릿의 상자는 서로 겹치지 않고, 모든 글은 20점 이상으로 찍힌다. 기본 가게 이름은 빈 글(판매자가 정한다).

**글 맞추기** — 글은 항목 상자 밖으로 나가지 않는다.
1. 상자 폭에 맞을 때까지 `fontSize`에서 글자를 줄인다(`minFontSize`까지).
2. **품종(`name`)**: `minFontSize`로도 한 줄에 안 맞으면 두 줄로 나눈다 — 공백이 있으면 두 줄 폭의 차이가 가장 작은 공백에서, 없으면 글자(보이는 글자 하나 단위) 사이에서 두 줄 폭의 차이가 가장 작은 곳에서. 두 줄이 상자에 맞는 가장 큰 글자 크기(`minFontSize` 이상)로 찍는다. 그래도 안 맞으면 `minFontSize` 두 줄로, 둘째 줄 끝을 `…`로 줄인다.
3. **그 밖의 글 항목**(가게 이름, 닉네임, 방송 제목): `minFontSize` 한 줄로, 끝을 `…`로 줄인다.
4. **숫자 항목**(번호, 가격, 날짜, 쪽, 상품 수, 상품 합계, 번호 목록)은 줄이지 않는다(말줄임표 없음). 번호 목록은 상자 안에서 `, ` 뒤에서만 줄을 바꾼다. `minFontSize`로도 안 맞으면 그 라벨을 만들지 않고 `DOES_NOT_FIT`(어느 항목인지)을 알린다 — 잘린 번호·가격이 찍힌 라벨이 나오지 않게.
- 그리기 결과는 그림과 함께 **배치 결과**를 준다: 항목마다 실제로 찍은 글(줄마다), 상자, 글자 크기, 맞추기 방법(`fit` / `shrunk` / `twoLines` / `truncated`), 네모로 그린 글자(`missing`). 말줄임표는 보이는 글자 하나를 가르지 않는다.

## L-6. 내보내기 (LBL-07, D-P1-07)

- **PNG**: 1비트 그림 그대로(크기 L-1, 검정·흰색 두 색만), 해상도 정보 203dpi(`pHYs` 7992점/m). 읽어 들이면 같은 1비트 그림이다.
- **라벨 크기 PDF**: 라벨 한 장 = 한 쪽, 쪽 크기 = 라벨 크기(50×30mm = 141.73×85.04pt). 그림은 실제 크기(폭 = 그림 점 ÷ 8 mm — 384점이면 48mm)로 쪽 가로 가운데·세로 꽉 차게, 손실 없이 넣는다.
- **A4 모아찍기 PDF**: A4 세로(210×297mm), 여백 10mm, 칸 사이 2mm, 칸 = 라벨 크기. 왼쪽 위부터 줄마다 채운다(L-1 표의 장 수). 칸마다 라벨 그림을 위와 같이 실제 크기로 넣고, 칸 테두리에 자르는 선(0.2mm, 회색)을 긋는다. 넘치면 다음 쪽. 한 PDF에 다른 크기의 라벨은 섞지 않는다(오류).
- 두 PDF 모두 인쇄 대화상자가 크기를 줄이지 않게(`PrintScaling None`) 적고, 만든 시각·구매자 이름 같은 값을 문서 정보에 넣지 않는다. 같은 그림이면 같은 바이트다.

## L-7. 프린터 어댑터 (LBL-06, LBL-12, D-P1-08)

- **어댑터**(`PrinterAdapter`)는 프린터 모델과 상관없는 계약이다: 프로필(모델·dpi·헤드 점 수·농도 범위), 연결 상태(`DISCONNECTED` 끊김 / `CONNECTING` 연결 중 / `CONNECTED` 연결됨 / `PRINTING` 출력 중)와 바뀔 때 알림, 이 환경에서 쓸 수 있는 연결 방법 목록, 연결(판매자가 누른 동작 안에서만 — 페이지가 열릴 때 스스로 연결하지 않는다), 연결 끊기, 출력(1비트 그림 한 장 + 농도 → 프린터가 끝났다고 알리면 끝). 실패는 언제나 아래 오류 코드와 한국어 문장으로 알린다(원래 예외를 그대로 던지지 않는다 — 기술 상세는 따로 담는다).
- **B1 어댑터**: `@mmote/niimbluelib`(정확한 버전 고정)로 B1 인쇄 방식, 농도 1~5(기본 3), 간격 있는 라벨 종류를 쓴다. 연결은 Web Bluetooth가 기본, Web Serial(USB)이 보조다. 기능 감지로 그 브라우저에 있는 방법만 보인다.
  - **마지막 줄 미출력 대응**: 그림 아래에 흰 줄 한 줄을 더해 높이 + 1줄로 보낸다(위 240줄은 받은 그림 그대로).
  - 연결한 프린터가 B1이 아니면 연결을 끊고 `WRONG_MODEL`. 그림 폭이 헤드 점 수(384)보다 넓으면 보내지 않고 `IMAGE_TOO_WIDE`.
  - 다른 모델은 프로필을 더해 붙인다(LBL-12). 지금 켜진 프로필은 B1 하나다.
- **가짜 프린터**: 같은 어댑터 계약을 지키고, 받은 그림을 받은 순서대로 복사해 기록한다. 몇 번째 출력에서 끊김·오류·지연을 낼지 미리 정할 수 있다. 시험과 개발에 쓴다(리허설 방송은 가짜 프린터로도 출력하지 않는다 — D-081).
- **테스트 라벨**(연결 마법사의 테스트 인쇄, LBL-06 AC1): 가게 이름, `테스트 라벨`, 한글 확인 글 `한글 확인: 가나다 똠햏 ㄱㄴㄷ`, 숫자 `0123456789`, 날짜(받은 날짜), 그림의 맨 위·맨 아래·맨 왼쪽·맨 오른쪽 줄을 지나는 테두리. 맨 아래 테두리가 찍히면 마지막 줄 대응이 된 것이다(HG-2).

**오류 코드와 문장** (화면에 그대로 쓴다)

## L-8. 출력 대기열 (LBL-08, LBL-11, LBL-09 폐기 표시, D-P1-09)

출력 대기열은 시각·난수를 읽지 않는 순수 함수다(시각은 부르는 쪽이 넣는다). 상태는 JSON으로 저장하고 다시 읽을 수 있다(서버 기록은 I1).
- **작업** = 라벨 한 장 출력: 작업 ID(부르는 쪽이 정한다 — 자동 출력은 효과 ID), 라벨 키(같은 라벨의 출력·재출력을 묶는 키 — 자동 출력은 찜과 확정버전), 종류(상품/포장/테스트), 라벨 데이터, 내용 키(L-10), 상태, 시도 횟수, 마지막 오류.
- **상태**: `WAITING` 대기 → `PRINTING` 출력 중 → `DONE` 출력함. 판매자가 뺀 작업은 `CANCELLED` 출력 안 함. 폐기 표시(`voided`)는 상태와 따로 붙는다(화면 낱말 "폐기", 출력한 것은 "폐기 — 버려 주세요").
- **멈춘 까닭의 문장**: 끊김 "프린터 연결이 끊겼어요." · 프린터 오류 "프린터 오류로 멈췄어요." · 판매자 "출력을 멈췄어요."
1. **순서·중복**: 넣은 순서대로 한 번에 하나씩 출력한다. 같은 작업 ID를 다시 넣으면 아무 일도 없다(끝난 작업이어도 같다 — 같은 효과가 두 번 출력되지 않게, R-13).
2. **시작 조건**: 프린터가 연결됨, 대기열이 멈추지 않음, 출력 중인 작업 없음, 대기 작업 있음 → 가장 먼저 넣은 대기 작업을 출력 중으로.
3. **멈춤**: 출력이 오류로 끝나거나 연결이 끊기면 대기열이 멈춘다(멈춘 까닭: 끊김 / 프린터 오류 / 판매자). 출력 중이던 작업은 대기 맨 앞으로 돌아가고(사라지지 않는다 — LBL-06 AC2) 시도 횟수 +1, 마지막 오류를 남긴다. 같은 작업을 저절로 되풀이하지 않는다. 끊김으로 멈춘 대기열은 다시 연결되면 이어서 출력하고, 프린터 오류로 멈춘 대기열은 판매자가 "다시 시작"을 눌러야 이어진다. 판매자가 멈출 수도 있다. 대기 중에 끊겨도 멈춤(끊김)이다. 멈춘 동안에도 작업은 넣을 수 있다.
4. **폐기**(라벨 키 단위 — VOID_LABEL·승계·취소): 그 라벨 키의 대기 작업은 출력하지 않고 `CANCELLED` + 폐기, 출력 중 작업은 끝난 뒤 폐기 표시, 출력한 작업은 폐기 표시("버려 주세요"). 폐기는 되돌리지 않는다.
5. **재출력**: 출력함 또는 출력 안 함 상태이고 폐기되지 않은 라벨 키만 다시 출력할 수 있다. 새 작업 ID와 지금의 라벨 데이터로 대기 맨 끝에 새 작업을 넣는다. 그 라벨 키의 작업이 대기·출력 중이거나, 폐기됐으면 재출력하지 않는다.
6. **빼기**: 판매자는 대기 작업을 뺄 수 있다(`CANCELLED`, 기록은 남는다).
7. **이력**: 라벨 키마다 출력 횟수(출력함이 된 작업 수)와 그때마다의 시각·기기 이름(부르는 쪽이 넣은 값)을 보인다.

## L-9. 라벨 데이터의 출처 (I1에서 연결, D-P1-10)

P1은 라벨 데이터를 받기만 한다. 엔진 상태에서 라벨 데이터를 만드는 일은 I1이 하고, 그때 아래를 따른다.
- 상품 라벨: `no`·`name` = 출력할 때 그 상품의 지금 번호·품종, `price` = 그 찜의 가격 스냅샷(확정 시점 가격 — 정산 금액과 같다, R-4·R-10), `date` = 그 상품이 속한 방송의 날짜, `buyer` = 감사 문구와 같은 이름(R-13 — 확정되는 순간 그 찜의 구매자 자신의 표시 이름, 문자 구매자의 찜과 문자찜으로 생긴 찜은 언제나 `{ kind: "sms" }`). 자동 출력 작업 ID = `PRINT_PRODUCT_LABEL` 효과 ID, 라벨 키 = (찜, 확정버전) — `VOID_LABEL` 효과가 같은 라벨 키를 폐기한다.
- 포장 라벨: (지금의 구매자, 날짜) 정산 묶음 하나. `broadcasts` = 그날 방송 선언 순서대로 그 묶음의 품목(확정 찜) 번호, `subtotal` = 코어 정산 결과의 상품 합계, `buyer` = 지금의 구매자의 표시 이름(문자 구매자면 `{ kind: "sms" }` — 메모를 넣은 `문자찜(메모)`는 쓰지 않는다).
- 리허설 범위의 라벨 효과는 출력하지 않는다(D-081).

## L-10. 재출력 필요 (LBL-11, D-P1-10)

- **내용 키** = 라벨 종류와 L-3·L-4의 값(템플릿을 뺀 다듬은 값)으로 정한 글. 같은 값이면 같은 키다.
- 라벨 키의 마지막으로 출력한 내용 키와 지금 라벨 데이터의 내용 키가 다르면 "재출력 필요"다(번호·품종·가격·구매자·날짜가 바뀐 경우). 템플릿(위치·글자 크기·가게 이름·가격 표기)만 바꾼 것은 재출력 필요가 아니다.
