## L-0. 기본 원칙

1. **미리보기 = PNG = PDF = 프린터로 보내는 그림** (LBL-03). 라벨 하나는 렌더 함수 하나가 만든 1비트 그림 하나다. 미리보기·PNG·PDF·프린터는 모두 그 그림을 그대로 쓴다(다시 그리지 않는다). 프린터 어댑터가 보내기 직전에 하는 점 옮기기(B1 마지막 줄 흰 줄 더하기 L-7, 테이프 프린터의 시계 방향 90도 돌림 L-12)는 다시 그리기가 아니다 — 점은 하나도 바뀌지 않는다.
2. 렌더는 두 단계다. **글 계산**(템플릿 + 라벨 데이터 → 항목마다 찍을 글, 포장 라벨의 쪽 나누기)은 캔버스 없이 도는 순수 함수이고 골든으로 고정한다. **그리기**(글 계산 결과 → 1비트 그림)는 글 계산 결과만 그린다 — 그리기 단계가 글을 새로 만들거나 바꾸지 않는다(줄이기·두 줄·말줄임표는 L-5).
3. 같은 라벨 데이터·템플릿·글꼴이면 같은 그림이다. 시각·난수·실행 환경의 언어·시간대·시스템 글꼴을 쓰지 않는다(NFR-02). 브라우저와 Node 시험은 같은 렌더 함수를 쓰고 캔버스만 바꿔 끼운다.
4. 라벨에는 판매자에게 필요한 글만 찍는다. 문자찜의 메모·전화번호·뒤 4자리는 어떤 라벨에도 찍지 않는다(DOMAIN_RULES R-11 "효과(감사 문구·라벨)", YT-04 AC1) — 라벨 데이터 형식에 그 칸이 아예 없다(L-3, L-4).

## L-1. 라벨 크기와 점 (LBL-04, D-P1-02)

| 크기(폭×높이 mm) | 그림(점) | 기본 | A4 한 장에 |
|---|---|---|---|
| 50×30 | 384×240 | **기본** | 24 (3열×8줄) |
| 50×20 | 384×160 | | 36 (3열×12줄) |
| 50×40 | 384×320 | | 18 (3열×6줄) |
| 50×15 | 384×120 | | 48 (3열×16줄) — 작은 크기 (N1) |
| 50×50 | 384×400 | | 15 (3열×5줄) (N1) |
| 테이프 12×40 (`tape12x40`) | 320×96 | | 76 (4열×19줄) — 작은 크기 (N1) |
| 테이프 15×30 (`tape15x30`) | 240×96 | | 96 (6열×16줄) — 작은 크기 (N1) |
| 테이프 15×50 (`tape15x50`) | 400×96 | | 48 (3열×16줄) — 작은 크기 (N1) |

- B1은 203dpi = 1mm에 8점으로 본다. 그림 높이 = 높이mm × 8. 그림 폭 = min(폭mm × 8, 384) — B1 인쇄 헤드는 384점(48mm)이라 50mm 라벨의 가운데 48mm에 찍힌다.
- 이 목록 밖의 크기는 쓰지 않는다(템플릿 검사 오류). 크기를 더하려면 기본 템플릿 두 벌(상품·포장 — 작은 크기는 상품 한 벌)과 골든 한 줄을 함께 더한다.
- **크기 ID** (N1, D-N1-03): 50mm 라벨은 `<폭>x<높이>`(mm — `50x30`), 테이프는 `tape<테이프 폭>x<길이>`(mm — `tape12x40`). 화면 이름은 `50×30`, `테이프 12×40`.
- **테이프 라벨**은 옆으로 눕혀 읽는 그림이다: 그림 폭 = 길이mm × 8, 그림 높이 = 96점(테이프 프린터 헤드 12mm — 15mm 테이프도 가운데 12mm에만 찍힌다). 테이프 프린터 어댑터가 시계 방향 90도로 돌려 보낸다(L-12 2). 읽는 방향의 크기(PDF 쪽·A4 칸)는 길이 × 테이프 폭이다(`tape12x40` = 40×12mm, `tape15x30` = 30×15mm).
- **작은 크기** = 높이 15mm 이하(50×15, 테이프 세 가지). 기본 상품 템플릿이 작은 템플릿이고(L-5), 포장 라벨은 만들지 않는다(L-4).
- 어느 프린터가 어느 크기를 쓰는지는 프린터 프로필이 정한다(L-12 1). B1은 50×30·50×20·50×40 그대로다 — 지금 화면(I1)이 보이는 크기 목록은 B1 목록 그대로 두고, 프로필마다의 목록으로 바꾸는 일은 통합 스프린트가 한다.
- **1비트**: 그린 뒤 흰 바탕에 합친 밝기(R·G·B 평균, 0~255)가 128 미만인 점은 검정, 나머지는 흰색이다. 회색·디더링은 없다.
- **1비트 그림 형식**(라벨 → 프린터·내보내기 공용): `{ width, height, data }` — `data`는 줄 순서(위→아래), 한 줄은 `ceil(width/8)` 바이트, 바이트 안은 왼쪽 점이 높은 비트, 1 = 검정.
- B1 마지막 줄 미출력(TECH_REVIEW §1.2)은 프린터 어댑터가 맡는다(L-7). 라벨 그림의 높이는 위 표 그대로다.

## L-2. 글 다듬기와 글꼴 (LBL-05, D-P1-04)

**글 다듬기** — 가게 이름, 품종, 옵션 글(O3), 유튜브 닉네임, 방송 제목에 쓴다. 차례대로:
1. 유니코드 NFC로 합친다(맥에서 복사한 풀어 쓴 한글 → 한 글자).
2. 줄바꿈·탭 같은 제어 문자(`\p{Cc}`)와 줄·문단 구분자(U+2028·U+2029)는 공백으로 바꾼다.
3. 보이지 않는 서식 문자(`\p{Cf}` — 폭 없는 공백·방향 바꾸기 문자·BOM·이음 문자 등)는 지운다. 라벨의 글 순서가 기기마다 뒤집히지 않게 한다.
4. 이어진 공백(`\p{Zs}` — 전각 공백·줄바꿈 없는 공백 포함)은 보통 공백 하나로 줄이고, 앞뒤 공백은 지운다.
- 다듬은 결과가 빈 글이면: 유튜브 닉네임은 `이름 없음`, 방송 제목은 `제목 없음`, 가게 이름은 머리글을 찍지 않는다, 품종은 빈 값으로 둔다(L-3).
- 이모지 같은 글자는 다듬기에서 지우지 않는다(아래 글꼴 규칙이 그리는 법을 정한다).
- 한글 채움 글자(U+3164·U+115F·U+1160·U+FFA0)·점자 빈칸(U+2800)처럼 서식 문자가 아닌 보이지 않는 글자는 다듬기에서 지우지 않는다 — 그런 닉네임은 빈 칸처럼 찍힐 수 있다(TD-P1-005). 라벨 다듬기는 범주 세 개만 쓰고(D-036), 닉네임의 보이지 않는 글자 정리는 채팅 수집 경로가 맡는다(Y1 트랙 D-Y05 — 합친 뒤 적용). (I1, D-I1-09)

**글꼴**
- 한글 글꼴 하나(Pretendard 또는 Noto Sans KR, SIL OFL 1.1)를 패키지에 넣고 그 글꼴로만 그린다. 실행 중 인터넷에서 글꼴을 받지 않고, 시스템 글꼴로 대신 그리지 않는다 — 어느 기기에서 그려도 같은 라벨이다. 열 감지 인쇄에서 잘 보이도록 굵은 굵기를 권한다.
- 글꼴은 적어도 다음을 모두 가진다: 한글 음절 11,172자(U+AC00~U+D7A3), 호환 자모 51자(U+3131~U+3163 — `ㅋㅋ`·`ㅠㅠ`), ASCII 출력 글자(U+0020~U+007E). 글꼴 라이선스 파일을 글꼴 옆에 둔다.
- 내장 글꼴에 없는 글자(이모지 등)는 다른 글꼴로 대신 그리지 않고 **빈 네모 하나**로 그린다. 서로 다른 없는 글자도 같은 네모다. 이모지 하나가 네모 몇 개가 되는지는 정하지 않는다. 그리기 결과는 항목마다 네모로 그린 글자를 알려 준다(L-5 배치 결과의 `missing`).

## L-3. 상품 라벨 (LBL-01, D-P1-03)

판매자 샘플 형식:
```
        -가게이름-
번호: 194   가격: 8 천원        26.10.08
품종:   왕비뇌신금
닉네임: 우주천사
```

**라벨 데이터** (이 밖의 칸이 있으면 입력 오류 `INVALID_DATA` — 라벨을 만들지 않는다)

| 칸 | 값 |
|---|---|
| `no` | 상품 번호, 정수 1~9999 |
| `name` | 품종(문자열, 비어도 된다) |
| `price` | 가격, 0 이상 안전한 정수 원 |
| `date` | 방송 날짜 `YYYY-MM-DD`(있는 날짜) |
| `buyer` | `{ kind: "youtube", name: <닉네임> }` 또는 `{ kind: "sms" }` — 문자찜은 다른 칸을 가질 수 없다 |
| `variant` (선택, O3) | 옵션 글(DOMAIN_RULES R-19 "표시" — 선택지 이름을 항목 순서대로 `/`로 이은 글, 예 `흰색/대형`). 적지 않거나 `null`이면 옵션 없음. 글이 아니거나 다듬은 결과(L-2)가 빈 글이면 `INVALID_DATA` (D-O3-01) |
| `qty` (선택, O3) | 수량, 정수 1~99. 적지 않으면 1. 그 밖(0·100·소수·글·`null`)은 `INVALID_DATA` (D-O3-01) |

- 옵션 방송이 아니거나 옵션 없는 수량 1 찜은 `variant`·`qty`를 적지 않는다(적어도 `variant: null`·`qty: 1`이면 같은 라벨이다) — 지금 라벨과 글자·그림까지 같다(CMT-07).

**항목** (템플릿 항목 ID · 찍는 글 · 끌 수 있나)

| 항목 | 찍는 글 | 값(골든이 보는 것) | 끄기 |
|---|---|---|---|
| `shop` | `-{값}-` (가운데 머리글) | 템플릿의 가게 이름을 다듬은 것. 비면 항목을 찍지 않는다 | 된다 |
| `number` | `번호: {값}` | 번호 그대로(앞에 0을 붙이지 않는다) | **안 된다** |
| `price` | `가격: {값}` | 아래 "가격 표기". 수량이 2 이상이면 `{수량}개 {가격 표기}`(예 `2개 34 천원` — O3, D-O3-02) | 된다 |
| `date` | `{값}` | 방송 날짜를 `YY.MM.DD`(`2026-10-08` → `26.10.08`) | 된다 |
| `name` | `품종: {값}` | 다듬은 품종. 비었으면 빈 값(`품종:`만 찍는다 — "품종 미입력" 같은 글을 라벨에 찍지 않는다). 옵션 글이 있으면 `{다듬은 품종} {다듬은 옵션 글}`(품종이 비면 옵션 글만 — O3, D-O3-02) | 된다 |
| `buyer` | `닉네임: {값}` | 유튜브 = 다듬은 닉네임(비면 `이름 없음`), 문자찜 = 언제나 `문자찜` | **안 된다** |

**가격 표기** (템플릿 `priceStyle`, 기본 `THOUSAND` — D-007)
- `THOUSAND`: 가격이 1,000의 배수이고 0보다 크면 `{가격 ÷ 1000을 세 자리 쉼표} 천원`(`8000` → `8 천원`, `150000` → `150 천원`, `1234000` → `1,234 천원`). 아니면 원 표기(`8500` → `8,500원`, `500` → `500원`, `0` → `0원`). 소수점(`8.5 천원`)은 쓰지 않는다.
- `WON`: 언제나 원 표기 — 세 자리 쉼표 + `원`(`8000` → `8,000원`). 코어 `formatWon`과 같다.
- `price`는 찜 금액(단가 × 수량)이다(L-9). 수량 2 이상이면 그 금액을 위 표기로 바꾼 글 앞에 `{수량}개 `를 붙인다 — 수량은 늘 숫자 항목(가격)에 있어 줄여지지 않는다(L-5 4).

**옵션 글·수량의 자리** (O3, D-O3-02): 옵션 글은 품종 자리, 수량은 가격 자리다. 템플릿은 바꾸지 않는다 — 판매자가 품종 항목을 끄면 옵션 글을, 가격 항목을 끄면 수량을 찍지 않는다(작은 템플릿은 품종이 꺼져 있다 — L-5). 무엇을 담을지는 포장 라벨·포장 모드(L-4·STL-08)가 늘 옵션 글과 수량을 보인다.

## L-4. 포장 라벨 (LBL-02, D-P1-05)

구매자 한 명의 정산 묶음(DOMAIN_RULES R-12 — 같은 날의 모든 방송) 하나를 라벨 한 장 이상으로 찍는다.

**라벨 데이터** (이 밖의 칸이 있으면 `INVALID_DATA`)

| 칸 | 값 |
|---|---|
| `date` | 묶음 날짜 `YYYY-MM-DD` |
| `buyer` | L-3과 같다 |
| `broadcasts` | 1개 이상. 방송 순서(그날 선언한 순서)대로 `{ title, numbers }` — `numbers`는 그 방송에서 이 구매자가 1등인 상품의 **항목**(1개 이상, 같은 방송 안에서 겹치지 않는다). 항목 = 상품 번호(정수 1~9999) 또는 (O3) `{ no, variant?, qty? }` — `no`는 번호, `variant`·`qty`는 L-3과 같은 검사(적지 않거나 `variant: null`이면 옵션 없음, `qty` 없으면 1), 다른 칸이 있으면 `INVALID_DATA`. 항목의 같음 = (번호, 다듬은 옵션 글) — 정수 `5`와 `{ no: 5 }`는 같은 항목이다 (D-O3-03) |
| `subtotal` | 상품 합계, 0 이상 안전한 정수 원 — 코어 정산 결과의 값을 그대로 받는다. 라벨 패키지는 금액을 다시 계산하지 않는다 |

**항목**

| 항목 | 찍는 글 | 값 | 끄기 |
|---|---|---|---|
| `shop` | `-{값}-` | L-3과 같다 | 된다 |
| `date` | `{값}` | 묶음 날짜 `YY.MM.DD` | 된다 |
| `buyer` | `{값}` | L-3과 같다(문자찜은 `문자찜`) | **안 된다** |
| `page` | `{값}` | 쪽 `k/n` — 한 장이어도 `1/1` | **안 된다** |
| `broadcast` | `{값}` | 그 쪽 번호들의 방송 제목(다듬은 것, 비면 `제목 없음`). 묶음에 방송이 둘 이상일 때만 찍는다 | **안 된다** |
| `count` | `상품 {값}개` | 묶음 전체 항목의 수량 합(옵션 없는 수량 1 항목만이면 번호 개수 — 지금과 같다. O3, D-O3-03) | 된다 |
| `subtotal` | `상품 합계 {값}` | `subtotal`을 원 표기(`30,000원`). 템플릿의 가격 표기와 상관없이 늘 원 표기다 | 된다 |
| `numbers` | 항목을 `, `로 이어 찍는다 | 그 쪽의 항목들. 옵션 없는 수량 1 항목은 번호, 아니면 **옵션 항목** 글 `{번호}[ {다듬은 옵션 글}][ ×{수량}]`(수량은 2 이상일 때만 — 예 `21 M`, `11 ×3`, `22 105/검정색 ×2`. O3, DOMAIN_RULES R-19 "표시") | **안 된다** |

**쪽 나누기**
1. 방송마다 따로 쪽을 만든다(한 쪽에는 한 방송의 번호만). 방송 순서는 받은 순서 그대로(제목으로 다시 줄 세우지 않는다), 한 방송 안의 번호는 작은 것부터. 같은 번호의 항목(변형)은 받은 순서 그대로다 — 서버는 상품의 변형 순서(항목 순서·선택지 순서)로 넘긴다(L-9, O3).
2. 한 쪽에 항목을 템플릿 `perPage`개까지 앞에서부터 채운다(기본: 50×30은 10 · 50×20은 8 · 50×40은 16 · 50×50은 20 — 50×50은 N1). 남으면 다음 쪽. **옵션 항목이 하나라도 있는 방송**은 그 방송의 쪽마다 `perPage`의 절반(내림, 적어도 1)까지만 채운다 — 옵션 항목 글이 길어 한 쪽에 다 들어가지 않는 일을 줄인다 (O3, D-O3-04).
3. 쪽 `k/n`의 n은 모든 방송의 쪽을 더한 수다.
- `count`·`subtotal`·`buyer`·`date`·`shop`은 모든 쪽에 같은 값이다.
- **포장 라벨의 크기** (N1, D-N1-03): 높이 20mm 이상(50×20·50×30·50×40·50×50)에서만 만든다. 작은 크기(L-1)의 포장 템플릿은 템플릿 검사 오류다(`INVALID_TEMPLATE`, 문제 `size` · "이 크기에는 포장 라벨을 만들 수 없어요. 높이 20mm 이상인 라벨을 골라 주세요."). 테이프·50×15 프린터를 쓰는 판매자의 포장 라벨은 그림 파일·PDF(L-6)로 낸다.

## L-5. 템플릿과 글 맞추기 (LBL-04, D-P1-06)

**템플릿** — 판매자 단위로 저장할 수 있는 JSON. `format: 1`, `kind`(`product`/`packing`), `size`(L-1 목록), `shopName`, `priceStyle`(상품), `perPage`(포장, 1~40), 항목마다 `{ visible, x, y, width, height, fontSize, minFontSize }`(점 단위, 상자 왼쪽 위 기준).
- 검사(`validateTemplate`)는 모르는 칸, 목록 밖의 크기, 끌 수 없는 항목을 끈 것, 라벨 밖으로 나간 상자, 글자 크기 16~120점 밖, `minFontSize > fontSize`, 작은 크기의 포장 템플릿(L-4)을 오류(`INVALID_TEMPLATE`)로 알린다. 문제마다 쉬운 한국어 한 문장이 있다(UX-03). 목록 밖 크기의 문장은 "쓸 수 없는 라벨 크기예요. 라벨 크기 목록에서 다시 골라 주세요."다(N1 — 크기가 프린터마다 달라 목록을 문장에 늘어놓지 않는다). 켠 상자가 겹치는 것은 오류가 아니라 경고다.
- 기본 템플릿: 크기마다 상품·포장 한 벌씩 패키지가 준다(작은 크기는 상품 한 벌). 기본 상품 라벨의 배치는 판매자 샘플을 따른다 — 맨 위 가운데 가게 이름, 둘째 줄 왼쪽부터 번호·가격·날짜, 셋째 줄 품종, 넷째 줄 닉네임. 기본 템플릿의 켠 상자는 서로 겹치지 않고, 모든 글은 20점 이상으로 찍힌다. 기본 가게 이름은 빈 글(판매자가 정한다).
- **작은 템플릿** (작은 크기의 기본 상품 템플릿, N1 — D-N1-03): 번호·가격·닉네임만 켜고 가게 이름·날짜·품종은 끈다. 꺼진 항목도 라벨 안에 상자가 있어 판매자가 켤 수 있다(켜면 L-5 맞추기 그대로 — 겹치면 경고). 항목·캡션·값은 L-3 그대로다(글 골든 G-LBL-N1-11~26). 보장: 번호 9999와 가격 `99,999,999원`·`99,999 천원`이 가장 짧은 테이프(15×30 = 240×96점)에서도 `DOES_NOT_FIT` 없이 20점 이상으로 들어간다. 닉네임은 다른 크기처럼 한 줄 `…`로 줄인다.

**글 맞추기** — 글은 항목 상자 밖으로 나가지 않는다.
1. 상자 폭에 맞을 때까지 `fontSize`에서 글자를 줄인다(`minFontSize`까지).
2. **품종(`name`)**: `minFontSize`로도 한 줄에 안 맞으면 두 줄로 나눈다 — 공백이 있으면 두 줄 폭의 차이가 가장 작은 공백에서, 없으면 글자(보이는 글자 하나 단위) 사이에서 두 줄 폭의 차이가 가장 작은 곳에서. 두 줄이 상자에 맞는 가장 큰 글자 크기(`minFontSize` 이상)로 찍는다. 그래도 안 맞으면 `minFontSize` 두 줄로, 둘째 줄 끝을 `…`로 줄인다.
3. **그 밖의 글 항목**(가게 이름, 닉네임, 방송 제목): `minFontSize` 한 줄로, 끝을 `…`로 줄인다.
4. **숫자 항목**(번호, 가격, 날짜, 쪽, 상품 수, 상품 합계, 번호 목록)은 줄이지 않는다(말줄임표 없음). 번호 목록은 상자 안에서 `, ` 뒤에서만 줄을 바꾼다 — 옵션 항목(L-4)은 그 항목 안의 공백에서도 바꿀 수 있다(글자 사이에서는 바꾸지 않는다, O3, D-O3-04). 줄은 앞에서부터 채운다. `minFontSize`로도 안 맞으면 그 라벨을 만들지 않고 `DOES_NOT_FIT`(어느 항목인지)을 알린다 — 잘린 번호·가격이 찍힌 라벨이 나오지 않게.
5. 상자가 너무 작아 캡션과 `…`조차 들어가지 않거나 한 줄 높이도 안 되면 그 항목이 무엇이든 `DOES_NOT_FIT`(그 항목)이다 — 상자 밖으로 그리지 않는다(I1, D-I1-09).
- **기본 템플릿이 보장하는 값** (I1, D-I1-09 — 50×50도 같다, N1): 번호 9999, 가격 `99,999,999원`·`99,999 천원`, 날짜는 어느 날짜든(2000-01-01~2099-12-31의 모든 `YY.MM.DD` — 상품·포장, 작은 템플릿에서 날짜를 켠 때도) 20점 이상(STB, D-STB-01 — D-O3-11과 같은 까닭으로 내장 글꼴은 숫자 폭이 달라 평범한 날짜 `26.10.08`만 확인하면 모자란다. 가장 넓은 날짜는 `04.04.04`), 포장 라벨 네 자리 번호 `perPage`개 + `상품 합계 99,999,999원` + `상품 999개`(P1 AC-P1-14). 그보다 긴 값(예: 원 표기 `100,000,000원` — G-LBL-013)은 기본 템플릿에서 `DOES_NOT_FIT`일 수 있다 — 잘린 금액을 찍지 않고 판매자에게 알린다(천원 표기면 `100,000 천원`). 수량이 붙은 가격(O3, D-O3-02): 50×20·50×30·50×40·50×50 기본 템플릿은 `9개 99,999원`·`99개 9,999원`·`9개 9,999 천원`·`99개 999 천원`, 작은 템플릿은 `99개 99,999,999원`·`99개 99,999 천원`이 20점 이상으로 들어간다 — 보장은 글자 수로 정하고 그 자리를 어느 숫자(0~9)로 채워도 같다(내장 글꼴은 숫자 폭이 달라 `9`만 확인하면 모자란다, D-O3-11). 그보다 긴 값(예 큰 템플릿 원 표기 `3개 300,000원`·`40개 40,000원`)은 `DOES_NOT_FIT`일 수 있다 — 원 표기로 막히면 천원 표기(기본값)로 바꾸면 들어간다. 품종 두 줄은 공백이 있으면 공백에서만 나누고, 그 나눔으로 안 맞으면 글자 사이 나눔을 따로 찾지 않고 `truncated`다(맞추기 2 그대로).
- 그리기 결과는 그림과 함께 **배치 결과**를 준다: 항목마다 실제로 찍은 글(줄마다), 상자, 글자 크기, 맞추기 방법(`fit` / `shrunk` / `twoLines` / `truncated`), 네모로 그린 글자(`missing`). 말줄임표는 보이는 글자 하나를 가르지 않는다.

## L-6. 내보내기 (LBL-07, D-P1-07)

- **PNG**: 1비트 그림 그대로(크기 L-1, 검정·흰색 두 색만), 해상도 정보 203dpi(`pHYs` 7992점/m). 읽어 들이면 같은 1비트 그림이다.
- **라벨 크기 PDF**: 라벨 한 장 = 한 쪽, 쪽 크기 = 라벨 크기(읽는 방향 — 50×30mm = 141.73×85.04pt, 테이프 12×40 = 40×12mm). 그림은 실제 크기(점 ÷ 8 mm — 384점이면 48mm)로 쪽 가로·세로 가운데에 손실 없이 넣는다(높이가 같으면 세로 꽉 참. 15mm 테이프는 96점 = 12mm라 위아래 1.5mm가 빈다 — N1).
- **A4 모아찍기 PDF**: A4 세로(210×297mm), 여백 10mm, 칸 사이 2mm, 칸 = 라벨 크기(읽는 방향). 열 수 = floor((190 + 2) ÷ (칸 폭 + 2)), 줄 수 = floor((277 + 2) ÷ (칸 높이 + 2)). 왼쪽 위부터 줄마다 채운다(L-1 표의 장 수). 칸마다 라벨 그림을 위와 같이 실제 크기로(칸 가운데) 넣고, 칸 테두리에 자르는 선(0.2mm, 회색)을 긋는다. 넘치면 다음 쪽. 한 PDF에 다른 크기의 라벨은 섞지 않는다(오류).
- 두 PDF 모두 인쇄 대화상자가 크기를 줄이지 않게(`PrintScaling None`) 적고, 만든 시각·구매자 이름 같은 값을 문서 정보에 넣지 않는다. 같은 그림이면 같은 바이트다.

## L-7. 프린터 어댑터 (LBL-06, LBL-12, D-P1-08)

- **어댑터**(`PrinterAdapter`)는 프린터 모델과 상관없는 계약이다: 프로필(모델·dpi·헤드 점 수·농도 범위), 연결 상태(`DISCONNECTED` 끊김 / `CONNECTING` 연결 중 / `CONNECTED` 연결됨 / `PRINTING` 출력 중)와 바뀔 때 알림, 이 환경에서 쓸 수 있는 연결 방법 목록, 연결(판매자가 누른 동작 안에서만 — 페이지가 열릴 때 스스로 연결하지 않는다. 예외는 출력 기기가 이미 연결했던 프린터로 저절로 다시 잇는 것 하나다 — 아래 "저절로 다시 잇기", QS1), 연결 끊기, 출력(1비트 그림 한 장 + 농도 → 프린터가 끝났다고 알리면 끝). 실패는 언제나 아래 오류 코드와 한국어 문장으로 알린다(원래 예외를 그대로 던지지 않는다 — 기술 상세는 따로 담는다).
- **B1 어댑터**: `@mmote/niimbluelib`(정확한 버전 고정)로 B1 인쇄 방식, 농도 1~5(기본 3), 간격 있는 라벨 종류를 쓴다. 연결은 Web Bluetooth가 기본, Web Serial(USB)이 보조다. 기능 감지로 그 브라우저에 있는 방법만 보인다.
  - **마지막 줄 미출력 대응**: 그림 아래에 흰 줄 한 줄을 더해 높이 + 1줄로 보낸다(위 240줄은 받은 그림 그대로).
  - 연결한 프린터가 B1이 아니면 연결을 끊고 `WRONG_MODEL`. 그림 폭이 헤드 점 수(384)보다 넓으면 보내지 않고 `IMAGE_TOO_WIDE`.
  - 다른 모델은 프로필을 더해 붙인다(LBL-12). NIIMBOT 어댑터의 켜진 프로필은 B1 하나다. Marklife 9종·바우아토 스티코팝(실험적)은 L-12의 어댑터다(N1). B1 프로필도 L-12 1의 칸(크기 목록·대체 경로 앱 등)을 가진다.
- **앱 네이티브 BLE (APP2, D-APP2-03)**: 안드로이드·아이폰 Expo 앱은 native BLE 모듈로 같은 B1 어댑터 계약의 `bluetooth` 방법을 제공한다. 브라우저의 Web Bluetooth 감지 결과로 아이폰 앱을 `UNSUPPORTED`로 처리하지 않는다. native 연결·특성 읽기/쓰기를 제외한 B1 작업 바이트·농도·마지막 흰 줄·오류 문장은 기존 어댑터 그대로이며, 현재 활성 native 프로필은 B1이다. L-12의 다른 프린터를 검증 없이 지원 표시하지 않는다. 그림은 서버가 L-0 renderer로 만든 L-1 그림을 받는다(APP-05, D-APP2-02); 앱에서 다시 그리거나 404를 빈 그림으로 바꾸지 않는다. 다른 앱으로 가도 의도적으로 연결을 끊지 않고, 재연결·출력 기기 소유권·받은 작업·실패한 라벨의 처리는 L-11 그대로다. 모의 BLE를 production 기본으로 고르지 않는다.
- **가짜 프린터**: 같은 어댑터 계약을 지키고, 받은 그림을 받은 순서대로 복사해 기록한다. 몇 번째 출력에서 끊김·오류·지연을 낼지 미리 정할 수 있다. 시험과 개발에 쓴다(리허설 방송은 가짜 프린터로도 출력하지 않는다 — D-081).
- **테스트 라벨**(연결 마법사의 테스트 인쇄, LBL-06 AC1): 가게 이름, `테스트 라벨`, 한글 확인 글 `한글 확인: 가나다 똠햏 ㄱㄴㄷ`, 숫자 `0123456789`, 날짜(받은 날짜), 그림의 맨 위·맨 아래·맨 왼쪽·맨 오른쪽 줄을 지나는 테두리. 맨 아래 테두리가 찍히면 마지막 줄 대응이 된 것이다(HG-2). 크기를 받으면 그 크기로 그리고(주지 않으면 50×30), L-1 목록 밖 크기면 그림을 만들지 않고 `INVALID_TEMPLATE`(문제 `size` · "쓸 수 없는 라벨 크기예요. 라벨 크기 목록에서 다시 골라 주세요.")이다(I1, D-I1-09 — 문장은 N1, D-N1-03). **작은 크기**(L-1)의 테스트 라벨은 `한글 확인: 가나다 똠햏`과 `0123456789 <날짜>` 두 줄, 그리고 같은 네 변 테두리만 찍는다(가게 이름·`테스트 라벨` 없음 — 높이 96~120점에 20점 이상으로 들어가게, N1).
- **농도**는 1~5의 정수만 보낸다. 밖이면 보내지 않고 `INVALID_DENSITY`다(화면은 1~5 중에서만 고르게 한다 — L-11).

- **자세히** (FB1, D-FB1-09): 오류의 접어 둔 상세(`detail`)에 원래 예외 글(영어 라이브러리 문장 등)을 **넣지 않는다** — 어떤 코드든, 어떤 어댑터든. 넣는 것은 쉬운 말 고정 문장뿐이다: 원인이 시간 초과(예외 글에 `timeout` 또는 `timed out`, 대소문자 무시)면 "프린터가 답하지 않아 기다리는 시간이 지났어요.", 저절로 한 번 더 해 봤으면 그 뒤에 " 한 번 더 해 봤지만 안 됐어요." 그 밖엔 상세가 없다. `WRONG_MODEL`의 "모델: {모델 이름}"은 그대로다.
- **B1 첫 확인 다시 잇기** (FB1, D-FB1-09): B1 블루투스에서 판매자가 기기를 고른 뒤 첫 확인(niimbluelib 협상)이 시간 초과로 실패하면, 고르기 창을 다시 띄우지 않고 **같은 기기로 한 번만** 1초 쉰 뒤 다시 잇는다(그동안 상태 `CONNECTING`). 두 번째도 실패하면 `CONNECT_FAILED`(상세에 위 두 문장). 그 사이 연결 끊기를 누르면 다시 잇지 않는다(`DISCONNECTED`). 출력이 아니라 연결이라 라벨이 두 번 찍히지 않는다. USB(Web Serial)·Marklife·바우아토는 다시 잇지 않는다.
- **블루투스 켜짐 확인** (QS1, D-QS1-03): `getAvailability()`가 false여도 연결을 한 번 시도한다(윈도우 크롬은 켜져 있어도 false를 돌려주는 일이 있다 — 크로미움 40901954). 그 시도가 어떤 이유로든 실패하면(고르기 창을 닫음 포함) `BLUETOOTH_OFF`다. **예외**: 판매자가 고른 기기가 다른 프린터라 `WRONG_MODEL`이면(이름이 다름·꾸러미 없음 — 기기를 골라 이었다는 것이 블루투스가 켜져 있다는 증거다) `BLUETOOTH_OFF`가 아니라 `WRONG_MODEL` 그대로다(D-QS1-11). true이거나 확인 중 예외면 확인하지 않은 것과 같다. 모든 블루투스 어댑터(B1, L-12 Marklife·바우아토)가 같다.
- **마지막 프린터 기억** (QS1, D-QS1-01): 어댑터는 이 기기에서 마지막으로 **연결에 성공한** 프린터(연결 방법 + 그 기기)를 기억한다. 연결에 성공하지 못한 기기, `WRONG_MODEL`인 기기는 기억하지 않는다.
  - **"다시 연결"**: 기억한 기기를 지금 얻을 수 있으면 고르기 창 없이 그 기기로 잇는다(niimbluelib 블루투스 `connect({ authorizedDevice })`, USB `connect({ authorizedPort })`). 얻을 수 없으면 지금처럼 고르기 창이다. 기억한 기기로 이은 시도가 실패하면(B1 첫 확인 다시 잇기 한 번 포함) 기억을 지우고 그 오류를 지금처럼 알린다 — 다음 "다시 연결"은 고르기 창부터.
  - **연결 방법 단추**("블루투스로 연결"·"USB로 연결" 등)는 언제나 고르기 창이다(다른 프린터로 바꾸는 길).
  - **새로고침 뒤**: 화면은 연결 방법과 기기를 알아보는 값(블루투스 기기 ID, USB 제조사 번호·제품 번호)을 그 기기의 브라우저 저장소에 둔다(서버로 보내지 않는다). USB는 `navigator.serial.getPorts()`가 돌려준 포트 가운데 같은 제조사·제품 번호가 **정확히 하나**일 때만 그 포트를 쓴다(0개·둘 이상이면 고르기 창). 블루투스는 `navigator.bluetooth.getDevices()`가 있을 때만 같은 ID의 기기를 쓴다(없거나 못 찾으면 고르기 창).
  - 기억한 기기로만 잇기(고르기 창을 띄우지 않음 — 저절로 다시 잇기가 쓴다): 기억한 기기를 얻을 수 없으면 시도 없이 실패(`DISCONNECTED`)다. 시험용 프린터(L-11 15)도 같은 계약을 지킨다.
- **해볼 일** (화면, FB1, D-FB1-09·D-FB1-17): `CONNECT_FAILED`·`DISCONNECTED` 오류 아래에 차례대로, 그 기기에 맞는 것만:

  | 줄 | 문장 | 보이는 때 |

  | ③ | "윈도우 설정 → 블루투스 및 장치에서 B1을 '장치 제거'한 뒤 여기서 '다시 연결'을 눌러 목록에서 B1을 골라 주세요. 윈도우에서 미리 연결(페어링)하지 않아도 돼요." | 윈도우(사용자 에이전트에 `Windows`)일 때만 |

  옛 ⑥(아이폰·아이패드 줄)은 없다 — 아이폰·아이패드는 연결할 수 없어(`UNSUPPORTED`, LBL-07) 이 목록을 볼 일이 없다(D-FB1-17). Marklife·바우아토 연결이면 ②의 `NIIMBOT 앱`은 "프린터 앱"으로, ③의 `B1`은 "프린터"로 바꿔 보인다. 오류 상자의 "다시 연결"은 하나이고 해볼 일 목록 **아래**에 있으며 기억한 프린터로 잇는다(`reconnect` — 기억이 없으면 고르기 창). 이 기기의 프린터가 끊겨 있고 이 기기에서 쓴 연결 방법이 있으면 출력 기기가 아니어도 프린터 칸의 연결 방법 단추 위에 "다시 연결"이 있다. 한 화면에 이 기기의 프린터를 다시 잇는 "다시 연결"은 하나다 — 출력 멈춤 띠 → 오류 상자 → 프린터 칸 차례로 앞의 것만(QL2, D-QL2-03). 그 단추는 보이면 그 화면의 주 버튼이다(이 기기의 출력 멈춤 띠 조치가 보이면 그것이 먼저 — D-FB1-18 (b)).

## L-8. 출력 대기열 (LBL-08, LBL-11, LBL-09 폐기 표시, D-P1-09)

출력 대기열은 시각·난수를 읽지 않는 순수 함수다(시각은 부르는 쪽이 넣는다). 상태는 JSON으로 저장하고 다시 읽을 수 있다(서버 기록은 I1).
- **작업** = 라벨 한 장 출력: 작업 ID(부르는 쪽이 정한다 — 자동 출력은 효과 ID), 라벨 키(같은 라벨의 출력·재출력을 묶는 키 — 자동 출력은 찜과 확정버전), 종류(상품/포장/테스트), 라벨 데이터, 내용 키(L-10), 상태, 시도 횟수, 마지막 오류.
- **상태**: `WAITING` 대기 → `PRINTING` 출력 중 → `DONE` 출력함. 판매자가 뺀 작업은 `CANCELLED` 출력 안 함. 폐기 표시(`voided`)는 상태와 따로 붙는다(화면 낱말 "폐기", 출력한 것은 "폐기 — 버려 주세요").
- **멈춘 까닭의 문장**: 끊김 "프린터 연결이 끊겼어요." · 프린터 오류 "프린터 오류로 멈췄어요." · 판매자 "출력을 멈췄어요." · 라벨 오류 "라벨을 만들지 못해 멈췄어요. 라벨 설정을 확인한 뒤 다시 시작해 주세요."(작업의 라벨을 그리지 못함 — 템플릿을 바꿔 `DOES_NOT_FIT` 등. I1, D-I1-09)
1. **순서·중복**: 넣은 순서대로 한 번에 하나씩 출력한다. 같은 작업 ID를 다시 넣으면 아무 일도 없다(끝난 작업이어도 같다 — 같은 효과가 두 번 출력되지 않게, R-13).
2. **시작 조건**: 프린터가 연결됨, 대기열이 멈추지 않음, 출력 중인 작업 없음, 대기 작업 있음 → 가장 먼저 넣은 대기 작업을 출력 중으로.
3. **멈춤**: 출력이 오류로 끝나거나 연결이 끊기면 대기열이 멈춘다(멈춘 까닭: 끊김 / 프린터 오류 / 판매자). 출력 중이던 작업은 대기 맨 앞으로 돌아가고(사라지지 않는다 — LBL-06 AC2) 시도 횟수 +1, 마지막 오류를 남긴다. 같은 작업을 저절로 되풀이하지 않는다. 끊김으로 멈춘 대기열은 다시 연결되면 이어서 출력하고, 프린터 오류로 멈춘 대기열은 판매자가 "다시 시작"을 눌러야 이어진다. 판매자가 멈출 수도 있다. 대기 중에 끊겨도 멈춤(끊김)이다. 멈춘 동안에도 작업은 넣을 수 있다.
   - 라벨 오류 멈춤도 프린터 오류처럼 "다시 시작"으로만 이어진다(작업은 대기 맨 앞, 마지막 오류 = 렌더 오류 코드 — 판매자가 템플릿을 고치거나 그 작업을 뺀 뒤).
   - 프린터가 출력을 시작하기 전에 거절한 경우(`BUSY`·`INVALID_DENSITY` 등)도 프린터 오류 멈춤으로 보고 시도 횟수 +1이다(TD-P1-004 — 라벨은 사라지지 않고, 화면이 이런 거절이 생기지 않게 막는다: L-11).
   - 아직 연결한 적이 없는 빈 대기열은 멈춤이 아니다. 손으로 푸는 멈춤(판매자·프린터 오류·라벨 오류)은 끊겼다 다시 연결돼도 저절로 풀리지 않는다.
4. **폐기**(라벨 키 단위 — VOID_LABEL·승계·취소): 그 라벨 키의 대기 작업은 출력하지 않고 `CANCELLED` + 폐기, 출력 중 작업은 끝난 뒤 폐기 표시, 출력한 작업은 폐기 표시("버려 주세요"). 폐기는 되돌리지 않는다.
   - 이미 폐기한 라벨 키로 새 작업이 오면 출력하지 않고 `CANCELLED` + 폐기로 기록만 남긴다(넣은 작업이 사라지지 않게). 출력 중에 폐기된 작업이 오류·끊김으로 끝나면 대기로 되돌리지 않고 `CANCELLED` + 폐기다(I1, D-I1-09).
5. **재출력**: 출력함 또는 출력 안 함 상태이고 폐기되지 않은 라벨 키만 다시 출력할 수 있다. 새 작업 ID와 지금의 라벨 데이터로 대기 맨 끝에 새 작업을 넣는다. 그 라벨 키의 작업이 대기·출력 중이거나, 폐기됐으면 재출력하지 않는다.
6. **빼기**: 판매자는 대기 작업을 뺄 수 있다(`CANCELLED`, 기록은 남는다).
7. **이력**: 라벨 키마다 출력 횟수(출력함이 된 작업 수)와 그때마다의 시각·기기 이름(부르는 쪽이 넣은 값)을 보인다.

## L-9. 라벨 데이터의 출처 (I1, D-P1-10·D-I1-02·D-I1-04)

P1은 라벨 데이터를 받기만 한다. 엔진 상태에서 라벨 데이터를 만드는 일은 서버(I1)가 하고, 아래를 따른다. 언제 만드는지는 L-11 4.
- 상품 라벨: `no`·`name` = 출력할 때 그 상품의 지금 번호·품종, `price` = 그 찜의 가격 스냅샷(확정 시점 가격 — 정산 금액과 같다, R-4·R-10. 옵션 방송(O3)에서는 찜 금액 = 단가 스냅샷 × 수량 — 코어 `ClaimInfo.amount`), `variant` = 그 찜의 옵션 글(코어 `ClaimInfo.variant`, 없으면 칸을 적지 않는다), `qty` = 그 찜의 수량(2 이상일 때만 적는다), `date` = 그 상품이 속한 방송의 날짜, `buyer` = 감사 문구와 같은 이름(R-13 — 확정되는 순간 그 찜의 구매자 자신의 표시 이름, 문자 구매자의 찜과 문자찜으로 생긴 찜은 언제나 `{ kind: "sms" }`). 자동 출력 작업 ID = `PRINT_PRODUCT_LABEL` 효과 ID, 라벨 키 = (찜, 확정버전) — `VOID_LABEL` 효과가 같은 라벨 키를 폐기한다.
- 포장 라벨: (지금의 구매자, 날짜) 정산 묶음 하나. `broadcasts` = 그날 방송 선언 순서대로 그 묶음의 품목(확정 찜) 항목 — 옵션 없는 수량 1 찜은 번호(지금 그대로), 아니면 `{ no, variant?, qty? }`. 같은 (번호, 옵션 글)의 찜이 둘 이상이면 수량을 더해 한 항목으로 넘기고, 같은 번호의 항목은 상품의 변형 순서(항목 순서·선택지 순서)로 넘긴다 (O3, D-O3-03), `subtotal` = 코어 정산 결과의 상품 합계, `buyer` = 지금의 구매자의 표시 이름(문자 구매자면 `{ kind: "sms" }` — 메모를 넣은 `문자찜(메모)`는 쓰지 않는다).
  - **상품 라벨의 구매자** (I1, D-I1-04): 찜이 문자찜으로 생겼거나(`sms` — 지정 구매자가 유튜브 채널이어도) 찜의 구매자 자신이 문자 구매자면 `{ kind: "sms" }`, 아니면 `{ kind: "youtube", name: 찜의 구매자 자신(그 유튜브 채널)의 표시 이름 }` — 합친 상대의 이름(`문자찜(메모)` 등)이 아니다. 이름은 그 라벨 키의 **첫 작업을 만든 때** 정하고 라벨 키에 고정한다: 자동 출력은 확정되는 순간(효과와 같은 기록), 손으로 출력(효과 없음)은 처음 누른 때. 같은 라벨 키의 재출력은 같은 이름이다 — 닉네임이 나중에 바뀌어도 재출력 필요가 아니다(L-10).
  - 번호·품종·가격 스냅샷은 출력 기기가 작업을 받을 때의 지금 값이다(대기 중에 품종 오타를 고치면 고친 품종으로 찍힌다).
- 리허설 범위의 라벨 효과는 출력하지 않는다(D-081). 리허설에는 출력 작업이 아예 없다(L-11 12).

## L-10. 재출력 필요 (LBL-11, D-P1-10)

- **내용 키** = 라벨 종류와 L-3·L-4의 값(템플릿을 뺀 다듬은 값)으로 정한 글. 같은 값이면 같은 키다. 옵션 글·수량(O3)도 값이다 — 옵션 없는 수량 1 라벨의 키는 O3 전과 글자까지 같다(배포 뒤 이미 출력한 라벨이 모두 "재출력 필요"가 되지 않게, D-O3-09).
- 라벨 키의 마지막으로 출력한 내용 키와 지금 라벨 데이터의 내용 키가 다르면 "재출력 필요"다(번호·품종·가격·구매자·날짜가 바뀐 경우). 템플릿(위치·글자 크기·가게 이름·가격 표기)만 바꾼 것은 재출력 필요가 아니다.
- 화면의 "재출력 필요"는 이 규칙 하나로 서버가 정한다(I1, D-I1-04). 엔진의 재출력 필요 표시(DOMAIN_RULES R-10, D-055)는 낱말로 쓰지 않는다 — 다시 출력해도 엔진 표시는 지워지지 않는다. 확정된 찜에서 실제로 바뀔 수 있는 값은 품종과 가격 스냅샷이다(번호를 바꾸면 찜이 끝나 라벨이 폐기되고, 구매자 이름·날짜는 라벨 키에 고정이다).

## L-11. 서버 출력 기록과 출력 기기 (I1, D-I1-01~D-I1-08·D-I1-10)

L-8의 대기열을 판매자 단위로 서버에 기록하고, 출력은 판매자가 정한 **출력 기기** 하나가 한다(LBL-08·LBL-10). 대기열의 상태(작업·멈춤·출력 기기)는 서버가 원본이고, 모든 기기 화면에 같은 것이 보인다(바뀌면 1초 안 — NFR-01).

1. **작업 기록**: L-8 작업에 더해 범위(방송 날짜 — 실제 범위만), 만든 까닭(`자동`·`손으로`·`다시 출력`·`포장`), 시도마다의 결과(출력함 / 오류 코드), 출력한 기기 이름·시각, 버릴 라벨 확인 여부를 남긴다. 판매자마다 따로이고(SYS-02), 서버를 다시 켜도 그대로다. 기록은 지우지 않는다.
2. **자동 작업** (LBL-09): 실제 범위의 `PRINT_PRODUCT_LABEL` 효과가 기록되는 **같은 트랜잭션**에서 작업 하나를 만든다 — 작업 ID = 효과 ID(범위 안에서 유일), 라벨 키 = (찜, 확정버전), 구매자 = 그 순간의 L-9 구매자. 효과가 없으면(자동 출력을 끈 방송 — G-ENG-061·303, 리허설) 작업도 없다. 판매자가 라벨 기능을 꺼 두었으면(L-13) 효과가 있어도 작업을 만들지 않는다 — 그 트랜잭션 안에서 켬/끔을 읽는다(N4a, D-N4a-01). "프린터 연결 시 자동"은 출력 기기가 연결돼 있고 대기열이 멈추지 않았으면 판매자가 아무것도 누르지 않아도 출력된다는 뜻이다. 출력 기기가 없거나 끊겨 있으면 작업은 대기로 남는다(사라지지 않는다).
3. **손으로 출력**: 판매자가 1등 찜의 "라벨 출력"을 누르면, 그 라벨 키(찜, 지금 확정버전)에 작업이 하나도 없을 때만 새 작업을 만든다(서버가 정한 ID, 구매자 = 그 순간의 L-9 구매자). 작업이 있으면 재출력(9)이다. 라벨 기능을 끈 동안 1등이 된 찜은 라벨 키에 작업이 없으므로 켠 뒤 "라벨 출력"이 처음 작업을 만든다 — 그 라벨 키에 `PRINT_PRODUCT_LABEL` 효과가 있으면 그 효과로 묶는다(7, L-13 8). 라벨 기능이 꺼져 있으면 손으로 출력을 받지 않는다(L-13 5).
4. **출력 기기가 받기**: 판매자마다 출력 중인 작업은 많아야 하나다. 출력 기기만, 대기열이 멈추지 않았을 때, 판매자의 모든 실제 범위를 통틀어 대기 맨 앞의 작업을 받는다(만든 순서 — 실패·끊김·출력 기기 바꾸기로 되돌아온 작업이 맨 앞, L-8 1·3). 상품 라벨의 데이터는 받을 때 서버가 지금 상태로 다시 만든다(L-9 — 구매자만 라벨 키에 고정). 그때 그 찜이 그 확정버전의 1등이 아니면 5의 폐기를 하고 다음 작업을 준다. 포장 라벨의 데이터는 요청할 때 정한다(12).
5. **폐기** (L-8 4, LBL-09): 라벨 키의 찜이 그 확정버전의 1등이 아니게 되면(그 엔진 기록이 커밋될 때 — 취소·무효·승계·역전·교체·충돌 바꾸기·번호 변경, 그리고 출력 기기가 받을 때의 확인) 그 라벨 키를 폐기한다. `VOID_LABEL` 효과도 같은 라벨 키를 폐기한다(이미 폐기됐으면 아무 일도 없다). 자동 출력을 끈 방송에서 손으로 출력한 라벨도 같다 — 엔진은 효과가 없는 라벨의 `VOID_LABEL`을 내지 않으므로(G-ENG-303) 서버가 상태로 정한다.
   - 출력함 작업이 폐기되면 **버릴 라벨**이다. 판매자가 "버렸어요"를 누를 때까지 모든 기기의 알림 띠에 남는다(누가 언제 눌렀는지 남긴다). 대기 작업의 폐기는 출력 안 함 + 폐기이고 버릴 라벨이 아니다.
6. **결과**: 출력 기기는 받은 작업마다 출력함 또는 실패(L-7 오류 코드)를 알린다. 끊김(`DISCONNECTED`)은 끊김 멈춤, 렌더 실패는 라벨 오류 멈춤, 그 밖의 실패는 프린터 오류 멈춤이다(L-8 3). 서버는 **지금 그 기기가 가진 시도**의 결과만 받는다 — 바뀌기 전 출력 기기나 이미 끝난 시도의 늦은 결과는 버린다(라벨이 두 장 나올 수는 있어도 빠지지 않는다, D-P1-09). 같은 결과를 다시 보내도 한 번만 기록한다.
7. **엔진 보고**: 작업이 출력함이 되었고 그 라벨 키의 `PRINT_PRODUCT_LABEL` 효과가 엔진에서 아직 실행 완료가 아니면, 서버가 그 효과 ID로 `effect.labelPrinted`를 그 범위에 기록한다 — 효과마다 한 번(재시도·서버 재시작·두 기기에도). 효과가 이미 취소됐어도 기록한다(늦은 보고 → 엔진이 `VOID_LABEL`을 내고 5가 폐기한다, R-13). 효과가 없는 라벨(자동 출력을 끈 방송에서 손으로 출력)·포장 라벨·출력 실패는 엔진에 알리지 않는다. 손으로 출력한 상품 라벨이라도 그 라벨 키 (찜, 확정버전)에 그 범위의 `PRINT_PRODUCT_LABEL` 효과가 있으면(라벨 기능을 끈 동안 나와 작업이 되지 않은 효과 — L-13 8) 자동 작업과 같이 그 효과를 보고한다(N4a, D-N4a-04)(`effect.failed`는 쓰지 않는다 — 출력 실패는 판매 상태를 바꾸지 않는다, R-13). `VOID_LABEL`에는 엔진 보고가 없다(DOMAIN_RULES R-13).
8. **멈춤과 이어서**: 멈춤(L-8 3 — 끊김·프린터 오류·판매자·라벨 오류)은 판매자 단위로 서버에 남는다. "다시 시작"(손으로 푸는 멈춤)은 어느 기기에서나 누를 수 있다. "다시 연결"은 출력 기기에서만 된다(블루투스 연결은 그 기기에서 판매자가 누른 동작 안에서만 — L-7). 다른 기기는 "출력 기기 '<이름>'에서 다시 연결해 주세요."를 보인다. **저절로 다시 잇기** (QS1, D-QS1-02): 출력 기기에서 연결된 프린터가 끊기면(판매자가 "연결 끊기"·다른 연결 방법을 고른 것이 아님) 그 기기의 화면이 기억한 프린터(L-7)로만, 고르기 창 없이, 첫 시도는 끊긴 때부터·그 뒤는 앞 시도가 끝난 때부터 1초·2초·4초·8초·16초·30초를 쉬고 **모두 6번** 다시 잇는다(시도끼리 겹치지 않는다 — D-QS1-11). 다 실패하면 그친다(판매자가 "다시 연결"을 눌러야 한다). 다시 이어진 뒤 60초 동안 끊기지 않아야 횟수를 새로 센다(60초 안에 또 끊기면 남은 횟수로). 판매자가 "다시 연결"을 누르면 기다림을 그치고 바로 한 번 잇는다 — 이어지면 그 연결부터 새로 세고, 실패하면 저절로 잇기도 그친다(지금처럼 오류 상자). "연결 끊기"·다른 연결 방법·출력 기기에서 내려옴·라벨 기능 끔(L-13)이면 그친다. 한 번에 연결 시도는 하나다. 다시 이어지면 끊김 멈춤이 풀려 대기 맨 앞부터 한 장씩 받는다(L-8 3·4) — 다시 잇기는 연결만 하고 라벨을 다시 보내지 않는다(결과를 알린 장은 다시 나오지 않고, 출력 중에 끊긴 장만 지금처럼 대기 맨 앞 — D-P1-09). 기다리는 동안 화면은 끊김, 시도하는 동안은 연결 중이다. 출력 기기 자신의 출력 멈춤 띠에는 까닭 문장 아래 저절로 잇는 동안(기다림·시도 모두) "프린터에 다시 잇고 있어요. ({n}/6)"(n = 지금 기다리거나 하는 시도의 차례), 6번 모두 실패해 그치면 "저절로 다시 잇지 못했어요. 아래를 해 본 뒤 '다시 연결'을 눌러 주세요." → 해볼 일 목록(L-7) → "다시 연결"이 보인다. "다시 연결"을 누르거나 이어지거나 위의 그치는 조작이 있으면 두 문장은 사라진다(QL2, D-QL2-04). 출력 기기가 아닌 기기는 저절로 잇지 않는다.
9. **재출력·빼기** (L-8 5·6, LBL-11): L-8 5의 조건에 더해, 상품 라벨은 그 라벨 키의 찜이 지금도 그 확정버전의 1등이어야 한다(아니면 "1등이 바뀐 라벨은 다시 출력할 수 없어요."). 재출력 작업은 새 ID로 대기 맨 끝에 들어가고 데이터는 4대로 받을 때 만든다. 판매자는 대기 작업을 하나씩 또는 확인 뒤 모두 뺄 수 있다(출력 안 함, 기록은 남는다). 출력·재출력·빼기는 엔진 기록이 아니므로 방송자 조치의 5초 대기(D-083)가 없다.
10. **출력 기기**: 판매자마다 많아야 하나. 그 기기에서 프린터를 연결한 뒤 판매자가 "이 기기에서 출력"을 눌러 정한다. 이미 다른 기기가 출력 기기면 확인 뒤 바꾼다 — 이전 기기는 더 받지 않고, 이전 기기가 가진 출력 중 작업은 대기 맨 앞으로 돌아간다(시도 +1, 마지막 오류 `DISCONNECTED`). **새로** 출력 기기를 정할 때 대기 작업이 있으면 대기열은 판매자 멈춤으로 시작한다("대기 중인 라벨 N장이 있어요. 출력 시작을 누르면 먼저 들어온 것부터 출력해요." + "출력 시작"). 같은 출력 기기가 끊겼다 다시 연결하면 그대로 이어서 출력한다(L-8 3). 출력 기기는 "출력 그만하기"로 내려놓을 수 있다(출력 중인 장이 끝난 뒤). 기기 이름(다듬은 뒤 1~20자, 판매자가 정함)은 이력에 남는다. 출력 기기의 실시간 연결이 끊기면 다른 기기에 "출력 기기('<이름>')가 연결되어 있지 않아요. 그 기기에서 라이브지니를 열고 화면을 켜 두세요."를 보인다(MOB1 D-MOB1-08 — 예전 문장 "출력 기기 '<이름>'와 연결이 끊겼어요."는 이름의 받침에 따라 조사가 틀렸다. 라벨 화면, 콘솔 알림 띠 맨 끝 항목(세는 알림 뒤 — 빨간 알림을 가리지 않게, D-MOB1-14), 포장 모드 접수 문장 뒤) — 시간이 지났다고 작업을 다른 기기로 넘기지 않는다(판매자가 출력 기기를 바꾼다).
11. **재출력 필요·이력**: 라벨 키마다 L-10의 재출력 필요와 L-8 7의 이력(횟수·시각·기기 이름)을 서버가 정해 보인다.
12. **포장 라벨** (LBL-02, D-I1-10): 판매자가 (구매자, 날짜) 정산 묶음의 "포장 라벨 출력"을 누르면 그때 L-9 데이터를 정해 쪽마다 작업 하나를 쪽 순서대로 만든다. 라벨 키 = (포장, 지금의 구매자, 날짜). 묶음에 1등 상품이 없으면 만들지 않는다("이 묶음에는 1등 상품이 없어 포장 라벨을 만들 수 없어요."). 재출력 필요는 그 묶음의 지금 데이터와 마지막으로 출력한 데이터의 내용 키로 정한다. 포장 라벨은 폐기하지 않는다.
13. **템플릿**: 판매자마다 상품·포장 템플릿 한 벌씩(저장한 적이 없으면 50×30 기본 템플릿). 서버는 `validateTemplate`을 통과하고 16KB 이하이며 가게 이름이 40자 이하인 것만 저장하고, 다른 기기가 먼저 바꿨으면 받지 않는다("다른 기기에서 라벨 설정이 바뀌었어요. 새로 불러온 뒤 다시 바꿔 주세요."). 출력 기기는 그릴 때의 템플릿으로 그린다(쌓인 작업도 — 템플릿만 바꾼 것은 재출력 필요가 아니다, L-10). 최악값이 들어가는지(L-5 "기본 템플릿이 보장하는 값")는 화면이 저장 전에 그려 보고 막는다. 저장 전 최악값의 날짜는 가장 넓은 날짜 `2004-04-04`(`04.04.04`)다(D-STB-01). 검사가 더 엄격해져 **이미 저장된 템플릿**이 새 최악값에 걸려도 서버·출력 기기는 그 템플릿을 그대로 쓰고(바꾸거나 지우지 않는다), 라벨 설정 화면을 열 때 같은 검사를 돌려 걸리면 저장 막힘과 같은 문장(어느 항목인지)을 경고로 보인다 — 판매자가 칸을 넓히거나 기본으로 되돌려 저장하면 사라진다(STB, D-STB-01). **가게 이름 채우기** (FB1, D-FB1-07): 서버가 템플릿을 쓰거나 내주는 모든 곳(템플릿 조회, 출력 기기가 받는 작업, 서버가 그리는 라벨 그림)에서 템플릿 `shopName`을 L-2로 다듬은 결과가 빈 글이면 그 판매자의 가게 이름(설정 "가게")으로 채워 내준다 — 저장된 템플릿 본문은 바꾸지 않고, 글 계산(L-3·L-4 `shop` — 비면 찍지 않음)과 라벨 골든은 그대로다. 찍지 않으려면 `shop` 항목을 끈다. 다른 판매자의 가게 이름은 어떤 경우에도 쓰지 않는다.
14. **리허설** (D-081, RA-S05-002): 리허설 범위의 효과는 작업이 되지 않는다. 리허설 범위에는 손으로 출력·재출력·포장 라벨을 요청할 수 없다("리허설 방송은 라벨을 출력하지 않아요."). 효과를 작업으로 바꾸는 서버 조회는 실제 범위만 읽도록 고정한다(리허설인지를 인자로 받지 않는다).
15. **시험용 프린터**: L-7 가짜 프린터는 서버가 시험 모드(E2E 기동)일 때만 화면의 연결 방법에 "시험용 프린터 — 실제로 출력되지 않아요"로 나온다. 운영 기동에는 없다.
16. **개인정보** (DAT-06, NFR-06): 작업 기록의 라벨 데이터는 L-3·L-4 칸뿐이다(메모·전화번호·뒤 4자리 없음 — L-0 4). 서버 로그에 라벨 데이터·기기 이름·템플릿 가게 이름을 남기지 않는다. 내려받는 파일 이름에는 날짜·번호·쪽만 넣고 구매자 이름·메모·전화번호를 넣지 않는다.

## L-12. Marklife·바우아토 프린터 (PRT-01·PRT-02·LBL-12, N1 — D-N1-02~D-N1-08·D-N1-11~D-N1-13)

Marklife 라벨프린터 9종과 바우아토 스티코팝(실험적)을 L-7 어댑터 계약 그대로 붙인다. 작업 바이트·이름으로 고르기·프로필 표·바로 연결할 수 없는 브라우저의 까닭은 프린터 골든(`tests/golden/printer/*.json`, G-PRT-N1-01~95)으로 고정한다. 바이트 규칙은 MIT 참고 구현(thermal-label/marklife)의 공개 문서에 적힌 사실을 옮긴 것이다 — GPL 코드(LaBLEr·BleWebler)는 옮기지 않는다. 참고 구현이 실기기로 확인한 것은 S2(YXQ 2)·P12·P15(L11)뿐이고 나머지는 추정이라, 실기기 확인은 HG-5(SPEC §9)다.

1. **프로필** (G-PRT-N1-65~75). 모두 203dpi.

| 프로필 ID | 화면 이름 | 방식 | 헤드(점) | 돌림 | 크기 (첫째가 기본) | 농도 | 이름 앞자리 | 대체 경로 앱 |
|---|---|---|---|---|---|---|---|---|
| `MARKLIFE_P50` | Marklife P50 | YXQ 3 | 384 | 없음 | 50×30·50×20·50×40·50×50 | 1~3 (기본 2) | `P50_` | Marklife 앱 |

- B1 프로필 `NIIMBOT_B1`도 같은 칸을 가진다: NIIMBOT B1, 방식 `NIIMBOT_B1`(niimbluelib), 384점, 돌림 없음, 크기 50×30·50×20·50×40, 농도 1~5(기본 3), 이름 앞자리 없음(연결한 뒤 모델 정보로 고른다 — L-7), 대체 경로 앱 NIIMBOT 앱.
- 목록: NIIMBOT 어댑터의 켠 프로필은 B1 하나(그대로). Marklife 어댑터의 기본 목록은 Marklife 9종(표 순서). **실험 목록**은 바우아토 하나이고, 부르는 쪽이 일부러 넘길 때만 쓴다(기본 목록에 없다). 프로필 하나를 더하는 일은 표에 한 줄을 더하는 것이다(코드 분기 없이).
- 바우아토는 실기기 확인(HG-5) 전까지 **실험적**이다. 기본 출력 경로는 라벨 그림 파일(PNG, L-6)을 Luck Jingle 앱으로 넘기는 것이고, 직접 출력은 판매자가 실험적 직접 출력을 고른 경우에만 쓴다(화면은 통합 스프린트).

2. **작업 바이트** (G-PRT-N1-01~34) — 1비트 그림 한 장(L-1 형식) + 농도 → 프린터로 보내는 바이트 전부를 만드는 순수 함수. 같은 그림·농도면 같은 바이트이고(시각·난수·실행 환경을 읽지 않는다), 브라우저와 Node가 같은 함수를 쓴다. 모두 간격 있는 라벨이다(연속 용지는 없다).
   - **돌림**: 돌림이 시계 방향 90도인 프로필은 받은 그림(폭 W × 높이 H)을 돌려 보낸다 — 보낼 그림의 점 (x, y) = 받은 그림의 점 (y, H−1−x), 보낼 그림은 폭 H × 높이 W. 받은 그림의 왼쪽 끝이 먼저 나온다.
   - 보낼 그림의 폭이 헤드 점 수보다 넓으면 보내지 않고 `IMAGE_TOO_WIDE`다. 좁은 그림은 채우지 않고 그 폭 그대로 보낸다(프로필의 크기에 맞는 그림은 라벨 패키지가 만든다). 그림이 L-1 형식이 아니면 `PRINT_FAILED`.
   - 래스터의 줄은 L-1 형식 그대로다(한 줄 ceil(폭/8)바이트, 왼쪽 점이 높은 비트, 1 = 검정). 폭 밖의 남는 비트는 점이 아니므로 받은 그림에 1이 있어도 늘 0으로 보낸다 — 라벨 밖에 엉뚱한 점이 찍히지 않게.
   - **YXQ 래스터** = `1F 10` + 한 줄 바이트 수(BE16) + 높이(BE16) + 압축 길이(BE32) + 줄 전부를 zlib으로 압축한 바이트. 압축 창은 1KiB(windowBits 10 — 첫 바이트 `28`)다. 기본 창(첫 바이트 `78`)은 쓰지 않는다 — 프린터가 받고도 버린다.
   - **L11 래스터** = `1D 76 30 00` + 한 줄 바이트 수(LE16) + 높이(LE16) + 줄 그대로(압축·길이 칸 없음).
   - 순서:
     - YXQ 2 (S2): `1F 70 01 <농도>` · `10 FF F1 02` · YXQ 래스터 · `1D 0C` · `10 FF F1 45`
     - YXQ 3 (P50) · YXQ 8 (X2): `1F 80 02 20` · `1F 70 02 <농도>` · `00`×6 · `1F C0 01 00` · `1F 11 51` · YXQ 래스터 · `1F 12 20 00` · `1F C0 01 01` · `1F 11 50`
     - L11 (Marklife 테이프 6종 · 바우아토): `00`×15 · `10 FF F1 02` · L11 래스터 · `1D 0C` · `10 FF F1 45`
   - **농도**: YXQ는 1~3 정수(1 흐리게 · 2 보통 · 3 진하게, 주지 않으면 2)이고 보내는 값은 YXQ 2·3이 `03`·`0A`·`0E`, YXQ 8이 `03`·`08`·`0E`다. 밖이면 보내지 않고 `INVALID_DENSITY`. L11·바우아토는 농도 명령을 보내지 않는다(프린터에 저장된 농도로 찍는다 — 받은 농도는 쓰지 않고 오류도 아니다).

3. **연결** — Web Bluetooth만 쓴다(USB·Web Serial 연결은 없다). 연결 방법 목록은 그 환경에 Web Bluetooth가 있으면 `bluetooth` 하나, 없으면 빈 목록이고 연결하면 `UNSUPPORTED`(문장은 6). 패키지를 import만 해서는 `navigator`를 건드리지 않고, 판매자가 누른 동작 안에서만 연결한다(L-7).
   - 브라우저의 기기 고르기 창은 이름이 켠 프로필의 앞자리로 시작하는 기기만 보이게 거르고(`namePrefix`), 함께 쓸 서비스로 `ff00`·`fd00`을 적는다.
   - **이름으로 고르기** (G-PRT-N1-41~64·76~78): 기기 이름이 프로필의 이름 앞자리로 시작하면 그 프로필이다 — 보는 것은 앞자리뿐이다. Marklife의 앞자리는 모델 이름 + 밑줄(`P12_`)이라 `P12`·`P12 Pro`·`P12PRO_…`·`Phomemo P12`처럼 이름이 같은 다른 기기는 고르지 않는다. 대소문자를 가리고 이름을 다듬지 않는다: 앞자리 앞에 무엇이 붙으면(공백 하나라도) 고르지 않고, 앞자리 뒤의 글(끝 공백·길이)은 보지 않는다. 기기 고르기 창의 `namePrefix` 거르기와 같은 판단이라, 창에 보인 기기가 이름 때문에 거절되지 않는다(D-N1-11). 앞자리끼리 겹치지 않으므로 맞는 프로필은 많아야 하나다.
   - 연결한 뒤 GATT 꾸러미를 차례로 찾는다: **A**(서비스 `ff00` — 쓰기 `ff02`, 알림 `ff01`, 흐름 제어 `ff03`) → **C**(서비스 `fd00` — 쓰기 `fd01`, 알림 `fd02`, 흐름 제어 없음). 둘 다 없거나, 이름이 켠 프로필과 맞지 않으면 연결을 끊고 `WRONG_MODEL`.
   - 고르기 창을 닫으면 `NOT_SELECTED`, GATT 연결 실패는 `DISCONNECTED`. `getAvailability()`가 false여도 한 번은 시도하고, 그 시도가 실패하면 어떤 이유든 `BLUETOOTH_OFF`다 — 다만 고른 기기가 다른 프린터라 `WRONG_MODEL`(이름이 켠 프로필과 다름·꾸러미 A·C 없음)이면 `WRONG_MODEL` 그대로다(L-7 "블루투스 켜짐 확인", QS1 D-QS1-03·D-QS1-11).

4. **보내기** — 작업 바이트를 앞에서부터 조각(패킷)으로 나눠 순서대로 쓴다.
   - 조각은 90바이트 이하다. 꾸러미 A의 `ff03`이 `02 lo hi`(MTU 알림, LE16)를 보내면 그 뒤 조각은 min(90, MTU − 3)바이트 이하다(MTU가 3 이하면 무시). 조각 크기는 줄기만 하고 90을 넘지 않는다.
   - 조각 사이에 30ms 쉰다(주입한 타이머). 간격은 앞 조각의 쓰기가 끝난 때부터 센다. 출력의 첫 조각은 쉬지 않는다.
   - **흐름 제어 (꾸러미 A)**: 보낼 수 있는 조각 수(크레딧)는 0에서 시작한다. `ff03`의 `01 n`을 받으면 크레딧 = min(4, 크레딧 + n)이다. 조각 하나를 쓸 때마다 크레딧 하나를 쓴다. 크레딧이 0이면 기다리고, 1초 동안 오지 않으면 조각 하나를 그냥 보낸다(알림을 놓친 것으로 본다). 1초는 30ms를 쉰 뒤 크레딧이 0인 것을 본 때부터 센다 — 크레딧이 끝내 오지 않으면 조각 사이는 1.03초다(D-N1-13). `ff03`·`ff01` 알림은 연결할 때 켠다(첫 `01 04`를 놓치지 않게). 꾸러미 C는 크레딧 없이 보낸다.

5. **끝 알림** — 출력은 프린터가 알림 특성(`ff01` 또는 `fd02`)으로 `AA`를 보내야 끝난다. 이번 출력의 첫 조각을 쓴 뒤 받은 `AA`만 센다. 모든 조각을 썼고 `AA`를 받았으면 출력 OK이고 상태는 `CONNECTED`로 돌아간다. **20초 동안 진행이 없으면** `TIMEOUT`, 그 전에 연결이 끊기면 `DISCONNECTED`다 — 모든 조각을 다 썼어도 `AA` 전이면 끊김이다. 20초는 출력을 시작할 때와 조각 하나의 쓰기가 끝날 때마다 새로 센다: 보내는 중이면 쓰기가 끝나지 않은 채 20초, 모든 조각을 쓴 뒤면 마지막 조각의 쓰기가 끝나고 `AA` 없이 20초다. 출력 전체 시간의 상한은 없다 — 작은 MTU·크레딧 없는 기기의 큰 라벨도 조각이 나가는 동안은 끝까지 보낸다(정상 출력을 시간 초과로 만들어 같은 라벨이 두 장 나오지 않게, D-N1-12). B1 어댑터·가짜 프린터의 시간 초과(L-7)는 그대로다. 바이트를 다 썼다는 것만으로 출력함이라 하지 않는다: 라벨이 조용히 빠지지 않게(L-8 3, D-P1-09 "두 장 나올 수는 있어도 빠지지 않는다"). `AA`를 받은 뒤의 끊김은 출력 실패가 아니다.
   - 나머지 계약(상태 네 가지와 알림, 출력 중 또 출력하면 `BUSY`, 연결 전 출력은 `NOT_CONNECTED`, 연결 끊기, 자동 연결 없음, 실패는 코드 + 문장 + 접어 둘 기술 상세)은 L-7 그대로다.

6. **오류 문장** (Marklife·바우아토 어댑터) — 코드는 L-7 표와 같다. 문장이 다른 것만 적는다. 나머지(`BLUETOOTH_OFF`, `DISCONNECTED`(+ `다시 연결`), `CONNECT_FAILED`(+ `다시 연결`, FB1 D-FB1-09), `NOT_CONNECTED`, `BUSY`, `IMAGE_TOO_WIDE`, `TIMEOUT`, `PRINT_FAILED`)는 L-7 표 문장 그대로이고, `PORT_BUSY`는 쓰지 않는다. B1 어댑터의 문장(L-7 표)은 바꾸지 않는다.

| 코드 | 문장 |
|---|---|
| `UNSUPPORTED` | 아래 "바로 연결할 수 없는 브라우저"의 까닭에 따라 |
| `NOT_SELECTED` | 프린터를 고르지 않았어요. 다시 연결을 누르고 목록에서 프린터를 골라 주세요. |
| `WRONG_MODEL` | 연결할 수 없는 프린터예요. 목록에 있는 프린터를 골라 주세요. |
| `INVALID_DENSITY` | 인쇄 농도는 1~3 사이의 정수로 정해 주세요. |

   **바로 연결할 수 없는 브라우저** (G-PRT-N1-81~95, NFR-05): 블루투스 연결 방법이 없을 때 까닭을 사용자 에이전트 글과 터치 점 수로 정한다. ① `iPhone`·`iPad`·`iPod`이 있거나, `Macintosh`가 있으면서 터치 점이 2개 이상이면 `IOS`. ② 아니면 `KAKAOTALK`·`Instagram`·`FBAN`·`FBAV`·`NAVER(inapp`·`Line/`·`DaumApps`·`; wv)` 중 하나가 있으면 `IN_APP`. ③ 아니면 `OTHER`. 글자 그대로(대소문자를 가려) 찾는다. 문장의 {앱}은 프로필의 대체 경로 앱이다.
   - `IOS`: 아이폰·아이패드에서는 프린터에 바로 연결할 수 없어요. 라벨을 그림 파일로 저장해 {앱}에서 인쇄해 주세요.
   - `IN_APP`: 카카오톡·인스타그램 같은 앱 안에서 연 화면에서는 프린터에 바로 연결할 수 없어요. 크롬에서 열거나, 라벨을 그림 파일로 저장해 {앱}에서 인쇄해 주세요.
   - `OTHER`: 이 브라우저에서는 프린터에 바로 연결할 수 없어요. 라벨을 그림 파일로 저장해 {앱}에서 인쇄해 주세요. ({앱}이 NIIMBOT 앱이면 L-7 표의 `UNSUPPORTED` 문장과 글자까지 같다.)

7. **가짜 기기** — Web Bluetooth 모양의 가짜(기기 고르기 창·GATT 꾸러미·쓰기·알림)를 시험과 개발에 쓴다. 받은 조각을 받은 순서대로 기록하고, 꾸러미(A·C·없음)와 기기 이름, 첫 크레딧 알림(`01 04` — 안 보냄 포함)과 조각마다의 보충, MTU 알림, `AA` 끝 알림(보냄·안 보냄·늦게), n번째 조각에서 끊김, n번째 조각의 쓰기가 끝나지 않음(멈춤 — 연결은 그대로, D-N1-12)을 미리 정할 수 있다. 시각·난수를 쓰지 않는다(주입한 타이머). 가짜 기기가 받은 조각을 이어 붙이면 작업 바이트 함수(2)의 결과와 바이트까지 같아야 한다.

8. 화면(프린터 고르기 마법사, 프로필마다의 크기·농도 고르기, 실험적 표시, 그림 파일 넘기기)과 서버(출력 기기의 프로필 기록)는 통합 스프린트가 한다. 이 절은 패키지가 지킬 규칙만 정한다.

## L-13. 라벨 기능 끄기 (SPEC RCP-01, N4a, D-N4a-01~D-N4a-06)

라벨 없이 파는 판매자를 위해 판매자 설정 하나로 라벨 기능 전체를 켜고 끈다. 엔진은 이 설정을 모른다 — 판정·효과·감사 문구·발송함 행은 켬/끔과 상관없이 같고(NFR-02), 서버가 효과를 출력 작업으로 만들지 않고 화면이 라벨 조작을 숨길 뿐이다.

1. **설정** (D-N4a-01): 판매자마다 "라벨 기능" 켬/끔 하나. 기본은 **켬**(기록이 없으면 켬). 판매 규칙 설정(DOMAIN_RULES 설정표)이 아니다 — 방송 설정 스냅샷·엔진 입력·골든 설정 키에 들어가지 않는다. `print.autoOnConfirm`(방송마다, 다음 방송부터)과 따로이고, 켬/끔은 **바꾼 때부터** 적용된다(방송 중에도). 판매자마다 따로다(SYS-02).
2. **이력** (D-N4a-01): 값이 실제로 바뀔 때마다 (바뀐 값, 시각(UTC 저장·KST 표시), 바꾼 계정) 한 줄을 남긴다. 지금과 같은 값으로 보내면 아무 일도 없고 기록도 없다. 이력은 지우지 않고, 서버를 다시 켜도 그대로다. 서버 로그에 켬/끔 요청 본문을 남기지 않아도 된다(바꾼 계정은 이력 표에만).
3. **효과 → 작업** (D-N4a-01): 실제 범위의 이벤트 기록 트랜잭션이 그 안에서 켬/끔을 읽는다. 꺼져 있으면 그 기록의 `PRINT_PRODUCT_LABEL` 효과로 작업을 만들지 않는다(L-11 2). 그 효과는 나중에 켜도 작업이 되지 않는다 — 켠 뒤에 기록된 이벤트의 효과만 자동 작업이 된다. 끄기·켜기 요청에 성공 응답을 받은 뒤 기록되는 이벤트는 반드시 바뀐 값을 따른다.
4. **폐기는 그대로** (D-N4a-02): 꺼져 있어도 L-11 5의 폐기(커밋마다 상태로, `VOID_LABEL`)를 그대로 한다. 끄기 전에 만든 작업·출력한 라벨의 찜이 1등이 아니게 되면 폐기되고, 출력한 것은 **버릴 라벨**이다. 폐기는 작업을 만들지 않는다.
5. **꺼져 있을 때의 요청** (D-N4a-03): 출력을 새로 시작하거나 라벨을 새로 만드는 요청은 거절한다(기록 없음, 코드 `LABELS_OFF`, 문장 "라벨 기능이 꺼져 있어요. 설정에서 켠 뒤 다시 해 주세요.") — 손으로 출력, 다시 출력, 포장 라벨 출력, 출력 기기 정하기("이 기기에서 출력"), 출력 기기의 작업 받기, 다시 시작·출력 시작, 라벨 설정(템플릿) 저장. 줄이거나 끝내는 요청과 조회는 받는다 — 버릴 라벨 "버렸어요", 출력 기기가 이미 가진 시도의 결과(L-11 6 — 출력함이면 L-11 7 보고), 대기 작업 빼기(하나·모두), 출력 멈추기, 출력 그만하기, 출력 기기의 프린터 연결 알림, 모든 조회, 켬/끔 바꾸기. 리허설 범위는 켬/끔과 상관없이 L-11 14 그대로다(리허설 거절이 먼저다).
6. **끌 때** (D-N4a-02): 대기 작업은 그대로 둔다(지우지도 출력 안 함으로 바꾸지도 않는다). 출력 기기 지정과 대기열 멈춤도 바꾸지 않는다. 출력 기기는 새 작업을 받지 못하고(5), 이미 받은 한 장은 마저 출력해 결과를 알린다.
7. **켤 때** (D-N4a-02): 대기 작업이 있고 대기열이 손으로 푸는 멈춤(판매자·프린터 오류·라벨 오류)이 아니면(멈추지 않았거나 끊김 멈춤) 판매자 멈춤 + 쌓인 라벨 안내("대기 중인 라벨 N장이 있어요. 출력 시작을 누르면 먼저 들어온 것부터 출력해요." + "출력 시작" — L-11 10과 같다)로 둔다. 손으로 푸는 멈춤이면 그 멈춤 그대로다. 대기 작업이 없으면 대기열 상태를 바꾸지 않는다.
8. **켠 뒤 손으로 출력** (D-N4a-04): 끈 동안 1등이 된 찜은 라벨 키에 작업이 없으므로 "라벨 출력"(L-11 3)으로 처음 출력한다. 그 라벨 키 (찜, 확정버전)에 그 범위의 `PRINT_PRODUCT_LABEL` 효과가 있으면 그 작업이 출력함이 될 때 L-11 7대로 그 효과를 보고한다(효과마다 한 번) — 자동 출력한 라벨과 같이 잠긴다(DOMAIN_RULES R-7 3, G-ENG-301).
9. **화면** (D-N4a-05): 꺼져 있으면 모든 기기에서(바뀌면 1초 안 — NFR-01) 라벨을 만들거나 출력하는 조작과 출력 상태가 보이지 않는다 — 메뉴 "라벨"·프린터 상태, 라벨 화면의 연결 마법사·출력 기기·대기열·이력·라벨 설정·자동 출력 설정·A4 내보내기, 라벨 상태, 라벨 미리 보기, 라벨 출력·다시 출력·포장 라벨 출력, 라벨 PNG·PDF, 알림 "출력 멈춤", Alt+P 창. 라벨이 있던 자리(라벨 화면·상품 자세히·정산 자세히)에는 "라벨 쓰지 않음 — 설정에서 켤 수 있어요."를 보인다. **버릴 라벨**(알림 띠·라벨 화면)만 남는다 — 끄기 전에 출력한 라벨이 엉뚱한 이름으로 포장되지 않게. 켬/끔을 아직 모르는 동안(불러오는 중·불러오기 실패)에도 라벨 조작을 보이지 않는다. 나중에 생기는 화면(포장 모드 I2, 시작 마법사·설정 화면 I3 등)도 같다 — 시작 마법사는 꺼져 있으면 프린터 단계를 건너뛴다.
10. **리허설**: 리허설은 켬/끔과 상관없이 출력이 없다(L-11 14). 꺼져 있으면 리허설 콘솔의 "리허설 방송은 라벨을 출력하지 않아요."도 보이지 않는다(라벨 문장이 아예 없다).
