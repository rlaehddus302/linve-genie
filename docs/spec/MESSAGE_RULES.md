# 메시지 규칙서 (MESSAGE_RULES)

> 버전 v0.1.0 · 2026-10-31 (KP1: 문자 종류·보낼 수 있는 시각·머리/꼬리 글·바이트·비용·수신 동의 — D-KP1-16~D-KP1-20) · 소유자: spec-keeper
> SPEC MSG-01·SCH-03(방송 알림 받기)·DAT-06(개인정보)의 세부. 이 문서와 [SPEC.md](SPEC.md)가 **진실의 원천**이다.
> 근거 법: 정보통신망법 제50조(영리 목적의 광고성 정보 전송 제한)와 시행령 제61조·제62조의3 — 미리 받은 수신 동의, 첫머리 "(광고)"와 보내는 사람, 무료 수신거부, 21시~다음 날 8시는 따로 동의, 2년마다 동의 사실 알림, 동의·거부·철회 처리 결과를 14일 안에 알림. 2026-10-01부터 과징금이 생기고 광고 전송을 맡아 보내는 일은 전송자격인증을 받은 사업자만 할 수 있다. 법 해석·처리방침 문장은 사용자 확인 몫(DECISIONS "사용자 확인 필요").
> 규칙은 서버(`apps/server`)의 순수 함수 넷(바이트 MR-4, 글 만들기 MR-3·MR-4·MR-5, 시각 MR-2, 동의 상태 MR-6)과 수신 동의 저장(MR-6)이다. **판정 엔진(`packages/core`)은 바꾸지 않는다.**
> 골든: `tests/golden/message/*.json`(G-MSG-KP1-*, 서버 단위 시험이 읽는다 — `tests/golden/README.md` "메시지 골든").
> 규칙을 바꾸려면 DECISIONS.md 결정 → 이 문서 → 골든 순서를 지킨다.

## MR-0. 원칙

1. **KP1은 문자를 보내지 않는다.** KP1은 이 규칙의 순수 함수(골든)와 방송 알림 수신 동의 모으기(SCH-03)까지만 한다. 실제 보내기(솔라피 연결·보내기 대기열·받은 결과)는 발송 스프린트에서 이 규칙대로 만든다(D-KP1-20). 그 전에는 어떤 문자·알림톡도 나가지 않는다.
2. **애매하면 광고로 본다.** 정해진 정보성 종류(MR-1 표) 밖의 글은 모두 광고성이다. 판매자가 직접 쓴 글은 내용과 상관없이 광고성이다.
3. **광고는 밤에 보내지 않는다.** 21:00~다음 날 07:59(KST)에는 광고성 문자를 보내지 않는다. 야간 수신 동의를 받지 않는다 — 받을 길 자체를 두지 않는다.
4. **동의가 확인된 번호에만 광고를 보낸다.** 동의 상태가 `ACTIVE`(MR-6)인 번호만.
5. **알림톡으로 광고를 보내지 않는다.** 카카오 알림톡은 정보성만 되고, 방송 알림은 광고라 문자(SMS·LMS)로만 보낸다.
6. **판매자가 보내는 사람이다.** 보내기는 판매자 본인 솔라피 계정·판매자가 등록한 발신번호로 한다(MR-7). 라이브지니가 광고 전송을 맡아 보내는 사업자가 되지 않는다.

## MR-1. 메시지 종류

| 종류 코드 | 무엇 | 구분 | 받는 사람 |
|---|---|---|---|
| `RECEIPT_LINK` | 주문 확인서 링크(RCP-02) | 정보성 | 그 묶음의 배송지·장부 연락처 |
| `PAYMENT_DUE` | 남은 금액·입금 계좌 안내 | 정보성 | 같음 |
| `SHIPPED` | 보낸 날·택배사·송장번호 | 정보성 | 같음 |
| `CONSENT_RESULT` | 수신 동의·철회 처리 결과(MR-6) | 정보성 | 그 번호 |
| `CONSENT_NOTICE` | 2년 수신 동의 사실 알림(MR-6) | 정보성 | `ACTIVE` 번호 |
| `BROADCAST_ALERT` | 방송 일정·시작 알림 | **광고성** | `ACTIVE` 번호 |
| `FREE_TEXT` | 판매자가 직접 쓴 글 | **광고성** (늘) | `ACTIVE` 번호 |

- 정보성 종류의 본문은 발송 스프린트가 정하는 고정 틀(값만 바뀜)로만 만든다 — 판매자가 정보성 본문에 글을 더할 수 없다. 틀 문장은 이번 판에 정하지 않는다.
- 사례: `compose.json` G-MSG-KP1-101·106~109.

## MR-2. 보낼 수 있는 시각 (순수 함수 — 골든 `window.json`)

- 광고성: 한국 시간 08:00:00 이상 21:00:00 미만에만 보낸다. 막히면 다음 08:00(KST)을 알린다 — 그 시각이 08:00 전이면 같은 날, 21:00 이후면 다음 날.
- 정보성: 시각 제한이 없다(거래를 끝내는 데 필요한 안내 — 밤 방송 뒤 바로 확인서·입금 안내).
- 보내는 순간(솔라피에 넘기는 순간)마다 다시 본다 — 예약해 둔 광고가 늦어져 21:00을 넘기면 보내지 않고 다음 08:00으로 미룬다.

## MR-3. 머리·꼬리 글 (순수 함수 — 골든 `compose.json`)

1. **본문 다듬기**: NFC, 줄바꿈 CRLF·CR → LF, 앞뒤 공백(`\s`) 지움. 비면 `EMPTY`.
2. **광고성**: 수신거부 번호(설정 — 판매자가 솔라피 등에서 받은 080 무료 번호)를 `-`·공백을 지워 읽는다. 비면 `NO_OPT_OUT`, `080` + 숫자 7~8자리가 아니면 `OPT_OUT_INVALID`. 글 = `(광고) {가게 이름}` + LF + 본문 + LF + `무료수신거부 {080 숫자}`. 판매자가 머리·꼬리를 지우거나 고칠 수 없다.
3. **정보성**: 글 = `[{가게 이름}] ` + 본문. 수신거부 번호는 보지 않는다.
4. 가게 이름은 설정 "가게"의 이름(1~30자, D-I2-02) 그대로.

## MR-4. 바이트와 SMS·LMS (순수 함수 — 골든 `bytes.json`·`compose.json`)

- 바이트 = 글의 코드 포인트마다 U+0000~U+007F면 1, 그 밖은 2. 글자 표로 거르지 않는다(그림 이모지도 2 — 받는 폰에서 깨질 수 있다는 안내는 화면 몫, D-036).
- 머리·꼬리를 더한 전체 글이 90바이트 이하면 `SMS`, 91~2,000바이트면 `LMS`, 넘으면 `TOO_LONG`(보내지 않는다). 그림 문자(MMS)는 하지 않는다.
- 오류 순서: `EMPTY` → `NO_OPT_OUT`·`OPT_OUT_INVALID` → `TOO_LONG`.

## MR-5. 비용 (순수 함수 — `compose.json`)

- 비용 = 한 건 값(종류별 — `SMS`·`LMS`) × 받는 사람 수, 정수 원. 한 건 값은 운영 설정(기본 SMS 20원·LMS 50원 — 솔라피 판매자 계정의 실제 값과 다를 수 있어 화면엔 "예상 비용"으로 적는다). 돈은 판매자 솔라피 계정에서 빠지고 라이브지니 요금(BILLING_RULES)과 상관없다.

## MR-6. 수신 동의 (방송 알림)

- **받는 곳**: 방송 일정 페이지(SCH-03)의 "알림 받기" 하나뿐. 판매자가 손님 대신 동의를 적을 수 없고, 손님 장부·구매·채팅에서 저절로 동의로 보지 않는다.
- **동의 칸**(문구 판 `MR-CONSENT-1`, 처음엔 비어 있는 필수 체크): "{가게}의 방송 알림(광고) 문자를 받을게요. 오전 8시~오후 9시 사이에만 보내요. 언제든 무료로 그만 받을 수 있어요. 번호는 그만 받을 때까지 보관하고, 2년마다 계속 받는지 알려 드려요."
- **기록**(덧붙이기): 번호마다(판매자 안 — 서버가 정규화한 휴대폰 번호의 전화번호 키로 같은 번호를 찾는다) 종류 `AGREE`(동의 — 문구 판·경로 `SCHEDULE_PAGE`·서버 시각), `VERIFY`(그 번호의 주인이 맞음을 확인 — 발송 스프린트의 확인 문자로만 생긴다), `WITHDRAW`(철회), `NOTICE`(2년 알림을 보냄). 휴대폰 번호 원문은 서버 마스터 키로 암호화해 두고 화면·응답·로그에 내지 않는다(판매자 화면엔 수만).
- **상태**(순수 함수, 골든 `consent.json`): `NONE`·`PENDING`(동의했고 번호 확인 전)·`ACTIVE`·`WITHDRAWN`·`EXPIRED`. 기준 날짜 = 마지막 `AGREE`의 KST 날짜와 그 뒤 마지막 `NOTICE`의 KST 날짜 중 늦은 날, 기한 = 기준 날짜 + 2년(2월 29일은 2월 28일), 오늘(KST) ≥ 기한이면 `EXPIRED`. 광고는 `ACTIVE`에만.
- **지우기**: `WITHDRAW`가 되면 그 번호 원문·전화번호 키를 바로 지운다(기록은 개인정보 없이 남는다). `EXPIRED`가 되면 그날 0시(KST)에 같은 방식으로 지운다(다시 받으려면 다시 신청). `PENDING`도 기한이 지나면 같다.
- **처리 결과 알림**: 동의·철회를 받으면 그 화면에 바로 "{가게} 방송 알림을 신청했어요 (2026-10-31)." / "{가게} 방송 알림을 그만 받아요 (2026-10-31)."를 보인다. 발송 스프린트부터는 14일 안에 `CONSENT_RESULT`도 보낸다(`ACTIVE`·확인된 번호에만). 2년 알림(`CONSENT_NOTICE`)은 기한 30일 전부터 보내고 보낸 날을 `NOTICE`로 남긴다.
- **번호 확인 전엔 보내지 않는다**: 공개 페이지라 남의 번호를 넣을 수 있다. 그래서 `VERIFY` 전(`PENDING`)에는 광고를 보내지 않는다. KP1에는 확인 문자를 보내는 길이 없어 모든 신청이 `PENDING`이다.

## MR-7. 보내는 길 — 판매자 본인 솔라피 계정 (발송 스프린트)

- 판매자가 설정 "문자 보내기"에서 자기 솔라피 계정의 API 키·비밀 키와 솔라피에 등록한 발신번호, 080 수신거부 번호를 넣는다. 키는 서버 마스터 키로 암호화하고 화면·응답·로그·백업에 내지 않는다(화면엔 끝 4자리). 발신번호 등록(사업자 서류)·080 번호·충전은 판매자가 솔라피에서 한다.
- 시험은 `127.0.0.1` 가짜 솔라피 서버로만 한다. 운영 기본은 꺼짐(운영자 스위치).
- 라이브지니는 판매자 계정의 키로 판매자 이름으로 부를 뿐 광고를 맡아 보내는 사업자가 아니다(MR-0 6). 판매자 사이에 발신번호·계정을 같이 쓰지 않는다.

## MR-8. 하지 않는 것

- 야간(21:00~07:59) 광고 수신 동의 받기·야간 광고 보내기.
- 알림톡·친구톡으로 광고 보내기, 그림 문자(MMS).
- 구매·채팅·장부를 광고 수신 동의로 보기, 판매자가 동의를 대신 적기.
- 라이브지니 이름이나 공용 발신번호로 판매자 광고 보내기(전송 위탁).
- 판매자 사이 수신자 목록 나누기.
