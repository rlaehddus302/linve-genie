## 읽는 법

- 항목마다 같은 순서로 적었다: **왜 필요한가 → 준비물 → 단계 → 시간·비용 → 끝났는지 확인하는 법**.
- **출시**는 두 가지로 나눠 쓴다.
  - **첫 실방송 전**: 사장님이 실제 방송에 라이브지니를 처음 쓰기 전.
  - **유료 출시 전**: 다른 판매자에게 돈을 받고 서비스를 열기 전.
- 이 문서에는 비밀값(비밀번호, 키, 토큰)을 하나도 적지 않는다. 사장님도 이 문서나 채팅, 메일에 적지 마세요. 다루는 법은 [비밀값 다루는 법](#비밀값-다루는-법)에 있다.

## 비밀값 다루는 법

**비밀값**은 남이 알면 서비스나 돈이 위험해지는 값이다. 이 가이드에서 생기는 비밀값은 아래와 같다.

| 비밀값 | 어디서 생기나 |
|---|---|
| 데이터베이스 연결 문자열 (`DATABASE_URL`) | 1번 호스팅 |
| 서버 마스터 키 (`LIVEJJIM_MASTER_KEY`) | 1번 직접 만듦 |
| 판매자 비밀번호 | 2번 |
| 구글 클라이언트 보안 비밀 | 3번 |
| 메타 앱 시크릿, 웹훅 확인 토큰 | 4번 |
| 팝빌 비밀 키 | 6번 |
| 포트원 API 시크릿 | 7번 |

지키는 규칙:

1. **비밀번호 관리자**(비밀번호를 암호화해 보관해 주는 앱. 예: 1Password, Bitwarden, 애플 암호 앱)에 넣는다.
2. 이 문서, 카카오톡, 메일, 메모장, 사진에 적지 않는다.
3. 개발 쪽에 건넬 때도 값을 보내지 않는다. **호스팅 업체 화면의 "환경 변수" 칸에 사장님이 직접 넣는다.** 환경 변수는 서버 프로그램이 읽는 설정값이다.
4. 새어 나간 것 같으면 그 업체 화면에서 새 값을 발급하고 개발 쪽에 알린다. **단, 서버 마스터 키는 함부로 바꾸지 말고 먼저 개발 쪽과 상의한다**(1번 참고).

## 1. 도메인과 호스팅(HTTPS)

**왜 필요한가**: 휴대폰 접속, 블루투스 프린터 연결, 로그인 유지(쿠키)가 모두 **HTTPS** 주소에서만 제대로 동작한다.

용어 풀이:
- **도메인**: 인터넷 주소. 예: `livejjim.kr`.
- **HTTPS**: 주소창에 자물쇠가 보이는 암호화된 연결.
- **호스팅**: 서버 컴퓨터를 빌려 주는 업체.
- **컨테이너**: 프로그램과 필요한 것을 상자 하나로 묶어 서버에 올리는 방식. 라이브지니는 컨테이너 1개로 돈다.
- **관리형 PostgreSQL**: 업체가 백업과 관리를 맡아 주는 데이터베이스(판매 기록을 저장하는 곳).

**준비물**
- 결제용 카드, 업무용 이메일
- 비밀번호 관리자 앱
- 도메인 이름 후보 2~3개
- 마스터 키를 따로 보관할 곳 (종이 봉투나 USB를 넣어 둘 금고·서랍)

**단계**

1. **도메인 사기**
   - 가비아, 후이즈, 카페24, Cloudflare 같은 도메인 업체에서 산다.
   - 홈페이지는 `livejjim.kr`, 서비스 화면은 `app.livejjim.kr`처럼 **같은 도메인 아래**에 둔다. 유튜브 검증(3-3) 때 홈페이지와 개인정보처리방침이 같은 도메인에 있어야 한다.
2. **호스팅 업체 고르기**
   - 컨테이너 1개 + 관리형 PostgreSQL을 함께 쓸 수 있는 업체를 고른다. 후보: Fly.io, Railway, Render 등(D-001). 개발 쪽과 비용을 보고 함께 정한다.
   - 서버 지역은 한국에서 가까운 곳(서울·도쿄 등)을 고른다. 판정이 빨라진다.
3. **데이터베이스 만들기**
   - 업체 화면에서 PostgreSQL을 하나 만든다.
   - **백업**(특히 "시점 복구": 원하는 시각으로 되돌리기)이 켜져 있는지 확인한다.
   - 업체가 보여 주는 **연결 문자열**(`postgres://`로 시작)을 비밀번호 관리자에 저장한다. 이것도 비밀값이다.
4. **서버 마스터 키 만들기**
   - 마스터 키는 판매자마다 있는 "전화번호 키"를 잠그는 열쇠다(D-073). 문자찜 구매자를 같은 사람으로 알아보는 데 쓴다.
   - 맥이면 "터미널" 앱을 열고 아래 한 줄을 입력한다. 무작위 글자 44자가 나온다.
     ```
     openssl rand -base64 32
     ```
     Node가 깔린 컴퓨터라면 `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"`도 같다.
   - 나온 값을 **두 곳**에 보관한다: (1) 비밀번호 관리자, (2) 종이에 적거나 USB에 담아 금고에. 화면 캡처, 채팅, 메일에는 남기지 않는다.
   - **경고: 마스터 키를 잃으면 되살릴 방법이 없다.** 그 뒤로 들어오는 문자찜은 이전 문자 구매자와 이어지지 않는다. 같은 전화번호라도 다른 사람으로 잡힌다.
   - 키를 바꾸는 것도 같은 문제를 만든다. 키를 바꿔 넣는 명령은 아직 없다. 바꿔야 할 일이 생기면 개발 쪽과 먼저 상의한다.
5. **환경 변수 넣기** (호스팅 업체 화면의 "Environment Variables" 또는 "Secrets")

   | 이름 | 넣을 값 |
   |---|---|
   | `DATABASE_URL` | 3단계의 연결 문자열 |
   | `LIVEJJIM_MASTER_KEY` | 4단계의 마스터 키 |
   | `LIVEJJIM_APP_ORIGIN` | 서비스 화면 주소. `https://app.livejjim.kr`처럼 끝에 `/`나 경로 없이 |
   | `PORT` | 업체가 정해 주는 경우가 많다. 업체 안내를 따른다 |

   - `LIVEJJIM_PGLITE_DIR`는 개발용이다. 운영에서는 넣지 않는다. `DATABASE_URL`과 함께 있으면 서버가 시작하지 않는다.
   - 유튜브·인스타·팝빌·포트원 키는 뒤에서 하나씩 더한다. 이름은 개발 쪽이 `.env.example`에 적어 준다.
6. **도메인 연결과 HTTPS**
   - 호스팅 업체 화면에서 "사용자 지정 도메인(Custom Domain)"에 `app.livejjim.kr`를 넣는다.
   - 업체가 보여 주는 값(CNAME 또는 A 레코드)을 도메인 업체 화면의 "DNS 설정"에 그대로 넣는다. DNS는 주소와 서버를 잇는 전화번호부다.
   - 몇 분~최대 48시간 뒤 업체가 HTTPS 인증서를 자동으로 붙인다(대부분 무료).
7. **배포 요청**
   - 컨테이너 설정 파일은 개발 쪽이 배포 단계(S12)에서 만든다. 사장님은 위 값을 넣은 뒤 개발 쪽에 "환경 변수와 도메인 준비 끝"이라고 알린다.

**시간·비용**
- 작업 반나절~1일, 주소 연결 대기 최대 48시간.
- 도메인 연 2~3만 원 안팎, 서버+데이터베이스 월 1~5만 원 안팎. 업체와 요금제에 따라 다르다 (확인 필요). 업체를 고를 때 확정한다(D-001).

**끝났는지 확인하는 법**
- [ ] 휴대폰에서 `https://app.도메인`을 열면 주소창에 자물쇠가 보이고 로그인 화면이 뜬다.
- [ ] 업체의 로그 화면에 `시작하지 못했어요.`로 시작하는 문장이 없다. 이 문장이 보이면 뒤에 무엇이 없는지 적혀 있다. 예: `서버 마스터 키(LIVEJJIM_MASTER_KEY)가 없어요.`
- [ ] 마스터 키가 비밀번호 관리자와 오프라인 보관처, 두 곳에 있다.
- [ ] 데이터베이스 백업이 켜져 있다.

## 2. 판매자 계정 만들기

**왜 필요한가**: 라이브지니에는 가입 화면이 없다. 운영자가 서버 명령으로 계정을 만든다(D-074).

**준비물**
- 가게 이름: 50자 이하
- 아이디: 영문 소문자로 시작, 3~32자, 영문 소문자·숫자·`_`·`.`·`-`만. 대문자로 넣어도 소문자로 바뀐다.
- 비밀번호: 8자 이상 200자 이하. 비밀번호 관리자에서 만들어 저장한다.
- 명령을 입력할 곳: 호스팅 업체 화면의 "Shell" 또는 "Console" 메뉴. 업체마다 다르다. 개발 쪽이 배포(S12) 때 정확한 방법을 알려 준다 (확인 필요).

**단계**

1. 호스팅 업체의 Shell(명령 입력 창)을 연다. 1번에서 넣은 환경 변수를 그대로 쓰는 곳이어야 한다.
2. 아래처럼 입력한다. `가게 이름`과 `아이디`는 실제 값으로 바꾼다.
   ```
   pnpm --filter @livejjim/server create-account --name "가게 이름" --login 아이디
   ```
3. `비밀번호:`가 나오면 비밀번호를 입력하고 Enter를 누른다. 입력해도 화면에 글자가 보이지 않는 게 정상이다.
4. `계정을 만들었어요.`가 나오면 끝이다.

**꼭 지킬 것**
- 비밀번호를 명령 줄에 쓰지 않는다. 명령 기록에 남는다. 명령도 비밀번호를 인자로 받지 않는다.
- 이 명령은 **운영 서버와 똑같은** `LIVEJJIM_MASTER_KEY`와 `DATABASE_URL`을 읽어야 한다. 다른 마스터 키로 만들면 운영 서버가 그 판매자의 전화번호 키를 풀지 못한다.
- 데이터베이스 표는 명령이 알아서 만든다.

**오류 문장과 할 일**

| 화면 문장 | 할 일 |
|---|---|
| `사용법: create-account --name "가게 이름" --login 아이디 ...` | `--name`이나 `--login`을 빠뜨렸다. 다시 입력 |
| `모르는 인자예요. ...` | 철자 확인. 쓸 수 있는 것은 `--name`, `--login` 두 개뿐 |
| `이미 있는 아이디예요.` | 다른 아이디로 |
| `아이디는 영문 소문자로 시작하는 3~32자...` | 아이디 규칙 확인 |
| `비밀번호는 8자 이상 200자 이하로...` | 비밀번호 길이 확인 |
| `서버 마스터 키(LIVEJJIM_MASTER_KEY)가 없어요.` | 환경 변수 확인(1번 5단계) |
| `데이터베이스 연결 설정이 없어요...` / `데이터베이스를 열지 못했어요...` | `DATABASE_URL` 확인 |

**알아 둘 것**
- 같은 아이디로 비밀번호를 10번 연속 틀리면 그 아이디는 15분 동안 로그인할 수 없다. 이미 로그인한 기기는 그대로 쓴다.
- 로그인은 30일 유지되고, 쓰는 동안 저절로 연장된다. 방송 중에 풀리지 않게 하려는 설정이다.
- 비밀번호를 바꾸거나 계정을 지우는 명령은 아직 없다. 필요하면 개발 쪽에 요청한다.

**시간·비용**: 10분, 없음.

**끝났는지 확인하는 법**
- [ ] PC 크롬과 휴대폰에서 새 아이디로 로그인된다.

## 3. 유튜브

**왜 필요한가**: 유튜브 라이브 채팅을 공식 방법(API)으로 읽고 감사 메시지를 쓰려면, **사장님 명의의 구글 클라우드 프로젝트**와 계정 연결 설정이 필요하다(D-019). API는 프로그램끼리 정보를 주고받는 공식 창구다.

### 3-1. 구글 클라우드 프로젝트 만들고 YouTube Data API 켜기

**준비물**
- 운영용 구글 계정. 판매 채널 계정과 나누는 것을 권한다.
- 1번의 도메인

**단계**

1. [console.cloud.google.com](https://console.cloud.google.com)에 운영용 계정으로 들어간다.
2. 위쪽 프로젝트 이름 → "새 프로젝트" → 이름(예: `livejjim`) → 만들기.
3. 왼쪽 메뉴 "API 및 서비스" → "라이브러리" → `YouTube Data API v3` 검색 → "사용".

**꼭 알아 둘 것**
- **프로젝트는 하나만 쓴다.** 서비스 하나에 프로젝트 하나가 정책이다. 할당량을 피하려고 프로젝트를 쪼개는 것은 금지다.
- **할당량**(하루에 쓸 수 있는 API 양)은 하루 10,000 units이다. 이 양을 **모든 판매자가 나눠 쓴다.**
  - 3시간 방송 1회(감사 메시지 100건 포함)에 약 2,200 units가 든다. 기본 할당량으로 하루 약 4회분이다.
  - 판매자 1명일 때는 충분하다. 여럿이면 3-4의 증설이 필요하다.

### 3-2. OAuth 동의 화면 설정(테스트 모드)

용어 풀이:
- **OAuth 동의 화면**: 판매자가 "라이브지니가 내 유튜브 채널을 써도 될까요?"에 허락하는 구글 화면.
- **갱신 토큰**: 한 번 허락하면 다시 로그인하지 않아도 계속 쓰게 해 주는 열쇠.

**단계** (콘솔 메뉴는 "OAuth 동의 화면" 또는 "Google 인증 플랫폼"으로 보인다)

1. "API 및 서비스" → "OAuth 동의 화면"(또는 "Google 인증 플랫폼") → 시작하기.
2. 앱 이름(`라이브지니`), 사용자 지원 이메일, 개발자 연락처 이메일을 넣는다.
3. 사용자 유형은 **외부(External)**를 고른다.
4. 브랜딩에 넣을 것: 홈페이지 주소, 개인정보처리방침 주소, 서비스 약관 주소, 승인된 도메인(1번의 도메인).
5. 데이터 액세스(범위, scope)에 아래 둘을 더한다. 지금 개발 중인 코드 기준이다.
   - `.../auth/youtube.readonly`: 내 채널과 방송 목록 읽기
   - `.../auth/youtube.force-ssl`: 채팅 읽기와 감사 메시지 쓰기
6. 대상 → **테스트 사용자**에 판매자의 구글 계정 이메일을 넣는다.
7. 클라이언트 → "클라이언트 만들기" → 유형 "웹 애플리케이션".
   - "승인된 리디렉션 URI"에는 개발 쪽이 알려 주는 주소를 넣는다. 지금 작업 중인 기준은 `https://app.도메인/api/youtube/oauth/callback`이다(바뀔 수 있음).
8. 화면에 나오는 **클라이언트 ID**와 **클라이언트 보안 비밀**을 비밀번호 관리자에 저장한다. 호스팅 환경 변수에 직접 넣는다. 이름은 개발 쪽이 `.env.example`에 적는다(작업 중 이름 예: `LIVEJJIM_GOOGLE_CLIENT_ID`, `LIVEJJIM_GOOGLE_CLIENT_SECRET`, `LIVEJJIM_GOOGLE_REDIRECT_URI`).

**테스트 모드의 제약**
- **갱신 토큰이 7일마다 만료된다.** 판매자는 매주 라이브지니 설정에서 "유튜브 다시 연결"을 눌러야 한다.
- **사용자는 100명까지다.** 프로젝트 평생 한도이고 되돌릴 수 없다.
- 연결할 때 "확인되지 않은 앱" 경고 화면이 뜬다. "고급" → "계속"을 눌러 넘어간다.
- 사장님 혼자 쓰는 초기에는 감수할 만하다. 판매자를 여럿 받기 전에 3-3 검증을 받는다.

**자동 게시 동의**: 감사 메시지는 판매자가 설정 화면에서 자동 게시에 **동의 체크**를 하기 전에는 올라가지 않는다(유튜브 정책, SPEC YT-04 AC2).

**시간·비용**: 반나절, 무료.

**끝났는지 확인하는 법**
- [ ] 판매자가 라이브지니 설정에서 유튜브 연결 → 구글 허락 화면 → 허락 → 라이브지니에 채널 이름이 보인다.

### 3-3. 앱 검증(민감 권한)

**왜 필요한가**: 유튜브 권한은 구글이 "민감" 등급으로 분류한다(콘솔에서 확인 필요). 검증을 받아야 경고 화면, 100명 상한, 7일 만료가 사라진다.

**준비물**
- **공개 홈페이지**: 내 도메인에 있고, 라이브지니가 무엇을 하는지 설명한다. 로그인 화면만 있으면 안 된다. 개인정보처리방침 링크가 있어야 한다.
- **같은 도메인의 개인정보처리방침**
  - 구글 사용자 데이터를 어떻게 읽고, 쓰고, 저장하고, 나누는지 적는다.
  - 구글 개인정보처리방침 링크(https://policies.google.com/privacy)를 넣는다.
  - 유튜브 서비스 약관 링크(https://www.youtube.com/t/terms)도 함께 넣는다.
  - 홈페이지와 동의 화면에 넣은 링크가 똑같아야 한다.
- **서치 콘솔 도메인 확인**: 내 도메인이 내 것임을 구글에 증명한다. 프로젝트 소유자나 편집자 계정으로 해야 한다.
- **권한 설명(영어)**: 범위마다 왜 필요한지, 더 좁은 범위로는 왜 안 되는지 적는다. 아직 만들지 않은 기능을 이유로 권한을 요청하면 안 된다.
- **영어 데모 영상**(유튜브 일부공개 링크로 제출)
  - 같은 앱 이름과 로고로 처음부터 끝까지 보여 준다.
  - 동의 화면 왼쪽 아래 언어를 **English**로 바꾼다.
  - 요청한 범위가 다 보이는 동의 화면을 보여 준다.
  - 범위마다 그것을 쓰는 기능을 보여 준다. 채널·방송 목록 고르기, 채팅이 찜이 되는 장면, 감사 메시지가 올라가는 장면.

**단계**

1. [search.google.com/search-console](https://search.google.com/search-console) → 속성 추가 → "도메인" → 내 도메인 입력 → 보여 주는 TXT 값을 도메인 업체 DNS 설정에 넣는다 → "확인".
2. 홈페이지와 개인정보처리방침을 올린다. 내용은 9번 법률 확인을 거친다.
3. OAuth 동의 화면 → "앱 게시"(프로덕션으로 전환) → 검증 제출. 권한 설명과 데모 영상 링크를 넣는다.
4. 구글이 메일로 질문하면 답한다. 스팸함도 확인한다.

**시간·비용**: 준비 1~2주, 검토 3~5영업일(TECH_REVIEW §2.5. 구글 공식 문서에는 기간이 없다), 무료.

**끝났는지 확인하는 법**
- [ ] 콘솔의 검증 상태가 "확인됨(Verified)"이다.
- [ ] 새 판매자가 연결할 때 경고 화면이 뜨지 않는다.
- [ ] 7일이 지나도 다시 연결하지 않아도 된다.

### 3-4. 할당량 증설 감사

**왜 필요한가**: 하루 10,000 units를 모든 판매자가 나눠 쓴다. 판매자가 여럿이면 방송 중에 채팅 수집이나 감사 메시지가 멈출 수 있다.

**준비물**
- 서비스 설명과 화면 캡처 또는 영상
- 사용량 추정: 3시간 방송 1회 ≈ 2,200 units × 판매자 수 × 하루 방송 수
- 30일 보관 규정을 어떻게 지키는지 설명(3-5)

**단계**

1. 판매자를 여럿 받기 **전에** "YouTube API Services - Audit and Quota Extension Form"을 제출한다. 안내: [developers.google.com/youtube/v3/guides/quota_and_compliance_audits](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits)
2. 유튜브 정책 준수 감사를 먼저 통과해야 증설된다. 담당자가 연락하면 답한다.

**시간·비용**: 처리 기간은 공개되지 않았다. 구글은 "가능한 한 빨리" 연락한다고만 적었다 (확인 필요). 무료.

**끝났는지 확인하는 법**
- [ ] 콘솔 "API 및 서비스 → 할당량"에서 하루 한도가 늘었다.
- [ ] 라이브지니 화면의 유튜브 사용량 표시(YT-08)가 새 한도를 보여 준다.

### 3-5. 30일 데이터 보관 규정

**왜 필요한가**: 유튜브 개발자 정책을 어기면 API가 막힐 수 있다.

- 정책 내용(TECH_REVIEW §2.6)
  - API로 받은 데이터는 **30일 안에 갱신하거나 삭제**해야 한다.
  - 판매자가 연결을 끊으면 7일(앱에서 끊은 경우) 또는 30일(구글 설정에서 끊은 경우) 안에 지워야 한다.
  - 삭제 요청은 7일 안에 처리해야 한다.
- 판매 장부(누가 무엇을 얼마에 샀는지)는 세법상 오래 보관해야 할 수 있다. 두 규칙이 부딪친다.
- 라이브지니의 설계 제안(D-012, D-078)
  - **유튜브 원본**(채팅 원문, API 닉네임)은 30일 규정을 따른다.
  - **판매자 장부**(판매자가 확정한 구매자 표시 이름, 거래 내역)는 판매자 소유 기록으로 따로 둔다.

**사장님이 할 일**
1. 유료 출시 전에 이 나눔이 정책과 세법에 맞는지 **법률 검토**를 받는다(9번).
2. 개인정보처리방침에 보관 기간과 삭제 방법을 적는다.

**끝났는지 확인하는 법**
- [ ] 법률 검토 의견을 받아 보관했다.
- [ ] D-012 상태를 확정했다(DECISIONS 표).

## 4. 인스타그램

**왜 필요한가**: 인스타 라이브 댓글을 공식 API로 받으려면 메타 개발자 앱과 메타 심사가 필요하다(SPEC PLT-01). 심사는 사장님 몫이다.

용어 풀이:
- **웹훅**: 댓글이 생길 때마다 메타가 라이브지니 서버로 바로 알려 주는 방식.
- **비즈니스 인증**: 메타가 사업자가 실제로 있는지 확인하는 절차.
- **고급 권한(Advanced Access)**: 앱에 역할이 없는 일반 사용자(다른 판매자)도 기능을 쓰게 하는 권한 등급. 받기 전에는 앱 관리자·개발자·테스터만 쓸 수 있다.
- **프로페셔널 계정**: 인스타의 비즈니스 계정 또는 크리에이터 계정.

**준비물**
- 사장님 페이스북 개인 계정(개발자 등록용)
- 메타 비즈니스 포트폴리오(옛 이름 "비즈니스 관리자")
- 사업자등록증, 1번의 도메인·홈페이지·개인정보처리방침
- 판매자의 인스타 **비즈니스 또는 크리에이터 계정**
- Facebook Login을 고르면 판매자의 **페이스북 페이지**와 그 페이지에 연결된 인스타 계정

### 로그인 방식 고르기

라이브지니는 두 방식을 모두 받을 수 있게 만들고 있다. 개발 기본값은 **Facebook Login**이다(백로그 N2). 하나를 골라 개발 쪽에 알린다.

| | Facebook Login | Instagram Login |
|---|---|---|
| 판매자 준비 | 인스타 프로페셔널 계정 + 연결된 페이스북 페이지 | 인스타 프로페셔널 계정만 |
| 심사받을 권한 (작업 중 코드 기준) | `instagram_basic`, `instagram_manage_comments`, `instagram_manage_messages`, `pages_show_list`, `pages_read_engagement`, `pages_manage_metadata` | `instagram_business_basic`, `instagram_business_manage_comments`, `instagram_business_manage_messages` |
| 판단 | 판매자들이 이미 페이지를 쓰면 | 판매자들에게 페이지가 없으면 더 쉽다 |

### 단계

1. [developers.facebook.com](https://developers.facebook.com)에서 개발자로 등록한다.
2. "앱 만들기" → 인스타그램 사용 사례 → 앱 유형 "비즈니스"를 고른다(화면 이름은 바뀔 수 있음, 확인 필요).
3. **판매자 계정 바꾸기**: 판매자 인스타 앱 → 설정 → "계정 유형 및 도구" → "프로페셔널 계정으로 전환" → 비즈니스 또는 크리에이터(메뉴 이름은 바뀔 수 있음). Facebook Login이면 페이스북 페이지에 연결한다.
4. **웹훅 설정**: 앱 대시보드 → 웹훅 → Instagram
   - 콜백 URL: 개발 쪽이 알려 주는 주소.
   - 확인 토큰: 개발 쪽과 같은 비밀값. 문서에 적지 않는다.
   - "확인 및 저장" → 필드 **`live_comments`**를 구독한다.
5. **앱 기본 정보**: 개인정보처리방침 주소, 아이콘, 카테고리를 넣는다. 사용자 데이터 삭제 안내 주소도 요구될 수 있다 (확인 필요).
6. **비즈니스 인증**: 메타 비즈니스 설정 → 보안 센터 → "인증 시작" → 사업자등록증, 회사 이름·주소·전화·웹사이트를 넣고 회사 메일이나 전화로 인증한다(메뉴 이름은 바뀔 수 있음).
7. **앱 심사**: 위 표의 권한마다 고급 권한을 요청한다.
   - 권한마다 쓰는 이유를 적고, 그 기능을 보여 주는 화면 녹화를 올린다(영어 권장, 확인 필요).
   - 심사자가 써 볼 시험 계정 정보는 메타 심사 양식에만 넣는다.
8. 앱을 **라이브 모드**로 바꾼다.
9. 앱 ID와 앱 시크릿을 비밀번호 관리자에 저장하고, 호스팅 환경 변수에 직접 넣는다. 이름은 개발 쪽이 알려 준다.

**주의**: 메타 문서에 따르면 `live_comments` 웹훅은 앱이 라이브 모드이고 고급 권한과 비즈니스 인증이 있어야 온다. 그래서 사장님 혼자 쓰는 단계라도 **인스타 판매를 시작하기 전에 심사가 먼저 필요할 수 있다** (확인 필요).

### 감사 메시지 안내 (판매자에게 꼭 알릴 것)

- 인스타 라이브 댓글에는 **공개 답글을 달 수 없다.** 그래서 라이브지니는 댓글 쓴 사람에게 **개인 답장(DM)**으로 감사 인사를 보낸다.
- DM은 **라이브 중에만**, 한 사람에게 **한 번만** 보낼 수 있다. 방송이 끝나면 보낼 수 없다.
- 상대가 답장하면 24시간 안에 한 번 더 보낼 수 있다.
- 방송 화면에 "감사 인사는 DM으로 보내 드려요" 같은 안내를 띄우면 시청자가 덜 헷갈린다.
- 인스타 댓글에는 쓴 시각이 따로 오지 않는다. 그래서 인스타 방송의 선착순은 **서버에 도착한 순서**로만 정한다.
- 방송이 끝나면 댓글을 다시 가져올 수 없다. 라이브지니는 받는 즉시 기록한다.

**시간·비용**: 무료. 비즈니스 인증과 앱 심사가 각각 수일~수주 걸린다 (확인 필요).

**끝났는지 확인하는 법**
- [ ] 앱 대시보드에서 권한마다 "고급 권한", 비즈니스는 "인증됨"으로 보인다.
- [ ] 판매자 계정으로 테스트 라이브를 켜고 다른 계정으로 `15`를 댓글로 달면 라이브지니 상품 보드에 찜이 생긴다(HG-3).
- [ ] 댓글 쓴 계정에 감사 DM이 한 번 온다.

## 5. 틱톡(베타)

**왜 이 항목이 있나**: 틱톡에는 라이브 댓글을 읽는 **공식 API가 없다.** 라이브지니는 비공식 연결로 **댓글만 읽는 베타**를 만든다(D-904).

**위험 고지** (판매자에게도 그대로 알린다)
- 틱톡 약관은 자동 수집과 역분석을 금지한다. 비공식 연결은 약관 위반이 될 수 있다.
- 틱톡이 언제든 연결을 막을 수 있다. 방송 중에 갑자기 끊길 수 있다.
- 판매자 계정이 제재를 받을 가능성도 배제할 수 없다 (확인 필요).

**라이브지니에 이미 들어간 안전장치**
- 판매자가 위험 고지를 읽고 **직접 켤 때만** 동작한다. 판매자마다 끌 수 있다.
- **운영자 전체 끄기 스위치**: 사장님이 환경 변수 하나로 모든 판매자의 틱톡 연결을 한 번에 끈다. 이름은 개발 쪽이 정한다(백로그 N2b-1).
- 틱톡에 글을 올리지 않는다. 감사 메시지도 없다.
- 판매자의 틱톡 로그인 정보(세션 쿠키)를 받지도 저장하지도 않는다.
- 연결이 막히면 **수동 입력**(댓글을 복사해 붙여넣기)으로 바로 넘어간다.

**사장님이 할 일**

1. **유료 출시 전 법률 검토**: 틱톡 약관, 공개 댓글 닉네임·사용자 ID 수집의 개인정보 문제, 위험 고지 문구를 변호사에게 확인받는다(9번).
2. 검토 결과에 맞춰 위험 고지 문구를 확정한다.
3. **끄기 스위치 연습**: 출시 전에 한 번 켜 보고, 모든 판매자의 틱톡 연결이 멈추는지 본다. 환경 변수를 바꾼 뒤 서버를 다시 시작하면 적용된다.
4. 틱톡의 경고·차단 소식을 듣거나 법률 의견이 부정적이면 **바로 끈다.**

**시간·비용**: 법률 검토 기간과 자문비 (확인 필요).

**끝났는지 확인하는 법**
- [ ] 법률 검토 의견서를 보관했다.
- [ ] 끄기 스위치를 켰을 때 틱톡 연결이 모두 멈추는 것을 봤다.
- [ ] 판매자용 위험 고지 문구를 확정했다.

## 6. 입금 자동 확인

**왜 필요한가**: 은행 입금 내역을 자동으로 가져와 정산 묶음과 맞춘다(SPEC PAY-01). 금액이 같고 입금자 이름이 맞는 확실한 건만 자동으로 기록하고, 애매한 건은 "확인 필요" 목록에 남는다.

용어 풀이:
- **팝빌**: 계좌 조회, 세금계산서 발행 같은 기능을 API로 빌려주는 회사. 라이브지니는 팝빌의 계좌조회(EasyFinBank)를 쓴다.
- **빠른조회 서비스**: 공동인증서 없이 조회 전용 비밀번호로 입출금 내역을 볼 수 있게 은행에 미리 등록하는 서비스. 은행마다 이름이 다르다(스피드조회, 간편조회, 바로바로서비스 등).

### 운영자(사장님)가 할 일 — 한 번만

1. [popbill.com](https://www.popbill.com)에 사업자로 가입한다.
2. [developers.popbill.com](https://developers.popbill.com)에서 **연동 신청**을 한다. 연동 아이디(LinkID)와 비밀 키(SecretKey)를 받는다. 비밀 키는 비밀값이다.
3. 개발 쪽이 테스트 환경에서 확인한 뒤 **운영 환경으로 전환**한다.
4. 요금을 누가 낼지 정한다. 판매자마다 팝빌 회원으로 내게 할지, 사장님이 "파트너 포인트"로 한꺼번에 낼지 고른다 (확인 필요).
   - 계좌를 등록하면 정한 기간(1~12개월)만큼 요금이 빠진다.
   - 해지하면 그 기간이 끝날 때 닫힌다.
5. 연동 아이디와 비밀 키를 호스팅 환경 변수에 직접 넣는다. 이름은 개발 쪽이 알려 준다.

### 판매자가 할 일 — 계좌마다

1. 인터넷뱅킹에서 **빠른조회 서비스**를 신청한다. 메뉴 예시(제3자 안내 기준, 바뀔 수 있음):
   - 국민: 계좌관리(개인) / 빠른조회 관리(법인)
   - 신한: 고객센터 → 회원서비스 → 간편조회서비스
   - 우리: 스피드조회 계좌 등록
   - 하나: 계좌정보관리 → 빠른조회 관리
   - 농협: 뱅킹서비스관리(개인) / 계좌관리(법인) → 빠른조회 등록
   - 기업: 계좌/이체관리 → 빠른조회 신청
2. 라이브지니에 계좌를 등록한다. 은행, 계좌번호, 계좌 비밀번호(4자리), 생년월일(개인) 또는 사업자번호를 넣는다. 은행에 따라 빠른조회 아이디·비밀번호나 인터넷뱅킹 아이디도 넣는다.
   - 라이브지니는 이 값을 암호화해 저장하고 기록(로그)에 남기지 않는다.

### 지원하지 않을 수 있는 계좌

- **카카오뱅크·토스뱅크는 지원하지 않을 가능성이 있다** (확인 필요).
- 새마을금고 개인사업자 계좌, 케이뱅크 개인 계좌도 안 될 수 있다 (확인 필요).
- 대신할 방법: 은행 앱에서 입금 내역을 복사해 라이브지니에 **붙여넣기**하거나 CSV 파일로 올린다. 매칭 규칙은 똑같다.

**시간·비용**
- 계약과 연동에 1~2주 (확인 필요).
- 계좌당 **월 5천 원 안팎**. 부가세 포함 월 5,500원이라는 2024년 자료가 있다 (확인 필요).
- 개발 계획은 1~5분마다 입금 내역을 가져오는 것이다. 30분마다 조회할 수 있다는 자료도 있어 조회 주기는 계약 때 확인한다 (확인 필요).

**끝났는지 확인하는 법**
- [ ] 다른 사람 이름으로 판매자 계좌에 1,000원을 넣어 본다. 몇 분 안에 라이브지니 입금 목록이나 "확인 필요" 목록에 나타난다.
- [ ] 카카오뱅크·토스뱅크 계좌라면 붙여넣기로 같은 결과가 나온다.

## 7. 요금 결제

**왜 필요한가**: 판매자에게 이용료(30일 이용권, 방송 N일권 같은 정량제)를 받으려면 결제대행사와 계약해야 한다(SPEC BIL-01·02). 계약은 사장님 몫이다.

용어 풀이:
- **PG(결제대행사)**: 카드 결제를 대신 처리해 주는 회사. 라이브지니는 토스페이먼츠를 쓴다.
- **포트원**: 여러 PG를 한 가지 방법으로 연결해 주는 중계 서비스. 라이브지니는 포트원 V2를 쓴다.
- **MID**: PG가 주는 상점 아이디. 계약이 끝나면 나온다.
- **단건 결제**: 살 때마다 결제하는 방식.
- **자동결제(빌링)**: 카드를 한 번 등록하면 다음 달부터 저절로 결제되는 방식.

**준비물**
- 사업자등록증
- **통신판매업 신고증**
- 대표자 신분증 사본, 인감증명서(발급 3개월 이내)
- 정산받을 통장 사본 (확인 필요)
- 결제 화면, 이용약관, 환불 규정이 보이는 서비스 홈페이지. PG 심사는 사이트가 실제로 있는지부터 본다.

**단계**

1. **사업자등록**: 홈택스에서 한다. 업종은 세무사와 정한다 (확인 필요).
2. **통신판매업 신고**
   - 정부24에서 "통신판매업신고-시.군.구"를 신청하거나 시·군·구청에 간다.
   - 서류: 신고서, 사업자등록증 사본, 대표자 신분증 사본, 사이트 주소 증빙, **구매안전서비스 이용확인증**(PG나 은행에서 받음).
   - 이용확인증과 PG 계약이 서로를 요구할 수 있다. 신고 전에 PG에 순서를 물어본다 (확인 필요).
   - 등록면허세: 지역별 12,000~40,500원(2025년 3월 기준). 처리는 보통 1주 안쪽이다.
3. **포트원 가입**: [admin.portone.io](https://admin.portone.io)에 가입한다. 개발 쪽이 쓸 **테스트 채널**을 먼저 만든다. 테스트 키로 개발과 시험을 진행한다.
4. **단건 결제 신청**: 포트원 관리자 화면 → "전자결제 신청" → 토스페이먼츠 → 단건(일반) 결제.
   - 평균 3영업일 안에 PG 연락이 온다. 스팸함도 본다.
   - 입점 심사 → 보증보험 가입 → 계약서와 서류 제출 → **MID 발급** → 카드사 심사(약 2주) → 실제 결제 가능.
5. **자동결제는 나중에**: 자동결제는 **별도 심사**이고 2~4주 걸린다(빌링용 MID를 따로 받는다). 처음에는 **30일 이용권을 단건 결제**로 팔고, 자동 갱신은 심사가 끝나면 켠다.
6. 운영 키(채널 키, API 시크릿, 웹훅 시크릿)를 호스팅 환경 변수에 직접 넣는다. 이름은 개발 쪽이 알려 준다.
7. **세금계산서·현금영수증**: 계좌이체로 받은 이용료는 **팝빌**로 발행한다(6번과 같은 팝빌 계약). 카드 결제분을 어떻게 처리할지는 세무사에게 확인한다 (확인 필요).

**약관에 꼭 넣을 것**
- **7일 전액 환불** 조항(백로그 N5).
- 정기결제를 넣을 때는 해지 방법. 환불 규정과 해지 방법이 분명해야 심사가 쉽다.

**만들지 않는 것**
- **환불되거나 출금되는 충전금(포인트)은 만들지 않는다.** 남이 맡긴 돈을 쌓아 두는 "선불 전자지급수단"으로 보여 등록 의무가 생길 위험(선불업 위험)이 있다.
- 정량제 이용권도 현금으로 돌려주거나 남에게 넘기지 않는다.

**시간·비용**
- 단건 결제: 신청부터 실제 결제까지 3주 안팎.
- 자동결제: 추가 2~4주.
- 비용: 카드 결제 수수료, 보증보험료(1년 계약. 기준요율 0.953%라는 포트원 안내가 있다), 등록면허세, 팝빌 발행 요금 (확인 필요).

**끝났는지 확인하는 법**
- [ ] 포트원 화면에 토스페이먼츠 **실제 채널**이 등록돼 있다.
- [ ] 사장님 카드로 소액 이용권을 사고 환불까지 해 본다. 라이브지니에 이용권이 생겼다가 환불 뒤 사라진다.
- [ ] 계좌이체 건으로 팝빌 현금영수증이나 세금계산서를 한 번 발행해 본다.

## 8. 프린터

### 8-1. NIIMBOT B1

**왜 필요한가**: 기본 라벨 프린터다. 크롬 브라우저에서 블루투스로 바로 출력한다.

**정품 RFID 라벨을 쓴다**
- 정품 라벨이 아니면 출력 농도가 거의 0이 된다.
- 특정 판매처 전용 라벨일 필요는 없다. NIIMBOT 정품이면 된다. 기본 크기는 50×30mm다.

**상업 사용 동의를 받는다 (D-009)**
- 라이브지니가 B1과 통신할 때 쓰는 공개 프로그램(`niimbluelib`)의 설명서에 "상업적 사용은 제조사 동의 필요"라는 문구가 있다.
- 유료 출시 전에 **NIIMBOT 국내 총판**에 문의해 동의나 공식 SDK(제조사가 주는 개발 도구)를 받는다. 국내 총판 연락처는 아직 찾지 못했다 (확인 필요). 구입처나 제조사 공식 채널에 물어본다.
- 문의할 때 적을 내용
  - 라이브 판매 관리 웹 서비스에서 B1로 라벨을 출력하려 한다.
  - 브라우저 블루투스로 출력한다. 오픈소스 `niimbluelib`(MIT)을 쓴다.
  - 상업 사용 동의 또는 공식 SDK 제공이 가능한지.
- 거절되면 라벨 그림(PNG)·PDF를 공식 NIIMBOT 앱으로 출력하는 방법으로 운영한다.

**연결할 때 알아 둘 것**
- PC·안드로이드 크롬에서 블루투스로 연결한다. PC는 USB 선 연결도 된다.
- 브라우저 보안 때문에 **창을 열 때마다 첫 연결은 직접 눌러야** 한다.
- 윈도우에서 USB가 안 되면 NIIMBOT 드라이버가 포트를 잡고 있는 것이다. 블루투스로 연결한다.

### 8-2. Marklife

- 지원 모델(SPEC PRT-01)
  - **P50**·S2·X2: 50mm 라벨
  - P11·**P12·P15**·L13(국내 LP90·LP15): 12~15mm 테이프. 번호·가격·구매자만 들어가는 작은 라벨을 쓴다.
- 이름이 같은 다른 회사 기기(Phomemo P12)는 지원하지 않는다.
- 사장님이 할 일: 실제 기기로 HG-2 확인(10번).

### 8-3. 바우아토(BAUATO) 스티코팝 — 통신 캡처(HG-5)

**왜 필요한가**: 바우아토는 Luck Jingle 제품(PPA2L)을 이름만 바꿔 파는 기기다. 공개된 통신 방법이 없다. 그래서 지금은 "실험적" 표시를 하고, 기본은 라벨 그림을 공식 앱(**Luck Jingle**)으로 넘겨 출력하는 방법이다. 직접 출력을 하려면 실제 기기의 블루투스 통신 기록이 필요하다.

**준비물**
- 안드로이드 폰 (삼성 갤럭시나 구글 픽셀 권장)
- 바우아토 프린터와 전용 롤(50×15, 50×30, 50×50 중 하나)
- 폰에 설치한 Luck Jingle 앱
- 메모할 종이 (출력 시각을 적는다)

**단계**

1. **개발자 옵션 켜기**
   - 삼성: 설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드 번호**를 7번 연속 누른다.
   - 픽셀: 설정 → 휴대전화 정보 → 빌드 번호를 7번 누른다.
   - "개발자 모드를 켰습니다" 같은 안내가 나오면 된다. 설정 첫 화면 맨 아래에 "개발자 옵션"이 생긴다.
2. **스누프 로그 켜기**: 설정 → 개발자 옵션 → **"블루투스 HCI 스누프 로그 사용"**을 켠다.
   - 스누프 로그는 폰이 블루투스로 주고받은 내용을 파일로 남기는 기능이다.
   - 고르는 칸이 나오면 "사용 설정됨"(전체 기록)을 고른다. "필터링됨"은 고르지 않는다 (확인 필요).
3. 이어폰, 시계 같은 **다른 블루투스 기기는 꺼 둔다.** 그 통신도 함께 기록되기 때문이다.
4. 폰의 **블루투스를 껐다가 다시 켠다.** 그래야 기록이 시작된다. 안 되면 폰을 다시 시작한다.
5. Luck Jingle 앱에서 프린터를 연결하고 **라벨 한 장을 출력**한다.
   - 무엇을 출력했는지 적어 둔다. 예: 50×30 롤에 글자 `TEST 123`.
   - 출력한 **시각**(몇 시 몇 분)을 적는다.
   - 출력된 라벨 사진을 찍는다.
6. **기록 파일 만들기**: 설정 → 개발자 옵션 → **"버그 신고"**(버그 리포트) → "전체 보고서"(있으면) → 몇 분 기다린다 → 알림이 오면 눌러 **공유** → 구글 드라이브나 메일로 zip 파일을 저장한다. 크기가 수십 MB일 수 있다.
7. 다시 개발자 옵션에서 **스누프 로그를 끈다.**
8. **개발 쪽에 전달**: zip 파일, 라벨 사진, 프린터 모델과 롤 크기, Luck Jingle 앱 버전, 폰 기종, 출력 시각.
   - 구글 드라이브의 "링크가 있는 특정 사용자만" 공유처럼 **비공개**로 보낸다.
   - zip에는 폰의 앱 목록과 기록 같은 개인 정보가 들어 있다. 공개 게시판이나 단체방에 올리지 않는다.

**파일이 안 보일 때**
- 기록은 보통 zip 안의 `FS/data/misc/bluetooth/logs/` 폴더에 있다. 이름은 `btsnoop_hci.log`이거나 끝이 `.cfa`인 파일이다.
- 삼성 일부 기종은 위치가 다를 수 있다 (확인 필요).
- 없으면 개발 쪽이 폰을 PC에 USB로 연결해 직접 받는다. 그때는 폰과 프린터를 가지고 만난다.

**끝났는지 확인하는 법**
- [ ] 개발 쪽이 파일 안에서 출력 데이터를 찾았다고 답했다.
- [ ] 그 뒤 라이브지니에서 바우아토로 직접 출력해 보는 확인을 한다(10번 HG-5).

### 8-4. 아이폰

- 아이폰 사파리에는 브라우저 블루투스 기능이 없다. 그래서 **아이폰에서는 프린터로 직접 출력할 수 없다.**
- 대신 라벨 그림(PNG)을 **공유**해 제조사 공식 앱(NIIMBOT, Luck Jingle 등)에서 출력한다.
- 또는 안드로이드 폰이나 PC를 **프린트 스테이션**(출력 전용 기기)으로 두고 아이폰에서 판매한다.
- 카카오톡 같은 앱 안의 브라우저에서도 직접 출력이 되지 않는다. 크롬에서 연다.

**시간·비용**: 정품 라벨 구입비. 제조사 동의 회신은 기다려 봐야 안다 (확인 필요).

### HG-1 리허설
- 홈 → "리허설 해 보기" → 가짜 채팅 시작 → 빠른 입력으로 상품 등록 → 충돌·취소 요청 알림 처리 → 되돌리기.
- 휴대폰에 앱으로 설치하고, 문자찜 입력, 구매자 합치기, 정산 입력까지 해 본다.
- **끝**: 헷갈린 낱말과 버튼을 적었고, 판매 규칙 기본값 중 바꿀 것을 정했다.

### HG-2 실제 B1과 Marklife 출력
- B1: 블루투스·USB 연결, 테스트 라벨의 **맨 아래 테두리**가 찍히는지, 한글(`가나다 똠햏 ㄱㄴㄷ`), 30장 연속 출력, 전원을 껐다 켠 뒤 "다시 연결"로 이어서 나오는지, 아이폰 PNG 공유 출력.
- Marklife: P50(50mm)과 P12/P15(12~15mm 테이프) 연결, 테스트 인쇄, 작은 라벨(번호·가격·구매자)이 잘리지 않는지, 여러 장(예: 10장) 연속 출력. Marklife 상세 목록은 프린터 화면 통합 때 개발 쪽이 더한다.
- **끝**: 빠짐·잘림 없이 나오고, 농도 값을 정했다.

### HG-3 실제 유튜브·인스타 테스트 방송
- **유튜브**
  - 판매자 계정을 3-2의 테스트 사용자에 넣고 연결한다.
  - 비공개나 일부공개로 방송을 켜고, 다른 계정으로 `15`처럼 채팅을 쓴다.
  - 찜이 생기는지, 감사 메시지가 채팅에 한 번만 올라가는지 본다.
  - 실측할 것: 방송 중에 영상 댓글이 되는지, 채팅 글자 수 제한이 몇 자인지(TECH_REVIEW §2.2에서 확인하지 못한 값).
  - 감사 메시지가 실패해도 판매 기록이 남고 다시 보낼 수 있는지 본다.
- **인스타**
  - 테스트 라이브에서 댓글 `15` → 찜이 생기는지 본다.
  - 감사 DM이 한 번 오는지, 방송이 끝난 뒤에는 DM을 보내지 않는지 본다.
- **끝**: 두 플랫폼 모두 채팅·댓글 → 찜 → 감사가 실제로 동작했다.

### HG-4 실제 목소리
- 녹음 20개를 들려주고 번호·가격·품종 인식 결과를 기록한다. 측정 결과는 `harness/sprints/I4/hg4-accuracy.md`로 남긴다.
- 실제 마이크로 상품 5개를 등록해 본다. 음성을 끄고도 모든 기능이 그대로인지 본다.
- **끝**: 정확도 보고서가 있고, 크롬 무료 음성 인식으로 충분한지 정했다.

### HG-5 바우아토 통신 캡처
- 8-3의 단계대로 기록 파일을 만들어 개발 쪽에 넘긴다.
- 개발 쪽이 직접 출력을 붙이면, 라이브지니에서 바우아토로 한 장 출력해 본다.
- **끝**: 파일을 넘겼고, 직접 출력이 되는지(또는 계속 Luck Jingle 앱 경로로 쓸지) 정했다.
