## 0. 우리 앱이 실제로 하는 일 (신청서에 쓸 사실)

- **가입은 받지 않습니다.** 판매자 계정은 운영자(틈)가 만들고, 판매자가 아이디·비밀번호로 한 번 로그인한 뒤 설정 → "로그인 방법"에서 카카오·네이버 계정을 **연결**해야 그 뒤 "카카오로 계속하기"가 됩니다(D-L1-01).
- **묻는 권한**
  - 카카오: **추가 권한(scope) 없음** — 카카오가 주는 회원 번호만 씁니다. 닉네임·이메일은 받으면 쓰지만 **없어도 연결·로그인이 됩니다**(설정에는 "카카오 계정"으로 보임).
  - 네이버: scope 없음 — **회원 식별값(id)** 만 필수로 씁니다. 이메일·별명은 받으면 가려서 보이는 데만 씁니다.
- **저장하는 것**: 공급자 계정 번호, 가린 이메일(예: `se***@gmail.com`)뿐. 공급자가 준 토큰은 그 요청 안에서 사용자 정보를 읽고 **버립니다**(저장 안 함).
- **보안**: 카카오는 PKCE(S256) + state, 네이버는 state(늘 보냄). 돌아오는 주소는 정확히 하나.
- 돌아오는 주소
  - 카카오: `https://<도메인>/api/auth/kakao/callback`
  - 네이버: `https://<도메인>/api/auth/naver/callback`
- 환경 변수: `LIVEJJIM_LOGIN_KAKAO_REST_API_KEY`(필수)·`LIVEJJIM_LOGIN_KAKAO_CLIENT_SECRET`(시크릿을 켰을 때만), `LIVEJJIM_LOGIN_NAVER_CLIENT_ID`·`LIVEJJIM_LOGIN_NAVER_CLIENT_SECRET`.

## 1. 카카오

### 1-1. 비즈 앱 전환이 필요한가?

| 하고 싶은 것 | 비즈 앱 필요? | 우리 앱 |
|---|---|---|
| 회원 번호만으로 로그인 | **아니오** | 지금 이대로 됩니다 |
| 닉네임(프로필) 받기 | 아니오(동의항목 설정만) [확인 필요 — 콘솔에서 "사용 가능" 표시 확인] | 선택 — 설정 화면에 이름 보이기용. 안 받아도 됨 |
| 카카오계정(이메일) 받기 | **예** — 비즈 앱 전환(사업자 정보 등록 또는 개인 개발자 비즈 앱) 뒤 동의항목 설정 | 받지 않아도 됨. 받으면 "연결한 계정" 표시가 알아보기 쉬워짐 |
| 전화번호·이름 등 개인정보 항목 | 예 + 개인정보 동의항목 **검수**(영업일 3~5일) | **받지 않음** |

**결론(권장)**: 처음엔 **비즈 앱 전환 없이, 동의항목은 닉네임(선택) 하나 또는 아무것도 없이** 시작합니다. 우리는 사업자(틈)가 있으니 나중에 이메일이 필요하면 "사업자 정보 등록"으로 비즈 앱 전환을 신청할 수 있습니다.

> 카카오 안내에 따르면 개인정보 동의항목 검수는 "실제 가입 화면에서 받는 항목과 신청 항목이 맞는지, 필수/선택이 맞는지, 개인정보처리방침과 맞는지"를 봅니다. 우리는 가입 화면이 없으니(연결만) 필요 없는 항목은 신청하지 않는 편이 안전합니다.

### 1-2. 체크리스트

- [ ] developers.kakao.com 로그인(사업자 대표 카카오 계정 권장 — 담당자가 바뀌면 "팀 관리"로 넘김 [확인 필요])
- [ ] 내 애플리케이션 → 애플리케이션 추가: 앱 이름 **라이브지니**, 회사명 **틈**, 아이콘(선택)
- [ ] 앱 → 플랫폼 → **Web 사이트 도메인** `https://<도메인>`
- [ ] 제품 설정 → 카카오 로그인 → **활성화 ON** (꺼져 있으면 오류 KOE004)
- [ ] **Redirect URI** `https://<도메인>/api/auth/kakao/callback` (다르면 오류 KOE006)
- [ ] 보안 → **Client Secret**: 카카오 안내상 REST API 키에 클라이언트 시크릿이 켜져 있으면 토큰 요청에 꼭 넣어야 함 → 켜져 있으면 값을 `LIVEJJIM_LOGIN_KAKAO_CLIENT_SECRET`에 (켰는데 비우면 로그인 실패)
- [ ] 동의항목: 닉네임 "선택 동의"(또는 아무것도 안 함). 동의 목적: 아래 1-3 문장
- [ ] (선택) OpenID Connect — 우리 코드는 쓰지 않음. 꺼 둬도 됨
- [ ] 동의 화면 미리 보기로 앱 이름·항목 확인
- [ ] 개인정보처리방침 주소 등록 칸이 있으면 `https://<도메인>/privacy` [확인 필요 — 콘솔 위치]
- [ ] 국외 이전 정보 등록: **서버가 국외면** 카카오 콘솔에 국외 이전 정보를 등록해야 하고, 그러면 필수 동의항목이 하나 더 생김(카카오 안내). 국내 서버면 해당 없음 [확인 필요 — 서버 지역 정한 뒤]
- [ ] 디자인 가이드: 카카오 로그인 버튼(노란색·말풍선 로고) 지침 확인 — 지금은 글자·색만 씀(D-L1-07 (4)) [확인 필요 — 공식 버튼 이미지가 필수인지]
- [ ] 시험: 시험 판매자로 설정 → 로그인 방법 → [연결하기] → 로그아웃 → "카카오로 계속하기"
- [ ] **실제 카카오가 PKCE(S256)를 받는지**, 취소 때 돌려주는 `error` 값이 `access_denied`인지 첫 연결 때 확인(D-L1-07 (5))

### 1-3. 제출 문장 (동의 목적·앱 설명)

- **앱 설명**: "라이브지니는 유튜브 라이브로 상품을 파는 판매자용 주문·정산 도구입니다. 카카오 로그인은 판매자가 이미 가진 라이브지니 계정에 카카오 계정을 연결해, 다음부터 아이디·비밀번호 대신 카카오로 로그인하는 데만 씁니다. 시청자·구매자는 카카오 로그인을 쓰지 않습니다."
- **닉네임 동의 목적**: "연결한 카카오 계정을 판매자가 설정 화면에서 알아보도록 표시하기 위해(선택)."
- **(비즈 앱 전환 시) 이메일 동의 목적**: "연결한 계정을 판매자에게 가린 이메일(예: se***@gmail.com)로 보여 주기 위해(선택). 이메일 원문은 저장하지 않습니다." — 실제로 원문을 저장하지 않으니 정직한 문장입니다.
- **비즈 앱 전환 신청 목적(필요할 때)**: "카카오 로그인 사용자 식별과 연결 계정 관리."

## 2. 네이버

### 2-1. 검수가 필요한가?

- 앱을 등록하면 **"개발 중"** 상태이고, 이때는 **앱 관리자와 등록한 테스트 아이디(멤버)만** 로그인됩니다. [확인 필요 — 멤버 최대 수]
- 다른 판매자가 쓰려면 **검수 요청 → 승인 → "서비스 적용"** 상태가 되어야 합니다(DEPLOY 4-3).
- 검수 기간: [확인 필요 — 보통 영업일 며칠로 알려져 있음. 네이버 개발자 센터 안내 확인]
- 참고: 네이버 개발자 센터(developers.naver.com)는 이 작업 환경에서 열리지 않아 공식 문서를 직접 확인하지 못했습니다. 아래 서류 목록은 일반적인 요구를 정리한 것이니 **신청 화면 안내를 기준**으로 하세요.

### 2-2. 체크리스트

- [ ] developers.naver.com → Application → **애플리케이션 등록**
- [ ] 애플리케이션 이름 **라이브지니** (동의 화면에 그대로 보임)
- [ ] 사용 API: **네이버 로그인**
- [ ] 제공 정보: **회원이름·이메일·별명 등은 고르지 않거나 "추가"로만** — 우리 코드는 회원 식별값(id)만 필수로 씀. [확인 필요 — 콘솔에서 필수로 하나 이상 고르게 하면 "별명" 또는 "이메일"을 선택하고 이유를 2-3 문장으로]
- [ ] 로그인 오픈 API 서비스 환경: **PC 웹**(필요하면 모바일 웹도) — 서비스 URL `https://<도메인>`, Callback URL `https://<도메인>/api/auth/naver/callback`
- [ ] Client ID·Client Secret → 서버 환경 변수
- [ ] 멤버 관리에 사장님·시험 판매자 네이버 아이디 추가 → 시험
- [ ] 네이버 로그인 버튼 디자인 가이드(초록색·N 로고) 확인 [확인 필요 — 공식 이미지 필수 여부]
- [ ] **검수 요청** — 아래 서류 준비

### 2-3. 검수 요청 서류 (준비물)

| 서류 | 내용 | 준비 방법 |
|---|---|---|
| 서비스 설명 | 아래 문장 | 그대로 붙여 넣기 |
| 서비스 URL | `https://<도메인>` — 로그인 안 해도 열리는 소개 화면 권장 | 공개 소개 화면 필요(GOOGLE 문서 1절 2와 같은 작업) [확인 필요] |
| 로그인 버튼 화면 캡처 | 로그인 화면 아래 "또는" 줄과 "네이버로 계속하기" | 운영 서버에서 캡처 |
| 로그인 뒤 화면 캡처 | 연결 후 설정 → 로그인 방법(연결된 계정 표시) | 캡처 |
| 제공 정보 사용처 캡처 | 받은 정보(이메일·별명)를 쓰는 곳 — 가린 이메일 표시 | 추가 정보를 고른 경우만 |
| 개인정보처리방침 | `https://<도메인>/privacy` — 수집 항목에 "간편 로그인 연결 정보(공급자 계정 번호, 가린 이메일)"가 이미 있음 | GAPS 문서대로 완성 |
| 테스트 계정 | 검수자가 들어가 볼 라이브지니 아이디·비밀번호 [확인 필요 — 요구 여부] | 시험용 판매자 계정을 따로 만들고, 비밀번호는 신청서에만 직접 적기(대화창에 붙이지 않기) |
| 로고 | 앱 아이콘 [확인 필요] | |

**서비스 설명 (제출 문장)**
> 라이브지니는 유튜브 라이브로 상품을 파는 소상공인 판매자를 위한 주문(찜)·정산·라벨 출력 웹 서비스입니다. 판매자 계정은 운영자가 만들어 드리며, 네이버 로그인은 판매자가 이미 가진 라이브지니 계정에 네이버 아이디를 연결해 다음부터 간편하게 로그인하는 데만 사용합니다. 네이버로 새로 가입하는 기능은 없습니다. 네이버 회원 식별값만 저장하고, 이메일을 받는 경우에도 가린 형태(예: se***@naver.com)만 저장합니다. 네이버가 준 접근 토큰은 저장하지 않습니다.

**추가 정보(이메일·별명) 사용 이유 — 골랐을 때만**
> 판매자가 설정 화면에서 어떤 네이버 아이디를 연결했는지 알아볼 수 있도록 가린 이메일 또는 별명을 표시합니다. 다른 목적(광고·마케팅)에는 쓰지 않습니다.

### 2-4. 검수에서 흔히 막히는 곳 (대비)

- 서비스 URL이 로그인 화면만 보이거나 준비 중 → 소개 화면 먼저
- 고른 제공 정보를 실제 화면에서 쓰지 않음 → **필요 없는 항목은 고르지 않기**
- 개인정보처리방침에 수집 항목이 없음 → GAPS 문서 1번(간편 로그인) 확인
- 버튼이 디자인 가이드와 다름 → 공식 버튼 확인 [확인 필요]

## 3. 공통 — 개인정보처리방침에 이미 있는 것/넣을 것

- 이미 있음: "간편 로그인을 연결하면: 공급자 계정 번호, 가린 이메일", "간편 로그인 동안 10분만 쓰는 확인 쿠키".
- 넣을 것: 카카오(주식회사 카카오)·네이버(네이버 주식회사)는 **로그인 수단 제공자**이며 우리가 그 회사에 개인정보를 맡기는(위탁) 것은 아님 [확인 필요 — 법률 검토] — 다만 "판매자가 연결을 끊으면 계정 번호·가린 이메일을 바로 지운다"는 보관 문장을 넣기(GAPS 문서 표 13번). 코드 확인: `social/service.ts` `unlink`가 연결 행을 지우고 그 공급자로 만든 세션도 지움.
