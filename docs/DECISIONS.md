# 결정 로그 (DECISIONS)

> 소유자: spec-keeper (추가), 사용자 (확정). 상태: `PROPOSED`(제안 기본값 적용 중) → `ACCEPTED`(사용자 확정) / `CHANGED`(사용자가 바꿈).
> `AUTO`: 자율 모드에서 spec-keeper·오케스트레이터가 판매자에게 가장 안전한 쪽으로 정해 적용한 값. 사용자가 언제든 바꿀 수 있고, 바뀌면 `CHANGED`로 적고 골든·코드를 함께 고친다.
> `필요 시점` = 이 스프린트 시작 전에 확정되어야 함. 확정 전에도 기본값으로 진행하되, 바뀌면 골든과 코드를 함께 고친다.

- S03b: 사용자만 할 수 있는 일 때문에 막힌 항목 없음. 전화번호 키는 테스트 전용 키로 골든·단위 테스트에서 확인하고, 실제 판매자별 비밀 키 보관은 S04 서버 몫이다. 직접 묶기(`MANUAL`, D-059)는 S03b 범위가 아니다(오케스트레이터 일정).
- S04: 사용자만 할 수 있는 일 때문에 막힌 항목 없음. 데이터베이스는 PGlite(내장 Postgres)로, 비밀값·계정은 시험용 값으로 확인한다. 실제 PostgreSQL·마스터 키·운영 계정은 배포(S12) 때 만든다. 유튜브 원본 30일 처리(D-012·D-078)는 S10 전에 정한다.
- S05: 사용자만 할 수 있는 일 때문에 막힌 항목 없음. 리허설은 서버 안 가짜 채팅 생성기로, 화면 확인은 Playwright(크로미움)와 PGlite·시험용 계정으로 한다. 실제 판매자의 리허설 사용성 확인은 HG-1(S06 끝)에서 한다. E2E를 `pnpm verify` 단계로 넣는 일은 검증 파이프라인 소유자(오케스트레이터, D-027) 몫이다.
- S06: 사용자만 할 수 있는 일 때문에 막힌 항목 없음. 문자찜·구매자·정산 화면과 PWA는 Playwright(크로미움, PC·휴대폰 크기)와 PGlite·시험용 계정으로 확인한다. 실제 휴대폰 설치·사용과 판매자의 리허설 사용성(HG-1)은 최종 보고에서 사용자가 확인한다(위 표).
- Y1: 사용자만 할 수 있는 일 때문에 막힌 항목 없음. 구글 연결·채팅 수집·감사 게시·할당량·봉인은 `127.0.0.1`의 가짜 구글·유튜브 서버와 PGlite·시험용 계정·주입한 시계로 확인한다. 실제 구글 클라우드 프로젝트·OAuth 검증(D-019)과 실제 테스트 방송(HG-3)은 사용자 몫이고 최종 보고에서 확인한다(위 표).
