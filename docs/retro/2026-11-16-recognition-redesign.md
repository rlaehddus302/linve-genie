## 0. 한 장 요약

**지금 구조의 병은 하나다. 번호·가격·품종이 한 묶음으로 LLM 답에서 나와야 등록된다.** 그래서 가장 느린 칸(LLM 12초)과 가장 틀리는 칸(품종)이 가장 급한 칸(번호)을 붙잡는다. 새 구조는 이 묶음을 푼다.

| 물음 | 고른 것 | 버린 것 | 근거 |
|---|---|---|---|
| 등록을 무엇이 시작하나 | **번호 하나만 들려도 바로 "확인 중"으로 올린다.** 가격·품종은 들리는 대로 그 상품에 붙인다 | 번호·가격 근거가 다 모일 때까지 기다리기, LLM 답을 기다리기 | 번호 근거는 LLM 없이도 상품 100%에 있었고, 실제 등록보다 가운데 15초 먼저 잡힌다 (잰 값, 1.4) |
| LLM은 어디에 | **등록 길에서 뺀다.** 뒤에서 맞추는 일만 한다(가격이 누구 것인지, 품종이 무엇인지). 답은 "후보 중에 고르기"만 | 줄마다 60초를 통째로 묻기, LLM이 번호·가격을 새로 적기 | 호출 87%가 헛돌았다. 규칙만의 가격은 67 ~ 88%, LLM은 94%라 LLM은 여전히 필요하다 — 다만 뒤에서 (잰 값) |
| LLM을 언제 부르나 | **상품마다, 일이 생겼을 때만**: 가격 맞추기 1번, 품종 묻기 0 ~ 1번, 값이 바뀜·거둠·주인 없는 금액일 때 | 줄 단위(지금), 상품 구간이 끝날 때 한 번(D-SCR-40에서 불합격) | 구간 방식이 떨어진 까닭은 LLM이 등록을 쥐고 있었기 때문이다. 등록을 규칙이 쥐면 덜 물어도 번호를 놓치지 않는다 |
| LLM에 무엇을 넘기나 | **상품 서류철**: 그 번호에 붙은 줄(옆 번호 줄은 표시만 해서), 규칙이 뽑은 후보 표, 장부에서 소리가 가까운 품종 5 ~ 8개, 지금 서버 값 | 시간 창(앞 60초), 2분 조각 | 옆 상품 값·이름이 섞인 사고(14·36·117·80번)는 창이 상품을 가리지 않아서 났다 |
| 품종 지식은 어디서 | **가게 장부**(그 가게가 판 이름·틀리게 들리는 모양·가격대). 방송 전에는 그 가게의 지난 방송 기록에서 미리 채우고, 방송 중·뒤에는 확정된 이름으로 저절로 쌓는다 | LLM이 인터넷을 뒤지기(등록 길), 전국 사전으로 거르기 | LLM은 120가지 중 7가지만 안다. 이름 대부분이 가게가 지은 이름이라 웹에도 드물다. 장부 안에서 소리로 찾으면 틀린 모양 64개 중 63개가 맞는다 (잰 값) |
| NER | **따로 학습한 NER은 지금 넣지 않는다.** 장부 이름은 소리 맞추기로, 장부에 없는 새 이름 자리는 "번호와 금액 사이·무늬 말 앞" 규칙으로 찾고 LLM이 확인한다. 확정될 때마다 학습 자료를 쌓아 2천 자리쯤 모이면 다시 본다 | 범용 NER, 제로샷 GLiNER | NER이 고칠 수 있는 것은 235개 중 22개의 일부(잰 값). 제로샷 한국어 F1 37 (공개 값) |
| 받아쓰기 | **흘러나오는 받아쓰기(중간 글)로 번호·가격을 먼저 잡고**, 지금의 조각 받아쓰기는 서류철에 넣을 "고운 글"로 남긴다. 모델은 8절의 시험으로 고른다 | 조각이 끝나야 글이 나오는 방식만 쓰기 | 지금은 말 끝 → 글 도착이 7 ~ 9초다 |
| 받아쓰기 힌트 | **무늬 말·"번"·"만 원" 같은 늘 나오는 낱말 10여 개만** 힌트로. 품종 이름은 힌트가 아니라 받아쓴 뒤 장부에서 소리로 되찾는다 | 품종 수백 개를 힌트에 넣기, 조각마다 다시 받아쓰기 | 힌트 몫은 품종 0 ~ 1개였다 (잰 값, D-SCR-39) |
| 화면 | **번호표 찾기(작은 검출 모델) → 초당 5장 따라가기 → 딱지 조각만 읽어 다수결.** 화면은 번호를 "맞추는" 근거다(유튜브 지연만큼 늦게 온다) | 1초 1장 화면 전체 읽기, 생김새로 품종 정하기, 화면 품종 글씨(네 장면에서 0) | 한 장 읽기는 4를 8로 읽는다. 1초 1장에서는 따라가기가 무너진다 (공개 값) |
| 소리는 어디서 | **휴대폰 마이크가 빠른 길**, 유튜브 소리·화면은 맞추는 길. 둘의 시간 차는 소리끼리 맞대어 잰다 | 유튜브 소리만 듣기 | 유튜브 지연은 어떤 모델로도 못 줄인다 |

기대(추정, 12절에서 잰다): 처음 보이기까지 말 끝에서 **가운데 2초 안팎, 열에 아홉 5초**(마이크 길). 유튜브 소리만 쓰면 여기에 유튜브 지연이 더해진다. LLM 호출은 방송당 1,750번 → 500번 안팎.

## 1. 문제를 다시 적는다

### 1.1 요구

1. 판매자가 말하고 나서 **최대한 빨리** 등록한다.
2. 차례를 기다리거나 다 모일 때까지 기다리지 않는다. **알아들은 것부터 올리고 나중에 맞춘다.**
3. 그러면서 틀린 값이 손님에게 나가지 않는다(감사 채팅·라벨·찜 판정). 11-12 방송의 사고가 이것이었다.

1·2와 3은 서로 당긴다. 푸는 길은 이미 엔진에 있다: **"확인 중" 상품**(D-RETRO-80). 확인 중인 동안 찜은 받아 두기만 하고, 밖으로 나가는 것은 확정한 값으로만 나간다. 그러니 "확인 중"으로는 얼마든지 일찍, 틀릴 수 있게 올려도 된다. 새 설계는 이 성질을 끝까지 쓴다.

### 1.2 제약

| 제약 | 뜻 |
|---|---|
| 돈을 쓰지 않는다 (D-RETRO-101) | 유료 API 금지. LLM은 구독(Codex) 또는 맥 미니에서 도는 모델 |
| 방송 전에 번호–품종 목록을 받을 수 없다 (D-RETRO-102) | 품종은 방송 중에 듣고 알아내야 한다 |
| 맥 미니 한 대 | 받아쓰기·화면·LLM이 같이 돈다. 여력은 아직 재지 않았다 |
| 유튜브에 쓰지 않는다 | 손님에게 채팅으로 되묻지 않는다. 묻는 곳은 판매자 앱뿐 |
| 판정은 순수 함수, 입력 먼저 기록 | 인식에도 같은 규칙을 적용한다 (3절) |

### 1.3 지금 20초가 어디서 나오나

| 구간 | 걸린 시간 (11-13, 잰 값) | 까닭 |
|---|---|---|
| 현장 말 → 유튜브 소리 | 재지 못함 (몇 초 ~ 십몇 초) | 유튜브가 방송을 내보내는 지연 |
| 말 끝 → 받아쓴 줄 도착 | 7 ~ 9초 | 0.4초 쉼이 나와야 조각이 끊기고, 조각이 끝나야 글이 나온다 |
| 줄 도착 → LLM 답 | 12초 (가운데) | 호출마다 프로그램을 새로 띄우고, 60초 분량을 읽힌다 |
| 근거가 모이기를 기다림 | 3 ~ 4초 | 번호 근거 + 가격 근거가 다 서야 보낸다 |

**세 구간이 한 줄로 이어져 있고, 세 칸(번호·가격·품종)이 한 묶음이다.** 번호는 첫 구간이 끝나면 이미 알 수 있는데도 마지막 구간까지 기다린다.

### 1.4 이번에 새로 잰 것 — "LLM 없이 얼마나 일찍, 얼마나 맞게 잡히나"

11-13 방송 새 규칙 구간(12:59 ~)의 받아쓰기·화면 기록에 단순 규칙을 돌렸다. 대상은 일꾼이 등록한 정답 번호 245개다. 규칙은 숫자 뒤의 "번"·"만 원"만 보는 가장 단순한 것이다(도구는 저장소 밖 임시 폴더, LLM 호출 없음).

| 무엇 | 값 |
|---|---|
| 번호 근거가 LLM 없이 있는 상품 | 245개 중 245개 (100%) |
| ㄴ 말로 "N번"이 들림 | 188 (77%) |
| ㄴ "번" 없이 N이 들리고 그때 화면에 번호표 N | 48 (20%) |
| ㄴ 화면 번호표만 (3장 넘게) | 9 (4%) |
| 말로 들린 "N번" 199가지 중 없는 번호 | 3가지 (1.5%) — 88, 333, 2132. (55·148·208은 영수증에 없지만 실제 상품) |
| 화면에 3장 넘게 읽힌 번호 297가지 중 없는 번호 | 33가지 (11%) |
| 번호 첫 근거 → 그날 실제 등록 | 가운데 15초 먼저 (90초 안에 근거가 있던 210개 기준) |
| 한 줄에 "N번"과 금액이 같이 들린 상품 | 162 (66%) |
| ㄴ 그 줄에 번호 하나·금액 한 가지 | 129개, 그 금액이 정답 113 (88%) |
| ㄴ 금액이 여럿이거나 번호가 여럿 | 33개, 후보 안에 정답 25 |
| "가장 가까운 금액"을 가격으로 삼는 단순 규칙 | 245개 중 165 맞음 (67%). 그날 일꾼(LLM)의 첫 등록은 230 (94%) |

읽는 법:

- **번호는 규칙으로 충분하다.** 말로 들린 "N번"은 98.5%가 진짜 상품이다. 듣자마자 올려도 된다.
- **화면만으로는 올리되 믿지는 않는다.** 열에 하나가 없는 번호다(한 장 읽기의 오독, 진열대의 다른 번호표).
- **가격은 규칙만으로 확정하면 안 된다.** 가장 좋은 경우(한 줄에 번호 하나·금액 하나)도 88%다. "먼저 올리고 LLM이 맞춘 뒤 확정"이어야 한다.
- 이 값은 조각 받아쓰기 기준이다. 흘러나오는 받아쓰기로 바꾸면 여기서 몇 초가 더 빠진다(8절).

## 2. 원칙 여섯 가지

1. **칸마다 따로, 들리는 대로.** 상품의 열쇠는 번호다. 번호가 잡히면 상품을 만들고, 가격·품종·개수는 저마다의 근거가 오는 대로 붙인다. 어느 칸도 다른 칸을 기다리지 않는다.
2. **등록 길에 LLM을 두지 않는다.** LLM은 느리고(12초), 한도가 있고, 가끔 멈춘다. 빠른 길은 규칙과 장부만으로 돈다. LLM이 멈춰도 상품은 올라오고 판매자가 눌러 확정할 수 있다.
3. **올리는 것과 내보내는 것을 가른다.** 올리는 것("확인 중")은 빠르고 틀려도 된다. 내보내는 것(찜 판정·감사 채팅·라벨)은 확정 뒤에만.
4. **근거를 먼저 적고, 판정은 한곳의 순수 함수.** 들은 것·본 것·LLM 답·판매자 손질을 모두 근거로 적는다. 상품 값은 근거 기록에서 계산한다. 같은 기록이면 같은 결과가 나오므로 방송을 다시 돌려 잴 수 있다.
5. **닫힌 목록에서 고른다.** 번호는 그 방송의 번호대와 화면 번호표에서, 가격은 들린 금액 후보와 가격대에서, 품종은 가게 장부에서. LLM도 "후보 중 하나 / 없음"만 답한다. 지어낼 자리를 없앤다.
6. **모르면 판매자에게 한 번 묻는다.** 근거가 갈리면 찍지 않고 단추 두 개로 묻는다. 부정은 왼쪽, 긍정은 오른쪽.

### 3.1 근거 기록

들어오는 것은 모두 한 줄씩 적는다. 판정 전에 적는다(절대 규칙 3과 같다).

| 근거 | 누가 | 담는 것 |
|---|---|---|
| 들은 번호 | 빠른 길 | 번호, "번"이 붙었나, 말한 시각, 그 낱말이 든 마디 |
| 들은 금액 | 빠른 길 | 금액, 단위를 말했나, 곁말(갑니다 / 빼 드릴게요 / 했었는데 / 씩 / 개), 같은 마디의 번호 |
| 들은 이름 | 빠른 길 | 들린 글자 그대로, 장부 이름과 소리 점수, 무늬 말, 형태, 개수 |
| 본 번호표 | 화면 | 딱지 번호(따라가기 번호), 읽은 값마다 횟수, 크기, 앞에 들었나, 처음·마지막 시각 |
| 채팅 번호 | 서버 | 손님이 친 번호와 시각(숫자만. 글과 닉네임은 담지 않는다) |
| LLM 답 | 맞추는 길 | 물음 종류, 고른 후보, 따온 줄 |
| 판매자 손질 | 앱 | 고친 칸. 손댄 칸은 잠근다 |
| 서버 응답 | 서버 | 등록됨 / 이미 있음 / 없음 … |

### 3.2 상품 기록과 칸의 상태

| 상태 | 뜻 | 화면에 | 밖으로 |
|---|---|---|---|
| 없음 | 근거가 없다 | "가격 듣는 중", 품종 빈칸 | 나가지 않음 |
| 들림 | 근거가 하나다 | 값을 흐리게, "확인 중" | 나가지 않음 |
| 맞음 | 서로 다른 근거 둘이 같다(4 ~ 6절의 조건) | 값 그대로 | 나감 |
| 판매자 확정 | 판매자가 누르거나 고쳤다 | 값 그대로 | 나감. 일꾼은 다시 건드리지 않는다 |

- **상품이 "판매 중"이 되는 조건 = 번호 칸과 가격 칸이 맞음 이상.** 품종은 조건이 아니다. 품종이 빈 채로 확정되고 뒤에 채워진다(지금도 그렇다).
- 고치는 규칙은 상태로 정해진다. 확인 중인 상품은 어느 칸이든 마음대로 고친다. 판매 중인 상품의 가격은 찜이 없으면 고치고 있으면 묻는다. 5배 넘는 변화는 언제나 묻는다. 판매자가 손댄 칸은 고치지 않는다.
- 한번 "맞음"이 된 값을 더 약한 근거로 덮지 않는다.

### 3.3 보내는 손 — 번호마다 한 줄

- 상품 기록이 바뀌면 "서버에 있어야 할 모습"과 "서버에 있는 모습"의 차이만 보낸다.
- **같은 번호의 요청은 앞 요청의 응답을 받은 뒤에 다음 것을 보낸다. 다른 번호끼리는 기다리지 않는다.** 11-13의 620·107번(바로잡기가 등록보다 먼저 닿음)은 이것으로 없어지고, "차례대로 등록되기를 기다리는 일"도 없다.
- 모든 요청에 같은 열쇠(requestId)를 붙여 두 번 보내도 한 번만 먹는다.

### 3.4 마이크 시각과 유튜브 시각 맞추기

마이크 소리는 지금의 소리고, 유튜브 소리·화면은 몇 초 ~ 십몇 초 전의 것이다. 둘은 같은 소리이므로 **소리 크기 흐름을 맞대어 시간 차를 잰다**(30초마다 다시). 그러면 "마이크로 356번을 들은 순간"에 화면에 어떤 딱지가 있었는지를 유튜브 화면이 도착했을 때 정확히 붙일 수 있다. 마이크가 꺼져 있으면 유튜브 소리 하나로 돌고 시간 차는 0이다.

## 4. 번호

### 4.1 빠른 길

| 들리거나 보인 것 | 하는 일 | 근거 (잰 값) |
|---|---|---|
| "N번" (그 방송 번호대 안) | 그 자리에서 **확인 중 등록**. 가격이 같은 마디에 있으면 같이, 없으면 가격 없이 | 없는 번호 1.5% |
| "번" 없는 N + 그때 화면에 딱지 N | 그 자리에서 확인 중 등록 | 상품의 20%가 이 경우 |
| "번" 없는 N뿐 | 올리지 않고 번호 후보로만 적는다(금액일 수 있다) | |
| 앞에 든 딱지 N만 (8초 안에 5번 읽힘) | 확인 중 등록, "가격 듣는 중" | 화면만의 없는 번호 9 ~ 11%. 124번 같은 상품을 살린다 |
| 손님 채팅에 올라온 적 없는 번호가 20초 안에 3명 | 올리지 않는다. 판매자에게 "N번이 안 올라온 것 같아요" | 놓친 상품의 안전망 |

번호대 밖의 번호(2132 같은 것)는 올리지 않고 후보로만 둔다.

### 4.2 맞추는 길과 확정

- **맞음이 되는 조건** (하나면 된다)
  - 말한 "N번" + 그 구간 화면의 앞 딱지가 N이거나 딱지가 없다. — 지금 규칙(D-SCR-12)과 같은 뜻이고, 그 규칙의 틀린 번호가 0.7%였다.
  - "번" 없는 N + 딱지 N이 3번 넘게 읽힘.
  - 딱지 N만 + 그 딱지가 앞에 있는 동안 들린 금액 + LLM이 그 금액을 이 상품 것으로 고름.
- **말과 화면이 다를 때**
  - 한 자리만 다르면 숫자 쌍 규칙을 쓴다(귀가 헷갈리는 3↔4·1↔2는 화면, 눈이 헷갈리는 8↔3·8↔9·6↔8은 말). 11-13에 7번 써서 7번 맞았다. 기록이 쌓이면 손으로 정한 쌍을 "말이 헷갈리는 표"와 "눈이 헷갈리는 표"에서 계산한 확률로 바꾼다.
  - 그 밖에는 확인 중으로 두고 카드로 묻는다: 번호표 사진과 `[107번 | 167번]`.
- **번호 옮기기**: 확인 중인 동안에는 일꾼이 옮긴다. 판매 중이 된 뒤에는 옮기지 않고 묻는다(6번 → 17번 사고).
- **거두기**: 확인 중으로 올렸는데 60초 안에 둘째 근거가 하나도 없으면 거둔다. 그 번호의 찜은 그대로 기다린다(엔진의 거두기 규칙).

### 4.3 번호를 다시 쓸 때·다시 소개할 때

판매 중인 번호가 다시 들리면 새 상품을 만들지 않고 같은 상품 기록의 다음 회차로 붙인다. 품종은 물려받고, 금액이 다르면 5절의 "값이 바뀜"으로 간다. 금액과 품종이 둘 다 크게 다르면 "같은 상품인가요?"를 묻는다(86·207번).

## 5. 가격

### 5.1 금액 읽기 (규칙)

- 받아쓴 글에는 숫자와 한글 수가 섞여 온다("5만원", "오만 원", "20", "삼십오"). 둘 다 읽는 수 읽기는 `packages/voice`의 규칙(R-15·R-17, 골든 시험 있음)을 그대로 쓴다.
- **단위 없는 수**는 가게의 가격 단위 설정(만 원 / 천 원)으로 읽는다. 그날 가격대(지금까지 확정된 값의 1/5 ~ 5배) 안이면 "보통", 밖이면 후보로만 둔다.
- **곁말로 뜻을 가른다.** 금액마다 갈래를 붙인다.

| 곁말 | 갈래 | 가격 후보인가 |
|---|---|---|
| "…갑니다 / 가요 / 갈게요 / 가겠습니다 / 가려요", "N번 M" | 지금 값 | 예 |
| "…빼 드릴게요 / 깎아 / 할인" | 깎는 값 | 아니오 (68번 "5만원 빼드리겠습니다") |
| "…했었는데 / 갔죠 / 아까" | 지난 값·다른 상품 값 | 아니오 (117번 "45번 아까 90 갔죠") |
| "…씩", "N개", "두 개 하면" | 낱개 값·묶음 값 | 후보로만, LLM에 묻는다 (241번 "2씩 … 20") |
| "…센치 / 층 / 두" | 크기·모양 | 아니오 |

### 5.2 빠른 길

| 경우 | 하는 일 | 근거 (잰 값) |
|---|---|---|
| 한 마디에 번호 하나 + 지금 값 하나 | 가격 칸 = 그 값, 상태 "들림" | 88% 맞음 |
| 한 마디에 금액이 여럿이거나 번호가 여럿 | 값을 정하지 않는다. 후보만 적고 "가격 듣는 중". 바로 LLM 물음 | 33개 중 후보 안에 정답 25 |
| 번호 없이 "자 이거 20 갑니다" | 지금 열려 있는 상품(10초 안에 말한 번호, 또는 앞에 든 딱지)이 하나뿐이면 그 상품의 후보로. 없으면 "주인 없는 금액"으로 적어 두고, 번호가 잡히면 붙인다 | 11-13 판매자의 말버릇. 256번이 이 경우 |
| 열 배 다른 값이 같이 들림 (2와 20, 18과 180) | 값을 정하지 않고 카드: `[2만 원 | 20만 원]` | 241번 |

### 5.3 확정

- **맞음이 되는 조건** (하나면 된다)
  - 규칙의 값 = LLM이 서류철에서 고른 값.
  - 같은 값을 그 번호와 함께 서로 다른 두 마디에서 들음. — LLM이 없어도 확정되는 길이다.
- 열 배 쌍이 있거나 가격대 밖이면 위 조건을 채워도 확정하지 않고 묻는다.
- 그 번호에 기다리는 찜이 있고 30초가 지나도록 맞음이 되지 않으면 카드를 올린다("356번 5만 원 맞나요? [아니요 | 맞아요]"). 찜이 끝없이 기다리지 않게 한다.

### 5.4 값이 바뀜

판매 중인 번호에 "N번 + 다른 금액"이 들리면:

1. 5배 넘게 다르거나 가격대 밖 → 고치지 않고 카드 (189번 500만 → 5,500원).
2. 그 마디나 앞뒤에 다른 번호가 있거나, 다른 딱지가 앞에 있다 → 고치지 않고 LLM에 "이 금액은 누구 것인가"를 묻는다. 답이 이 상품이면 카드 (36·14번).
3. 그 밖: 찜이 없으면 고치고, 있으면 카드 (83·262·299번 — 한 번만 말해도 카드가 뜬다).

## 6. 품종

### 6.1 지식을 어디서 가져오나 — 인터넷도 전국 사전도 아니고 가게 장부

| 후보 | 판단 | 근거 |
|---|---|---|
| LLM이 방송 중에 인터넷을 뒤진다 | **버린다** | 이름 대부분이 가게가 지은 이름(예명)이라 웹에 없거나 드물다. 검색은 호출을 더 느리게 한다. LLM은 모르는 이름에도 그럴듯한 설명을 붙인다(지어낸 이름 25개 중 6개에 "어렴풋이 안다") |
| LLM이 아는 지식으로 바로잡는다 | **버린다** | 120가지 중 "안다" 7가지. 문맥 없이 고치게 하면 64개 중 16개를 지어낸다 |
| 미리 조사한 전국 사전으로 거른다 | **버린다** | 11-13 품종 118가지 중 64가지가 사전에 없었다. 거름이 맞는 이름 47개를 버렸다 |
| 전국 사전을 철자 맞추는 데만 쓴다 | 쓴다 (맨 뒤 순위) | 장부에 없는 이름이 사전에 있으면 사전 철자로. 거르지는 않는다 |
| **가게 장부** | **고른다** | 틀리게 받아쓴 모양 64개 → 가게 목록에서 자모 거리로 63개 맞음(전국 사전에서는 86 ~ 91%). 장부 있음 87 ~ 93%, 없음 82 ~ 83% |

**장부는 세 때에 쌓는다.**

| 언제 | 어디서 | 급 |
|---|---|---|
| 방송 전 (처음 오는 가게) | **그 가게의 지난 방송 기록**: 다시 보기의 채팅에 남은 감사 글("N번 [품종] ₩값 …"), 방송 제목·설명. 읽기만 한다. 인터넷을 쓰는 곳은 여기 하나다 | 낮음 (확정 전) |
| 방송 중 | 판매자가 누르거나 고친 이름, 두 근거가 같아 맞음이 된 이름 | 높음 |
| 방송 뒤 | 영수증·정산서와 맞대기, "확인 중 품종" 한꺼번에 확인받기 | 높음 |

장부 한 줄: `쿠스 | 틀리게 들리는 모양: 코스, 구스 | 판 횟수 | 가격대 | 급`. 틀리게 들리는 모양은 확정될 때 (들린 글자 → 확정 이름)으로 저절로 쌓인다.

### 6.2 빠른 길 — 장부 이름 찾기

- 굳은 글이 올 때마다 낱말 1 ~ 3개를 이어 붙여 자모로 풀고, 받아쓰기가 섞는 소리를 접은 뒤(ㅎ↔ㅇ, ㅐ↔ㅔ, 된소리 …) 장부 이름과 견준다. 지금 일꾼의 방식 그대로다(`variety.py`의 `sjamo`·`ledger_said`, 문턱 86). 몇 밀리초면 끝난다.
- 장부 이름이 그 번호와 같은 마디나 바로 옆 마디에 있으면 **품종 칸 = 장부 이름, 상태 "들림"**. 무늬 말(색금·녹금·찐녹 …)·형태(군생·통째 …)·개수는 따로 칸에 넣는다.
- 장부에 없는 이름 자리는 생김새로 찾는다: "N번"과 금액 사이의 말, 무늬 말 바로 앞의 말. 닉네임·모양 말·군말을 거른 뒤 남으면 **들린 그대로 "확인 중 품종"** 으로 넣는다. 이 자리 찾기가 NER이 하던 일의 대신이다.
- "이름 없이 무늬 말만"("색금 갑니다")이면 가게 말버릇대로(예: SP · 색금).

### 6.3 맞추는 길

- **품종 묻기**(7절의 물음 B): 상품이 올라가고 25초 뒤, 품종 칸이 맞음이 아니면 한 번. 서류철과 **장부에서 소리가 가까운 후보 5 ~ 8개**를 주고 "후보 중 하나 / 후보에 없음(그러면 들린 글자를 그대로 따옴) / 이름 없이 무늬 말뿐 / 모름" 가운데 고르게 한다. D-SCR-37의 품종만 묻기가 이 물음이고, 그것으로 87%·93%가 나왔다. 달라지는 것은 장부 전체(400개까지) 대신 가까운 후보만 주는 것과 답을 고르기로 묶는 것이다.
- **맞음이 되는 조건**: 장부 이름이 서로 다른 두 마디에서 들림 / 장부 이름 + LLM이 같은 이름을 고름 / 판매자가 누름.
- 장부에 없는 이름은 저절로 맞음이 되지 않는다. 판매자가 한 번 눌러야 하고, 누르면 장부에 들어가 다음부터는 바로 붙는다.
- 품종 근거는 시간 제한 없이 쌓는다. 한참 뒤 다시 들고 나와 이름을 말하면 그때 채운다.

### 6.4 NER을 어떻게 쓰나

| 후보 | 판단 | 근거 |
|---|---|---|
| 범용 한국어 NER | 버린다 | 사람·곳·기관만 찾는다. 품종 갈래가 없다 |
| 제로샷 GLiNER | 버린다 | 한국어 제로샷 F1 37, 한국어로 미세 조정해도 76 (공개 값). 품종 이름이 보통 낱말(영웅·최강·지존·슬로건)이라 앞뒤 말 없이는 못 가린다 |
| 한국어 인코더(KLUE-RoBERTa 등)를 우리 자료로 미세 조정 | **지금은 넣지 않고 자료만 쌓는다** | 지금 자료는 가게 둘, 상품 430개쯤이다. NER이 고칠 수 있는 것은 "받아쓰기에 정답이 있는데 다른 말을 고른" 22개의 일부다. 받아쓰기가 틀린 이름은 NER도 틀린 대로 뽑는다 |
| 장부 소리 맞추기 + 자리 규칙 + LLM 고르기 | **고른다** | 6.2 · 6.3 |

자료가 쌓이면 다시 본다. 확정될 때마다 (그 상품의 줄, 품종이 있던 자리)가 학습 자료로 저절로 남는다. 2천 자리쯤 모이면 작은 인코더를 미세 조정해 "이름 자리 찾기"와 "닉네임 거르기"에서 규칙보다 나은지 방송 기록으로 견준다. 나으면 빠른 길의 자리 규칙을 바꿔 끼운다(몇 밀리초라 빠른 길에 둘 수 있다).

## 7. LLM — 언제 부르고, 무엇을 넘기고, 누구에게 묻나

### 7.1 부르는 때 (트리거)

줄이 올 때마다가 아니라 **상품 기록에 풀 일이 생겼을 때** 부른다. 같은 번호의 같은 물음은 한 번에 하나만 날아가고, 날아가는 동안 새 근거가 오면 끝난 뒤 한 번 더 묻는다.

| 물음 | 부르는 때 | 기다림 | 상품마다 |
|---|---|---|---|
| **A. 가격 맞추기** | 확인 중 상품에 금액 후보가 하나라도 생겼는데 5.3의 둘째 조건(두 마디에서 같은 값)으로 확정되지 않았을 때 | 말이 0.6초 쉬거나 첫 금액에서 3초 | 1번 (금액 후보가 여럿이면 바로) |
| **B. 품종 묻기** | 올라가고 25초 뒤에도 품종 칸이 맞음이 아닐 때. 다음 상품이 먼저 열리면 그때 | — | 0 ~ 1번 |
| **C. 값이 바뀜** | 판매 중인 번호에 다른 금액이 들리고 5.4의 2에 걸릴 때 | 말이 쉴 때 | 드묾 |
| **D. 주인 없는 금액** | 번호 없이 들린 금액이 15초 동안 어느 상품에도 붙지 못했을 때, 또는 두 상품 사이에서 점수가 비슷할 때 | — | 드묾 |
| **E. 거둠·고쳐 말함** | 그 상품 구간에 "번호 떼 / 이거 빼 / 아니 이거 ○○예요"가 들릴 때 | — | 드묾 |
| 묻지 않음 | 번호 하나·금액 하나를 두 마디에서 같게 듣고 장부 이름까지 붙은 상품 | | 0번 |

방송 하나(상품 290개)에 A 290 + B 200 + 나머지 수십 = **500번 안팎(추정)**. 지금은 1,750번이다.

D-SCR-40(상품 구간이 끝날 때 묻기)이 불합격한 것과 무엇이 다른가: 그 시험에서는 LLM이 번호를 찾아야 등록이 됐다. 덜 물으니 번호를 놓쳤고, 구간이 끝나기를 기다리니 늦었다. 여기서는 번호와 첫 값을 규칙이 올리고, LLM은 이미 올라온 상품의 칸을 맞추기만 한다. 덜 물어도 놓치는 번호가 없고, 물음이 늦어도 상품은 이미 보인다.

### 7.2 넘기는 조각 — 상품 서류철

시간으로 자르지 않고 **상품으로 모은다.** 단단히 자르지도 않는다(구간을 잘못 자르면 정답 줄이 빠진다). 그 번호의 줄을 가운데 두고 옆 번호의 줄은 표시만 해서 같이 준다.

```
상품 356번 — 지금 서버 값: 5만 원 · 품종 없음 · 확인 중
번호 근거: 말 1번(L3), 번호표 12번 읽힘
금액 후보: ① 5만 원(L3, "N번 M")  ② 4만 원(L6, "갑니다")
장부에서 소리가 가까운 이름: ㉠ 모리셔스  ㉡ 모리스  ㉢ 몰디브  (없으면 "없음")

 L1 [17:11:52] (화면: 356 크게) 자 다음 거 보여 드릴게요
*L3 [17:12:01] (화면: 356 크게) 모리세스입니다 356 5만원            ← * = 이 번호를 말한 줄
 L4 [17:12:05] ○○님 감사합니다                                    ← 닉네임은 가린다
▷L5 [17:12:09] (화면: 117 크게) 117번 기억해 주시구요              ← ▷ = 다른 번호의 줄
 L6 [17:12:14] 4만원 갑니다
```

- 줄 고르기: 이 번호를 처음 말한 줄의 15초 앞부터, 마지막으로 이 번호가 들리거나 보인 때의 10초 뒤까지. 스무 줄·60초를 넘으면 이 번호 줄에 가까운 쪽을 남긴다.
- 화면 표시는 따라간 딱지 기준이다("356 크게"는 그 딱지가 앞에 들려 있었다는 뜻).
- 물음마다 답 모양이 다르고, 모두 **고르기**다.

| 물음 | 답 모양 |
|---|---|
| A · C · D | `{ 지금 값: ①/②/없음, 갈래: {②: "다음 상품 값"}, 따온 줄: "L3" }` |
| B | `{ 이름: ㉠/㉡/㉢/"후보에 없음"/"무늬 말뿐"/"모름", 들린 글자: "모리세스", 무늬: "색금", 형태, 개수, 따온 줄 }` |
| E | `{ 뜻: 거둠/품종 고침/가격 고침/아님, 따온 줄 }` |

- **검사**: 따온 줄이 서류철에 없거나, "후보에 없음"의 들린 글자가 그 줄에 없으면 그 답은 버린다. LLM이 적은 금액·번호는 받지 않는다(고른 기호만 받는다).

### 7.3 누구에게 묻나

| 후보 | 속도 | 돈·한도 | 판단 |
|---|---|---|---|
| 구독 Codex를 호출마다 새로 띄우기 (지금) | 9 ~ 17초 (잰 값) | 구독. 요금제마다 5시간 한도가 있다 (공개 값) | 맞추는 길에서는 쓸 수 있다. 등록 길에서는 못 쓴다 |
| 구독 Codex를 띄워 둔 채 묻기 (`codex app-server`) | 재지 않음. 12초의 얼마가 띄우는 시간이고 얼마가 답하는 시간인지부터 잰다 | 같음 | **잰 뒤 바꾼다.** 물음마다 답 모양을 정할 수 있다 (공개 값). 문서에 "운영용으로는 지원하지 않는다"는 말이 있어 방송 중 끊김에 대비해야 한다 |
| 맥 미니에서 도는 작은 모델 (4B급, 답 모양 강제) | 입력 300·출력 60토큰에 2 ~ 3초 (추정, 기본 M4 공개 값에서 계산) | 없음 | **후보 1순위로 시험한다.** 고르기 물음은 작은 모델이 할 만한 일이다. 한국어 품질은 공개 근거가 없어 우리 기록으로 재야 한다 |
| 유료 API | 1 ~ 3초 | 돈 | 쓰지 않는다 (D-RETRO-101) |
| 소리를 직접 듣는 모델 | 8절 | | 8절 |

**정하는 법**: 이미 받아 둔 물음과 답이 있다(등록 물음 3천 개 남짓, 품종 물음 2,674개, 영수증 정답). 서류철 모양으로 물음을 다시 만들어 맥 미니 모델 후보(Qwen3 4B, Gemma 4 E4B, Kanana 1.5 등 — 존재는 확인했고 한국어 품질은 모른다)에 넣고, 영수증과 맞는 비율이 구독 모델보다 2%p 넘게 낮지 않으면 A·B를 맥 미니 모델로 옮긴다. 낮으면 구독 모델을 띄워 둔 채 쓰고, 맥 미니 모델과 규칙이 갈릴 때만 구독 모델에 묻는 두 층으로 간다.

어느 쪽이든 **LLM이 멈춰도 등록은 멈추지 않는다.** 상품은 확인 중으로 올라와 있고, 두 마디에서 같은 값을 들으면 LLM 없이 확정되며, 나머지는 판매자가 누른다.

## 8. 받아쓰기와 힌트

### 8.1 구조 — 글을 두 번 쓴다

| | 빠른 글 | 고운 글 |
|---|---|---|
| 무엇 | 흘러나오는 받아쓰기의 중간 글. 낱말이 두 번 이어 같게 나오면 "굳은 낱말"로 넘긴다 | 쉼에서 끊은 조각을 통째로 받아쓴 글 (지금 방식) |
| 언제 | 말하고 1 ~ 2초 | 말 끝에서 몇 초 뒤 |
| 어디에 쓰나 | 번호·금액·무늬 말·장부 이름 찾기 (빠른 길) | 서류철, 품종 근거, 방송 뒤 기록 |
| 틀리면 | 고운 글이 오면 근거를 고쳐 적는다. 확인 중인 값은 저절로 맞춰진다 | — |

고운 글은 조각 끝에서 숫자가 갈리는 문제("28" → "38번 20 / 8만원")가 있다. 빠른 글은 조각을 기다리지 않으므로 이 문제가 없고, 두 글의 숫자가 다르면 그것도 "값이 갈림" 근거가 된다.

### 8.2 모델 후보

조건: 맥 미니에서 무료로, 한국어, 말하고 1 ~ 2초 안에 글. 지금은 길이 둘이고 모델도 둘이다 — 화면 일꾼은 Whisper large-v3-turbo(MLX), 휴대폰 마이크 길의 받아쓰기 일꾼은 기본이 Cohere transcribe이고 힌트를 무시한다. 둘 다 조각이 끝나야 글이 나온다.

| 후보 | 한국어 (공개 값) | 빠른 글이 되나 | 낱말 알려 주기 | 맥에서 | 판단 |

**0단계에서 재는 표**: 11-13 소리 150분(D-SCR-39와 같은 구간, 상품 129개)에 위 굵은 후보와 지금 모델을 돌려 (가) 말 → 굳은 낱말까지의 시간 (나) "N번"이 맞게 적힌 상품 수(지금 118) (다) 금액이 맞게 적힌 상품 수(지금 95) (라) 장부로 되찾은 뒤 품종이 맞은 상품 수(지금 85 / 92) (마) 맥 미니에서 화면 일꾼과 같이 돌 때의 여유를 본다. 한 번에 하나만 바꾼다.

**되찾기가 힌트보다 크다는 근거**: 받아쓴 뒤 낱말 목록으로 묶어 고치는 방식이 고유 이름 오류를 49%까지(상대) 줄였다는 연구, 소리 단위 편집 거리로 닫힌 목록에서 되찾는 방식이 가볍고 잘 듣지만 목록이 커지면 비슷한 소리끼리 헷갈린다는 연구가 있다(공개 값). 가게 장부는 100 ~ 400개라 그 걱정이 작다. 우리 기록의 64개 중 63개가 같은 이야기다.

### 8.3 힌트를 어떻게 쓰나

| 무엇 | 판단 | 근거 |
|---|---|---|
| 품종 이름 수백 개를 힌트로 | 하지 않는다 | Whisper 힌트는 260자쯤. 넣은 45종에서만 +5개, 소리 맞추기로 견주면 힌트 몫 0 ~ 1개 (잰 값) |
| 조각마다 후보를 골라 다시 받아쓰기 | 하지 않는다 | 조각의 64%를 두 번 받아쓴다. 더 맞힌 것 1 ~ 2개 (잰 값) |
| 늘 나오는 낱말 10여 개 (색금·녹금·찐녹·창·SP·번·만 원) | 넣는다 | "색금"이 31%만 맞게 적힌다. 낱말 수가 적어 어느 모델의 힌트에도 들어간다. 받아쓴 뒤의 바로잡기(세금·새끔 → 색금)는 그대로 둔다 |
| 품종 이름 | **받아쓴 뒤에 장부에서 소리로 되찾는다** | 64개 중 63개 (잰 값). 힌트보다 이쪽이 훨씬 크다 |
| 글자가 아니라 소리 낱낱(음소)에서 장부 이름 찾기 | 다음 차례의 후보 | "8세초"(팔색조)처럼 글자가 아주 달라진 경우는 글에서 못 찾는다. 방송당 몇 개라 뒤로 미룬다 |
| 긴 힌트를 받는 모델(문맥 글을 따로 받는 종류) | 8.2의 시험에서 장부 전체를 넣어 본다 | 한도가 크면 판단이 달라질 수 있다 |

## 9. 화면 — 찾기 · 따라가기 · 읽기

### 9.1 화면이 하는 일

화면은 유튜브를 거쳐 오므로 마이크보다 늦다. 그래서 화면은 등록을 시작하는 근거가 아니라(번호를 말하지 않은 상품만 빼고) **번호를 맞추고, 지금 든 상품이 무엇인지 알려 주는 근거**다. 금액과 이름을 어느 번호에 붙일지 정할 때 "그때 앞에 들려 있던 딱지"가 가장 센 단서가 된다.

### 9.2 후보와 고른 것

| 단계 | 지금 | 후보 | 고른 것 | 근거 |
|---|---|---|---|---|
| 찾기 | 없음 (화면 전체를 글자 읽기에 넣는다, 장당 370ms) | 색·모양 규칙(시제품) / YOLO 계열 / RF-DETR / 글로 찾는 검출기 | **작은 검출 모델을 번호표 수백 장으로 미세 조정. RF-DETR Nano가 1순위** | 색·모양 규칙은 작은 딱지를 71%만 찾는다 (잰 값). RF-DETR Nano는 M4급에서 장당 10ms 안팎이고 Apache-2.0이다 (공개 값). YOLO 계열은 AGPL이라 서비스에 쓰려면 따져야 한다. 글로 찾는 검출기는 느려서 첫 학습 자료를 자동으로 만드는 데만 쓴다 |
| 따라가기 | 없음 (장면마다 가장 큰 글자) | ByteTrack · BoT-SORT · OC-SORT 등 / SAM 계열 | **초당 5장 + 가벼운 추적기** | 1초 1장에서는 위치로 잇는 추적이 모두 무너진다 (공개 값). 시제품에서 초당 5장이면 확정까지 가운데 0.6초였다 (잰 값). SAM 3.1은 720p에서 초당 0.5장이라 실시간이 아니다 (공개 값) |
| 읽기 | Apple Vision 한 장 | Apple Vision / PP-OCRv6 인식기 / 숫자 전용 모델 / 작은 시각 모델 | **딱지 조각에 PP-OCRv6 인식기(숫자만 허용) + 같은 딱지의 읽기를 믿는 정도로 더하기. 둘이 갈릴 때만 Apple Vision을 한 번 더** | 조각 5,317개: PP-OCRv6 다른 번호 0.4%·자릿수 빠짐 9.0%, Vision 다른 번호 2.6%·자릿수 빠짐 2.7% (잰 값). 틀리는 모양이 서로 달라 같이 쓰면 메운다. 여러 장 투표는 한 글자 오독을 주로 고친다 (공개 값) — 4 → 8이 그 경우다 |
| 앞에 든 딱지 가리기 | 가장 큰 글자 | 크기 / 가운데 / 움직임 | **크기 × 가운데 × 움직임** | 진열대 딱지는 멈춰 있고 손에 든 화분은 움직인다. 초당 5장이면 움직임을 볼 수 있다 (추정) |
| 품종 글씨·이름표 | 읽지 않음 | 한글 인식기 / 작은 시각 모델 | **넣지 않는다. 비율만 잰다** | 네 장면에서 0개 (잰 값). PP-OCRv6에는 한국어가 없고, 한글 손글씨는 어느 모델도 공개 근거가 없다. 앞에 든 화분 조각을 한글 인식기에 넣어 장부 이름과 맞는 비율이 상품의 5%를 넘으면 근거로 더한다 |
| 식물 따라가기 (딱지가 붙기 전부터) | 없음 | 손에 든 화분 검출 + 추적 | **뒤로 미룬다** | "주인 없는 금액"(5.2)으로 대부분 풀린다. 그래도 남는 것이 얼마인지 본 뒤 |
| 같은 화분인지 (사진 닮음) | 없음 | DINO 계열 임베딩 | **뒤로 미룬다. 번호를 옮기거나 다시 쓸 때의 근거로만** | 생김새로 품종을 정하지 않는다 |

초당 5장의 값: 찾기 10ms + 조각 읽기 10ms × 딱지 수 = 장당 30 ~ 50ms, 한 코어의 15 ~ 25% (추정). 지금 방식(한 코어의 43%)보다 가볍다.

## 10. 서버·앱이 바뀌어야 하는 것

| # | 무엇 | 지금 | 왜 필요한가 |
|---|---|---|---|
| 1 | **가격 없는 확인 중 등록** | 금액 없는 임시 등록은 서버가 받지 않는다 | "번호만 들려도 올린다"의 전제다. 확정에는 가격이 꼭 있어야 한다는 것은 그대로 둔다 |
| 2 | 확인 중 상품의 칸 채우기·후보 고치기 입구 | 고치기는 되지만 후보를 나중에 고치는 입구가 없다 | 가격·품종이 뒤에 붙는다 |
| 3 | 칸마다의 상태 (들림 / 맞음 / 판매자 확정) | 상품 단위 "확인 중"과 까닭 낱말만 | 앱이 "가격 듣는 중", "확인 중 품종"을 칸마다 보인다 |
| 4 | 확인 카드 입구 (가격 두 가지 · 번호 두 가지 · 값이 바뀜 · 거둘까요 · 안 올라온 번호) | 일꾼 기록에만 남는다 | 묻는 길이 있어야 "모르면 묻는다"가 된다 |
| 5 | 가게 장부를 서버에 두고 일꾼이 받아 가기 | 파일 | 방송마다 쌓이고 여러 기기가 같이 본다 |
| 6 | **판정을 한곳으로** | 음성 길(`packages/voice`, 규칙, 휴대폰 마이크)과 화면 일꾼(파이썬, LLM)이 따로 돈다 | 수 읽기 규칙이 둘이고, 한쪽이 올린 상품을 다른 쪽이 모른다. 근거 기록 → 상품 기록 함수를 하나 두고, 맥 미니는 듣기·보기·묻기만 한다. 서버 쪽에 두면 판매자 손질을 바로 알고 요청 차례 문제(620·107번)도 없다 |

## 11. 지연 예산 (추정 — 12절에서 잰다)

| 구간 | 마이크 길 | 유튜브 소리만 |

### 13.2 아직 모르는 것 (0단계에서 잰다)

- 흘러나오는 받아쓰기의 굳은 낱말이 숫자를 얼마나 맞게 적는지. 빠른 글이 자주 틀리면 화면의 값이 자주 바뀌어 판매자가 불안해한다.
- 현장 마이크 소리의 품질(음악·잡음), 판매자 휴대폰이 늘 판매자 가까이에 있는지.
- 맥 미니 한 대에 받아쓰기 둘 + 화면 초당 5장 + 작은 모델이 같이 도는지. 맥 미니의 칩과 메모리를 이 글을 쓰며 확인하지 못했다.
- 맥 미니 모델의 한국어 고르기 품질, Codex를 띄워 둘 때의 시간.
- 처음 오는 가게의 장부를 지난 방송 기록에서 얼마나 채울 수 있는지.
- 판매자가 방송 중 카드를 몇 장까지 눌러 줄 수 있는지.

### 13.3 정해 주실 것 (실물 · 비용 · 법률)

| 무엇 | 내 권고 |
|---|---|
| 휴대폰 마이크를 등록의 주된 소리로 삼아도 되나 | 삼는다. 유튜브 지연을 없애는 길은 이것뿐이다. 판매자가 방송 내내 앱을 켜 둔 휴대폰을 곁에 둬야 한다 |
| "확인 중 품종"(장부에 없는 이름)을 감사 채팅·라벨에 쓸까 | 쓰지 않는다. 번호·가격만 내보내고, 이름은 판매자가 눌렀을 때와 방송 뒤 한꺼번에 확인받을 때 채운다. 장부 없는 가게에서 확인 중 이름의 84%가 맞았지만(잰 값) 라벨에 틀린 이름이 찍히면 되돌리기 어렵다 |
| 가격 없는 "확인 중" 상품을 앱 목록에 보일까 | 보인다("가격 듣는 중"). 손님 찜이 붙을 자리가 일찍 생긴다 |
| 구독 요금제의 한도 | 지금 요금제가 5시간에 몇 번까지 되는지 확인이 필요하다. 호출을 500번 안팎으로 줄이는 것과 맥 미니 모델이 이 걱정을 던다 |
| 검출 모델의 라이선스 | 저장소의 `tag_yolo11n_r2.pt`는 AGPL 계열 도구로 만든 것이다. 서비스에 쓰기 전에 Apache-2.0인 RF-DETR로 다시 학습하는 쪽을 권한다 |
| 지난 방송 기록 읽기 | 그 가게의 공개된 다시 보기와 채팅을 읽어 장부를 만든다. 가게마다 동의를 받고 한다 |
