## 0. 생각이 어떻게 정리됐나

두 번의 방송과 그 뒤 논의로 방향이 다섯 가지로 모였다.

1. **"한 번 듣고 맞히기"를 버리고, 번호마다 근거를 쌓는 상품 기록으로 간다.** 상품은 번호로 묶인 긴 기록이고, 소개는 그 안의 회차다. 품종은 회차를 넘어 쌓고, 가격은 회차마다 다시 본다.
2. **상품 하나에 LLM 호출 하나.** 지금은 받아쓰기 줄마다 최근 60초를 통째로 묻는다. 답의 87%가 아무것도 바꾸지 않고, 옆 상품의 값과 이름을 끌어온다. 상품 경계는 LLM이 아니라 화면 번호표와 말한 번호로 먼저 자른다.
3. **품종은 전국 사전으로 거르지 않고, 그 가게의 장부 안에서 고른다.** 장부에 없는 이름은 버리지 않고 "확인 중 품종"으로 올린다. 사전 거름(D-SCR-15)은 내가 묻지 않고 넣은 결정이고, 틀린 이름 21개를 막으려다 맞는 이름 47개를 버렸다.
4. **근거는 소리 하나가 아니다.** 화면 글씨(잎 손글씨·이름표), 소리, 가게 장부, 식물 사진. 화면에 품종이 안 보이는 상품도 있으니 근거마다 "있음 / 없음"을 따로 두고, 둘이 같으면 확정, 하나뿐이거나 다르면 판매자가 한 번 눌러 확인한다.
5. **빨리 올리되 틀린 값은 손님에게 나가지 않게.** 먼저 "확인 중"으로 올려 찜을 받고, 감사 채팅과 라벨은 확정된 값만 쓴다. 방송 중에는 운영을 바꾸지 않는다.

자동으로 100%는 어떤 기술로도 안 된다. 판매자가 품종을 말하지 않은 상품, 이름 없이 "색금"으로만 판 상품, 소개하다 만 상품이 있기 때문이다. 100%는 "자동으로 최대한 맞히고, 확실하지 않은 것만 한 번 눌러 확인"으로 간다.

## 3. 정한 구조

```
 화면 ──▶ 번호표 추적 ──▶ 소개 회차(상품 경계) ─┐
          잎 글씨·이름표 읽기 ──▶ 근거: 화면 글씨 │
          식물 사진 ──▶ 근거: 사진 닮음, 같은 화분 │
                                                  ▼
 소리 ──▶ 받아쓰기(가게 이름 힌트) ──▶ 그 회차의 줄 ──▶ 상품 기록(번호마다)
                                                  │      · 번호 근거
 가게 장부 ──▶ 소리가 가까운 후보 3개 ──▶ LLM 한 번 ─┘      · 가격 근거(회차마다)
   (품종·무늬·형태·별칭·가격대·확정 사진)                    · 품종 근거(회차를 넘어 쌓임)
                                                          │
                              근거가 맞으면 확정 ◀──────────┤
                              아니면 "확인 중" → 판매자가 한 번 눌러 확정
                                                          │
                              확정된 값만 감사 채팅·라벨로. 확정 결과는 가게 장부로 돌아간다
```

### 3.1 근거 네 가지와 "없음"

| 근거 | 무엇 | 없을 때 |
|---|---|---|
| 화면 글씨 | 잎에 쓴 매직 손글씨, 화분의 이름표 | 소리와 장부로 판단 |
| 소리 | 판매자가 말한 이름 | 화면과 사진으로 판단 |
| 가게 장부 | 그 가게가 파는 품종, 별칭, 가격대 | 새 품종 후보로 둔다 |
| 사진 닮음 | 그 가게의 확정 사진과 비교 | 쓰지 않는다 |

- 두 근거가 같은 이름이면 확정한다.
- 근거가 하나뿐이면 "확인 중 품종"으로 올린다. 값은 보이되 감사 채팅과 라벨에는 쓰지 않는다.
- 근거끼리 다르면 후보를 단추로 보여 판매자가 고른다.
- 판매자가 이름을 말하지 않았고 화면에도 없으면 빈칸이 맞다. 무늬 말만 말했으면 그 가게 말버릇대로 넣는다(예: 색금만 말하면 SP).

### 3.2 상품 기록과 소개 회차

- 화면 번호표 추적 구간 하나, 또는 말한 번호가 바뀌는 곳까지가 회차 하나다.
- 11-13에 3분 넘게 떨어져 말과 화면 둘 다로 다시 소개된 번호는 12개다(느슨하게 세면 286개 중 44개). 간격은 가운데 값 29분, 길게는 3시간 47분이었다.
- **품종**은 회차를 넘어 쌓는다. 확정된 품종은 다시 뽑지 않는다.
- **가격**은 회차마다 다시 본다. 다시 소개하며 번호와 함께 다른 값을 말하면 "가격이 바뀐 것 같아요" 카드를 올린다(120번 12만 → 10만은 잡았고, 83·262·299번은 놓쳤다).
- **같은 번호가 같은 화분인지**는 사진으로 본다. 영수증에는 같은 번호를 다른 상품에 다시 쓴 것이 있다(86·207번). 식물이 다르면 번호 재사용으로 보고 묻는다. 사진 비교가 얼마나 맞는지는 재지 않았다.

### 3.3 번호·가격·품종마다

| | 지금 | 바꾸는 것 |
|---|---|---|
| 번호 | 말한 번호 + 번호표 3장, 숫자 쌍 규칙. 틀린 것 0.7% | 번호표를 추적해 다수결로 읽는다. 근거가 모자라면 버리지 않고 "확인 중"으로 올린다. 바로잡기는 등록 응답 뒤에 보낸다. 번호와 가격을 여러 번 말한 상품은 다른 번호표가 보여도 옮기지 않는다 |
| 가격 | 말한 금액 = LLM 금액이면 바로, 아니면 같은 답 2번 | 그 회차의 줄만 근거로 쓴다. 고친 값이 5배 넘게 다르거나 가격대를 벗어나면 고치지 않고 묻는다. 한 줄에 다른 번호가 같이 있으면 그 줄의 금액은 쓰지 않는다. 내린 값은 한 번만 또렷이 말해도 카드로 올린다 |
| 품종 | LLM이 자유롭게 적고 전국 사전으로 거름. 맞음 49%, 빈칸 32% | 가게 장부에서 소리가 가까운 후보 3개를 찾고 LLM은 "그중 하나 또는 목록에 없음"만 고른다. 장부에 없는 이름은 "확인 중 품종". 이름을 품종 / 무늬 / 형태 / 개수로 나눠 적는다 |

| B7 | 개수·통째 | 이름에서 뗀 "3개", "통째"를 따로 보낸다 | 66·68·133·179·216번 |
| B8 | 가게 말버릇 | "이름 없는 색금은 SP", "종자 = 종자용 SP"를 가게 설정으로 둔다 | 빈칸 15개, 무늬 말끼리 다름 18개 |
| B9 | 거둔 상품 | "번호 떼", "이거 빼"가 그 회차에 나오면 "거둘까요?" 카드 | 153번 |

### C단계. 받아쓰기

|---|---|---|

| C2 | 별칭 배우기 | 확정될 때마다 (들린 모양 → 확정 이름)을 가게 별칭으로 쌓는다. 코스 → 쿠스처럼 힌트로도 안 잡히는 모양을 바꾼다 |

### D단계. 화면과 속도 — 재 보고 정하는 것

| # | 무엇 | 넣는 조건 |
|---|---|---|

| D2 | 번호표 읽기 모델 바꾸기 | M6에서 나으면 |

| D4 | 식물 추적 | 번호표가 붙기 전에 말한 가격을 그 상품에 묶는 데 쓴다. B1 ~ B2만으로 부족한지 본 뒤 |

| D6 | LLM 호출 방식 | M7의 결과와 5절의 결정대로. 구독을 유지하면 띄워 두기(`codex app-server`)를 시험한다 |
| D7 | 느린 길 | 근거가 안 맞는 상품만 뒤에서 따로 푼다: 그 구간을 힌트 넣어 다시 받아쓰기, 장면 사진 읽기, 장부 찾기. 방송 뒤 영수증 대조도 여기서 한다 |

| # | 무엇 |
|---|---|

### 4.3 품종 방식의 근거 (11-13 기록으로 잰 것)

새 규칙 구간 상품 235개.

| 방식 | 맞음 |
|---|---|
| 지금: LLM 이름을 전국 사전으로 거름 | 49% |
| LLM이 가장 많이 적은 이름 그대로 | 69.8% |
| 그 이름을 그날 가게 목록에서 소리가 가장 가까운 이름에 맞춤 | 78.7% |
| LLM 없이 편집 거리로만 받아쓰기에서 목록 이름 찾기 | 57 ~ 58% |

받아쓰기에 실제로 나온 틀린 모양 64개를 정답 품종에 맞추는 시험.

| 맞추는 방법 | 가게 목록 120개에서 | 전국 사전 2,456개에서 |
|---|---|---|
| 글자(음절) 편집 거리 | 83% | 66% |
| 자모 편집 거리 | 98% | 86% |
| 소리가 가까운 자모에 가중치를 준 편집 거리 | 98% | 91% |
| LLM에게 문맥 없이 고치게 함 | 38% | |

- 맞추는 공식보다 **어느 목록에서 찾느냐**가 훨씬 크다. 자모 단위로 가게 목록에서 찾으면 64개 중 63개가 맞는다.
- 편집 거리만으로 LLM을 대신할 수는 없다. 어느 낱말이 품종이고 어느 상품의 것인지를 가르는 일이 남는다. 그 몫이 B2(상품 단위)와 B6(답 칸)이다.
- 78.7%는 **그날 영수증을 가게 목록으로 쓴 값**이다. 장부가 다 찬, 다시 오는 가게의 가장 좋은 경우다. 처음 오는 가게는 장부가 비어 있어 LLM 이름 그대로(69.8%)에 "확인 중 품종"으로 시작한다.
- 64개는 정답과 소리가 비슷한 모양을 골라 만든 표본이라 쉬운 쪽으로 기울어 있다.

## 5. 정해 주셔야 할 것

| 무엇 | 내 권고 |
|---|---|
| 배포 보류를 언제 푸나 | A단계를 로컬에서 만들고 두 방송 기록으로 재현 수치를 보여 드린 뒤에. 풀면 멈춰 둔 것(1.3)부터 올린다 |
| LLM을 API로 바꿀지 (돈이 든다) | M7로 지연과 비용을 먼저 잰다. 답을 가게 목록 안으로 강제하고 지시문을 캐시할 수 있어 속도와 정확도 둘 다에 닿는다. 테스트 기간에는 구독을 유지하기로 하셨으므로, 재는 시험만 허락해 주시면 된다 |
| 방송 전에 번호–품종 목록을 받을 수 있나 | 받을 수 있으면 품종 문제가 번호 문제(틀림 0.7%)가 된다. 가게가 해 줄 수 있는 일인지 여쭤봐야 한다 |
| 방송 주인이 채팅에 친 번호 | "판매자 찜"으로 받는다. 지금 가게가 실제로 그렇게 상품을 뺀다 |
| 번호 없는 "패스"·"취소" | 자동 취소는 하지 않고, 그 손님의 찜이 하나일 때만 취소 요청 카드로 띄운다 |
| 직배 | 뜻(직접 배송인지, 다른 가게 앞으로 보내는 것인지)을 먼저 알려 주셔야 한다 |
| 틀린 감사 채팅 | 지우지 않고 "[수정] N번 …" 글을 한 번 더 올린다. 유튜브에 쓰는 일이라 결정이 필요하다 |
| 같은 번호 다시 쓰기 | 한 방송에 번호당 상품 하나인 지금 규칙을 바꿔야 한다. B4의 물음 카드로 시작한다 |

## 6. 하지 않기로 한 것

| 무엇 | 까닭 |
|---|---|
| 전국 품종 사전으로 LLM 이름 거르기 | 맞는 이름 47개를 버렸다. 가게마다 품종이 다르다 |
| 줄마다 최근 60초를 통째로 묻기 | 87%가 헛돌고 옆 상품을 끌어온다 |
| LLM에 인터넷 검색 붙이기 (등록 길) | 가게가 지은 이름은 웹에 드물고 호출이 더 느려진다. 방송 뒤 처음 본 이름 확인에만 쓸 수 있다 |
| "모르면 비슷한 품종으로 고쳐라" 지시 | 없는 이름을 지어낸다 |
| 범용 NER, LLM 미세 조정 | 막힌 곳은 모델 지식이 아니라 닫힌 목록과 받아쓰기다 |
| 글자 뜻 임베딩으로 품종 찾기 | 셀브를과 쉘브르는 뜻이 아니라 소리가 가깝다. 찾는 열쇠는 자모 편집 거리다 |
| 식물 생김새만으로 품종 정하기 | 교배종끼리 닮았다. 사진은 같은 화분인지와 후보 추천에만 쓴다 |
| 지식 그래프 도구 들이기 | 가게당 품종 수백 개라 표 몇 개면 된다. 방송 뒤 자동으로 쌓는 방식만 가져온다 |
| 라이브 채팅으로 손님에게 번호 묻기 | 답이 찜으로 읽히고, 아무나 답하고, 유튜브에는 감사 채팅 말고 쓰지 않는다 |
| 휴대폰 자체 받아쓰기 | 기기마다 결과가 다르고 가게 이름 힌트를 넣기 어렵다 |
| LLM 첫 답을 확인 없이 확정 등록 | 11-12 사고의 가장 큰 원인 |
| 방송 중 서버 재시작, 일꾼 교체, 맥 미니 빌드 | F1, F2 |

## 7. 아직 모르는 것

- **화면 품종 글씨가 얼마나 읽히는지.** 720p, 1초 1장, 글씨가 뒤집히고 잘려 있다. M1을 재 봐야 D1을 넣을지 정할 수 있다.
- **상품 경계를 얼마나 맞게 자르는지.** 번호표를 늦게 들거나 두 상품을 같이 들면 한 상품의 줄이 갈린다. M2.
- **임시 등록의 실제 속도.** 재현에서 "그 초에 올림"이 실제로는 받아쓰기 7 ~ 9초 뒤다. 5초 목표는 유튜브 소리로는 닿지 않을 수 있고, 휴대폰 마이크(D5)가 필요할 수 있다.
- **처음 오는 가게의 품종.** 장부가 비어 있으면 확인 카드가 많이 뜬다. 판매자가 방송 중 몇 번까지 눌러 줄 수 있는지 모른다.
- **31·45번.** 영수증 값(38만·75만)이 방송 말(40만·90만)과 다르다. 받아쓰기에 내린 값을 말한 줄은 없다. 방송 밖에서 정한 값으로 보인다. 11-15에 "다시 소개하며 내린 값을 놓쳤다"고 답한 것은 근거가 없어 여기서 바로잡는다.
- **맥 미니 한 대의 여력.** 화면 일꾼, 받아쓰기 일꾼, 번호표 추적을 같이 돌릴 수 있는지.
- **11-13 15시부터 품종 빈칸이 두 배가 된 까닭.**
- 11-13 복기 10절의 것들(78·185·242·280번의 실제 판매가 등)은 그대로 남아 있다.
