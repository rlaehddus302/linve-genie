## 1. 문제 정의

### 1.1 입력

방송 하나는 시각 축(방송 초 `t`) 위의 세 흐름이다. 일꾼 실행 폴더(`<영상>-<YYYYMMDD_HHMMSS>/`)에 이렇게 남는다.

| 흐름 | 파일 | 한 줄 모양 | 만드는 곳 |
|---|---|---|---|
| 받아쓰기 조각 | `transcript.jsonl` | `{"start_sec", "end_sec", "text"}` | Silero VAD 자르기(0.4초 멈춤, 최대 20초) + `mlx-community/whisper-large-v3-turbo`(`sw/audio.py`, `language="ko"`, 힌트 없음) |
| 화면 번호표 | `screen.jsonl` | `{"sec", "t": [[숫자, …, 너비, 높이], …]}` (1초 1장) | Apple Vision OCR 두 번(전체 + 가운데 2배 확대) → 1~3자리 숫자 → `sw/screen.py`의 `Screen.build()`가 초마다 후보 번호(`cand`)와 가장 크게 보인 번호(`mains`)를 만든다 |
| 등록 LLM 물음·답 | `llm_live.jsonl` | `{"upto", "why", "user", "answer", "at", "sec"}` | `sw/llm_live.py` `LlmRegister._ask` |
| 일꾼 이벤트 | `events.jsonl` | `LLM등록`·`LLM이름고치기`·`LLM품종묻기` … | 같은 곳 |

손님 채팅은 이 길(LLM 등록)에서 쓰지 않는다. 손님 닉네임은 받아쓰기 속 "○○님" 같은 부름에서만 걸러 낸다(3.6절).

### 1.2 출력

판매 중으로 등록된 상품 번호 `n`마다 (금액, 품종 이름 `v̂(n)`). 품종 칸은 문자열 하나이고 빈칸일 수 있다. 일꾼 안에서는 `variety.split_parts`가 이름을 (품종 바탕, 무늬 말, 형태, 개수)로 나눠 다룬다. 예: "테라로사 색금" → (테라로사, 색금, "", ""), "채홍 3개" → (채홍, "", "", 3개). 서버로는 바탕 + 무늬 말을 붙인 이름(`join_parts`)이 간다.

### 1.3 정답 만들기

| 방송 | 정답 | 파일 모양 | 손질 |
|---|---|---|---|
| 11-13 | 전산 직원 영수증(방송 뒤) | `truth.json`: 줄 298개, 칸 `no, name, price, qty, sold, row, …`. 한 번호에 줄이 여럿일 수 있다 | 번호마다 이름 목록 `T(n)`을 모은다. 영수증에 없지만 방송에서 판 4개(55·148·153·208번)를 이름 없이 더한다. 금액만 바꾸는 손질(6개 번호에 두 값을 정답으로)은 품종과 관계없다 |
| 11-12 | 방송 끝 서버 DB(판매자가 손으로 고친 뒤) | `products.json`: `{"note", "products": [{no, name, price, phase, sold}]}` 173개 | `phase == "CLOSED"`(판매자가 지운 번호) 11개와 남아 있지만 틀린 번호 {2, 5, 27, 123}을 뺀 158개 |

**채점 대상**(분모) = 재현이 끝났을 때 가짜 서버에 **판매 중**(임시 등록이 아닌)으로 남은 번호 ∩ 정답 번호 ∩ 정답 이름이 있는 번호. 11-13은 판매 중 정답 번호 286개 가운데 이름 없는 4개를 빼 **282개**, 11-12는 판매 중 정답 번호 155개 가운데 **147개**다. 등록하지 못한 번호(11-13: 107·124번, 확인 중으로 남은 135·272번 / 11-12: 209·313·397번)는 분모에 들지 않는다 — 품종 정확도는 "등록된 상품의 품종"에 대한 조건부 정확도다.

정답 파일은 손님 정보가 섞여 있어 저장소에 넣지 않았다(D-SCR-17).

### 1.4 무늬 말과 동치류

영수증은 품종 이름 없이 파는 상품을 무늬·종류를 이르는 말(색금, 녹금, SP, 종자, 찐녹, 녹색금, 창녹금 …)로 적는다. 11-13 영수증은 같은 뜻의 상품을 "색금"(19개)으로도 "SP"(17개)로도 적었고, 사용자 메모는 "그냥 색금 = 품종 SP"다(D-SCR-32, `DECISIONS.md` D-SCR-38 아래 단락). 그래서 **바탕 품종이 없는 이름끼리는 같은 것으로 보는 채점**(M_eq)을 함께 적는다. 무늬 말 집합은 채점 코드의 `GEN`이다(7.2절).

상품을 둘로 나눈다.

- **R (진짜 품종 이름이 있는 상품)**: 정답 이름 가운데 하나라도 `variety.split_parts(x)[0]`(바탕 품종)가 비어 있지 않은 것. 11-13 209개, 11-12 92개.
- **P (영수증이 무늬 말만 적은 상품)**: 나머지. 11-13 73개, 11-12 55개.

### 2.3 답 창고 — 재현이 결정적인 까닭

1. **등록 답**: 방송 중 `llm_live.jsonl`에 물음마다 넣은 글(`user`)·답(`answer`)·받은 시각(`at`)·걸린 초(`sec`)가 남는다. 재현은 LLM을 부르지 않고 이 답을 기록된 시각에 그대로 넣는다(`sw/replay_live.py` `replay_run`, `reg.par = 0`).
2. **품종만 묻기 답**: `LLM_NAME_ASK_CACHE=<폴더>`를 주면 `llm_live.ask_name`이 묻는 대신 `sha1(지시문 글 + "\0" + 묻는 글)`을 열쇠로 `<폴더>/<열쇠>.json`(`{"answer": …, "user": …}`)을 읽는다. 없으면 묻는 글을 `<폴더>/todo.jsonl`에 적고 **빈 답**으로 넘긴다(LLM을 부르지 않는다). 창고가 있으면 답을 그 자리에서 받는다(`NAME_ASK_SYNC`).
3. 창고 채우기(저장소 밖 `$SP/lab/ask/fill.py <동시 수>`): `todo.jsonl`의 묻는 글을 위 2.2절 codex 명령(지시문 = `variety.ASK_SYS`, 스키마 = `variety.ASK_SCHEMA`)으로 묻고 같은 열쇠로 저장한다. 3번까지 다시 묻는다.
4. 그래서 **같은 코드 + 같은 창고 + 같은 기록**이면 재현은 결정적이다. 가짜 시계(`FakeTime`)가 1초씩 흐르고, 품종 묻기는 동기로 답을 받으며, 스레드에 따른 차례 흔들림이 없다. 2026-11-16 같은 창고로 다시 돌려 같은 수를 얻었다(5.4절).

창고의 역사: (가) 책상 계산(`ask/run.py`)이 "묻기 끔" 재현(H 판)이 남긴 품종 고르기 기록(`LLM_NAME_DUMP`)으로 여덟 조건의 묻는 글을 만들어 먼저 채웠다(11-15 13:23~13:29). (나) 일꾼 코드가 실제로 만든 묻는 글 가운데 창고에 없던 **858개**(`ask/todo_pass1.jsonl`)를 채웠다. (다) 그 뒤 규칙을 고칠 때마다 생긴 새 묻는 글을 같은 방식으로 채웠다. 지금 창고는 2,674개다(1단계 시험의 것 포함). 최고 수치 판(L 판, 5절)의 여덟 실행은 모두 **답 없음 0**이었다(`LLM품종묻기` 이벤트의 `answer`가 빈 것이 없다 — 11-13 실행마다 287번, 11-12 실행마다 156번 물음).

## 3. 파이프라인

### 3.1 등록 물음 (번호·가격·품종을 함께 묻는 길)

`LlmRegister.tick()`이 1초마다 돈다(`sw/llm_live.py`).

- **묻는 때(`LLM_TRIGGER=line`, 기본)**: 새 받아쓰기 줄에 `CUE = [0-9번만천원십]`이 있거나 그 줄 동안 크게 보인 번호표가 앞 줄과 다르면 묻는다. 아무 일 없이 `SAFETY = 60`초(방송 초)가 지나면 한 번 묻는다. 이미 정해진 번호만 다시 보이는 줄은 묻지 않는다(`SKIP_SETTLED`, D-SCR-16). 화면 읽기가 그 줄 끝까지 오기를 `SCREEN_WAIT = 3`초까지 기다린다. 동시 `PAR = 4`.
- **보내는 줄**: 묻는 줄의 시작 시각 앞 `WINDOW = 60`초(`LLM_REG_WINDOW`)에 시작한 줄 전부. 한 줄 모양: `L{i} [H:MM:SS] (화면: {span_note}) {mask(text)}`. `span_note`는 그 줄 시작 1초 전 ~ 끝 1초 뒤에 크게 보인 번호와 초 수, 그다음 보인 번호 3개다("334 크게 5초 / 333, 34").
- **2분 조각·30초 겹침에 대해**: D-SCR-03(11-12 새벽)의 첫 라이브 등록과 끝난 방송 시험(`sw/llm_b6.py` + `sw/llm_b4.chunks`: 2분 조각, 30초 겹침)은 그 방식이었다. 커밋 `c8c9b9ec`(11-12 06:18)부터 라이브 일꾼은 위의 "이벤트마다 앞 60초" 방식이다. **최고 수치는 60초 방식에서 나왔다.** 재현은 그날 실제로 물은 창과 답을 그대로 쓴다.

### 3.4 소리(자모) 견주기

**자모 풀기** `jamo(s)`: 완성형 한글 음절마다 초성 + 중성 + 종성(있으면)을 호환 자모 문자로 이어 쓰고, 마지막에 `ㅔ → ㅐ`로 바꾼다. 한글이 아닌 글자는 그대로 둔다. 예: "쉘브르" → `ㅅㅞㄹㅂㅡㄹㅡ`.

**소리 접기** `sjamo(s) = jamo(s).translate(_FOLD)` — 가게 장부(좁은 목록)에서만 쓴다(전국 사전에서는 다른 품종끼리 붙어서 쓰지 않는다).

| 접는 것 | 한 소리로 |
|---|---|
| 모음 | ㅛ·ㅜ·ㅠ → ㅗ, ㅑ·ㅘ → ㅏ, ㅕ·ㅝ → ㅓ, ㅖ·ㅒ·ㅔ·ㅞ·ㅙ·ㅚ → ㅐ, ㅢ·ㅟ → ㅣ |
| 자음(초성·종성 모두 — 같은 호환 자모 문자이므로) | ㅋ·ㄲ → ㄱ, ㅌ·ㄸ → ㄷ, ㅍ·ㅃ → ㅂ, ㅊ·ㅉ → ㅈ, ㅆ → ㅅ, ㅎ → ㅇ |

겹받침(ㄳ·ㄺ …)은 접지 않는다. 이 접기로 "채용"과 "채홍"(ㅎ→ㅇ), "셀브로"와 "쉘브르"가 같은 열이 된다.

**거리**: `rapidfuzz.fuzz.ratio(a, b)` = 100 × (1 − InDel(a, b) / (|a| + |b|)). InDel은 넣기·빼기만 세는 편집 거리(바꾸기는 2로 센다)이므로 "편집 거리 비율"이라고 부른 값의 정확한 정의는 이것이다. **소리 가까운 자모마다 다른 가중치를 주는 편집 거리는 코드에 없다** — 개선 계획 4.3절의 "가중치 편집 거리 98% / 91%" 시험은 책상 계산이었고, 일꾼은 위의 "접기(같은 소리 = 비용 0) + 균일 InDel"로 그것을 근사한다.

**문턱**

| 쓰는 곳 | 비교 | 문턱 | 상수(환경변수) |
|---|---|---|---|
| `Ledger.near(name)` | 글자 같으면 100. 아니면 `process.extractOne(sjamo(key), 장부 sjamo들, fuzz.ratio)` | 접은 자모 길이 ≤ 5 또는 글자 수 ≤ 2면 **80**, 아니면 **72** | `LLM_LEDGER_CUT_SHORT`·`LLM_LEDGER_CUT`·`LLM_LEDGER_SHORT_LEN = 2` |
| `Ledger.inside(name)` | 장부 이름(4자 이상, `LEDGER_PREFIX = 3` 초과)이 앞이나 뒤에 통째로 들어 있으면 가장 긴 것("은갈치퍼플" → 은갈치). 2자 이름은 앞에 있고 나머지가 무늬·형태 말일 때만("밀레창") | — | |
| `ledger_said(lines)` (받아쓰기에서 장부 이름 찾기) | 낱말 1~3개 이어 붙인 말(조사 뗌)마다: 2자 이하면 장부와 **글자가 같을 때만**, 3자부터는 `near(cutoff=86)`이고 100이 아니면서 어느 쪽이든 접은 자모 길이 ≤ 5면 버림. 무늬 말뿐인 장부 이름은 세지 않음. 한 줄에서 겹치는 말은 긴 쪽 하나, 줄마다 1(번호 바로 옆이면 2) | **86** | `LLM_LEDGER_SAID_CUT`, `LLM_LEDGER_SAID_ADJ = 1` |
| `canon(name, dic)` (전국 사전) | 글자 같으면 그대로. 3자 이상이면 `dict_name`: 접지 않은 `jamo`로 `process.extract(limit=3, fuzz.ratio)`, 뒤 무늬 말(`SUFFIX`)이 같은 후보만. 안 되면 뒤 `AFFIX`·앞 `창`을 떼고 바탕만 견준다 | **88** | 함수 인자 |
| `not_a_name`의 손님 | `fuzz.ratio(jamo(닉네임), jamo(이름))` | **85** | |

### 3.5 품종 고르기 차례 `pick_shop` (D-SCR-29~36)

입력: LLM 이름들 `N`(답한 순서), 그 상품의 줄들, 사전, 장부, 손님 집합(`nicks ∪ nicknames(lines)`), 번호.

1. 이름마다 `tidy` → `not_a_name`이면 버림 → `shop_name`. 바탕이 없고 무늬 말만 있으면 `only[무늬]++`. 아니면 `votes[바탕]++`(무늬 말이 붙어 있었으면 `pats[(바탕, 무늬)]++`).
2. `heard = ledger_said(lines, …)` (장부 이름이 나온 줄 수, `LLM_LEDGER_SAID = 2`).
3. `top = argmax votes` (답 수, 장부에 있나, 사전에 있나, 나중 답 순).
4. **장부 이름 먼저**(D-SCR-34): 표 안에 장부 이름이 있는데 `top`이 장부 밖이면, 장부 이름 가운데 1위 `ours`에 대해 `votes[ours] × 3 ≥ votes[top]`(`LLM_LEDGER_WEIGHT = 3`)이면 `top = ours`. 까닭: 같은 받아쓰기를 거듭 읽은 답은 같은 틀린 말을 거듭 적는다(11-12 방송 364번: 아리랑 2번, 야래향 1번).
5. **이름 없는 상품**(D-SCR-31): `sum(only) > votes[top]`이면 `top = None`.
   그렇지 않고 `top`이 없으며 무늬 말 답도 없고 `heard`의 1위가 2줄 이상이면 **받아쓰기의 장부 이름**을 쓴다(3줄 이상이면 굳음). LLM이 모르는 이름을 적었을 때는 덮지 않는다(`LLM_LEDGER_SAID_OVER = 0`).
6. `top`이 있으면 그 이름. 무늬 말은 그 바탕에 붙은 무늬 말 1위가 `2 × 횟수 ≥ votes[top]`일 때만 붙인다. 확실 = 장부에 있음 또는 (사전에 있고 답 2번 이상). 굳음 = 장부에 있고 답 2번 이상. 확실하지 않으면 **확인 중 품종**(`name_unsure`, D-SCR-30).
7. 이름이 없고 무늬 말 답이 있거나 받아쓰기에 무늬 말(`pattern_said`, `_PAT_SAID`의 일곱 정규식)이 2줄 이상이면 그 무늬 말. 장부에 말버릇(`habits`)이 있으면 그 말로(11-13 장부: 색금 → SP, D-SCR-32).
8. LLM이 이름을 하나도 적지 않았으면 받아쓰기에 2번 넘게 나온 전국 사전 이름(무늬 말 제외, 판매자가 부정한 횟수를 뺌 — `denied`)을 장부 철자로.
9. 아니면 빈칸.

### 3.7 부정한 이름

- `ledger_said`: 장부 이름 바로 다음 낱말이 `^(아니|아님|아닌|아녀)`이면 세지 않는다("요거는 아베 아니죠" — 11-13 방송 41번, "청사 아니야 황소야").

### 3.8 보낸 뒤 다시 고르기 (D-SCR-35, `LLM_NAME_REPICK = 1`)

보낸 번호에 새 등록 답이 올 때마다 `_repick_name`이 처음 고를 때 쓴 답 + 그 뒤 답(첫 답 시각 −60초 ~ +`NAME_WINDOW = 180`초, `leftover` 제외)을 모두 `pick_shop`에 다시 넣고, `should_rename(지금, 새 이름, extra, 지금 급)`이 바꿀지 정한다. 급: 장부 2, 전국 사전 1, 모르는 이름 0.

| 지금 | 새 이름 | 바꾸나 |
|---|---|---|
| 빈칸 | 무늬 말 또는 모르는 LLM 이름 | 답 `LLM_NAME_FILL = 2`번 이상일 때 |
| 빈칸 | 그 밖 | 바꾼다 |
| 무늬 말뿐 | 장부 이름 | 답 2번 이상이거나 받아쓰기의 장부 이름일 때 |
| 이름 | 무늬 말뿐 | 지금이 모르는 이름이고 답 2번 이상 |
| 같은 바탕 | 무늬 말이 더 붙음 | 바꾼다("테라로사" → "테라로사색금") |
| 이름 | 급이 낮은 이름 | 바꾸지 않는다 |
| 이름 | 받아쓰기의 장부 이름 | 지금이 장부 이름이 아니면 |
| 이름 | 급이 높은 이름 | 답 2번 이상, 또는 지금 이름도 이 답들에 있고 그 수 ≤ 새 이름 수 |
| 이름 | 같은 급 | 답 2번 이상이고 지금 이름보다 많을 때 |

번호마다 3번까지(`LLM_NAME_MAX_FIX_SHOP`). 굳은 이름과 판매자가 손댄 이름은 건드리지 않는다. 다시 내놓은 상품은 서버가 처음 이름을 지키므로 일꾼도 처음 보낸 이름을 적어 두고, 서버 이름이 비었을 때만 채운다.

### 3.9 품종만 따로 묻기 (D-SCR-37, `LLM_NAME_ASK=1` — 기본은 끔)

**왜**: 등록 답의 품종은 번호·가격을 찾는 글에 곁들여 적은 것이라, 답을 아무리 모아도 "이 상품은 품종 이름 없이 무늬 말로만 판 것"을 가리지 못했다(11-13 장부 있음, 묻기 끔에서 틀린 38개 가운데 대부분이 P 상품).

**언제** (`_name_asks`): 상품을 보내면 `names[no]`에 `t0` = 그 등록 답 줄의 방송 시작 초가 적힌다. 받아쓰기가 `t0 + LLM_NAME_ASK_AFTER(25)`초까지 들어오면(`heard = 마지막 줄의 end_sec`) 그 상품을 한 번 묻는다. 방송 끝이면 남은 상품도 다 묻는다. 보낼 때 이미 25초가 지났으면 다음 tick에 묻는다. 앞 실행(다시 켜기 전)이 올린 번호는 묻지 않는다(`ask = "건너뜀"` — 11-12 방송 326번). 라이브에서는 등록과 따로 한 줄(`ThreadPoolExecutor(1)`)로 묻는다.

**묻는 글** (`variety.ask_prompt(no, lines, ledger, mask)`):

```
상품 번호: <번호>
가게 장부: <장부의 정식 이름 가운데 바탕 품종이 있는 것, 가나다순 최대 400개(ASK_LEDGER_MAX), 쉼표로> 또는 "없음"

*L0 [H:MM:SS] <가린 받아쓰기>     ← 그 번호(앞뒤가 숫자가 아닌 <번호>)가 나온 줄은 앞에 *
L1 [H:MM:SS] …
```

줄들은 3.2절의 `_product_lines`(첫 줄 앞 30초 ~ 뒤 20초, 다른 번호 줄에서 끊음)이다.

**지시문** `sw/prompts/name_ask_system.txt`(18줄) 요지: ① `name` = 판매자가 이 상품을 가리켜 말한 품종 이름, 무늬·종류 말(색금·녹금·찐녹·녹색금·창녹금·창색금·금·철화·복륜·수박·힘줄·종자·SP)은 `pattern`으로 ② 이름 없이 무늬 말만 말했거나 이름을 모른다고 했으면 `name = ""` ③ 손님 이름·모양 말(청수·입성 …)·가격·다른 번호 상품 이름·"…아니야"라고 한 이름은 아님 ④ 고쳐 말했으면 나중 이름 ⑤ "○○ 닮았다"는 low ⑥ 알 수 없으면 둘 다 "", 지어내지 않음. 장부 이름과 소리가 비슷하면 장부 철자로.

**답 모양** `name_ask.schema.json`: `{"name": str, "pattern": str, "quote": str, "in_ledger": bool, "confidence": "high"|"low"}`.

**답 읽기** `parse_ask` → `{"name", "pattern", "confidence"}`. `ask_name_of(ans, ledger, dic)` → (이름, 종류):
- `name`이 품종 말이면 `shop_name`으로 맞춰 바탕이 남으면 종류 = 장부 / 사전 / 모름.
- 아니면 `pattern`(또는 "SP")이 있고 "금" 하나가 아니면 → 말버릇을 거친 무늬 말, 종류 = 무늬.
- 아니면 쓸 답 없음.

**답을 쓰는 규칙** `variety.use_ask(now, kind, high, now_rank)`:

| 지금 이름 | 묻기 답 | 쓰나 | 책상 계산 근거(여덟 조건, 상품 1,287개 분 — 결과 문서) |
|---|---|---|---|
| 빈칸 | 확실한 답, 또는 무늬 말 | 채운다 | 18건 중 답 11건이 맞음 |
| 무늬 말뿐 | 무엇이든 | 둔다 | 47건 중 지금 34건, 답 7건 |
| 이름(급 무관) | "이름 없이 무늬 말뿐" · 확실 | 쓴다(그리고 굳힌다) | 79건 중 지금 19건, 답 57건 |
| 모르는 이름(급 0) | 장부·사전 이름 · 확실 | 바꾼다 | 22건 중 지금 3건, 답 9건 |
| 이름 | 다른 이름(그 밖) | 둔다 | 장부 이름끼리 다른 403건 중 지금 383건, 답 372건 |

`_apply_ask`의 뒷처리: 답 이름이 지금 이름과 같고 확실하면 굳힌다(`held`). 바꿀 때는 "무늬 말뿐 · 확실"일 때만 굳히고, 이름으로 채우거나 바꾼 것은 굳히지 않는다(뒤 등록 답이 더 아는 이름을 내면 3.8절대로 다시 바뀐다). 판매자가 손댄 이름은 건드리지 않는다. 이름 없이 올라간 번호는 묻기로 채운 뒤에도 `NAME_FOLLOW = 60`초 동안 계속 묻는다(덜 물으면 다음 상품이 늦게 올라가 11-12 방송 430번 금액이 틀리게 고쳐졌다).

"묻기 답만 쓰기"(답이 있으면 무조건 답)는 11-13 장부 있음에서 230 → **212**로 오히려 나빴다(답이 빈칸 31개를 낸다 — 책상 계산 `ask/score.py`의 "묻기만").

## 4. 평가 프로토콜

### 4.1 재현 (`sw/replay_live.py`, D-SCR-17)

- `load_run(폴더)`: 줄을 일꾼이 읽은 시각을 추정한다. `LLM등록` 이벤트의 `line_seen_wall`이 있으면 그 값, 없으면 `end_sec + 가운데 늦음`(늦음 = 기록된 값들의 가운데값, 방송 0초 = 가장 작은 늦음 − `STT_MIN 1.5`초), 그 줄을 넣은 물음보다 늦지 않게, 그리고 단조 증가하게. 화면 장은 `wall0 + sec + SCREEN_LAG 2`초에 들어간다.
- `replay_run`: 가짜 시계가 1초씩 흐른다. 기록된 물음마다 물은 시각에 "날아가는 중"으로 넣고 `at`에 답을 넣는다. 새 로직이 "묻지 않겠다"고 한 줄들(`reg.skipped`)만으로 된 물음의 답은 넣지 않는다. 새 로직이 더 묻고 싶어 한 물음(가격 확인)은 답이 없으므로 횟수만 센다. 마지막 답 뒤 `TAIL = 40`초 더 흘린다.
- `FakeServer`: 같은 번호는 처음 값이 남고, 임시 등록·확정·거두기·번호 바꾸기·이름·금액 고치기를 계약서대로 적용한다. 판매자의 손 조작은 흉내 내지 않는다.
- 한 방송의 여러 실행은 이름순으로 차례로 흘리고, 앞 실행의 이벤트를 다음 실행에 넘기며(`prior`), 서버는 하나를 이어 쓴다.

**바뀌는 것과 고정된 것**: 받아쓰기·화면 번호표·등록 LLM 답·그 답이 온 시각은 그날 기록 그대로다. 판정 규칙(환경변수와 코드)만 바뀐다. 품종 물음 답은 2.3절의 창고에서 온다(방송 뒤 한 번 받은 답). 재현의 품종 묻기는 답을 그 자리에서 받는다(라이브의 6초쯤 걸리는 시간이 들어 있지 않다).

### 4.2 채점 도구 (저장소 밖 — 핵심 코드는 7절)

- `lab.py --sw <screen-worker 폴더> --data 13|12 --tag <이름> [--logic <옛 llm_live.py>] [--env K=V,…] [--ask <등록 답 창고>]`: 정답을 읽고, `RL.load_logic(logic, env)`으로 `llm_live`를 그 환경변수로 새로 읽어, 실행들을 `replay_run`으로 흘린 뒤 채점한다. 결과 `out/<data>_<tag>.txt`(수치)와 `.json`(`metrics`, 가짜 서버 상태, 번호마다 등급 `grades`, 이벤트, 서버 요청).
- `run.sh <base|lab> <13|12> <tag> [lab.py 인자]`: `TZ=Pacific/Honolulu <python> -I lab.py …`. `lab` = 이 작업 폴더의 `packages/screen-worker`, `base` = 고치기 전 판 사본.
- `brk.py <13|12> <tag>[:odd|:even] …`: `.json`의 등급을 R/P로 나누고 절반 장부용으로 홀수·짝수 번호만 골라 센다.
- **환경변수는 두 번 준다**: `--env`로 준 값은 `load_logic`이 `llm_live`를 읽는 동안만 들어가므로 `llm_live` 위쪽 상수에는 걸리지만, `sw/variety.py`는 처음 한 번만 읽히므로 그 상수(`LLM_LEDGER_*`)와 `ask_name`이 실행 중 읽는 값에 대비해 같은 값을 프로세스 환경에도 준다(`LLM_SHOP_LEDGER=… ./run.sh … --env LLM_SHOP_LEDGER=…`).

### 4.3 지표

| 이름 | 정의 | 문서 표기 |
|---|---|---|
| M_strict | 등급 ∈ {같음, 이름 같음} | "글자가 같아야 맞음" — **실제로는 퍼지 일치를 포함한다**(아래) |
| M_eq | 등급 ∈ {같음, 이름 같음, 무늬 말끼리 다름} | "무늬 말끼리는 같은 것으로" |
| M_exact | 등급 = 같음 | 이 문서에서 새로 셈 |
| R 맞음 | R 상품의 M_strict | "진짜 품종 이름이 있는 상품" |
| P 맞음 | P 상품의 M_eq | "영수증이 무늬 말만 적은 상품 — 무늬 말끼리 같게" |
| 절반 장부 값 | (홀수 장부 실행의 짝수 번호 맞음) + (짝수 장부 실행의 홀수 번호 맞음) | |

등급 `grade(예측, 정답)`(7.2절 코드)은 다음 차례로 정한다. `strip` = 띄어쓰기 지우고 대문자, 가운뎃점 지우고, 끝의 "N개"·통째·통채와 쉼표 뒤를 뗀다. `base` = `GEN`이면 "", 아니면 끝의 `AFF` 무늬 말을 되풀이해 뗀 것.

1. 예측이 비면 **빈칸**. 2. `strip`이 같으면 **같음**. 3. 둘 다 바탕이 없으면 **무늬 말끼리 다름**. 4. 둘 다 바탕이 있고 바탕이 같거나 자모 `difflib.SequenceMatcher` 비율 ≥ 0.80이면 **이름 같음**. 5. `strip` 전체의 자모 비율 ≥ 0.82면 **이름 같음**. 6. 예측만 바탕이 없으면 **무늬 말만 적음**. 7. 정답만 바탕이 없으면 **정답은 무늬 말**. 8. 아니면 **다른 이름**.

번호에 정답 이름이 여럿이면(11-13) 가장 좋은 등급을 쓴다(`best_grade`). **주의**: "이름 같음"은 무늬 말이 다른 같은 품종("레다" ↔ "레다색금")과 자모가 80% 넘게 같은 철자 차이를 맞음으로 친다. 그래서 M_strict는 글자 그대로의 일치보다 넉넉하다. 최고 판에서 11-13은 맞음 213개 가운데 39개, 11-12는 130개 가운데 14개가 "이름 같음"이다(M_exact 174 / 116).

## 6. 타당성 위협

1. **규칙을 고른 데이터 = 잰 데이터.** `use_ask` 결정표(3.9절)는 두 방송 여덟 조건의 책상 계산으로 정했고, D-SCR-34~36의 손질은 두 방송의 틀린 사례를 하나씩 보고 만들었다. 문턱(72·80·86·88, 가중 3)도 같은 데이터로 다듬었다. 떼어 둔 시험 방송이 없다. 다른 방송에서는 덜 오를 수 있다.
2. **실제 방송에서 한 번도 돌리지 않았다.** 품종 묻기는 상품마다 LLM을 한 번 더 부른다(11-13이면 287번, 한 번에 6초쯤). 재현은 답을 그 자리에서 받으므로 지연·줄 막힘·실패·구독 한도의 영향이 없다. 그래서 기본값은 끔이다.
3. **"장부 있음"은 사실상 정답 철자 목록이다.** 그날 영수증 전체에서 만든 장부라 판 품종이 모두 들어 있다. 다시 오는 가게의 가장 좋은 경우다. 절반 장부(채점 상품 품종의 26~42%만 장부에 있음)가 더 현실적이다. 또 절반 장부는 장부 있음과 다르게 만들었다(바탕이 아닌 이름 그대로, 무늬 말뿐인 이름 포함, 말버릇 없음 — 3.11절). 장부 있음과 절반의 차이에는 이 차이도 섞여 있다.
4. **"장부 없음"에도 새는 곳이 있다.** 전국 사전에 섞인 `data/varieties_seller.json`에는 11-12 방송의 정답 이름을 넣었다(D-SCR-17의 품종 수치 단락). 거둔 이름(`varieties_harvest.json`)은 지난 방송 채팅·제목에서 거둔 것이고, 라이브 길에서는 시험 방송의 것을 빼지 않는다(`exclude_src`를 쓰지 않음). 특히 11-12 "장부 없음"은 처음 오는 가게보다 유리하다.
5. **정답의 잡음과 치우침.** 11-13 정답은 방송 뒤 영수증이라 판매자가 방송에서 말한 이름과 다른 것이 있다(5.5절의 9개 이상). 11-12 정답은 방송 끝 DB라 그날 일꾼이 넣고 판매자가 고치지 않은 이름이 정답이 된다 — 일꾼이 그날 낸 답 쪽으로 치우칠 수 있다. 색금 = SP 동치는 사용자 메모 한 줄에 기댄다.
6. **지표가 넉넉하다.** M_strict도 자모 80% 퍼지 일치와 무늬 말 차이를 맞음으로 친다(4.3절). 글자까지 같은 것만 세면 61.7% · 78.9%다. 분모는 판매 중으로 등록된 상품뿐이다(놓친 번호는 품종 틀림으로 세지 않는다).
7. **LLM 답은 물음마다 한 번 받은 표본이다.** 같은 물음을 다시 하면 다른 답이 나올 수 있고, 그 분산은 재지 않았다. 등록 답도 그날 한 번의 표본이다.
8. **재현의 한계.** 새 로직이 더 묻고 싶어 한 물음의 답은 없다. 시각은 추정이다(`STT_MIN 1.5`, `SCREEN_LAG 2`). 판매자의 손 조작, 서버 왕복은 없다.
9. **표본이 작다.** 방송 둘, 가게 둘. 두 가게의 품종 구성(국내 교배종 비중, 무늬 말로 파는 비율 26%·37%)이 다르면 수치가 크게 달라진다.
10. **채점·장부 도구가 저장소 밖에 있었다.** 세션 임시 폴더라 지워질 수 있다. 이 문서 7절에 핵심을 옮겼다.

CHO = "ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ"; JUNG = "ㅏㅐㅑㅒㅓㅔㅕㅖㅗㅘㅙㅚㅛㅜㅝㅞㅟㅠㅡㅢㅣ"; JONG = " ㄱㄲㄳㄴㄵㄶㄷㄹㄺㄻㄼㄽㄾㄿㅀㅁㅂㅄㅅㅆㅇㅈㅊㅋㅌㅍㅎ"
def jamo(s):
    o = []
    for ch in s:
        c = ord(ch) - 0xAC00
        o += [CHO[c // 588], JUNG[c % 588 // 28], JONG[c % 28]] if 0 <= c < 11172 else [ch]
    return "".join(o).replace(" ", "")
norm = lambda s: re.sub(r"\s+", "", (s or "")).upper()
strip = lambda n: re.sub(r"(\d+개|통째|통채|,.*)$", "", re.sub(r"[·ㆍ]", "", norm(n)))
AFF = ("복륜금", "색금종자", "녹색금", "색금", "창금", "녹금", "찐녹", "철화", "산반", "복륜", "종자", "무지", "수박", "힘줄", "금")
GEN = {"색금", "녹금", "SP", "종자", "찐녹", "녹색금", "창녹금", "창색금", "금", "창금", "SP녹금", "SP색금", "종자녹금", "종자색금", "종자찐녹", "종자녹색금", "녹금종자", "색금종자"}
def base(n):
    n = strip(n)
    if n in GEN: return ""
    ch = True
    while ch:
        ch = False
        for x in AFF:
            if n.endswith(x) and len(n) - len(x) >= 2: n = n[:-len(x)]; ch = True; break
    return n
sim = lambda x, y: difflib.SequenceMatcher(None, jamo(x), jamo(y)).ratio()
def grade(d, t):
    d0, t0 = strip(d), strip(t)
    if not d0: return "빈칸"
    if d0 == t0: return "같음"
    bd, bt = base(d), base(t)
    if not bd and not bt: return "무늬 말끼리 다름"
    if bd and bt and (bd == bt or sim(bd, bt) >= 0.8): return "이름 같음"
    if sim(d0, t0) >= 0.82: return "이름 같음"
    if not bd and bt: return "무늬 말만 적음"
    if bd and not bt: return "정답은 무늬 말"
    return "다른 이름"
def best_grade(d, names):
    order = ["같음", "이름 같음", "무늬 말끼리 다름", "정답은 무늬 말", "무늬 말만 적음", "다른 이름", "빈칸"]
    return min((grade(d, t) for t in names), key=order.index)
