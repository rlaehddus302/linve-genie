## 이번 스프린트에서 하지 않는 것 (범위 밖)

- 알림톡·문자로 미입금 손님에게 독촉 보내기 — 카카오 비즈니스 채널·발송 계약·비용이 필요한 **사용자 결정 필요** 사항(DECISIONS "사용자 확인 필요" — 손님 독촉·메모 보관).
- 새 연락처·주소·실명 모으기. 배송지(T1)·전화 끝자리 규칙은 지금 그대로.
- 플랫폼(유튜브·인스타그램·틱톡·문자)을 넘어 저절로 같은 사람으로 합치기. 합치기는 지금의 "구매자 합치기"(그날 안)뿐.
- 판정 규칙 바꾸기: 노쇼 손님의 찜을 자동으로 거절·보류·뒤로 미루기. 판정 엔진·엔진 골든 변경.
- 늦게라도 낸 이력(입금 시각 비교)·노쇼 표시 손으로 끄기·손님 등급 여러 단계.
- 손님 기록 엑셀 내보내기, 백업 파일에 메모 넣기, 메모·기록 보관 기간 정하기(사용자 확인).
- 새 차단 기능(전화번호 차단·"모든 손님"에서 바로 차단).

## 그대로 지키는 것 (회귀 금지)

- 판정·대기·승계·라벨·감사 메시지·정산 금액·입금 확인(N3) 결과는 이 스프린트 전과 같다.
- 날짜별 구매자 목록·자세히·합치기·지난 구매(D-090·D-091·D-I2-08)는 지금 동작 그대로이고 그 위에 더하기만 한다.
- 보조자 허용 목록(SYS-04)은 늘지 않는다. 기존 `GET /api/days/:date` 응답에 손님 기록·메모 칸을 더하지 않는다.

## 수용 기준

### 요약 계산 (골든 — D-CRM1-03·D-CRM1-04·D-CRM1-05)

**AC-CRM1-01** [server] 손님 기록 골든
- Given `tests/golden/regulars/summary.json`(13사례)
- When 서버 단위 시험이 모든 `regulars/*.json`을 읽어 서버의 요약 순수 함수(입력 `today`·`settings`·`bundles`)로 돌리면
- Then 사례마다 `out`과 깊은 같음. 파일 수 1·사례 수 13을 고정값으로 단언(빠지면 실패), 모르는 키·`kind`는 읽기 오류. `TZ`를 `UTC`·`Asia/Seoul`·`America/Los_Angeles`로 바꿔도 같은 결과. 묶음 순서를 거꾸로 넣어도 같은 결과
- 확인: 단위(골든)

**AC-CRM1-02** [server] 금액은 정수 원
- Given 구매 묶음 상품 합계 33,333원 × 3
- When 요약을 내면
- Then 누적 구매 금액 99,999(정수), 응답 JSON에 소수점 숫자가 없다. 금액은 코어 묶음 값의 합이고 다시 계산하지 않는다
- 확인: 단위

### 같은 손님 모으기 (D-CRM1-02)

**AC-CRM1-03** [server] 표지로 날짜를 넘어 한 번만 따라간다
- Given 실제 날짜 10-01·10-08·10-15에 유튜브 채널 `UC_A`가 찜하고 셋 다 입금 완료(상품 합계 30,000·15,000·20,000), 10-15엔 `UC_A`가 문자 구매자 `sms:r1`(전화 뒤 1234)과 합쳐져 있고 `sms:r1`의 전화번호 키로 10-20에 다른 문자 구매자 `sms:r9`가 입금 완료 10,000
- When 10-15의 구매자 `UC_A` 손님 기록을 보면
- Then 구매 4번·누적 75,000원·마지막 구매 10-20 (계산: 10-01·10-08·10-15는 채널로, 10-20은 합친 구성원의 전화번호 키로 — 30,000 + 15,000 + 20,000 + 10,000). 10-20 묶음의 다른 구성원 표지로 더 넓히지 않는다
- 확인: 단위(PGlite) + 적대(모형 대조)

**AC-CRM1-04** [server] 플랫폼이 다르면 다른 손님
- Given 같은 닉네임 "다육이맘"의 유튜브 구매자 `UC_A`와 인스타그램 구매자 `ig:777`이 다른 날짜에 각각 입금 완료
- When 각자의 손님 기록과 "모든 손님"을 보면
- Then 서로의 묶음이 섞이지 않고 "모든 손님"에 두 줄(종류 "유튜브"·"인스타그램")이다. 닉네임·메모가 같아도 잇지 않는다
- 확인: 단위 + E2E

**AC-CRM1-05** [server] 전화번호 없는 문자 구매자는 그날만
- Given 전화번호 없이 메모 "김씨"로 만든 문자 구매자가 10-01·10-08에 따로 입금 완료
- When 10-08의 그 구매자 손님 기록을 보면
- Then 구매 1번(그날 묶음만). "모든 손님"에 이 구매자 줄이 없다. 메모 칸 자리에 "전화번호 없는 문자 손님은 다른 날과 이어지지 않아 메모를 남길 수 없어요."
- 확인: 단위 + E2E

**AC-CRM1-06** [server] 리허설은 넣지 않는다
- Given `UC_A`가 리허설 범위 10-01에 찜·입금, 실제 범위 10-08에 입금 완료
- When 실제 10-08의 손님 기록·"모든 손님"을 보고, 리허설 10-01 구매자 화면을 열면
- Then 실제 쪽은 구매 1번(리허설 묶음 없음). 리허설 날짜 구매자 목록에 꼬리표·"누적 큰 순"·거르기가 없고 자세히에 "손님 기록" 칸이 없다. 리허설 날짜를 고른 손님 기록 조회는 거절된다(아무 숫자도 내지 않음)
- 확인: 단위 + E2E

**AC-CRM1-07** [server] 30일 봉인 날짜도 센다
- Given 40일 전 실제 날짜(봉인됨)에 `UC_A` 입금 완료 12,000
- When 오늘 날짜의 `UC_A` 손님 기록을 보면
- Then 그 날짜가 구매 1번·12,000원으로 들어 있다(봉인 장부 기준). 봉인 날짜에는 아무것도 쓰지 않는다
- 확인: 단위(PGlite·주입한 시계)

### 미입금·취소 (D-CRM1-03·D-CRM1-04)

**AC-CRM1-08** [server] "입금 안 함" 사유 읽기
- Given `UC_A`의 1등 찜 셋을 방송자가 각각 사유 "입금 안 함"·" 입금안함 "·"입금 안 함 (연락 없음)"으로 취소(서로 다른 날짜 10-01·10-02·10-03), 대기 찜 하나를 사유 "입금 안 함"으로 취소(10-04), 1등 찜 하나를 직접 배정 교체(`replaceTo=CANCEL`) 사유 "입금 안 함"으로 밀어냄(10-05)
- When 손님 기록을 보면
- Then 미입금 날 = 10-01·10-02·10-05 → 3번, 마지막 10-05. 10-03은 공백을 뺀 글이 `입금안함`과 달라 아니다. 10-04는 1등이 아니었으므로 미입금도 취소도 아니다. 취소 횟수 = 4(10-01·10-02·10-03·10-05)
- 확인: 단위 + 적대(사유 변형 — 전각 공백·줄 나눔·탭, 비슷한 글 "입금 안함?"·"입금 안 함함")

**AC-CRM1-09** [server] 입금을 적으면 바로 빠지고, 되돌리면 다시 든다
- Given 오늘 10-26, 기다리는 날 3일, `UC_A`의 10-20 묶음(상품 합계 15,000, 배송비 3,000) 미입금 → 손님 기록 "미입금 1번"
- When (1) 입금 확인(N3) 붙여넣기로 18,000원이 자동 확인되면 (2) "입금 확인 되돌리기"를 하면
- Then (1) 다음 조회에서 미입금 0번, 구매 1번·누적 15,000원(상품 합계, 배송비 빼고) (2) 다시 미입금 1번·구매 0번. 손으로 적은 입금(STL-07)도 (1)과 같다
- 확인: 단위(PGlite) + E2E

**AC-CRM1-10** [server] 오늘 날짜는 서버 시각의 KST
- Given 서버 시계 `2026-10-25T15:30:00Z`(KST 10-26 00:30), `UC_A`의 10-22 미입금, 기다리는 날 3일
- When 손님 기록을 보면
- Then 미입금 1번(오늘 KST 10-26 > 10-25). 서버 시계 `2026-10-25T14:59:59Z`(KST 10-25 23:59:59)면 0번. 화면 기기 시계·시간대와 상관없다
- 확인: 단위(주입한 시계)

### 설정 "손님 관리" (D-CRM1-05)

**AC-CRM1-11** [server][web] 기본값과 검사
- Given 새 판매자
- When 설정 화면을 열면
- Then "손님 관리" 칸: 단골 횟수 3번, 단골 금액 100,000원, 입금 기다리는 날 3일. 단골 횟수 1·100, 단골 금액 999·100,000,001·"10.5", 기다리는 날 0·31을 넣고 저장하면 서버가 거절하고 칸 아래 D-CRM1-05의 문장. 단골 금액을 비우고 저장하면 "금액 기준 안 씀"으로 저장된다. 저장은 화면 아래 저장 막대 하나(D-FB1-06)
- 확인: 단위 + E2E

**AC-CRM1-12** [server][web] 바꾸면 바로 다시 센다
- Given `UC_A` 구매 2번·누적 45,000원, 단골 아님(금액 100,000)
- When 단골 횟수를 2로 저장하고 구매자 화면을 다시 열면
- Then `UC_A` 줄에 "단골". 판매 규칙 설정·이미 있는 방송의 엔진 스냅샷·판정 결과는 그대로(이벤트 로그에 새 이벤트 없음)
- 확인: E2E

### 구매자 화면 (D-CRM1-06)

**AC-CRM1-13** [web] 목록 꼬리표
- Given 그날 구매자 셋 — A(단골), B(입금 늦음 주의), C(단골이면서 입금 늦음 주의이고 차단 중)
- When 휴대폰(375px)에서 구매자 목록을 보면
- Then A 줄 "단골", B 줄 "입금 늦음 주의", C 줄 "단골"·"입금 늦음 주의"·"차단" 글자가 모두 보인다(색만으로 구분하지 않음). 꼬리표 없는 손님 줄은 지금과 같다
- 확인: E2E

**AC-CRM1-14** [web] "누적 큰 순"과 거르기
- Given 그날 구매자 A(누적 50,000)·B(누적 120,000)·C(누적 50,000, 이름이 A보다 앞)·D(누적 0, 입금 늦음 주의)
- When "누적 큰 순"을 누르고, 이어서 "입금 늦음 주의만"·"단골만"·"모두"를 차례로 누르면
- Then 순서 B → C → A → D (같은 금액은 이름 순). "입금 늦음 주의만" = D 한 줄, "단골만" = B 한 줄(금액 100,000 기준), "모두" = 넷. "찜 없는 구매자도 보기"를 켜도 거르기가 함께 적용된다. 기존 "이름 순"·"합계 큰 순"은 지금 그대로
- 확인: E2E (+ web 단위 정렬)

**AC-CRM1-15** [web] 자세히 "손님 기록" 칸
- Given 올해 2026, `UC_A` 구매 3번·누적 125,000원·마지막 구매 10-15, 미입금 2번·마지막 10-22, 취소 1번
- When 구매자 자세히를 열면
- Then "지난 구매" 위에 "손님 기록" 칸: "누적 구매 125,000원 · 3번", "마지막 구매 10월 15일(목)", "미입금 2번 · 마지막 10월 22일(목)", "취소 1번", 꼬리표. 기록이 없으면 "아직 입금 완료된 구매 없음"·"미입금 없음"·"취소 0번". 지난해 날짜는 "2025년 12월 29일(월)"처럼 연도가 붙는다. 영어 상태값(`PAID`·`UNPAID` 등)이 보이지 않는다
- 확인: E2E

**AC-CRM1-16** [server][web] "모든 손님" 보기 목록
- Given 표지 25개가 기록 묶음을 가짐(그중 채팅만 하고 품목·입금·취소가 없는 표지 5개는 따로 더 있음)
- When 구매자 화면 위 "모든 손님"을 고르면
- Then 줄 20개 + "더 보기", 누르면 나머지 5개(채팅만 한 표지는 없음). 줄 = 이름(가장 최근 실제 날짜의 표시 이름)·종류("유튜브"/"인스타그램"/"틱톡"/"문자 · 끝자리 1234")·꼬리표·누적 구매 금액·구매 횟수·마지막 구매일·미입금 횟수. 기본 "누적 큰 순", "최근 산 순"(구매 없는 손님은 맨 뒤)·"미입금 많은 순"(같으면 누적 큰 순), 거르기 "단골만"·"입금 늦음 주의만". 찾기 칸에 지난 날짜에만 쓴 닉네임이나 끝자리 4개를 넣으면 그 손님이 나온다. 응답에 전화번호 키·전화번호가 없다
- 확인: 단위(서버 쪽수·정렬) + E2E

**AC-CRM1-17** [web] "모든 손님" 자세히 → 그날 구매자 자세히
- Given "모든 손님"의 `UC_A` 줄(실제 날짜 10-01·10-08·10-22 기록)
- When 줄을 누르고, 날짜 줄 "10월 22일(목)"을 누르면
