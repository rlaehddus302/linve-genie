# T1 test-notes (domain)

시험: `tests/adversarial/t1/`
- `pure-properties.test.ts` — PC-2 배송지 읽기를 스펙 문장으로 다시 쓴 기준 구현과 무작위 대조(전각 공백·제어 글자·제로폭·풀어 쓴 한글·전각 숫자·+82), PC-4 사실 조합 전부(1,440가지), 30일 보관 경계(보관 끝 시각 ⇔ 정리 작업 날짜, KST 자정·해 바뀜), 멈춘 시도 2분, Code 128 되살리기·검사값, 연락처 가리기, 송장번호 글, 가장 긴 바른 배송지·보내는 사람이 운송장에 들어가는지(TOO_LONG이 바른 입력에서는 나지 않는다).
- `server-attacks.test.ts` — 같은 시청자가 두 가게에서 산 경우(배송지·조회·취소 나눔), 같은 화면 요청 번호 10번 동시·다른 날짜/명령에 재사용, 접수 결과 기다리는 동안 잠금(판매자·구매자 양식·포장 취소), chunked 큰 양식 본문, 링크 이스케이프·가림, 취소 → 다시 접수 → 운송장 수, 동시 취소 3번, 취소와 집하 엇갈림, 날짜 나눔, "모름" Y에 X 합치기(D-I2-20 배송 뒤 바뀜).
- `book-random.test.ts` — 접수·취소·집하·시계·포장 취소·구매자 다시 적기·판매자 확인을 섞은 무작위 열(40회, seed 7). 불변식: 살아 있는 시도 ≤ 1, 택배사 쪽 살아 있는 접수 ≤ 1이고 우리 쪽도 살아 있음, BOOKED ⇔ 포장 기록 배송 완료(그 송장), 확인 전 배송지로 새 요청 번호가 가지 않음, 택배사 요청에 구매자 ID 없음.

라운드 1(끊기기 전)에서 찾아 개발이 고친 것: 같은 요청 번호에 주입한 거절이 들어 택배사엔 접수·우리는 FAILED(7a2a9cf), chunked 양식 본문을 끝까지 모으던 일(9af06b7). 둘 다 위 시험이 다시 본다.
