# I2 test-domain 노트 (라운드 0)

시험 파일: `tests/adversarial/i2/server-i2.test.ts` (`npx vitest run --config vitest.adversarial.config.ts tests/adversarial/i2/`)

## 실패로 남긴 것

| ID | 시험 | 내용 |
|---|---|---|
| TD-I2-001 | `TD-I2-001 상품 목록 가져오기 — 미리 보기에서 본 500줄을 그대로 등록` | 품종 40글자 안팎 500줄: 미리 보기 `register: 500` → 같은 줄을 등록에 보내면 413 `PAYLOAD_TOO_LARGE` "보낸 내용이 너무 커요." (등록 경로는 64KB 본문 상한, 미리 보기만 3MB) |

## 지적만 (시험 없음)

- TD-I2-002 (web) 포장 체크리스트의 바뀐 품목 안내가 `multi = spansBroadcasts(entry.items) || spansBroadcasts([...add, ...remove])` — 지금 품목이 1부 7번 하나이고 뺄 것이 2부 7번 하나면 둘 다 한 방송이라 "뺄 것: 7번"으로 방송 제목 없이 나온다(남아 있는 1부 7번과 구별되지 않음). 웹 컴포넌트 안의 조합이라 test-domain 영역에서 실패 시험으로 못 남겼다 — test-e2e 또는 웹 단위 시험 몫.
- TD-I2-003 (spec) CSV의 `,,` 줄(엑셀이 빈 행을 CSV로 저장한 모양)은 R-18 1의 "공백만 있는 줄"이 아니라 `NUMBER_INVALID` 문제 줄이고 500줄 상한에도 센다. 같은 시트를 .xlsx로 올리면 칸이 모두 빈 행은 건너뛴다 — 입력 형식에 따라 결과가 갈린다.
- TD-I2-004 계정을 만들 때 가게 이름은 50자(UTF-16)까지인데 가게 설정은 1~30글자 — 31자 이상 이름의 판매자는 설정 화면에서 계좌만 고쳐 저장해도 이름 칸 오류로 거절된다.
- TD-I2-005 (spec) 포장 상태는 상품 키 `<방송>/<지금 번호>` 집합으로만 견준다 — 포장 뒤 번호 변경으로 번호가 비고 그 번호로 다른 상품을 새로 등록해 같은 구매자가 1등이 되면 다른 상품인데 `포장 완료`로 보인다.
- TD-I2-006 전체 기록 내려받기·백업 만들기의 동기 CPU(정규 JSON 요약값 + JSON + gzip)가 이벤트 10만 건에서 약 0.55초 이벤트 루프를 막는다(PGlite면 DB 읽기까지 합쳐 약 1.3초). 판매 중 한 판매자가 "전체 기록(JSON)"을 누르면 그동안 모든 판매자의 요청이 기다린다.

## 통과한 공격 (회귀로 남김)

- 엑셀 복사(탭 글)와 .xlsx 행 입구의 결과가 같다(속성 2000회), `normalizeText` 두 번 = 한 번(등록 검사 `isNormalizedName`이 미리 보기 품종을 늘 받는다).
- 합친 문자 구매자 ID → 확인서·라벨·지난 구매는 지금의 구매자, 포장 명령은 `BUYER_NOT_FOUND`.
- 번호 변경·합치기·떼어 내기 뒤 라벨 번호 = 체크리스트 품목(방송 선언 순 → 번호 순), 포장 명령은 범위 seq·정산 그대로.

## 통과해서 남기지 않은 공격 (개발자 시험과 겹침)

- 복구 뒤 서버를 다시 켜지 않은 채 쓰기: 캐시된 범위 ID가 지워진 범위라 외래 키로 `SAVE_FAILED` — 기록이 깨지지는 않는다(재시작 안내는 dev-notes에 있음).
- 백업 파일 손상·seq 빈틈·재생 오류·형식 번호, 30일 보관, 04:00 경계, 다른 판매자 격리, 송장 7·8·20·21자리·휴대폰 모양, 같은 요청 번호, 두 기기 동시 포장, 판매대장 366·367일·남의 방송 — 개발자 서버 시험에 이미 있다.
