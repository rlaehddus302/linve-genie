- TD-I2-006 전체 기록 내려받기·백업 만들기의 동기 CPU(정규 JSON 요약값 + JSON + gzip)가 이벤트 10만 건에서 약 0.55초 이벤트 루프를 막는다(PGlite면 DB 읽기까지 합쳐 약 1.3초). 판매 중 한 판매자가 "전체 기록(JSON)"을 누르면 그동안 모든 판매자의 요청이 기다린다.

## 통과한 공격 (회귀로 남김)

- 엑셀 복사(탭 글)와 .xlsx 행 입구의 결과가 같다(속성 2000회), `normalizeText` 두 번 = 한 번(등록 검사 `isNormalizedName`이 미리 보기 품종을 늘 받는다).

- 번호 변경·합치기·떼어 내기 뒤 라벨 번호 = 체크리스트 품목(방송 선언 순 → 번호 순), 포장 명령은 범위 seq·정산 그대로.

## 통과해서 남기지 않은 공격 (개발자 시험과 겹침)

- 복구 뒤 서버를 다시 켜지 않은 채 쓰기: 캐시된 범위 ID가 지워진 범위라 외래 키로 `SAVE_FAILED` — 기록이 깨지지는 않는다(재시작 안내는 dev-notes에 있음).
- 백업 파일 손상·seq 빈틈·재생 오류·형식 번호, 30일 보관, 04:00 경계, 다른 판매자 격리, 송장 7·8·20·21자리·휴대폰 모양, 같은 요청 번호, 두 기기 동시 포장, 판매대장 366·367일·남의 방송 — 개발자 서버 시험에 이미 있다.

## 통과한 공격 (회귀로 남김)

- D-I2-17 경계: VT·FF·NBSP·U+3000은 공백 → 한 칸, NEL(U+0085)·U+001C~001F·DEL·U+0080~009F·NUL·ESC는 NAME_CONTROL, U+007E·U+00A1·U+200B는 그대로. 제어 글자만 있는 품종도 NAME_CONTROL(품종 미입력 아님). 순서: 번호·같은 번호·이미 있는 번호 다음, 휴대폰 번호·가격보다 먼저. .xlsx 칸 안 줄바꿈·탭은 공백. 미리 보기를 건너뛴 등록 본문의 NEL·U+001F·NUL·U+009F 품종은 거절(아무것도 등록 안 함). UTF-8 CSV 파일의 NEL·DEL.
- D-I2-19: 두 상품 번호 맞바꾸기(키 집합·ID 집합 모두 같음) → 포장 다시 확인, 뺄 것 = 포장 때 번호·지금 품종. 바꿨다 되돌린 번호 → 포장 완료. 다시 확인 상태에서 같은 키로 포장 완료 → 새 기록, 그다음 같은 명령은 기록 없음. 옛 상품 품종을 바꾸면 뺄 것 품종도 따라감. 백업 → 검사 → 다른 서버 복구 뒤 포장 상태·새로 담을 것·뺄 것 같음.
- D-I2-20: 품목이 모두 빠진 포장 다시 확인도 합치기 409(seq 그대로), 포장 취소 뒤 합치기 200. Z → X → Y 여러 단계에서 Y 배송 완료면 Z·X 떼어 내기 모두 409. 배송한 Y에 합치기 200(배송 뒤 바뀜) → 떼어 내기 409 → 배송 취소 뒤 200. 동시 요청 12번씩: 포장 완료 ↔ 합치기, 배송 완료 ↔ 떼어 내기 — 늘 하나만 성공, 둘 다 남는 경우 없음.
- D-I2-21: `,,`·`"",,`·공백만·U+3000·NBSP·넓은 빈 열 줄이 머리글 앞뒤·상품 사이에 있어도 CSV와 .xlsx 미리 보기가 같다. 상품 500 + 빈 줄 300 → 500개 등록할 줄. 닫히지 않은 따옴표 줄(`",,`·`"",,"`)은 CELLS이고 500줄에 센다. 속성 시험(2,000번): 빈 행 다섯 모양·제어 글자 품종을 끼운 표의 탭 글·CSV·.xlsx 행 입구 결과가 같다.

## 지적만

- 포장 완료 명령은 상품 키 목록만 받는다(D-I2-19 그대로). 체크리스트를 연 사이 같은 번호에 다른 상품이 들어오면 화면이 바뀐 품목 안내를 띄우지만(AC-I2-37), 안내 전에 누른 포장 완료는 키가 같아 받아진다. 화면이 실시간 알림으로 품목 집합을 다시 받는 한 실제 사고 가능성은 낮다 — 지적 없음, 참고만.
- .xlsx 칸의 엑셀 이스케이프(`_x0001_`)는 exceljs가 풀지 않을 수 있다(품종에 `_x0001_` 글자 그대로). 실제 판매자가 넣을 일이 드물어 시험하지 않았다.
