## 지적

- **TE-BND1-001 (web, minor, 실패 시험)** 열어 둔 콘솔에서 유튜브를 이으면 밴드 칸이 그대로 "밴드 글 잇기"를 보인다 — 밴드·글·확인 세 단계를 고른 뒤 "잇기"에서야 거절 문장을 본다(새로 고침하면 맞다). 밴드 칸의 연결 보기(`canLink`·`blockCode`)를 유튜브 잇기 뒤에 다시 받지 않는다. 같은 계열: 다른 방송에서 밴드를 잇거나 끊어도 열어 둔 다른 방송 콘솔의 막힘(`BAND_IN_USE`)이 그대로다(SSE `band` LINK는 그 방송 것만 받음).
- **스펙 확인 필요** AC-BND1-80 ③ "1번 2개요 → 보드 1번 1등"은 STRICT 기본 설정 파서 골든(`tests/golden/parser/chat.yaml` "15번 2개 가능해요?" → 언급만)과 어긋난다. AC-BND1-33은 "그 회차 파서 결과대로"라 시험은 골든대로("1번 2개요" 언급만, "1번이요" → 1등) 썼다.
- **스펙 확인 필요** AC-BND1-73 "확인하지 않은 알림이 있으면 '밴드에서 지우거나 고친 댓글이 {N}개 있어요.'" — 늦게 읽음(LATE) 알림만 남으면 띠 줄이 없다(화면은 `unseenEdits`만 셈). 문장 뜻으로는 맞지만 "확인하지 않은 알림"과 범위가 다르다.
- **server, minor** E2E 기동의 밴드 시간은 읽기 간격(1초·3초)만 줄었고 늦게 읽음 기준 60초·다시 시도 시간표(10·20·40·80초)는 운영 값이다 — 시나리오 ⑥·AC-BND1-73 시험이 각각 61초·최대 120초를 기다린다. E2E용으로 줄이는 설정(예: `E2E_BAND_LATE_MS`)이 있으면 시험이 짧아진다.
