# APP1b 통합 보고

2026-10-30 · 상태: 최종 자동 검증 진행 중. 실방송 전후 재생 비교는 자료 부재로 미확인.

## 결과

웹과 Expo 앱이 인증된 같은 서버 읽기 세션을 사용한다. 기존 `VoiceController` 전체와 사전·이력·계정 별칭을 서버에서 실행하고, 기기는 카드·폼·문자찜·고침·기록을 표시하며 기존 HTTP 쓰기 API를 호출한다. 별도의 간소화 파서로 교체하지 않았다. 웹/앱 빌드에서 추출기·품종 사전 구현을 제거했다.

끄기·재연결 후 남은 항목은 서버가 서명한 한정된 복원표로 이어진다. 자동 기한과 미처리 소리는 되살리지 않는다. 음성이 꺼진 카드의 수동 조작은 마이크 없는 임시 제어 연결로 처리한다. 오프라인 수동 상품 등록은 기존 요청 번호·outbox 계약을 유지하며, 문자찜의 재연결 자동 재전송은 하지 않는다.

## 동등성과 회귀

- 독립 domain 시험 **422/422**: 기존 골든 out419개와 서버/이전 controller의 snapshot·효과 차등419개, 복원 거절·BLE 경계 포함. 텍스트361개는 원문, 구조화 same-number58개는 원래 out을 검증한 뒤 같은 상품/상태/설정의 합성 발화로 차등 비교했다. 서버가 순수 함수 out419개를 직접 반환한 시험이라고 주장하지 않는다.
- 기존 전체 골든964개와 코어 파일을 보존했다. AC-APP1b-01~27의 근거는 `acceptance.md`, `audit-spec.md`, `test-notes-domain.md` 및 APP1 E2E 대응표에 연결했다.
- R66은 등록 DB 반영과 기기 목록 갱신의 순서 차이였다. 동일 상품 등록 완료 ACK 뒤 정정을 보내며 실패/만료에는 확인 오류를 남긴다. R7 다른 번호 안내는 기존 4초 표시 순서를 보존했다.
- 기기 설정 즉시 저장, Chrome 고지·재시작·종료 기록, LG 지원검사·동의, 서버 이력 실패/지연, 두 기기 거절과 별도 HTTP 중복 방어를 재검증했다.

## 독립 감사

- `audit-spec.md`: SA-APP2-001 복원 거절 시 마이크 종료 해결. 역할별 판정과 AC 추적성 확인.
- `audit-risk.md`: RA-APP1b-001(취소된 캡처 부활), RA-APP1b-002(지연 조회 뒤 늦은 자동 쓰기) 모두 수정 후 RESOLVED. 전송·모바일·실서버24개 재검증 통과. 열린 blocker/major 없음.
- APP1 `test-notes-e2e.md`: TE-APP1-001~012 전부 해결. 마지막 선택20/20, WebKit37개 확인. 중복되는 선택 실행을 고유 총수로 더하지 않았다.

- 등록 충돌에서 이미 존재하는 같은 번호가 반환될 때 원래 서버 카드와 실제 상품을 확인하고 ACK 대기를 끝낸다. 등록 실패/만료/복원 시 남은 대기도 정리한다. I4 충돌·R66·R7 선택3개를 재검증했다.
- N3 이력 대기3개는 브라우저 route 대신 실제 서버 조회 observer에서 hold/release하여 기존2초 fallback·카드 순서·자동쓰기0 단언을 유지했다.
