# APP1b 수용 기준 — 같은 읽기를 서버에서

- 근거: SPEC APP-05 AC1~AC8, VOC-02~VOC-04·VOC-06, DOMAIN_RULES R-17·R-21·R-22·R-24, D-APP-20·21, D-APP1b-01~04.
- 범위: 기존 음성 읽기·카드·정정·문자찜 처리의 의미를 바꾸지 않고 서버 흐름으로 옮긴다. 서버 → 웹 순서. 기존 골든·수용 기준을 약화하지 않는다.
- 등록·정정·문자찜 쓰기는 기기가 기존 HTTP API로 요청하고, 서버가 기존 인증·소유권·이벤트 기록·중복 방지를 그대로 수행한다. 읽기 웹소켓이 직접 상품을 등록하지 않는다.
- 판정·금액·추출 규칙 변경, 새로운 음성 정확도 튜닝, 새 모델 도입은 범위 밖이다. 실방송 자료·기기 부재는 측정 불가로 기록하고 통과로 세지 않는다.

## 공용 계약

1. 기기 연결은 APP1의 `/api/voice/stream?broadcastId=…&device=…`와 세션·출처 검사를 공유한다. 크롬 최종 글 경로는 같은 주소에 `mode=chrome`으로 열며 일꾼 할당 없이 같은 인증된 읽기 흐름을 사용한다. 한 판매자 한 흐름·다른 기기 거절·같은 기기 재연결·방송 끝·로그아웃 종료는 APP1 그대로다.
2. 읽기 세션은 기존 `VoiceController`가 가진 덩어리 모으기, 카드, 후보/신뢰도, 최근 상품 정정, 번호 변경, 취소/되돌리기, 문자찜, 최근 입력 중복 판단을 그대로 재사용한다. DOM·기기 저장소·소켓·시간·실제 쓰기는 어댑터로 분리하며 별도 간소화 파서를 만들지 않는다. 타입을 공유하는 것은 허용하나 읽기 구현을 웹/앱 번들로 가져오지 않는다.
3. 서버 출력은 전체 읽기 상태(상품 카드·문자찜 카드·후보·신뢰도·고침 제안·되읽기·상태·이유)와 기기가 수행할 효과를 보존한다. 효과는 등록·고치기·번호 변경·문자찜·되돌리기 등 기존 쓰기 계약과 대응한다. 각각 흐름 안에서 유일한 ID를 가지며 기기는 결과를 같은 ID로 돌려준다. 미확인 효과를 연결 복구 후 새 요청 번호로 자동 재실행하지 않는다.
4. 현재 방송 상품·판매 방식·번호 범위·사전·판매 이력·계정 별칭은 서버의 인증된 판매자·방송에서 읽는다. 기기는 동의·기기 설정(바로 등록 등), 대화상자/화면 상태, 기기 시각, 사용자 조작을 보낸다. 기기가 보낸 상품/판매자 정보로 서버 권한이나 판정 자료를 대체하지 않는다.
5. 서버와 기기는 `packages/voice-session`의 `./wire` 공용 명령·응답 타입을 사용하며 서버 실행은 `./server`에 둔다. 임의 메서드명/속성명으로 객체를 호출하지 않는다. Map 등은 명시적인 JSON 표현으로 왕복하며 카드/효과 ID·시각·품종 후보·문자찜 상세를 누락하지 않는다. 미지원 형식은 오류로 닫고 가짜 성공·로컬 추출로 대체하지 않는다.
6. 받아쓴 최종 글은 APP1의 글자 수·시각 검사 후 같은 세션에서 즉시 읽는다. 크롬 최종 글(굳은 중간 글로 확정한 앞부분 포함)도 같은 경로다. 중간 자막·마이크·재연결 감시는 기기에서 유지한다. 발화 중 자동 확정 멈춤에 필요한 상태는 서버에 전달한다.
7. 말 끝 시각은 기기 기준을 보존한다. 바로 등록 효과를 실행하기 직전 기기가 10초 초과 여부를 다시 확인한다. 늦었거나 시각을 알 수 없으면 카드 확인으로 남기고 자동 쓰기를 하지 않는다. 재연결 동안의 PCM·뒤늦은 옛 흐름 결과는 재생하지 않는다.
8. 읽기 JSON 입력 한 틀은 16KiB, 최종 글은 2,000자. PCM과 JSON을 합한 기기 입력은 흐름 시작 기준 고정 1초 창마다 65,536바이트 이하다. 새 한도는 APP1b 제어 글에 한하며 일꾼 결과 검사는 APP1 그대로다. 기록에는 받은 글/JSON/세션 값/예외 원문을 남기지 않는다.
9. 계정 별칭은 기존 `readLearnedAliases`/`learnAlias`의 정규화·흔한 말 거절·LRU 200개 규칙을 따른다. 최초 기기 이전은 계정의 같은 들은 말을 덮어쓰지 않으며 성공 응답을 받은 뒤 기기에 이전 완료를 표시한다. 사용자가 새로 고른 이름은 기존 배우기처럼 갱신한다. 다른 판매자·보조자에게 읽기/쓰기 권한을 주지 않는다.

### JSON 봉투 (공용 타입 `packages/voice-session/src/wire.ts`)

- 기기 → 서버는 `type: "voice.session"`이며 op가 `hello`/`context`일 때 `context: { now, dialogOpen, smsAutoAllowed, settings?, smsSettings?, consent?, learned? }`, `capture`일 때 첫 PCM 기기 시각 `at`, `command`일 때 허용 목록 `method`와 검증된 `args`, `effectResult`일 때 해당 흐름의 `id`와 `value`, `chromeResult`일 때 `result: { text, final, slot?, lead?, flushedAtEnd? }`다. `learned`는 최초 계정 병합의 입력이며 계정 값을 임의로 대체하지 않는다.
- 서버 → 기기는 `type: "voice.state"`의 `snapshot`과 `display`(카드/문자찜 설명·남은 초·기록·마스킹된 음성로그), 또는 `type: "voice.effect"`의 `id`, `method`, `args`, 선택적 `spokenEndAt`다. snapshot의 Map/Set은 `$map`/`$set` 값으로 왕복하며 prototype/함수는 보내거나 복원하지 않는다.
- 비동기 쓰기는 `effectResult`로 회신하고 상품 등록 성공은 `noteVoiceRegistered` 명령으로 기존 controller에 알린다. 허용 목록에 있더라도 인자의 타입·길이·범위를 검사한다. 다른 세션의 효과 ID·미발급 ID·이미 끝난 효과의 응답은 상태를 바꾸지 않는다.
- 이 봉투는 전송 형식이며 판단의 정답은 기존 스펙·골든이다. 기기별 효과 응답 도착 순서·통신 지연 때문에 기존 카드/정정/문자찜 의미가 바뀌지 않는지 차등 시험으로 확인한다.

## 완료 판단

`pnpm verify`, 보호 경로 게이트, 범위의 골든·적대·E2E·차등 시험을 통과하고 각 기준을 구현/시험 위치와 연결한다. 실제 재생 자료 미확인·HG는 보고에 따로 남긴다. 서버 이전의 동등성 실패를 기존 기대값 수정으로 숨기지 않는다.
