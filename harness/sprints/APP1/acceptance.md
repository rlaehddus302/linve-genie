# APP1 수용 기준 — 자체 받아쓰기 (라이브지니 받아쓰기)

- 스프린트: APP1 · spec ID: **VOC-06**, **VOC-07** (연결: VOC-01, VOC-05, VOC-02~VOC-04 그대로) · 근거 결정: 사용자 결정 **D-APP-01**, AUTO **D-APP-03~D-APP-15·D-APP-18**, 세부 **D-APP1-01~D-APP1-15**(AUTO, `docs/DECISIONS.md` "자체 받아쓰기 (APP1 자율 결정)")
- 한 줄: ②폰(브라우저)·PC 마이크 소리를 라이브지니 서버 음성 웹소켓으로 보내고, 서버가 먼저 붙어 있는 받아쓰기 일꾼(파이썬, Cohere 기본)에게 넘겨 받은 글을 그 기기로 돌려준다. 받은 글은 지금의 읽기·바로 등록(VOC-02~VOC-04)에 그대로 들어간다.
- 개발 영역과 순서: **device → server → web**. 테스트: **domain**(`tests/adversarial/app1/**`), **e2e**(`tests/e2e/app1/**` + 기존 음성 E2E 준비 단계, D-APP1-13). dev-core 없음.
- 골든: **바뀌지 않는다.** 판정·정산·파서 규칙(DOMAIN_RULES R-17·R-21·R-22 포함)과 `tests/golden/**` 기대는 그대로다. `tests/golden/known-unimplemented.yaml`은 비어 있는 채로 둔다(이 스프린트 범위의 골든 없음 — 남길 항목도 없다).
- 정답의 우선순위: DOMAIN_RULES·SPEC(VOC-06·VOC-07) → DECISIONS(D-APP-*, D-APP1-*) → 이 문서. 따옴표 문장은 글자 그대로 쓴다(E2E가 글자로 찾는다).
- 시각: 기기는 넘겨받은 시계(단위 시험은 입력 시각, E2E는 Playwright 시계 또는 실제 시간), 일꾼은 넘겨받은 표본 수. 화면 코드에 시험용 갈림길을 넣지 않는다(모의 일꾼은 아래 약속을 따르는 진짜 웹소켓 상대).

## 약속 (D-APP1-01 — 파이썬 일꾼·서버·화면·모의 일꾼이 모두 이것을 따른다)

### 기기 ↔ 서버: 음성 웹소켓
- 주소: `GET /api/voice/stream?broadcastId=<방송 ID>&device=<기기 표지>` (웹소켓 업그레이드). 로그인 세션 쿠키로 인증. `device`는 화면이 켤 때 만든 무작위 글(영숫자 8~64자, 메모리에만).
- 업그레이드 전에 거절하는 것은 **`Origin` 다름·없음(403)** 하나뿐이다. 나머지 거절은 업그레이드를 받은 뒤 `closing`을 보내고 닫는다(브라우저는 실패한 업그레이드의 까닭을 읽을 수 없어서).
- 기기 → 서버: **이진 틀 = PCM16 little-endian 16kHz 모노**(보통 3,200바이트). 글 틀은 받지 않아도 된다(오면 1KB 이하만, 무시).
- 서버 → 기기 (글 틀, JSON 한 줄):
  - `{"type":"ready"}` — 일꾼 흐름이 잡혔다. 이 뒤부터 소리가 받아쓰기로 간다. `ready` 전에 온 소리는 버린다.
  - `{"type":"result","text":"…","startMs":0,"endMs":1234}` — 조각 하나의 최종 결과. `startMs`·`endMs`는 이 흐름(연결)에서 일꾼이 받은 첫 표본부터 잰 밀리초 정수.
  - `{"type":"closing","reason":"<까닭>"}` 뒤 닫음. 까닭:

| 까닭 | 언제 | 기기가 하는 일 (D-APP1-03) | 기기 문장 |
|---|---|---|---|
| `OTHER_DEVICE` | 같은 판매자의 흐름이 다른 `device`로 이미 있음 | 멈춤, 다시 잇지 않음 | "음성은 다른 기기에서 듣는 중이에요." |
| `BUSY` | 연결된 일꾼의 자리가 다 참 | `ready` 전: 멈춤 / `ready` 뒤 다시 이을 때: 다시 잇기 셈 | "지금 받아쓰기가 바빠요. 상품은 빠른 입력으로 넣어 주세요." |
| `NO_WORKER` | 연결된 일꾼이 없음(일꾼 토큰 설정이 없을 때 포함) | `BUSY`와 같음 | "받아쓰기 서버가 꺼져 있어요. 상품은 빠른 입력으로 넣어 주세요." |
| `ENDED` | 그 방송이 없거나 그 판매자 것이 아니거나 켜져 있지 않음, 듣는 중 방송 끝 | 지금처럼 음성 끔(D-V3-52) | 새 문장 없음 |
| `AUTH` | 로그인 없음·세션 만료·로그아웃·보조자 계정 | 멈춤, 다시 잇지 않음 | "로그인이 끝나 음성 듣기를 멈췄어요. 다시 로그인해 주세요." |
| `RATE` | 1초 창에 65,536바이트 넘음, 틀 하나 65,536바이트 넘음, 글 틀 1KB 넘음 | 다시 잇기 셈 | (한도에 걸리면 "듣기 멈춤 …") |
| `WORKER_LOST` | 그 흐름의 일꾼 연결이 끊김 | 다시 잇기 셈 | (한도에 걸리면 "듣기 멈춤 …") |

  - `closing` 없이 닫히거나 연결이 안 되면 다시 잇기 셈(`ready` 전이면 첫 켜기의 연결 실패도 다시 잇기 셈 — 서버에 닿지 않는 것은 "다시 잇는 중").
- 서버는 15초마다 핑, 30초 안에 답이 없으면 닫는다(D-APP1-04). 같은 판매자·같은 `device`가 새로 열면 옛 흐름을 닫고(옛 쪽엔 까닭 없이 닫음) 새 흐름을 받는다.

### 일꾼 ↔ 서버: 일꾼 웹소켓
- 주소: `GET /api/voice/worker`, 머리글 `Authorization: Bearer <일꾼 토큰>`. 토큰은 서버 환경변수 `LIVEJJIM_TRANSCRIBE_WORKER_TOKEN`과 상수 시간 비교. 없거나 틀리면 401로 거절(업그레이드 전), 거절 기록에 토큰 값·머리글 없음. 서버에 토큰 설정이 없으면 일꾼 웹소켓은 늘 401(그리고 기기는 `NO_WORKER`).
- 일꾼 → 서버 첫 틀: `{"type":"hello","maxStreams":4}` (1~64 정수가 아니면 닫음). 모델 이름은 보내지 않아도 된다(보내도 로그에 남기지 않음).
- 서버 → 일꾼: `{"type":"open","stream":<n>}` · `{"type":"close","stream":<n>}` (n은 그 일꾼 연결 안에서 1부터 늘어나는 정수, 1~4,294,967,295). **이진 틀 = 흐름 번호 4바이트(big-endian 부호 없는 정수) + PCM**.
- 일꾼 → 서버: `{"type":"result","stream":<n>,"text":"…","startMs":<정수>,"endMs":<정수>,"procMs":<정수>}`. 빈 글은 보내지 않는다. 서버 검사(D-APP1-14): 글이 문자열·2,000자 이하, 시각은 0 이상 정수, `startMs ≤ endMs`가 아니면 버리고 셈만.
- 일꾼은 `close`를 받거나 연결이 끊기면 그 흐름의 아직 받아쓰지 않은 소리를 버린다. 서버에 닿지 않으면 1·2·4·8·16·30초(가장 길게 30초) 간격으로 다시 붙는다.

## 수용 기준

### device — 받아쓰기 일꾼 (파이썬)

**AC-APP1-01** [device] (VOC-07 AC4, D-APP-07, D-APP1-02) 쉼 0.4초에서 끊기
- Given 자르기 함수에 30ms 틀마다 말 확률을 넣는다(합성): 말 2.0초 → 조용 0.4초 → 말 1.0초 → 조용 1.0초
- When 틀을 차례로 넣는다
- Then 조각 두 개가 나온다: 첫째 `startMs` 0·`endMs` 2,000(±30), 둘째 `startMs` 2,400(±30)·`endMs` 3,400(±30). 조용 0.37초(0.4초보다 짧음)는 끊지 않아 조각 하나다.
- 확인: 파이썬 `unittest`(vitest가 불러 게이트 안)

**AC-APP1-02** [device] (VOC-07 AC4) 쉬지 않는 말은 20초에서 끊기
- Given 쉬지 않는 말 45초(합성)
- Then 조각 셋: 20초·20초·5초(각 ±30ms). 조각 소리 표본 수 = 길이 × 16 (ms당 16표본). 조각을 이어 붙이지 않는다(20초 넘는 조각 없음).
- 확인: 파이썬 단위

**AC-APP1-03** [device] (D-APP1-01) 틀 묶기·풀기
- Given 흐름 번호 1·258·4,294,967,295와 PCM 3,200바이트
- Then 묶은 이진 틀의 앞 4바이트가 big-endian 번호이고 풀면 같은 번호·같은 바이트. 4바이트보다 짧은 틀·0번은 버린다(예외로 죽지 않음). `hello`의 `maxStreams`는 설정 값(기본 4).
- 확인: 파이썬 단위

**AC-APP1-04** [device] (D-APP-10, D-APP1-11) 흐름 한도
- Given `--max-streams 2`인 일꾼에 `open` 세 번
- Then 셋째는 받지 않고(서버가 한도를 지키므로 오면 그 흐름에 결과를 내지 않고 `close` 대상으로), 앞 둘은 그대로 받아쓴다. `close` 뒤 그 흐름의 남은 소리로 결과를 내지 않는다.
- 확인: 파이썬 단위(가짜 모델 — 받은 조각 길이를 글로 돌려주는 함수)

**AC-APP1-05** [device] (D-APP-03, D-APP-04) 저장·로그 없음
- Given 일꾼을 가짜 모델로 돌려 표지 글 "십오번 이만원"을 결과로 내게 한다
- Then 일꾼의 로그 출력(표준 출력·오류 포함)에 표지 글·토큰 값·소리 바이트가 없고, 일꾼이 쓴 파일이 없다(임시 폴더 비교). 로그에는 셈(흐름 수·조각 수·처리 시간)만.
- 확인: 파이썬 단위

**AC-APP1-06** [device] (D-APP-14) 모델 설정
- 일꾼 설정 `--model cohere|whisper`(기본 `cohere` = `CohereLabs/cohere-transcribe-03-2026`, `whisper` = large-v3-turbo), 언어 한국어 고정. 모르는 값이면 시작하지 않고 쉬운 문장으로 끝낸다. 모델·silero·`websockets`는 실행 때만 불러온다(단위 시험은 이것들 없이 돈다).
- 확인: 파이썬 단위(설정 읽기), 사용법 `packages/voice/transcriber/README.md`(설치·`--token-file`·`--max-streams`·맥 미니 상시 켜 두기)

### device — 기기 쪽 엔진 (TypeScript)

**AC-APP1-10** [device] (VOC-06 AC2, D-APP-06, D-APP1-09) 16kHz 바꾸기와 조각
- Given 48,000Hz 1초(48,000표본)와 44,100Hz 1초(44,100표본)를 128표본씩 나눠 넣는다
- Then 각각 정확히 조각 10개, 조각마다 3,200바이트(1,600표본, PCM16 little-endian). 1.5초를 넣으면 조각 15개. 1.0 → 32,767, -1.0 → -32,767, 1.5 → 32,767, -1.5 → -32,768.
- 확인: 단위

**AC-APP1-11** [device] (VOC-06 결과) 결과만 최종
- Given 엔진이 `ready`·`result`(`text` "15번 2만 원")·모르는 틀·깨진 JSON을 받는다
- Then 알리는 결과는 `{ text: "15번 2만 원", final: true }` 하나뿐(중간 결과 없음), 나머지는 예외 없이 무시.
- 확인: 단위

**AC-APP1-12** [device] (VOC-06 끊김, D-APP-05, D-APP1-03) 다시 잇기
- Given `ready`를 받은 뒤 연결이 닫힌다(까닭 없음)를 되풀이
- Then 다시 잇는 간격 1·2·4·8·8초, 상태 "다시 잇는 중". 최종 결과 없이 60초 안 여섯 번째 끊김이면 멈춤("듣기 멈춤" 상태, 까닭 연결 실패). 그 사이 `result`가 오면 센 것을 비운다. 끊긴 동안 넣은 소리 조각은 보내지 않고 버린다(다시 이어진 뒤 보내는 첫 조각은 이은 뒤에 잡은 소리).
- Given `ready` 전 첫 `closing` `BUSY`·`NO_WORKER` → 다시 잇지 않고 그 까닭으로 멈춤. `ready` 뒤 다시 이을 때 받은 `BUSY`·`NO_WORKER` → 다시 잇기 셈. `OTHER_DEVICE`·`AUTH` → 언제든 멈춤. `ENDED` → 멈춤.
- 확인: 단위(가짜 연결·넘겨받은 시계)

**AC-APP1-13** [device] (VOC-06 늦은 글, D-APP-12, D-APP1-08) 말 끝 시각
- Given 흐름의 첫 소리를 기기 시각 T에 잡았고 결과 `endMs` 3,000
- Then 말 끝 시각 = T + 3,000. 처리 시각이 T + 13,000이면 바로 처리 가능(10,000 정확히), T + 13,001이면 늦은 글. 다시 이은 흐름은 그 흐름의 첫 소리 시각으로 다시 잰다.
- 확인: 단위

**AC-APP1-14** [device] (VOC-06 AC3, D-APP-04) 비밀 없음
- `packages/voice`에 받아쓰기 서버 주소·일꾼 토큰·`/api/voice/worker`를 받는 옵션이 없다. 엔진은 부르는 쪽이 넘긴 연결 함수로만 연다(cloud.ts 원칙).
