# P2 수용 기준 — 문서·음성 패키지 (병렬 트랙)

- 스프린트: P2 (병렬 트랙 — 2단계 문서, 4단계 음성의 패키지 몫. 화면·서버 연결은 I2·I4) · spec ID: **STL-04**, **STL-05**, **STL-06**, **VOC-01**, **VOC-02**, **VOC-03**, **VOC-05** (연결: VOC-04 데이터 모델, STL-01·02·03·07·09, R-6, R-10, R-11, R-12, PRD-01 AC3·AC4, UX-01, UX-03, UX-06, NFR-02, NFR-05, NFR-06, NFR-07, DAT-06, SPEC §1 "방송 후 정산 10분", §8 2단계 "명세서 PDF·엑셀 대장이 골든 정산 결과와 일치") · 규칙: DOMAIN_RULES v0.1.13 R-12, R-14, R-15, **새 R-17**(음성 문장 추출) · 근거 결정: **D-201~D-209**(AUTO), D-013, D-029, D-032, D-048, D-088
- 개발 영역: **device** · 테스트: **domain** · 사람 확인 지점 없음(실제 목소리·마이크 정확도는 S13 HG-4, 실제 인쇄·공유 모양은 I2 뒤 2단계 끝 보고 — DECISIONS "사용자 확인 필요")
- **dev-core가 없다.** 판정·정산 규칙은 바꾸지 않는다. 문서가 기대는 정산 결과는 골든 G-ENG-201·202로 고정했고 지금 코어로 통과한다. 코어는 이미 있는 조회 함수(`getSettlement`·`listSettlements`·`listClaims`·`listProducts`·`getProduct`·`getBuyer`·`listBroadcasts`·`getBroadcast`)와 순수 함수(`parseAmount`·`parseKoreanNumber`·`formatWon`·R-3 정규화)를 그대로 쓴다. 코어 `src`의 동작을 바꿔야 할 것 같으면 고치지 말고 dev-notes·`disputesWithSpec`으로 올린다. 예외 하나: 이미 있는 순수 함수(R-3 정규화 `normalizeText` — 지금 `packages/core/src/parse/text.ts`에만 있다)를 코어 공개 API(`index.ts`)로 내보내는 한 줄은 dev-device가 최소 변경으로 할 수 있다(동작 변경 없음, dev-notes에 남긴다).
- 목표(백로그): `packages/documents` — 구매 내역 확인서 PDF(한글 글꼴 내장, 제목·법정 증빙 아님 고지, 구매자·번호·품종·가격·합계·배송비·조정·최종 금액·주문 날짜·회차·입금 계좌), 한 명·전원 일괄 PDF, 휴대폰 공유 이미지, 엑셀 판매대장(STL-06 열). 금액은 코어 정산 결과 그대로, 전화번호는 뒤 4자리만. `packages/voice` — `SpeechEngine` 어댑터(Web Speech 기본, Deepgram·리턴제로 골격 — 키 없이 가짜로 시험), 추출기(문장 → 번호·품종·가격·신뢰도, 코어 금액·수사 파서 재사용, 자모 유사도 품종 사전, 판매 이력으로 사전 확장), 제안 카드 데이터 모델. 화면·서버 연결은 하지 않는다.
- carryOver: 없음. 모호한 점 → 결정 → 수용 기준

## A. 음성 문장 추출 (VOC-02·VOC-03, R-17, D-202·D-203)

### AC-P2-01 [device] 추출 함수
- 근거: R-17 머리말·1·6, D-202
- Given 문장 하나, `claim.maxNumber`(생략하면 999), 품종 사전(이름 목록)
- When `packages/voice`의 추출 함수를 부른다
- Then 결과는 정확히 네 키 `{ no, name, price, confidence }`다. `no`·`name`·`price`는 값 또는 `null`, `confidence`는 `HIGH`/`LOW`. 다른 키는 없다.
- Then 순수 함수다: 같은 입력이면 같은 결과, 넘긴 사전·설정을 바꾸지 않고, 시계·난수·네트워크를 쓰지 않는다. 어떤 문자열(빈 문자열, 문자열이 아닌 값, 제어 글자, 1만 글자, HTML)에도 예외를 던지지 않는다. 정규화한 문장이 300글자를 넘으면 전부 `null`·`LOW`(골든 마지막 문서).
- Then 금액은 코어 `parseAmount`(R-14, 원 단위), 번호는 코어 `parseKoreanNumber`(R-15), 정규화는 코어의 R-3 정규화 함수를 다시 쓴다(새로 구현하지 않는다 — 코어와 결과가 갈라지지 않게. 공개 API로 내보내는 한 줄은 머리말의 예외).
- 확인: 골든(`parser/voice-extract.yaml` 69사례 전부), 단위 테스트, 속성 테스트(임의 문자열 → 예외 없음·네 키·결정성)

### AC-P2-02 [device] 번호 (R-17 3)
- 근거: R-17 2·3, D-202
- Then 번호 표시는 `X번`(붙여 씀) 또는 `X` `번`(띄어 씀), `번`이 붙은 토큰은 끝말을 뗀 모양도 본다(`15번이요`·`15번엔`). `X`는 숫자 1~4자리 또는 한자어 수사 글자만이고 `이` 한 글자는 아니다.
- Then 예(골든): `십오번` → 15, `백오번` → 105, `일번` → 1, `한 번`·`이번`·`이 번`·`열다섯 번`·`15번째`·`세 번째` → 표시 아님, `15번 16번` → `null`, `15번이요 15번` → 15, `1000번`(maxNumber 999) → `null`, maxNumber 50에서 `50번` → 50·`51번` → `null`.
- 확인: 골든, 단위 테스트

### AC-P2-03 [device] 가격 (R-17 4)
- 근거: R-17 4, R-14, D-202, D-048
- Then 가격 묶음 = 번호 표시 토큰을 넣지 않은 이어진 토큰 1~6개, 마지막 토큰은 읽는 모양을 차례로 넣어 R-14(원 단위)로 처음 읽히는 값이 100원 이상이고 `원`이나 한글 수·단위가 있는 가장 긴 것. 서로 다른 값이 둘 이상이거나 금액 조각이 있으면 `null`.
- Then 예(골든): `만오천 원`·`만 오천 원`·`1만 5천 원`·`15,000원`·`만오천원에`·`만원이요`·`오천원짜리` → 그 금액, `10000`·`10`·`십`·`99원`·`0원`·`공짜`·`만오` → `null`, `백 원` → 100, `만 원 하던 거 오천 원에` → `null`, `1만 500`·`이 만원짜리`·`2 만원`·`오 천 원` → `null`(조각), `만원 이 가격에` → 10,000(원으로 끝난 묶음 뒤는 보지 않는다), `만원 만원`·`오천 원 오천 원` → 그 금액.
- Then `price.unit` 설정은 결과를 바꾸지 않는다(같은 문장을 `THOUSAND`·`WON` 어느 쪽으로 불러도 같다 — 추출 함수가 그 설정을 받지 않아도 된다).
- 확인: 골든, 단위 테스트

### AC-P2-04 [device] 품종 (R-17 5)
- 근거: R-17 5, D-203
- Then 창 = 번호 표시·가격 묶음 토큰을 뺀 이어진 토큰 1~4개(빠진 토큰에서 끊긴다), 마지막 토큰은 읽는 모양마다. 유사도 = 1 − 자모 편집 거리 ÷ 긴 쪽 자모 수(자모 = 공백 지우고 NFD로 푼 코드 포인트), 거리 × 5 ≤ 긴 쪽 자모 수인 짝만 후보, 비교는 분수로. 가장 높은 유사도의 이름이 하나면 그 이름(사전에 적힌 모양), 여럿이면 나머지를 모두 품는 이름만, 아니면 `null`. 사전에 없는 말은 품종이 되지 않는다.
- Then 예(골든): `핑크 프릴` → `핑크프릴`, `핑크푸릴` → `핑크프릴`(0.9, LOW), `나울` → `라울`(0.8 경계, LOW), `벨루` → `null`(0.71), `로나` → `null`(짧은 이름), `라울이랑` → `라울`, `십이 지권` → `십이지권`, `핑크프릴 금` → `핑크프릴 금`(품는 이름), `핑크프릴 라울` → `null`, 사전 `[핑크프릴, 핑크프린]`에서 `핑크프리` → `null`(동률), 빈 사전 → `null`.
