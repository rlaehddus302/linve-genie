### AC-S03-02 [core] 입력 오류 — 조용히 무시하지 않는다 (carryOver SA-S02-002)
- 근거: R-1 "입력 오류와 맞지 않는 명령", D-050
- Given 아무 상태
- When 다음 이벤트로 `applyEvent`: R-1·README에 없는 종류(`chat.message`·`sms.claim`·`settlement.paid`·`'__proto__'`·종류 없음), 필수 필드 없음, 값 형식이 틀림(번호 0·문자열 번호, 음수·소수 금액, 재고 0, 열거값 오타, 빈 사유, 수신 시각 `24:00`·`8:01`·`20:01:60`), 선언하지 않은 방송, `seq`·`at`이 수가 아님, 이벤트가 객체가 아님
- Then 입력 오류를 던진다(`NotImplementedError`와 구별되는 오류 하나, 구별하는 도우미 함께 export). 넘긴 상태는 바뀌지 않는다.
- Then 형식 검사 함수는 같은 상태·이벤트에 대해 `applyEvent`가 입력 오류를 던질 때만 문제를 돌려준다(속성 테스트: 무작위 이벤트·변형 이벤트에서 둘의 판정이 같다).
- Then 형식은 맞지만 상태에 맞지 않는 명령(AC-S03-04)은 입력 오류가 아니다.
- S02 단위 테스트 "맞지 않는 명령·형식이 틀린 이벤트는 아무것도 바꾸지 않는다"의 형식 오류 항목은 이 기준의 테스트로 바꾼다. 스펙이 바뀌어서 하는 교체이지 테스트 약화가 아니다. 맞지 않는 명령 항목은 그대로 둔다.
- 확인: 단위 테스트, 속성 테스트

### AC-S03-05 [core] 처리 비용 — 상태가 커져도 이벤트당 비용이 늘지 않는다 (carryOver TD-S02-002, RA-S02-001, RA-S02-006)
- 근거: NFR-01, NFR-04, AC-S02-05
- Then (보류 찜) 아직 없는 번호 하나에 서로 다른 구매자의 보류 찜을 하나씩 N개 쌓는 전체 시간: N = 20,000이 N = 5,000의 8배를 넘지 않는다(이벤트당 일정이면 4배, 배열 통째 복사면 16배).
- Then (한 구매자의 찜) 미리 등록한 상품 N개를 한 구매자가 하나씩 확정받는 전체 시간: N = 8,000이 N = 2,000의 8배를 넘지 않는다.
- Then (`checkInvariants`) 상태 크기 4배에서 시간이 8배를 넘지 않는다(구매자×찜 이중 순회·번호별 펼침 복사 없이 한 번 순회).
- Then (처리 시간, AC-S02-05 대체) AC-S02-05의 로그(상품 500·채팅 10,000·조치 100)에 S03 이벤트(문자찜 2,000, 상품 수정 50, 번호 변경 10, 합치기·떼어 내기 20, 정산 기록 100)를 섞어 `RECEIVED_TIME` 설정으로도 한 번: 전체 5초 안. 이벤트 하나 시간은 처음 1,000건(준비 구간)을 뺀 p99가 20ms 이하이고, 최댓값은 NFR-01 예산 300ms 미만(느슨한 상한, CI 부하에서 흔들리지 않게).
- 확인: 단위 테스트(시간 측정), 적대 테스트
