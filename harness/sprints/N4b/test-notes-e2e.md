# N4b test-notes (e2e)

라운드 0 — `tests/e2e/n4b/` (support · flow · screens · attacks · probes). 실행: `E2E_PORT_OFFSET=1700 pnpm e2e`.

## 실패로 남긴 것
- TE-N4b-001 (flow.spec.ts): 기본 묶음(Vite 미리 보기 + E2E 서버)에서 링크 `<화면 주소>/r/<토큰>`이 E2E 서버로 가지 않는다.
  `apps/web/e2e/serve.ts`가 미리 보기 프록시에 `/api`만 E2E 서버로 넘기고, `vite.config.ts`의 `'^/r(/|$)'`는 설정 파일의
  `LIVEJJIM_API_URL` 기본값(http://localhost:3000)을 그대로 쓴다. 이 기계에서는 3000번의 다른 서비스가 404를 준다.
  같은 흐름은 서버가 화면을 내는 묶음(@served)에서 통과한다.
- TE-N4b-002 (attacks.spec.ts): 영수증 보내기 화면을 연 뒤 다른 기기에서 가게 이름을 바꾸면 줄은 다시 받지만
  복사·공유 글의 가게 이름은 `/api/me`를 처음 받은 값 그대로다(구매자 문서는 새 이름).

## 통과한 공격 (회귀로 남김)
- 콘솔 주 버튼 하나(실제·리허설·봉인한 날짜), 방송 중 안내, 없는 방송
- 같은 날 안내, 전원 PDF·ZIP(UTF-8 비트·기본 JPEG)·이 방송 판매대장(다른 방송 행 없음), 한 사람 JPG·PDF 이름
- 실시간 입금·취소 반영, 빈 날짜, 두 번 누르기·응답 유실 뒤 같은 요청 번호, 끊기 창 Esc·1 키·포커스, 끊은 뒤 새 주소
- 글 공유(text만·AbortError 무안내), 클립보드 실패 글 칸, 발송함 행 없음, 모두 복사 버튼 없음
- 리허설 화면·ZIP 이름, 보조자(버튼 없음·데이터 요청 없음·API 403), 375px 두 화면(44px·16px·가로 스크롤)
- 구매자 문서 이스케이프, 합치기·떼어 내기와 링크, 서비스 워커 등록 브라우저·오프라인(@served), /privacy 12절

## 라운드 2 — `tests/e2e/n4b/round2.spec.ts` (모두 통과, 회귀로 남김)
- 구매자 문서: 가게 이름·은행·예금주·안내 문장의 HTML 이스케이프, 계좌 없는 가게는 "입금 계좌" 칸 없음, 과입금 줄·문서(환불할 금액)
- 주소: `?fbclid=…` 꼬리도 같은 문서, `/r`·`/r/`·끝 `/`·모르는 파일 이름은 같은 404 문서(기본 묶음·@served), 다른 메서드 405
- 판매자 쿠키가 와도 같은 바이트·Set-Cookie 없음, HEAD 본문 없음·같은 머리글, 1분 60번(문서+그림) 넘으면 429(다른 링크는 그대로)
- 문서 그림 inline, "그림 저장"·"PDF로 받기" 이름 `확인서-YYYY-MM-DD-…`, 줄의 끝 시각과 문서 끝 시각이 같은 날·같은 분
- 다른 기기와 엇갈림: 먼저 끊긴 링크 끊기도 오류 없음, 다른 기기가 만든 뒤 "링크 만들기"는 그 링크, 동시 만들기·전부 만들기도 구매자마다 링크 하나, 다른 기기 합치기·떼어 내기의 실시간 줄 수
- 리허설 한 사람 JPG·PDF 이름 `리허설-확인서-YYYY-MM-DD-<이름>`
- 관찰(시험 아님): 같은 날 두 번째 방송에 찜이 들어오면 찜마다 receipt-buyers를 다시 받는다(30찜 → 31번). 스펙 위반은 아니다.
