# SMS3 사용자 확인 필요 (HG-SMS3)

> 이번 스프린트는 가짜 알림·가짜 요청·에뮬레이터로 시험했다. 아래는 실제 기기·실제 은행·실제 앱 빌드에서만 확인할 수 있는 것이다. 막히지 않는다(blocking 아님) — 틀려도 "자동으로 적히지 않는 쪽"(확인 필요·읽지 못함)으로만 틀린다. 근거는 `docs/DECISIONS.md` "사용자 확인 필요" 표의 SMS3 줄.

| ID | 확인할 것 | 어떻게 | 틀렸을 때 지금 동작 | 근거 |
|---|---|---|---|---|
| HG-SMS3-01 | 실제 기본 문자 앱(삼성 메시지·구글 메시지·통신사 문자 앱)의 알림에서 보낸 곳(번호·연락처 이름)과 본문이 읽히는지, 같은 문자가 알림 갱신으로 다시 떠도 같은 `id`인지 | 판매자 안드로이드 휴대폰에 앱 설치 → 다른 휴대폰에서 `15 홍길동` 문자 → 콘솔 보드에 15번 문자찜 | 문자찜이 들어오지 않음 → 손 입력(ORD-08) | D-SMS3-02·D-SMS3-21(e) |
| HG-SMS3-02 | 판매자 은행 앱 알림의 모양 — 앱 패키지 이름(설정 → 앱 정보)이 DP-9 1 표와 같은지, 제목·본문에서 금액·입금자명·잔액이 읽히는지 | 실제 소액 입금 1건 → 입금 확인 화면 | 표 밖이면 믿지 않는 곳(확인 필요), 못 읽으면 "읽지 못한 은행 알림" 줄 | D-DEP2-02·D-DEP2-03 |
| HG-SMS3-03 | 은행 입금 문자의 보낸 대표번호가 DP-9 1 표와 같은지(은행 문자 알림을 켠 경우) | 실제 소액 입금 1건 → 입금 확인 화면 | 표 밖 번호면 확인 필요 `UNTRUSTED_SOURCE` | D-DEP2-02 |
| HG-SMS3-04 | 제조사 배터리 절약(삼성 "절전 앱"·"사용하지 않는 앱 재우기" 등)이 알림 읽기를 끄는지, 화면이 꺼진 채 1시간 방송에서 빠짐없이 보내는지 | 방송 1회 실제로, 끝난 뒤 문자 앱 수와 받은 수 비교 | 10분 넘게 받지 않으면 콘솔 "휴대폰에서 문자가 오지 않고 있어요" 알림 | D-SMS3-02, AC-SMS3-31 |
| HG-SMS3-05 | 아이폰 단축어("메시지 받을 때" 자동화 + "URL 콘텐츠 가져오기"에 받기 토큰)가 화면 잠김·여러 통 동시 도착에서 빠짐없이 보내는지 | 웹 설정의 안내대로 판매자가 직접 만들기 → 문자 3통 동시 | 빠진 문자는 손 입력 | D-SMS3-02·D-SMS3-23 |
| HG-SMS3-06 | 안드로이드 알림 읽기 권한을 쓰는 앱의 구글 플레이 심사(권한 사용 설명) | 스토어 등록 전 | APK 직접 설치 | D-SMS3-02 |
| HG-SMS3-07 | 네이티브 모듈 `LivejjimNoticeModule.kt`(안드로이드)·`LivejjimNoticeModule.swift`(아이폰 App Intent)가 실제 앱 빌드(Expo 개발 빌드·출시 빌드)에서 컴파일되고 동작하는지. 아이폰 App Intent "라이브지니에 문자 보내기"를 안내에 넣을지는 이 확인 뒤 다시 본다 | `expo prebuild` 후 안드로이드 스튜디오·Xcode 빌드 | 앱 빌드 실패 시 웹 단축어 안내만(지금 기본) | D-SMS3-21·D-SMS3-23 |
