# SMS3 리포트 — 문자·입금 알림 자동 받기

**결과: PASS (SMS3 범위)** — 수정 라운드 2회와 사용성 고침 1회를 마쳤다. 남은 blocker·major 기능 지적은 없다.

`pnpm verify` 2회차는 7단계 중 6단계가 통과했다. 남은 실패는 e2e 1건이고, int/next에서 온 SMS3 밖 시험(AC-I3-23 유튜브)이다.

- 작업 폴더: `.claude/worktrees/youthful-taussig-064c9a`, 원격 `sprint/SMS3`. 시작점은 `origin/int/next`(f4b04dd7)이고, 여기에 `spec/sms-deposit-intake`(5f966b11)와 `dev/mobile-notice`를 합쳤다. BASE는 3b403c44.
- 개발: core·device·server·web / 테스트: domain·e2e / 감사: spec·risk / 사용성 1회
- 판정·정산 엔진 규칙(R-1~R-25)과 엔진 골든은 바꾸지 않았다. 넣는 것은 지금의 `sms` 이벤트이고, 적는 것은 지금의 `settlement.payment`다.

## 영역별로 만든 것

- **core (AC-01·02)**: R-26 `parseSmsText`(`packages/core/src/parse/sms-text.ts`)와 골든 러너 suite `sms-text`(선택 키 `from`)를 만들었다.
  - 골든 `parser/sms-text.yaml`은 130사례 모두 통과한다. 사례 `775,776,777`은 R-3의 금액 모양이라 `{}`로 고쳤다(D-SMS3-15).
  - 골든 합계는 파일 40 · 파서 935 · 엔진 159 · 통과 1094다.
- **server (AC-03~25)**:
  - **받기 토큰**: 해시만 저장한다. 다시 만들면 옛 토큰은 바로 무효다. 꺼짐은 403 `INBOX_OFF`이고, 401은 토큰이 틀렸을 때만이다. 틀린 토큰은 IP마다 10분에 20번까지 받는다.
  - **입구 하나** `POST /api/inbox/messages`: 0~20건, 기기 입구만 256KB, 판매자마다 1분 600건이다.
  - **가르기 C-05**: 은행 대표번호는 숫자·하이픈·공백으로만 된 보낸 곳이어야 믿는다.
  - **합치기 C-06**: 같은 문자 표지는 실제로 저장된 뒤에만 남긴다.
  - **방송 창**: 실제 방송에서 끝난 뒤 10분까지이고, 서버 도착 시각으로 센다. 시작 후 12시간이 넘은 방송은 창이 아니며 알림을 띄운다.
  - **늦게 온 문자**: `LATE` 카드로 둔다.
  - **문자찜**: 바로 넣는다. 판매 중이 아니면 `NOT_ON_SALE`, 넣지 못하면 `REJECTED` 카드다. `STATE_FORMAT`은 500을 돌려 기기가 다시 보내게 한다.
  - **취소 요청**: 판매자가 승인해야 취소된다. 이름만 온 취소 요청은 승인할 수 없다.
  - **카드 잡기**: 조건부 UPDATE로 원자적으로 잡는다. 동시에 눌러도 찜은 하나다.
  - **보관 규칙 C-07**: 처리한 카드의 이름·뒤 4자리는 바로 지운다. 서버를 켤 때와 30분마다 판매자 전체를 정리한다(카드 24시간, 은행 알림 줄 30일).
  - **DP-9 `readBankNotice`**: 골든 `deposit/notice.json` 53사례를 모두 통과한다. 다음을 막는다.
    - 되돌림 낱말이 든 알림(D-DEP2-08)
    - 시각·날짜 조각을 금액으로 읽는 것(D-DEP2-09·16)
    - 보낸 곳 모양(D-DEP2-10)
    - 입금자명 끼워넣기(D-DEP2-11)
    - 국제·해외·국외발신(D-DEP2-12)
  - **휴대폰 알림 입금 자동 확인**: 같은 은행의 잔액이 이어질 때만 한다(D-DEP2-13). 외부 키 `bal:`의 시각은 분 단위다. 원천은 `PHONE`이고, 은행 알림 줄을 두며, 입금 취소는 판매자가 되돌린다.
  - **마이그레이션**: 0030, 0031.
- **device (AC-26·27)**: `packages/mobile-notice`를 C-01~C-04에 맞췄다. TS·Kotlin·Swift 공용 사례를 쓴다.
  - 기본 문자 앱과 `filters.bankApps` 앱 알림만 읽는다.
  - `skipWords`는 은행 대표번호가 아닌 문자에만 쓴다(D-SMS3-26).
  - 보낸 곳은 원문 그대로 보낸다.
  - 대기열은 암호화한 1,000건이고, 넘치면 버린 건수를 경고한다.
  - 응답 처리:
    - 401은 멈춤.
    - 403은 대기열을 지키고 10분마다 다시 본다.
    - 429는 1분 쉰다.
    - 5xx는 같은 id로 다시 보낸다.
    - 400·413은 한 건씩 다시 보낸다.
  - READ_SMS를 쓰지 않고, 로그를 남기지 않는다.
- **web (AC-28~32)**:
  - **설정 "휴대폰 알림 받기"**: 토큰은 한 번만 보인다. 헤더 값·받는 주소 복사 단추가 있다. 다시 만들기·끄기에는 확인 창이 있다. 아이폰 단축어는 칸 단위로 안내하고, id는 날짜(초까지)+보낸 사람으로 만든다.
  - **앱 알림 읽기 안내**(`apps/mobile`).
  - **콘솔 "문자 확인" 칸**:
    - 카드 종류: 확실하지 않음·이름만 옴·판매 중 아님·늦게 옴·넣지 못함.
    - 승인 전 확인 창이 뜬다.
    - 맨 위 줄에 "확인할 문자 n"이 보인다.
    - "문자로 받음" 표시를 붙인다.
    - 봉인한 날짜에도 볼 수만 있다.
  - **알림**: 받기 멈춤 알림과 12시간 방송 알림이 있다.
  - **입금 확인 화면**: 휴대폰 알림 원천과 은행 알림 줄("이름 모름" 포함)을 보인다.
- **tests**:
  - **domain** `tests/adversarial/sms3`: 120개 모두 통과한다. 처음에 버그 4건을 잡아 고쳤다.
  - **e2e** `tests/e2e/sms3`: chromium에서 PC·375로 34개다. 마지막 전체 실행은 33/34였고, 실패 1건은 흔들림이라 시험을 고친 뒤 그 파일을 3회 연속 통과했다.

## 자율 결정

D-SMS3-01~38, D-DEP2-01~17은 모두 AUTO다(`docs/DECISIONS.md` "문자·입금 알림 자동 받기 (SMS3 자율 결정)"). 다음 단계를 막는 결정은 없다. 주요한 것:

- **D-DEP2-13**: 휴대폰 알림 입금은 같은 은행의 잔액이 이어질 때만 자동 확인한다. 은행마다 첫 입금과, 잔액을 보이지 않는 은행의 입금은 늘 확인 필요다. 잘못된 입금 확인이 없는 쪽을 골랐다.
- **D-DEP2-08~12**: 되돌림 낱말, 시각 조각, 보낸 곳 모양, 입금자명 끼워넣기, 국제발신은 모두 읽지 못함 또는 믿지 않음으로 둔다.
- **D-SMS3-27·28**: 꺼짐은 403, 한도는 600, 기기 대기열은 1,000건이다.
- **D-SMS3-29·30**: 시작 후 12시간이 넘은 방송은 창이 아니다. 늦게 온 문자는 `LATE` 카드로 둔다.
- **D-SMS3-39**: 화면에는 "토큰" 대신 "받기 열쇠"라고 쓴다. 첫 `pnpm verify`에서 기존 기준 AC-I3-90(설정 화면 금지 낱말)이 깨져 바꿨다. 설정 칸 단추도 보조 모양으로 바꿔, 설정 화면의 주 버튼이 하나가 되게 했다(AC-N4a-15·32).
