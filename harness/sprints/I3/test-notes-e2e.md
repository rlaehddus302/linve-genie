## 실패로 남긴 것
- **TE-I3-001** (`youtube.spec.ts` "TE-I3-001 AC-I3-24") — 채팅이 조용한 라이브를 이으면(예정 방송이 시작돼도) 수집 상태가 첫 채팅이 올 때까지 "시작하는 중"에 머문다. 가짜 서버 스트림은 새 메시지가 없으면 응답 묶음을 하나도 쓰지 않고(`fake-google.ts #chatStream`), 수집기는 첫 응답 묶음을 기록한 뒤에야 `LIVE`로 적는다(`collector.ts`). 실제 유튜브 streamList는 연결하면 첫 응답(빈 목록이어도)을 바로 준다고 알고 있어 운영에선 덜할 수 있지만, AC-I3-24 E2E("예정 방송을 시작하면 '채팅을 받는 중'")가 통과하지 않는다.

## 통과해 버린 공격 (회귀로 남김)
- 보조자 지우기 → 아무것도 누르지 않은 보조자 화면이 로그인 화면으로(실시간 연결 닫힘 → 다시 붙기 401).
- 확인하지 못한 감사: 수집 스트림·목록 조회를 막고 `acceptHang` + 문자찜 판매로 `UNCONFIRMED`를 만들 수 있다(유튜브 채팅 판매로는 스트림이 살아 있어야 해서 안 된다 — 판매를 문자찜으로).
- 실시간 끊김 흉내: Playwright `setOffline`은 열린 SSE를 끊지 않는다(알림이 그대로 온다). `page.route('**/api/stream', abort)` + `window.stop()`으로 끊어야 다시 붙음(두 번째 `ready`) 경로를 탄다.
- 이스케이프(채널·방송 제목·시청자 이름에 `<img onerror>`·`<script>`·U+202E), 결과 코드 `?youtube=<img…>`, 서버가 내는 화면의 폴더 밖 경로(`curl --path-as-is`로 `%2e%2e`·`%2f`·`%5c`·`%00` 모두 404).

## 스펙 확인이 필요한 것 (시험 없음)
- 마법사를 마친(또는 닫은) 판매자가 `/start`를 직접 열거나 "시작 마법사 다시 하기"로 열고 한 단계만 넘긴 뒤 떠나면 상태가 `IN_PROGRESS`로 다시 적혀, 실제 방송이 없으면 `/`에 올 때마다 마법사가 다시 저절로 열린다. AC-I3-50 "마치거나 닫으면 다시 자동으로 열리지 않는다"와 "단계를 옮길 때 상태를 서버에 적는다"가 부딪힌다(dev-web 결정 1은 "다시 하기"만 다시 켠다고 적었지만 `/start` 직접 열기도 같다).
- AC-I3-13 "규칙을 저장하거나 동의를 바꾸면(이 기기·다른 기기 SSE) 요약이 바로 바뀐다" — 다른 기기에서 **규칙을 저장**한 것은 서버 알림이 없어 열린 설정 화면의 요약이 바뀌지 않는다(dev-web 결정 8). 문장이 동의에만 걸리는지 판정이 필요하다.

## 참고 (제품 밖)
- 화면 프록시(`apps/web/e2e/serve.ts`)를 거친 `page.request` 한 번에 약 300ms가 걸린다(서버 바로는 3~10ms). 많이 부르는 시험은 `directApi()`로 서버를 바로 부른다.
