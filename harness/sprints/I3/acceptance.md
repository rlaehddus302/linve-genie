## A. 유튜브 연결 화면 (YT-01, D-I3-02)

### AC-I3-01 [web] 설정의 유튜브 칸 — 상태마다
- 근거: YT-01, UX-01, UX-03, D-I3-02, Y1 계약 1
- Given 판매자가 로그인했다
- When `/settings/youtube`를 연다(설정 화면의 "유튜브" 칸과 같다)
- Then 서버가 503 `YOUTUBE_NOT_CONFIGURED`면 "유튜브 연동을 준비하지 않은 서버예요." 한 줄만 보이고 연결·동의 버튼이 없다(오류 표시가 아니라 안내).
- Then **연결 안 됨**: 권한 안내(아래)와 버튼 "구글로 유튜브 연결하기".
- Then **연결됨**: 채널 이름(이스케이프), "읽기 권한 있음", 글쓰기 권한 "있음"/"없음"(글자로), 자동 게시 동의(B절), 사용량(AC-I3-37), 버튼 "연결 끊기".
- Then **다시 연결 필요**: "유튜브 연결을 다시 해 주세요." + 버튼 "다시 연결하기"(연결 시작과 같은 요청). 자동 게시 동의가 하나라도 켜져 있으면 "구글 화면에 글쓰기 권한도 함께 나와요. 빼고 허락하면 자동 게시가 꺼져요."(D-Y1-01)
- Then 권한 안내(연결 안 됨·다시 연결 필요일 때 버튼 위): 연결하면 할 수 있는 일 셋 — 내 채널 이름 보기, 내 라이브 방송 목록 보기, 방송 채팅 읽기(찜 받기) — 과 "연결만으로는 내 채널에 글을 쓰지 않아요.", 감사 메시지 자동 게시는 아래에서 따로 동의하고 그때 구글 화면에서 글쓰기 권한을 한 번 더 허락한다는 문장, 구글 인증 정보는 암호로 바꿔 보관하고 채팅 내용은 방송 날짜부터 30일 뒤에 지운다는 문장, 언제든 연결을 끊거나 구글 계정 설정에서 권한을 거둘 수 있다는 문장, 개인정보처리방침 링크.
- Then 영문 상태값(`CONNECTED`·`RECONNECT_NEEDED` 등)·권한 주소(`youtube.readonly` 등)·토큰·만료 시각은 화면 어디에도 없다.
- 확인: E2E(가짜 유튜브 묶음 — 연결 안 됨·연결됨·다시 연결 필요(가짜 서버 `oauth.refresh`에 `invalid_grant`), 기본 묶음 — 준비 안 됨)

### AC-I3-02 [web] 연결하기·돌아오기
- 근거: YT-01, D-I3-02, Y1 계약 1·7
- Given 연결 안 됨(또는 다시 연결 필요)
- When "구글로 유튜브 연결하기"(또는 "다시 연결하기")
- Then `POST /api/youtube/connection/start`가 준 `authorizeUrl`로 **같은 탭에서 최상위 이동**한다(새 창·팝업·iframe 없음). 그 주소는 localStorage·sessionStorage·주소창 밖 어디에도 저장하지 않고 콘솔에 찍지 않는다.
- Then 가짜 승인을 마치고 `/settings/youtube?youtube=<결과>`로 돌아오면 결과 문장을 한 번 보인다 — `connected` "유튜브 채널을 연결했어요." · `STATE_INVALID` "연결 시간이 지났어요. 다시 시도해 주세요." · `ACCESS_DENIED` "구글에서 연결을 허락하지 않았어요. 다시 시도해 주세요." · `NO_CHANNEL` "이 구글 계정에는 유튜브 채널이 없어요." · `CHANNEL_TAKEN` "이 채널은 연결할 수 없어요. 운영자에게 문의해 주세요." · `CHANNEL_MISMATCH` "처음 연결한 채널과 달라요. 바꾸려면 먼저 연결을 끊어 주세요." · `GOOGLE_FAILED` "구글에 연결하지 못했어요. 잠시 뒤 다시 시도해 주세요." · 그 밖의 값 "연결 결과를 알 수 없어요. 아래 연결 상태를 확인해 주세요." 결과 문장은 화면 낭독기가 읽는 상태 영역(role `status` 또는 `alert`)이다.
- Then 결과를 보인 뒤 주소의 `youtube` 값을 지운다(주소 바꾸기 — 뒤로 가기 기록을 늘리지 않음). 새로고침해도 결과 문장이 다시 나오지 않는다. 연결 상태는 늘 서버(`GET /api/youtube/connection`)로 다시 읽는다(결과 코드로 상태를 짐작하지 않는다).
- Then 시작 마법사 4단계에서 시작했으면 돌아온 뒤 마법사 4단계에 결과 문장이 보인다(AC-I3-54).
- 확인: E2E(가짜 승인 — 허락·거절(`deny`)·채널 없음·다른 채널로 다시 연결)

### AC-I3-03 [web] 연결 끊기
- 근거: YT-01, D-I3-02, UX-03
- Given 연결됨
- When "연결 끊기"
- Then 확인 창 "유튜브 연결을 끊을까요?" — 끊으면 진행 중인 방송의 채팅 수집과 감사 메시지 자동 게시가 멈추고 자동 게시 동의도 지워진다, 이미 받은 찜과 판매 기록은 그대로다. 유튜브 방송을 이어 채팅을 받는 중인 실제 방송(끝나지 않음)이 있으면 "지금 채팅을 받는 방송: <제목>"을 함께 보인다. 버튼 "연결 끊기"·"그대로 두기", 처음 포커스는 "그대로 두기", Esc는 "그대로 두기"와 같다.
- Then "연결 끊기"면 `POST /api/youtube/connection/disconnect` 뒤 연결 안 됨 화면이 되고 동의가 꺼져 보인다. "그대로 두기"면 아무 요청도 보내지 않는다.
- 확인: E2E

### AC-I3-04 [web] 다른 기기에도 1초 안에

### AC-I3-05 [web] 화면에 비밀이 없다
- 근거: YT-01, DAT-06, NFR-06, Y1 계약 7

## B. 감사 메시지 설정·자동 게시 동의 (YT-04 AC2, YT-05, YT-07, D-Y12, D-I3-03)

### AC-I3-10 [web] 만들기 — 판매 규칙 `thanks.*`
- 근거: YT-04, YT-05, YT-07, DOMAIN_RULES 설정표·설정 스냅샷, D-070, D-I3-03, G-ENG-701

- Then "만들기" 묶음에 세 칸: "실시간 채팅에 감사 메시지 남기기"(켜기/끄기 — `thanks.liveChat`), "영상 댓글"(선택지 "남기지 않음"/"판매마다 댓글"/"방송이 끝나고 요약 댓글 1개" — `thanks.videoComment` `OFF`/`PER_SALE`/`SUMMARY`), "몇 초 동안의 판매를 한 메시지로 묶을까요? (0이면 하나씩)"(숫자 0~600 — `thanks.batchWindowSec`). 지금 저장된 값이 채워져 있다.

- Then 저장 뒤 새로 만든 방송은 새 규칙으로, 이미 진행 중인 방송은 옛 규칙으로 감사가 생긴다(G-ENG-701) — E2E로: 실시간 채팅 감사를 끄고 저장 → 진행 중이던 1부에서 확정 → 감사 메시지 목록에 그 판매의 실시간 채팅 감사가 있다 → 새 2부에서 확정 → 그 판매의 실시간 채팅 감사가 없다.
- 확인: E2E(가짜 유튜브 묶음)

### AC-I3-11 [web] 자동 게시 동의 켜기
- 근거: YT-04 AC2, D-Y02, D-Y12, D-Y1-05, D-I3-03
- Given 연결됨, 실시간 채팅 자동 게시 꺼짐
- When "실시간 채팅 자동 게시 켜기"
- Then 설명 창: 구매 감사 메시지를 내 채널 이름으로 실시간 채팅에 자동으로 남긴다는 문장, "동의한 뒤에 확정된 판매부터 남기고, 그 전 판매는 남기지 않아요.", 그 전 판매는 감사 메시지 목록에서 하나씩 보낼 수 있다는 문장, 구글 화면에서 글쓰기 권한을 한 번 더 허락해야 할 수 있다는 문장. 버튼 "동의해요"·"닫기", 처음 포커스는 "닫기". "닫기"·Esc면 아무 요청도 보내지 않는다.
- Then "동의해요"면 `PUT /api/youtube/consent { target: 'LIVE_CHAT', enabled: true }` — `{ connection }`이면 바로 켜짐과 켠 때("10월 25일 오후 8:01에 동의함", KST)를 보인다. `{ authorizeUrl }`이면 최상위 이동하고, 가짜 승인 뒤 돌아오면 켜져 있다. 구글에서 거절하고 돌아오면 꺼진 그대로이고 결과 문장(AC-I3-02)을 보인다.
- Then "영상 댓글 자동 게시 켜기"도 같다(설명 창의 대상 낱말만 "방송 영상 댓글로"). 두 대상은 따로다.
- Then 연결 안 됨·준비 안 된 서버면 켜기 버튼이 잠기고 "유튜브를 먼저 연결해 주세요."(준비 안 된 서버는 AC-I3-01 문장).
- 확인: E2E(가짜 — 게시 권한 없음 → 승인 → 켜짐, 게시 권한 있음 → 바로 켜짐, 거절)

### AC-I3-12 [web] 자동 게시 동의 끄기

### AC-I3-13 [web] 대상마다 요약 한 줄

### AC-I3-20 [web] 콘솔 유튜브 칸이 보이는 때

### AC-I3-24 [web] 수집 상태

## HG-3 확인 목록 (I3 화면) — 사람 확인, 최종 보고에서

Y1의 "HG-3 확인 목록"(`harness/sprints/Y1/acceptance.md`)에 화면 항목을 더한다. 사용자의 구글 계정·구글 클라우드 프로젝트(D-019)와 배포한 서버(https)가 필요하다. 약 40분.

1. **배포**: 컨테이너를 업체에 올리고(D-001) `/health/ready` 200 → 로그인 → 시작 마법사가 처음 한 번 뜨는지 → 다섯 단계를 끝까지(프린터 단계는 I1을 합친 뒤라면 실제 연결).
2. **연결 화면**: 설정 → 유튜브의 권한 안내 문장과 구글 동의 화면이 맞는지(읽기만), 돌아온 뒤 "유튜브 채널을 연결했어요." 구글 동의 화면의 개인정보처리방침·약관 주소가 `/privacy`·`/terms`로 열리는지.
3. **자동 게시 동의**: 설명 창 → 구글 글쓰기 권한 → 켜짐. 동의하기 전 판매는 자동으로 안 나가고 목록에서 하나씩 보낼 수 있는지. 요약 한 줄이 실제 동작과 맞는지.
4. **잇기·수집**: 콘솔에서 내 라이브 목록·주소 붙여넣기 둘 다, 예정 방송은 "유튜브 방송이 시작되면 채팅을 받아요."였다가 시작하면 바뀌는지. 구글 계정에서 앱 권한을 거두면 콘솔 고정 영역에 "유튜브 채팅을 받지 못하고 있어요 — 유튜브 연결을 다시 해 주세요."가 뜨고 "다시 연결하기"로 돌아오는지.
5. **감사 실패**: 일부러 채팅을 끈 뒤 판매 → "감사 실패" → 다시 보내기. 확인하지 못한 감사 문장("이미 올라갔을 수 있어요")이 실제 상황에서 이해되는지, "유튜브에 올라가 있어요"가 알림을 지우는지.
6. **사용량**: 설정의 숫자가 구글 클라우드 콘솔과 대체로 맞는지, "한국 시간 … 다시 채워져요" 시각이 맞는지.
7. **보조자**: 설정에서 보조자를 만들어 휴대폰으로 로그인 → 문자찜 입력만 되는지, 지우면 바로 로그아웃되는지.
8. **판단**: 알림 띠에서 세지 않는 실패(동의 안 함·방송 안 이음), 봉인 7일 전 경고, 마법사 자동으로 여는 조건, 보조자 권한 중 바꾸고 싶은 것. 개인정보처리방침·약관 초안의 법률 검토(D-012).
