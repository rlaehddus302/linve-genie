# KP1 test-notes (e2e)

폴더 `tests/e2e/kp1/`에 40건이 있다(크로미움 기본 묶음, PC 1280px와 375px). 그중 39건이 통과하고 1건(TE-KP1-001)이 실패한다.
실행 명령:
`cd apps/web && E2E_ONLY=chromium E2E_PORT_OFFSET=300 pnpm exec playwright test kp1 --workers=1`

- 장부와 손님 기록은 판매자의 모든 실제 날짜를 넘어 모인다. 그래서 시험마다 새 판매자(`/_e2e/sellers`)로 시작한다.
- 실제 날짜의 유튜브 구매자는 시험 모드 경로 `POST /api/deposits/test/chat`로 만든다(CRM1 도우미).
- 구매자 링크(`/r/…`)와 공개 페이지(`/s/…`)는 로그인하지 않은 새 브라우저 문맥으로 연다.
- 실제 유튜브와 실제 문자는 쓰지 않는다. 시간에 기대어 기다리는 곳은 없다.

## 실패 시험 (버그)

- **TE-KP1-001** (minor, category test/ux, area web)
  - 관련: AC-KP1-21, SCH-02
  - 파일: `apps/web/e2e/serve.ts:50`, `apps/web/vite.config.ts:18`
  - 무엇이 틀렸나:
    - 설정 "방송 일정"에서 공개를 켜면 `/s/<토큰>` 주소(앱 출처)가 보인다.
    - 그런데 E2E 기본 묶음의 화면 미리 보기 서버와 개발 서버(`vite`)의 프록시는 `/api`·`/r`만 서버로 넘기고 `/s`를 넘기지 않는다.
    - 그래서 판매자가 받은 주소를 열면 공개 일정 페이지 대신 앱 첫 화면(라이브지니 소개·로그인)이 열린다.
  - 재현: `tests/e2e/kp1/schedule.spec.ts` "TE-KP1-001: …"
    - 설정에서 켠다.
    - 보이는 주소를 로그인 없는 휴대폰에서 연다.
    - 본문에 가게 이름이 없다(실패).
  - 기대: 그 주소가 서버의 공개 페이지로 간다. `^/s(/|$)` 프록시 한 줄이면 된다.
  - 운영(서버가 `LIVEJJIM_WEB_DIR`로 화면을 같은 출처에서 낼 때)에서는 `/s`가 화면보다 먼저 등록되어 맞게 열린다. 서버 주소로 바로 연 시험은 모두 통과한다.
  - 그래서 운영 사고는 아니다. 다만 개발 서버와 E2E 기본 묶음에서는 판매자가 받은 주소가 열리지 않는다.
  - 덧붙임: 서비스 워커(`apps/web/pwa/service-worker.ts:78`)는 `/r`만 제외한다. 앱을 설치한 판매자가 오프라인에서 자기 공개 주소를 열면 앱 껍데기가 뜬다(nit, 시험 없음).

## 스펙 확인 필요 (시험 없음)

- **TE-KP1-002** (spec, minor) — 링크 화면의 "배송지를 받았어요" 칸은 PC-3 그대로 받는 분 이름 전체를 보인다(예: "받는 분 홍길동 · 연락처 끝 5678"). 바로 아래 장부 칸은 "홍\*동"으로 가린다. 한 화면에 가린 이름과 전체 이름이 함께 나오므로, 링크가 남에게 넘어갔을 때 가리는 의미가 없다(CR-2 "링크가 남에게 넘어가도"). 계약서 §7-1에 이미 적힌 것과 같다. PC-3도 가릴지 spec-keeper가 정해야 한다. 지금 시험은 장부 칸만 본다.

## 기타

- 공개 켜기 칸은 서버 응답 뒤에 바뀌는 제어 칸이다. 그래서 Playwright `check()`는 "상태가 바뀌지 않았다"고 실패한다. 시험은 누른 뒤 결과 문장을 기다린다(제품 결함 아님).
- AC-16의 "보조자 403", AC-19의 "보조자 403", AC-26·27·28(노출·판정 영향)은 서버 단위 시험과 `tests/adversarial/kp1/**`이 맡는다.
- AC-21의 "1분 60번", AC-22의 신청 한도·저장 내용도 서버 단위 시험과 도메인 시험이 맡는다. E2E는 신청·그만 받기 뒤의 수만 본다.
- 리허설 묶음에는 링크를 만들 수 없다(409 "리허설 방송은 공유 링크를 만들지 않아요."). 그래서 AC-02의 리허설 경우는 링크를 만들 때 409인지로 본다. 봉인 날짜 묶음의 칸 없음은 도메인 시험이 맡는다.
