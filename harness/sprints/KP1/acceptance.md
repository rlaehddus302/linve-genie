## 수용 기준

### 골든 (server)

**AC-KP1-01** [server] 골든 셋 그대로
- When 서버 단위 시험이 `customers/`·`message/`·`report/`의 모든 `*.json`을 읽어 같은 이름의 순수 함수로 돌린다
- Then 137사례 모두 `out`과 깊은 같음(TZ를 바꿔도). 시험은 폴더별 파일 수·사례 수(4·44, 4·57, 5·36)를 고정값으로 단언하고, 모르는 `kind`·키·중복 ID는 실패
- 확인: 단위(골든)

### 손님 장부 — 동의 (server·web)

**AC-KP1-02** [server][web] 동의 칸 보이기
- Given 실제 날짜 묶음, 품목 있음, 배송비 예외 없음, 구성원 중 유튜브 구매자 하나
- When 구매자가 확인서 링크를 연다 Then 배송지 양식 아래 빈 체크 칸과 `CR-CONSENT-2` 글(`{기간}` = 지금 설정 "1년", D-KP1-46 — "고르면 받는 분·연락처·주소를 30일 뒤에 지우지 않고"로 시작)
- Given 직접 수령·합배송·품목 없음·리허설·봉인 날짜·표지 없는 묶음(전화번호 없는 문자 구매자만) Then 칸이 없다
- 확인: 단위 + [e2e]

**AC-KP1-03** [server] 고르고 저장
- When 칸을 고르고 배송지를 저장 Then 같은 트랜잭션에서 장부 줄(표지 = 구성원 표지)이 생기고 연락처 다섯 칸(배송 메모 없음)이 암호화되어 있고, 동의 기록 `AGREE`(문구 판·12개월·경로 `RECEIPT_LINK`+날짜, 개인정보 없음)
- When 칸을 고르지 않고 저장 Then 장부는 그대로(새로 생기지도 지워지지도 않는다), 묶음 배송지는 PC-3대로
- When 표지 A·B를 가진 두 줄이 있는데 합친 묶음(A·B 구성원)에서 고르고 저장 Then 한 줄로 합쳐진다(먼저 만든 ID, 표지 A∪B), 연락처는 이번 값
- 확인: 단위

**AC-KP1-04** [web] 판매자는 대신 적을 수 없다
- 판매자 묶음 자세히의 배송지 저장에는 동의 칸이 없고 저장해도 장부가 생기지 않는다. 장부를 만드는 판매자 API가 없다
- 확인서 링크에서 동의 칸을 골라 저장한 요청에 그 가게 판매자(또는 보조자)의 유효한 로그인 쿠키가 함께 오면 배송지는 PC-3대로 저장되지만 장부 줄·동의 기록은 생기지 않고 "판매자 로그인 화면에서는 손님 대신 동의할 수 없어요."(D-KP1-23)
- 확인: 단위 + [e2e]

**AC-KP1-05** [web] 이미 저장한 손님
- 링크에 "저장해 둔 배송지가 있어요 (받는 분 홍*동 · 연락처 끝 5678)"와 [저장한 정보 지우기]. 주소 원문은 링크에 없다
- 확인: [e2e]

### 손님 장부 — 지우기 (server)

**AC-KP1-06** [server] 지우는 날
- Given 마지막 주문 2026-01-31, 동의 24개월, 설정 12개월 Then 지우는 날 2027-01-31, 그날 00:00 KST가 지난 첫 정리(시작 때·1시간마다)에서 줄·표지·연결 코드가 사라지고 동의 기록 `EXPIRE`
- When 설정을 6개월로 줄인다 Then 다음 정리에서 이미 지난 줄은 바로 지운다
- [web][server] When 판매자가 설정에서 1년 → 6개월로 바꿔 저장하고 새 기간으로 지울 줄이 2개 Then 저장 전에 "지금 줄이면 손님 2명의 저장한 배송지가 1시간 안에 지워져요. 되돌릴 수 없어요." [줄이기]·[그대로 두기] 창, [그대로 두기]면 설정은 1년 그대로. 지울 줄이 0개이거나 기간을 늘리면 창 없이 저장(D-KP1-45)
- Given 그 판매자의 봉인 장부 하나를 못 읽는다 Then 그 회차 정리는 그 판매자의 장부를 지우지 않고(운영 경보 로그 개수만) 읽게 된 뒤 정리에서 지운다(D-KP1-28)
- 확인: 단위(가짜 시계, `retention.json` 값으로)

**AC-KP1-07** [server][web] 손님·판매자 지우기
- 링크 [저장한 정보 지우기] → 확인 → 바로 지움 + "지웠어요."(`WITHDRAW`). 판매자 손님 자세히 "저장한 배송지" 칸 [저장한 배송지 지우기] → 확인 → `SELLER_DELETE`(판매자 화면 글에 "장부" 낱말 없음, D-KP1-47). 묶음 배송지와 동의 기록은 그대로
- 확인: 단위 + [e2e]

### 손님 장부 — 다음 주문에 보이기 (server·web)

**AC-KP1-08** [server][web] "확인 전"으로 보이기
- Given 장부 줄(유튜브 UC_A)이 있고 새 날짜에 UC_A 묶음(품목 1, 배송지 없음)
- Then 판매자 묶음 자세히에 "지난 주문 배송지예요 — 확인해 주세요" + 다섯 칸, 택배 접수 판단의 배송지 상태 `UNCONFIRMED`(PC-4), 구매자 링크엔 "지난번 배송지로 보낼게요 (받는 분 홍*동 · 연락처 끝 5678)…"
- When 판매자가 [배송지 확인] Then 그 묶음 배송지(출처 장부 확인, 확인함)로 저장되어 출처 글이 "손님이 지난번에 적은 배송지 · 판매자가 확인함"(새로 고쳐도 같음, "판매자가 적었어요" 아님 — D-KP1-44)이고 그 뒤 장부를 바꿔도 묶음 배송지는 그대로
- When 확인 전에 장부를 지운다 Then 보이던 칸이 바로 사라진다(복사하지 않았다)
- Given 구성원 표지가 서로 다른 장부 줄 둘에 걸친 합친 묶음 Then 보이지 않는다
- 확인: 단위(`prefill.json`) + [e2e]

### 연결 코드 (server·web)

**AC-KP1-09** [server] 코드 받기
- 장부 줄이 있는 손님 링크의 [다른 계정도 잇기] → 48낱말 중 서로 다른 두 낱말 코드, 그 판매자의 살아 있는 코드·끝난 지 24시간 안 된 코드와 겹치지 않음(D-KP1-26), 24시간, 새로 받으면 전 코드는 없어짐
- 끝난 코드 행은 표지·화면 이름·끝 4자리가 바로 비고, 끝난 지 24시간 지난 행은 정리에서 지워진다(D-KP1-27)
- 확인: 단위

**AC-KP1-10** [server] 채팅에서 읽기
- Given 살아 있는 코드 "구름 바다", 번호 방송 When 채팅 "구름바다" / "구름 바다!" / 옵션 방송의 "구름 바다" / 리허설 / 방송자 글
- Then 첫째만 코드(그 채팅의 표지·화면 이름을 "확인 기다림"으로), 나머지는 아니다. 그 채팅은 판정에서 주문·취소·언급이 아니다(이벤트는 다른 채팅과 똑같이 기록)
- And 코드는 한 번만 — 다음 채팅이 같은 코드를 쳐도 붙지 않는다. 코드 글·채팅 본문은 로그에 없다
- 확인: 단위(`code.json`) + [domain]

**AC-KP1-11** [server][web] 손님 확인
- 링크에 "유튜브 '홍길동'(끝 1234)이 코드를 쳤어요. 내 계정이 맞나요?" — [네] Then 그 표지를 이 줄에 더한다. 그 표지가 이미 다른 장부 줄에 있으면 붙이지 않고 코드를 끝내며 "이 계정은 이을 수 없어요." — 다른 줄은 그대로(D-KP1-24). [아니에요] Then 버리고 코드 끝. 24시간 안에 확인하지 않으면 버림
- And 손님 기록(BUY-06) "모든 손님"은 그대로 두 줄이다(합치지 않음). 판매자 손님 자세히에 "이 손님이 직접 이은 계정: …" 한 줄
- 확인: 단위 + [e2e]

### 손님 엑셀 (device·server·web)

**AC-KP1-12** [device][server] 기본 열
- "모든 손님"의 [엑셀로 받기] → `손님-YYYY-MM-DD.xlsx`, 시트 "손님", 누적 큰 순 전부(거르기와 상관없이), 기본 열 9개(CR-6). 금액은 숫자 칸 정수
- When 이름이 `=1+1`·`@SUM` Then 칸 글은 `'=1+1`·`'@SUM`. 제어 글자는 빠진다
- 확인: 단위(문서 패키지)

**AC-KP1-13** [web][server] 연락처 열은 고를 때만
- 처음엔 빈 "연락처·주소도 넣기". 고르면 경고 한 줄과 함께 받는 분·연락처·주소·상세 주소·우편번호·보관 끝나는 날 열이 더해진다. 받을 때마다 서버 기록(누가·언제·연락처 포함 여부, 파일 내용 없음)
- 확인: 단위 + [e2e]

### 콘솔 손님 표시 (server·web)

**AC-KP1-14** [server][web] 꼬리표
- Given 설정 "방송 화면에 손님 표시"가 정해지지 않음(처음) Then 꼬리표·1등 옆 "입금 늦음 주의" 없음(D-KP1-43)
- Given 설정이 "보이기", 실제 방송, 채팅 손님 A(입금 늦음 주의), B(단골, 누적 125,000원), C(앞선 실제 날짜 기록 없음), D(앞선 기록 있음·단골 아님) Then 줄 이름 뒤 "입금 늦음 주의"·"단골 · 누적 125,000원"·"처음"·없음. 화면 읽기 "손님: 단골, 누적 125,000원"
- Given 리허설 Then 꼬리표 없음
- 확인: 단위(`badge.json`) + [e2e]

**AC-KP1-15** [web] 끄는 설정
- Given 설정이 정해지지 않은 판매자 When 실제 방송 콘솔을 연다 Then "방송 화면에 손님 표시를 보일까요? 이 화면을 방송에 내보내면 손님도 볼 수 있어요." [보이기]·[안 보이기]를 한 번 묻고, 답하기 전엔 꼬리표·1등 옆 주의가 없다(D-KP1-43)
- When [보이기] Then 꼬리표가 나오고 설정 화면도 켜짐, 콘솔을 다시 열어도 묻지 않는다. When [안 보이기] Then 꼬리표 없음, 다시 묻지 않는다. When 답 없이 닫음 Then 숨긴 채, 콘솔을 다시 열면 또 묻는다. 리허설 콘솔은 묻지 않는다
- 보이기로 정한 뒤 설정에서 끄면 채팅 꼬리표와 1등 옆 "입금 늦음 주의"가 바로 모두 사라진다. 설명 문장이 보인다
- 확인: [e2e]

**AC-KP1-16** [server][web] 받기 간격
- 콘솔은 새 채팅 구매자를 모아 4초 이상 간격으로 50명씩 묻고, 받은 구매자는 다시 묻지 않는다. 조회가 실패하면 꼬리표 없이 그대로(오류 띠 없음). 보조자 403
- 확인: 단위 + [e2e](요청 수 셈)

### 방송 리포트 (server·web)

**AC-KP1-17** [server] 계산 범위
- 리포트 = 실제 날짜 하나의 모든 회차, 리허설 묶음·찜 없음. 볼 때 계산(입금을 더 적으면 받은 돈이 바로 는다). 봉인 날짜: 돈·손님·품종은 봉인 장부 값, 시간대·몰린 상품은 "보관 기간이 지나 볼 수 없어요."
- 확인: 단위 + [domain](봉인 날짜)

**AC-KP1-18** [server] 숫자 맞음
- 판매대장(STL-06)의 같은 날짜 상품 합계·수량 합과 리포트 판매 금액·수량이 같다(배송비·조정 빼고). 받은 돈은 정산 화면의 받은 금액 합과 같다
- 확인: 단위 + [domain](임의 기록 속성 시험)

**AC-KP1-19** [web] 화면
- 순서 돈 → 손님 → 비교 → 몰린 상품 5개 → 품종 10개(더 보기) → 시간대 막대. 375px에서 가로로 넘치지 않음. 손님 이름·연락처 없음. 앞선 방송이 없으면 "처음 방송이라 비교할 게 없어요". 방송 중엔 "방송 중이라 숫자가 바뀌고 있어요"
- 볼 곳: 정산 화면 날짜의 "방송 리포트", 방송을 끝낸 콘솔의 "오늘 리포트 보기". 보조자 403
- 확인: [e2e] + [ux]

### 방송 일정·알림 받기 (server·web)

**AC-KP1-20** [server][web] 일정 적기
- 날짜·시각·제목(1~40)·소개(0~100) — 다가오는 일정 11번째는 "다가오는 방송은 10개까지 적을 수 있어요." 휴대폰 번호 모양은 받지 않는다(R-1 문장)
- 확인: 단위 + [e2e]

**AC-KP1-21** [server] 공개 페이지
- 켜면 `/s/<토큰>`(로그인 없음): 가게 이름·다가오는 일정(지난 것 빠짐)·채널 주소. 손님·판매 정보 없음, `noindex`, `Referrer-Policy: no-referrer`, 스크립트 없음, 접속 주소(IP)마다 1분 60번(토큰 전체 1분 3,000번 상한, D-KP1-22) — 한 주소가 막혀도 다른 주소는 열린다. 다시 만들면 옛 주소 404, 끄면 404
- 확인: 단위 + [e2e]

**AC-KP1-22** [server] 알림 받기 신청
- 번호 + 빈 필수 체크 — 체크 없이 보내면 저장 안 함("알림 받기에 동의해 주세요."). 휴대폰 번호가 아니면 저장 안 함. 저장하면 `AGREE`(문구 판 `MR-CONSENT-1`, `SCHEDULE_PAGE`), 상태 `PENDING`, 화면 "{가게} 방송 알림을 신청했어요 (2026-10-31)."
- 알림 양식에 "아직 문자를 보내지 않아요. 보내기는 준비 중이에요." 한 줄(동의 칸 글 밖, D-KP1-48)
- "그만 받기"에 번호 → `WITHDRAW`, 그 번호 원문·키를 바로 지움, "… 그만 받아요 (날짜)." 없는 번호여도 같은 문장(있는지 알려 주지 않음)
- 같은 접속 주소(IP)에서 1분 10번 넘으면 막음 — 다른 주소의 신청은 막히지 않는다(D-KP1-22). 그 가게 판매자·보조자 로그인 쿠키가 함께 온 신청은 저장 안 함(D-KP1-23). 번호 원문은 암호화, 로그·응답에 없음
- 확인: 단위 + [domain]

**AC-KP1-23** [web] 판매자에겐 수만
- 설정 "방송 알림": 번호 확인 전(`PENDING`, D-KP1-48)·받는 중(`ACTIVE`)·그만 받음 수, 칸에 "아직 문자를 보내지 않아요. 보내기는 준비 중이에요." 한 줄. "신청 기다림" 글 없음. 번호 목록·내려받기·대신 넣기 없음
- 확인: [e2e]

**AC-KP1-24** [server] 아무것도 보내지 않는다
- KP1 서버에 문자·알림톡을 보내는 코드 경로가 없다 — 바깥 연결(가짜 솔라피 포함) 0번. `consent` 함수로 상태를 정하고 기한(`EXPIRED`)이 된 신청은 그날 0시 KST 뒤 첫 정리에서 지운다
- 확인: 단위 + [domain]

### 메시지 규칙 (server)

**AC-KP1-25** [server] 순수 함수 넷

- 확인: 단위

### 노출·개인정보 (domain)

**AC-KP1-26** [server][domain] 판매자만·판매자마다
- 장부·연결 코드·손님 표시·손님 엑셀·리포트·일정 설정·동의 수 경로: 로그인 없음 401, 보조자 403, 다른 판매자 것 404, `Cache-Control: no-store`
- 판매자 A의 장부·동의는 판매자 B의 어떤 화면·조회·꼬리표에도 나오지 않는다(같은 사람이 두 가게에서 사도)
- 확인: 단위 + `tests/adversarial/kp1/**`

**AC-KP1-27** [domain] 새는 곳 없음
- 확인서·확인서 링크(이름 가운데 `*`·끝 4자리 밖)·라벨·감사 메시지·판매대장·판매자 백업·"전체 기록 내려받기"·서버 로그에 장부 연락처·표지 값·코드 글·동의 번호가 없다. 운영자 복구 뒤에도 장부는 그대로이고 다른 사람을 가리키지 않는다
- 확인: `tests/adversarial/kp1/**`

**AC-KP1-28** [domain] 판정 영향 없음
- 같은 채팅 기록에 장부·연결 코드·손님 표시를 켜고 끈 두 실행의 엔진 상태(1등·대기·금액·발송함)가 같다
- 확인: `tests/adversarial/kp1/**`
