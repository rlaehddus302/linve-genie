# KP1 dev-notes

## dev-web 갈래 D — 방송 리포트·방송 일정·방송 알림

만든 것: `apps/web/src/lib/{report,schedule}.ts`, `components/{ReportPage,ScheduleSettings,AlertCounts}.tsx`, `components/kp1-report.css`(공용 styles.css를 건드리지 않으려 따로 둠), 시험 `apps/web/test/kp1-report-schedule.test.tsx`.
붙인 줄: `lib/router.ts`(`/report?date=` — 메뉴는 정산), `App.tsx`(경로 하나), `SettlementsPage.tsx`(날짜 줄 "방송 리포트" — 실제 범위만), `ConsolePage.tsx`(끝낸 실제 방송의 "오늘 리포트 보기"), `SettingsPage.tsx`("방송 일정"·"방송 알림" 절 — 판매자만).

가정
- 리포트 주소에 날짜가 없으면 정산 화면으로 안내만 한다("볼 날짜가 없어요. …"). 오늘 날짜로 짐작해 열지 않는다.
- 비교 문장: 평균 쪽은 "최근 N번 평균보다 …원 많아요/적어요", "…과 같아요". 개수 단위 "개", 손님 "명".
- 몰린 상품 줄은 "N번 이름"만 쓴다 — 하루에 회차가 둘 이상이면 번호가 겹칠 수 있다(응답에 회차 이름이 없음). 필요하면 서버가 회차 이름을 주도록 계약을 늘려야 한다.
- 시간대 칸이 자정을 넘기면 "다음날 00:00~00:10"으로 적는다. 막대 길이는 칸의 판매 금액 기준, 막대는 화면 낭독기에서 숨기고 같은 줄 글("20:00~20:10 · 3개 · 15,000원")로 읽힌다.
- 방송 중 리포트는 저절로 새로 받지 않고 "새로 보기" 버튼으로 다시 받는다(숫자가 눈앞에서 바뀌어 헷갈리지 않게).
- 일정 제목·소개 칸은 화면이 길이를 자르지 않는다(maxLength 없음, "12/40자" 글자 수만). 41자도 보내 서버 문장을 보인다.
- 다가오는 일정이 10개면 적기 양식 위에 "다가오는 방송은 10개까지 적을 수 있어요."를 미리 보이되 버튼은 막지 않는다(누르면 서버 409 문장, 같은 문장 두 번 안 보임).
- 일정 지우기·새 주소 만들기는 확인 창을 한 번 띄운다. 공개 끄기는 바로 하고 "전에 알려 준 주소는 이제 열리지 않아요."를 보인다.

앱(apps/mobile): 정산·리포트 화면이 없어 리포트 링크는 붙이지 않았다. 설정 화면(`src/screens/SettingsScreen.tsx`)에 "방송 일정"·"방송 알림"은 아직 없다 — 웹 설정에서만 한다(이번 갈래 범위 밖으로 남김).
