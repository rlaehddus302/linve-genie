- 공통 전제: 지금까지의 결과(`pnpm verify` 7단계 — typecheck·lint·test·golden·adversarial·coverage·e2e, 골든 러너, 코어 순수성 린트, 서버 저장·API·SSE·로그인·리허설·증분 조회·출력 기록, 화면)가 그대로 유지된다. 외부 계정·실기기·도커·인터넷은 필요 없다. 시계·타이머·난수는 주입해 시험한다(다시 시도·기한·확인 시간은 주입한 시계로 빠르게 돈다). E2E가 도는 명령엔 `E2E_PORT_OFFSET=1100`.

- 이 문서가 따옴표로 정한 판매자에게 보이는 문장(오류·상태·알림)은 서버가 그대로 돌려준다(화면이 글자로 쓴다, UX-01·UX-03). 프로그램이 읽는 값은 영문 코드로 함께 준다. 바꿔야 하면 dev-notes에 이유를 남기고 spec-keeper가 판정한다.
- 메타 API의 세부(권한 이름·주소·오류 코드)는 2026-10 메타 문서 기준의 **기본값**이고 설정이나 어댑터 안에 둔다 — 메타가 이름을 바꿔도 판정·기록 규칙은 바뀌지 않는다. 시험은 가짜 메타 서버가 같은 모양으로 답하는 것을 기준으로 한다.

## A. 플랫폼 공통 연결 (PLT-03, D-N2-02·D-N2-05·D-N2-08·D-N2-12)

### AC-N2-01 [server] 플랫폼 값과 키 접두어
- 근거: PLT-03, R-11, D-N2-02
- Then 플랫폼은 `YOUTUBE`·`INSTAGRAM`·`TIKTOK` 셋이다. 서버 함수 하나가 구매자(채널) 키 → 플랫폼을 정한다: `ig:`로 시작 → `INSTAGRAM`, `tt:` → `TIKTOK`, `sms:` → 문자 구매자(플랫폼 없음), 그 밖 → `YOUTUBE`(리허설 가짜 채널 `sim_…`도 — D-082).
- Then 인스타 수집이 적는 키는 늘 `ig:` + 메타가 준 값 그대로다(IGSID·댓글 ID를 자르거나 바꾸지 않는다). 메타가 준 값이 비었거나 접두어를 붙여 256자를 넘으면 그 댓글은 기록하지 않고 형식 틀린 변경으로 센다(AC-N2-35).
- 확인: 단위 시험(표: `ig:6024400000000001`·`ig:01012345678`·`tt:1`·`sms:s1`·`UC_A`·`sim_a1`)

### AC-N2-02 [server] 플랫폼 능력 조회
- 근거: PLT-03, D-N2-05, D-N2-11, D-N2-12
- Then 로그인한 판매자는 플랫폼마다 할 수 있는 것을 조회한다: `platform`, `ready`(이 서버에서 지금 연결할 수 있는지), `receivedTime`(실제 시각순을 쓸 수 있는지), `thanks`(`PUBLIC_CHAT` 공개 채팅 / `DM_PER_COMMENT` 댓글마다 DM 한 번 / `NONE`), `videoComment`(영상 댓글·요약), 그리고 쓸 수 없는 것마다 이유 문장.
- Then 값: `YOUTUBE` = receivedTime 예·thanks `PUBLIC_CHAT`·videoComment 예·ready 아니오(이 바탕엔 유튜브 연동이 없다 — 합칠 때 Y1이 정한다). `INSTAGRAM` = receivedTime 아니오(이유 "인스타그램 라이브는 댓글마다의 시각이 없어 실제 시각순으로 판정할 수 없어요.")·thanks `DM_PER_COMMENT`·videoComment 아니오·ready = 설정이 있으면 예(AC-N2-17). `TIKTOK` = ready 아니오(이유 "틱톡 라이브는 아직 지원하지 않아요.")·thanks `NONE`.
- 확인: 통합 시험

### AC-N2-03 [server] 한 회차에 플랫폼 하나 — 잇기 공통 규칙
- 근거: PLT-03, YT-09 AC1, R-0 6, DAT-05, D-081, D-N2-08
- Then 회차 b의 라이브 연결을 조회한다: `platform`(없으면 null), `state`(`NONE` 없음 · `WAITING` 기다리는 중 · `LINKED` 이어짐), `liveId`(인스타 미디어 ID — `LINKED`일 때), 이은(기다리기로 정한) 시각·조치자(판매자 계정 또는 서버), 이을 때 연결돼 있던 인스타 계정 ID.
- Then 회차마다 끊지 않은 연결(`WAITING`·`LINKED`)은 하나뿐이다 — 데이터베이스 유일 제약(판매자, 회차, 끊지 않은 것). 같은 회차에 두 요청이 동시에 와도 하나만 받는다(시험).
- Then 받지 않는 경우(아무것도 바꾸지 않고 코드와 문장):
  - 다른 판매자의 회차·없는 회차: 404(있는지 알리지 않는다)
  - 리허설 회차: `REHEARSAL` "리허설 방송에는 라이브를 이을 수 없어요."
  - 끝난 회차(`broadcast.end` 기록됨): `ENDED` "끝난 방송에는 라이브를 이을 수 없어요."
  - 이미 끊지 않은 연결이 있음(같은 플랫폼이어도): `ALREADY_LINKED` "이 방송에는 이미 라이브가 이어져 있어요. 먼저 연결을 끊어 주세요."
- Then 잇기·기다리기·끊기는 엔진 이벤트가 아니다 — 그 범위의 이벤트 기록·`seq`가 그대로다. 누가·언제는 서버 기록에 남는다(DAT-05). 같은 요청 번호로 두 번 보내도 한 번만 한다.
- 확인: 통합 시험

### AC-N2-04 [server] 틱톡 자리

### AC-N2-10 [server] 연결 시작 — 승인 주소 (어댑터 둘)
- 근거: PLT-01, D-074, D-N2-06
- Given 로그인한 판매자(세션), 설정 있음(AC-N2-17)
- When 연결을 시작한다(상태를 바꾸는 요청 — `Origin` 검사·JSON, D-074)
- Then 로그인 방식은 설정(기본 `FACEBOOK`, 다른 값 `INSTAGRAM`)이고 승인 주소를 돌려준다: 앱(클라이언트) ID, 설정에 고정한 돌아오는 주소 하나, `response_type=code`, `state`(무작위 32바이트 이상), 권한 목록. 권한 목록의 기본값(설정으로 바꿀 수 있음):
  - `FACEBOOK`(페이스북 로그인): `instagram_basic`, `instagram_manage_comments`, `instagram_manage_messages`, `pages_show_list`, `pages_read_engagement`, `pages_manage_metadata`
  - `INSTAGRAM`(인스타그램 로그인): `instagram_business_basic`, `instagram_business_manage_comments`, `instagram_business_manage_messages`
- Then `state`는 그 로그인 세션에 묶여 서버에 저장되고(해시로) 10분 뒤 또는 한 번 쓰면 무효다. `state`·`code`는 승인 주소 밖 어디에도(응답의 다른 곳·로그·이벤트 기록) 남지 않는다.
- Then 이미 연결돼 있으면(연결됨·다시 연결 필요) 같은 시작이 다시 연결이다(같은 계정만 받는다 — AC-N2-11).
- 확인: 통합 시험(가짜 서버)

### AC-N2-11 [server] 돌아오기 — 토큰 받기·계정 확인
- 근거: PLT-01, SYS-02, D-N2-06
- Given AC-N2-10의 승인 주소로 가짜 메타에서 승인하고 돌아왔다(`code`, `state`)
- Then `state`가 그 세션의 것이고 10분 안이고 처음 쓰는 것일 때만 `code`를 토큰으로 바꾼다 — `FACEBOOK`: 짧은 사용자 토큰 → 긴 사용자 토큰 → 허락받은 페이지 중 인스타그램 프로페셔널 계정이 붙은 페이지와 그 페이지 토큰. `INSTAGRAM`: 짧은 토큰 → 긴 토큰(60일)·계정 정보. 인스타 계정 ID·username·계정 종류(비즈니스·크리에이터)·받은 권한(댓글 읽기·메시지 각각)을 저장하고 화면 주소로 돌려보낸다(결과는 코드로만 — 토큰·`code`는 주소에 넣지 않는다).
- Then 받지 않는 경우(토큰을 저장하지 않고 화면 주소로 돌려보내며 코드와 문장):
  - `state`가 없음·다름·10분 지남·이미 씀·다른 세션: `STATE_INVALID` "연결 시간이 지났어요. 다시 시도해 주세요."
  - 사용자가 거절: `DENIED` "인스타그램 연결을 허락하지 않았어요. 다시 시도해 주세요."
  - 허락받은 프로페셔널 계정이 없음(개인 계정·페이지에 계정이 안 붙음 포함): `NO_ACCOUNT` "연결할 수 있는 인스타그램 프로페셔널(비즈니스·크리에이터) 계정이 없어요."
  - 둘 이상: `MANY_ACCOUNTS` "인스타그램 계정을 하나만 골라 다시 연결해 주세요."
  - 댓글 읽기 권한을 빼고 허락: `NO_COMMENT_PERMISSION` "댓글을 읽는 권한을 허락해야 연결할 수 있어요. 다시 연결해 주세요."
  - 그 계정이 이미 다른 판매자에 연결됨: `ACCOUNT_TAKEN` "이 인스타그램 계정은 연결할 수 없어요. 운영자에게 문의해 주세요."(다른 판매자를 알리지 않는다)
  - 이 판매자가 이미 다른 계정에 연결됨(연결됨·다시 연결 필요 모두): `OTHER_ACCOUNT` "처음 연결한 계정과 달라요. 바꾸려면 먼저 연결을 끊어 주세요." — 같은 계정이면 받고 토큰·권한만 바꾼다(다시 연결)
  - 웹훅 구독 실패: AC-N2-12
- Then 메시지 권한만 빼고 허락했으면 연결은 되고 메시지 권한 없음으로 저장한다(DM 동의를 켤 때 다시 요청 — AC-N2-41).
- Then 같은 `code`·`state`로 두 번 와도 한 번만 처리한다.
- 확인: 통합 시험(가짜 서버 — 허락·거절·권한 빼기·계정 0/1/2개)

### AC-N2-21 [server] 인스타 라이브 잇기 조건 — 실제 시각순은 막는다
- 근거: PLT-01, PLT-03, ORD-09, R-6, D-070, D-N2-05, D-N2-08
- Given 연결됨, 회차 b
- When 미디어 M(목록에서 고름)으로 b에 잇는다
- Then 아래를 모두 만족할 때만 잇는다(하나라도 아니면 잇지 않고 코드와 문장):
  - AC-N2-03의 공통 조건(이 판매자의 회차·리허설 아님·끝나지 않음·끊지 않은 연결 없음)
  - b의 설정 스냅샷 `contention.policy`가 `ARRIVAL`: 아니면 `RECEIVED_TIME_NOT_ALLOWED` "인스타그램 라이브는 실제 시각순으로 판정할 수 없어요. 판매 규칙을 '접수순'으로 바꾼 뒤 새 방송을 시작해 주세요."
  - M이 연결한 계정의 진행 중 라이브(잇는 순간 `live_media`로 확인): 아니면 `NOT_LIVE` "진행 중인 내 인스타그램 라이브만 이을 수 있어요."
  - M이 끝나지 않은 다른 회차에 이어져 있지 않음: 아니면 `LIVE_TAKEN` "이미 다른 방송에 이어진 인스타그램 라이브예요." — 동시에 이어도 하나만
- Then 이은 시각(서버 시계)·이은 판매자 계정·그때의 인스타 계정 ID를 남긴다. 이은 뒤 도착한 M의 댓글부터 b에 기록한다(AC-N2-32). 이전에 온 댓글은 이미 기록하지 않았다(AC-N2-24).
- Then 시험: 판매 규칙을 `RECEIVED_TIME`으로 두고 시작한 회차(`broadcast.start` 스냅샷)에 잇기 → 거절, 연결 없음. 같은 날 `ARRIVAL` 회차에는 이어진다.
- 확인: 통합 시험(가짜 서버)

### AC-N2-22 [server] 인스타그램 기다리기 — 첫 댓글에 저절로 잇기
- 근거: PLT-01, PLT-03, D-N2-08
- When 판매자가 회차 b를 "인스타그램 기다리기"로 정한다(미디어 없이)
- Then 조건은 AC-N2-21에서 미디어 조건(`NOT_LIVE`·`LIVE_TAKEN`)을 뺀 것과 같고, 인스타 연결이 있어야 한다(연결됨·다시 연결 필요 — 없으면 `NOT_CONNECTED` "인스타그램 계정을 먼저 연결해 주세요."). 상태는 `WAITING`이다.
- Then 그 판매자의 연결 계정에서 끝나지 않은 회차에 이어지지 않은 미디어 M의 댓글 웹훅이 오면: 그 판매자의 `WAITING` 회차(끝나지 않은 것)가 **정확히 하나**이면 그 회차를 M에 잇고(조치자 서버, 이은 시각 = 그 웹훅을 처리한 시각, 그때의 인스타 계정 ID) 그 댓글부터 기록한다. 둘 이상이면 잇지 않고 기록하지 않으며 알림 `MANY_WAITING` "인스타그램을 기다리는 방송이 둘 이상이라 고르지 못했어요. 하나에 이어 주세요."(AC-N2-24처럼 센다).

- Then 그 댓글에 `SENT` 또는 `FAILED(UNCONFIRMED)` 행이 이미 있으면 새 행은 `FAILED(ONE_REPLY)` "이 댓글에는 이미 DM을 보냈어요. 댓글 하나에 DM은 한 번만 보낼 수 있어요. 인스타그램에서 직접 보내 주세요." — 자동·수동 모두 다시 보낼 수 없다. 보내는 중(`SENDING`) 행이 있으면 새 행은 그 결과를 기다린다(`WAITING`) — 결과가 `SENT`·`UNCONFIRMED`면 `ONE_REPLY`, 보내지 않음으로 끝나면 보낼 수 있다(기한은 그대로).
- Then 시험: (가) 댓글 하나 "15 28" → 가짜 서버 DM 1개(두 줄), 두 행 모두 `SENT`, 게시 보고 2개 (나) 같은 댓글 사람의 28번이 대기였다가 승계로 확정 → 새 행 `ONE_REPLY`, 가짜 서버 DM 그대로 (다) 첫 DM이 `REJECTED`로 끝난 댓글에서 나중 효과는 보낸다.
- 확인: 통합 시험

### AC-N2-44 [server] DM 글
- 근거: YT-04 AC1, R-13 감사 문구, D-N2-09

### AC-N2-45 [server] 보내기 직전 확인·상태·이유 문장
- 근거: R-13 "실행 직전에 찜이 더 이상 확정이 아니면 효과는 SKIPPED", D-N2-10
- Then 보내기 직전과 다시 시도 직전마다 모은 행마다 그 범위의 지금 엔진 상태에서 효과를 본다: 취소됐으면 그 행은 `SKIPPED(CANCELLED)` "확정이 풀린 판매라 보내지 않았어요."이고 빼고 글을 다시 만든다(남은 행이 없으면 보내지 않는다). 이미 완료(게시 보고 있음)면 `SENT`(보내지 않는다). 단 타임아웃 확인(AC-N2-48)은 그 시도에 실제로 보낸 글로 한다.
- Then 행의 상태는 `WAITING`(이유: 다시 시도 대기 `RETRY` · 다시 연결 필요 `RECONNECT` · 앞 DM 결과 기다림 `PREVIOUS`) · `SENDING`(이유 `CONFIRM` "보내졌는지 확인하는 중이에요." — 확인 중일 때) · `SENT` · `SKIPPED`(`CANCELLED`·`NO_RECIPIENT`·`NOT_SUPPORTED`) · `FAILED`(이유) 중 하나다. `FAILED` 이유 문장:
  - `NO_CONSENT` "자동 DM에 동의하기 전의 감사예요."
  - `NO_LINK` "이어진 인스타그램 라이브가 없어요."
  - `NOT_MY_ACCOUNT` "지금 연결한 인스타그램 계정의 라이브가 아니라 보내지 않았어요." — 그 회차를 이은 때의 인스타 계정과 지금 연결한 계정이 다름
  - `ONE_REPLY` (AC-N2-43)
  - `LIVE_ENDED` "인스타그램 라이브가 끝나 DM을 보낼 수 없어요."
  - `NO_PERMISSION` "DM을 보낼 권한이 없어요. 인스타그램 연결을 다시 해 주세요."
  - `EXPIRED` "너무 늦어 보내지 않았어요."
  - `GAVE_UP` "여러 번 보내지 못했어요."
  - `REJECTED` "인스타그램이 받지 않았어요."
  - `UNCONFIRMED` "보내졌는지 확인하지 못했어요. 인스타그램에서 확인하고 없으면 다시 보내 주세요."
- 확인: 통합 시험

### AC-N2-46 [server] 보냄과 게시 보고

### AC-N2-47 [server] 다시 시도
- 근거: YT-06, R-13, D-N2-10
- Then 다시 시도할 오류: 네트워크 오류, 5xx, 429, 메타 속도 제한·일시 오류, 보내지지 않은 것으로 확인된 타임아웃(AC-N2-48). 2·4·8·16·32초 뒤(주입한 시계) 최대 5번 다시 시도하고, 그래도 안 되면 `FAILED(GAVE_UP)`. 기다리는 동안은 `WAITING(RETRY)`.

- Then 메타 오류 코드 → 위 분류의 표는 dev-server가 dev-notes에 적고, 가짜 서버가 같은 코드로 오류를 낸다.
- 확인: 통합 시험(오류 주입·주입한 시계)

### AC-N2-48 [server] 타임아웃·서버 재시작 — 두 번 보내지 않음

## 합칠 때 맞출 것 (오케스트레이터 — 이 스프린트의 기준이 아니다, D-N2-01)

1. **유튜브 발송함 실행기(Y1)가 인스타 회차의 감사 행을 집지 않게** — Y1 실행기는 이어진 유튜브 방송이 없으면 `FAILED(NO_LINK)`로 바꾼다. 인스타 회차(플랫폼 `INSTAGRAM`)의 `POST_THANKS` 행을 Y1이 집으면 DM은 보냈는데 "감사 실패" 알림이 거짓으로 뜨고 발송함 행 상태가 둘이 된다. Y1 실행기의 행 고르기에 "그 회차의 플랫폼이 유튜브이거나 없음"을 더한다.
2. **한 회차 한 플랫폼에 `youtube_links` 넣기** — 유튜브 잇기(AC-Y1-12)와 인스타 잇기·기다리기(AC-N2-03)가 서로의 끊지 않은 연결을 보고 `ALREADY_LINKED`로 막는다. 플랫폼 능력 조회의 `YOUTUBE.ready`를 Y1 설정 여부로.
3. **이름 정리** — Y1 수집 함수의 이름 정리(D-Y05: `.` → `·` 등)를 인스타 경로에 적용하지 않는다(D-N2-03: username 그대로). 인스타 수집이 `ingestChat` 공통 경로를 탄다면 인스타 키(`ig:`)일 때 정리를 건너뛴다.
4. **채팅 원문 분리·30일 봉인(D-Y11)** — 봉인은 날짜 범위 단위라 같은 범위의 인스타 댓글 원문도 함께 지워진다. 판매 장부는 봉인된 상태로 남으므로 그대로 둔다(D-N2-14와 부딪치지 않는다 — 고정 기한을 두지 않았을 뿐 지우는 것을 막지 않는다).
5. **골든 합계·허용 목록·결정 표** — 러너 자체 시험 합계(AC-N2-81, Y1의 G-ENG-401·402·chat Y1 사례·다른 트랙과 더함), `known-unimplemented.yaml`의 `sprint`, DECISIONS "사용자 확인 필요" 표와 AUTO 범위.
6. **N4 carryOver** — 판매대장 채널 칸(STL-06, 문서 패키지)에 인스타그램 찜은 "인스타그램"(키 접두어, D-N2-15).

## 공격 관점 (test-domain 참고)

- 서명: 헤더 없음·대문자 16진·`sha1=`·길이 다름·다른 앱 시크릿·본문 한 바이트 바꿈·다시 직렬화한 본문, 1MB 경계, JSON 아님, 빈 본문.
- 테넌트: 다른 판매자 계정의 `entry`를 섞은 요청, 다른 판매자 회차 ID로 잇기·기다리기·DM 재전송·조회, 같은 인스타 계정을 두 판매자가 연결.
- 저절로 잇기: 기다리는 회차 둘, 끝난 회차, 리허설 회차(기다리기 자체가 안 됨), 끝낸 직후의 댓글, 같은 라이브로 1부·2부, 연결을 끊은 계정의 댓글.
- 중복·순서: 같은 댓글 ID 재배달(본문 다름), 묶음 안 반복, 동시 두 요청, 저장 실패 중간 재배달, 늦은 `entry.time`.
- 키: 숫자만인 IGSID가 휴대폰 번호 모양(`01012345678`)일 때 방송자 조치·합치기·정산 기록, 접두어 포함 256자 경계, 빈 IGSID·댓글 ID.
- DM: 한 댓글 다섯 번호, 같은 댓글 승계 뒤 감사, 보내는 중 생긴 같은 댓글 감사, 문자찜과 합친 인스타 구매자(메모·뒤 4자리 누출 없음), 동의 끈 뒤·연결 끊은 뒤·다른 계정으로 다시 연결한 뒤, 타임아웃 + 조회 실패, 실행기 둘, 리허설 행, `thanks.liveChat` 끈 회차.
- 실제 시각순: `RECEIVED_TIME` 스냅샷 회차에 잇기·기다리기, 같은 날 실제 시각순 유튜브 회차와 인스타 회차.

## HG-N2 확인 목록 (사용자 — 메타 앱 심사 뒤, 최종 보고)

1. 메타 개발자 앱(앱 ID·시크릿·웹훅 확인 토큰·돌아오는 주소)과 공개 HTTPS 웹훅 주소를 운영 설정에 넣고, 앱 대시보드에서 `live_comments` 웹훅 필드를 구독한다.
2. 인스타그램 프로페셔널 계정(페이스북 페이지에 연결, "메시지 접근 허용" 켬)으로 연결 → 연결 상태에 계정 username·권한 둘이 보인다.
3. 회차를 "인스타그램 기다리기"로 정하고 휴대폰에서 라이브 시작 → 다른 계정으로 댓글 "15" → 1~2초 안에 콘솔에서 15번 1등.
4. DM 동의를 켠 상태에서 그 시청자 계정의 DM함에 감사 한 통(`15번 … 님 구매 감사합니다`)이 오고, 같은 댓글로 두 번 오지 않는다. "15 28" 댓글은 한 통에 두 줄.
5. 라이브를 끝낸 뒤 수동 재전송 → "인스타그램 라이브가 끝나 DM을 보낼 수 없어요."
6. 연결 끊기 → 메타 앱 설정에서 앱 연결이 사라진다.
