## A. 서버 — 작업 기록과 자동 출력 (LBL-08, LBL-09, R-13, L-9, L-11 1~5·14)

### AC-I1-01 [server] 작업 기록·격리·재시작
- 근거: LBL-08 "출력 작업은 서버에 기록되어 어느 기기에서 출력했는지, 성공/실패가 남는다", L-11 1, SYS-02, D-I1-01
- Then 출력 작업(L-8 작업 + 범위 날짜 + 만든 까닭 `자동`/`손으로`/`다시 출력`/`포장` + 시도마다의 결과 + 출력한 기기 이름·시각 + 버릴 라벨 확인), 출력 기기, 대기열 멈춤, 템플릿이 판매자 단위로 데이터베이스에 저장된다. 스키마는 마이그레이션 하나로 더하고 `test/schema.test.ts`식 대조 시험이 통과한다.
- Then 서버를 다시 켜도 작업·상태·시도 기록·멈춤·출력 기기 지정·템플릿이 그대로다(출력 기기의 프린터 연결은 다시 연결해야 한다 — 끊김 멈춤으로 보인다).
- Then 다른 판매자의 작업·기기·템플릿은 조회·조치·실시간 알림 어디로도 보이지 않고, 다른 판매자의 작업 ID로 조치하면 없는 작업과 같은 응답이다(있는지 알 수 없다). 작업 기록을 지우는 API는 없다.
- 확인: 서버 단위, 적대

### AC-I1-02 [server] 자동 작업은 효과와 같은 기록에서
- 근거: LBL-09, R-13, L-11 2, D-I1-02, 골든 G-ENG-301~303
- Given 실제 방송(설정 `print.autoOnConfirm: 예`)
- When 채팅·문자찜·방송자 조치로 찜이 1등이 된다(첫 판정·승계·역전·교체·충돌 바꾸기·메시지 변환·재고 늘림 — 한 이벤트에 여럿이면 여럿)
- Then 그 이벤트의 기록·발송함 행과 **같은 트랜잭션**에서 효과마다 작업 하나가 생긴다: 작업 ID = 효과 ID, 라벨 키 = (찜, 확정버전), 종류 상품, 까닭 `자동`, 상태 대기, 구매자 = 그 순간의 L-9 구매자. 트랜잭션이 실패하면 이벤트·작업 모두 없다(한쪽만 남지 않는다).

### AC-I1-05 [server] 폐기와 버릴 라벨
- 근거: LBL-09 "이전 라벨은 '폐기' 표시", L-8 4, L-11 5, D-I1-02, 골든 G-ENG-301·302·303
- Given 라벨 키 (찜 c, 확정버전 v)의 작업이 있다
- When c가 v의 1등이 아니게 된다 — 방송자 취소·무효, 취소 요청 승인, 시청자 자동 취소, 실제 시각순 역전, 교체, 충돌 바꾸기, 번호 변경(찜이 번호 바뀜으로 끝남)
- Then 그 이벤트가 커밋될 때(늦어도 출력 기기가 다음 작업을 받기 전에) 그 라벨 키가 폐기된다: 대기 작업 → 출력 안 함 + 폐기(출력되지 않는다), 출력 중 작업 → 결과가 출력함이면 "폐기 — 버려 주세요", 실패면 출력 안 함 + 폐기(대기로 되돌리지 않는다), 출력함 작업 → "폐기 — 버려 주세요". 폐기는 되돌리지 않는다.
- Then 같은 라벨 키의 `VOID_LABEL` 효과가 와도 두 번 폐기되지 않는다. 자동 출력을 끈 방송에서 손으로 출력한 라벨도 같은 규칙으로 폐기된다(엔진의 `VOID_LABEL` 없이 — G-ENG-303).
- Then "폐기 — 버려 주세요"가 된 작업은 **버릴 라벨**이다. "버렸어요"를 기록하면(누가·언제 남김, 다시 보내도 한 번) 버릴 라벨에서 빠진다. 대기 작업의 폐기는 버릴 라벨이 아니다.
- Then 재고 2에서 한 1등만 끝나면 그 사람의 라벨 키만 폐기된다(G-ENG-302).
- 확인: 서버 단위, 적대

## B. 서버 — 출력 기기·결과·멈춤 (LBL-06 AC2, LBL-08, LBL-10, L-8 3, L-11 4·6~10)

### AC-I1-06 [server] 출력 기기가 받기
- 근거: L-11 4, L-8 1·2, D-I1-01
- Then 작업을 받을 수 있는 것은 그 판매자의 지금 출력 기기 하나뿐이다. 다른 기기가 받으려 하면 거절("이 기기는 출력 기기가 아니에요.")하고 아무것도 바뀌지 않는다.

- Then 받을 때 라벨 키의 찜이 그 확정버전의 1등이 아니면 AC-I1-05의 폐기를 하고 다음 작업을 준다(그 작업은 출력되지 않는다).

### AC-I1-07 [server] 결과 보고

### AC-I1-09 [server] 멈춤·다시 시작·출력 시작

### AC-I1-10 [server] 출력 기기 정하기·바꾸기·그만하기
- 근거: LBL-10, L-11 10, D-I1-01·03
- When 기기가 출력 기기가 되겠다고 알린다(기기 ID, 기기 이름 — 앞뒤 공백·제어 문자를 지운 뒤 1~20자)

- 확인: 서버 단위, 적대

## C. 서버 — 손으로 출력·재출력·재출력 필요·포장·템플릿·실시간 (LBL-02, LBL-04, LBL-11, L-10, L-11 3·9·11~13·15·16)

### AC-I1-11 [server] 손으로 출력·재출력·빼기
- 근거: LBL-11, L-8 5·6, L-11 3·9, D-I1-04
- Then **라벨 출력**: 실제 범위의 지금 1등 찜에 대해, 그 라벨 키(찜, 지금 확정버전)에 작업이 하나도 없을 때만 새 작업(까닭 `손으로`, 서버가 정한 ID, 구매자는 그때 L-9로 정해 고정). 작업이 있으면 거절(재출력을 쓰게 한다).
- Then **다시 출력**: 그 라벨 키의 작업이 출력함 또는 출력 안 함이고, 폐기되지 않았고, 대기·출력 중 작업이 없고, 그 찜이 지금도 그 확정버전의 1등일 때만 새 작업(까닭 `다시 출력`, 대기 맨 끝, 데이터는 받을 때). 거절 문장: "폐기한 라벨은 다시 출력할 수 없어요." · "이 라벨은 이미 출력을 기다리고 있어요." · "아직 출력한 적이 없는 라벨이에요." · "1등이 바뀐 라벨은 다시 출력할 수 없어요."
- Then 같은 요청 번호로 다시 보내면 같은 결과이고 작업이 두 번 생기지 않는다. 이 조치들은 엔진 기록이 아니어서 5초 대기 없이 바로 처리된다.
- Then **빼기**: 대기 작업 하나를 출력 안 함으로(기록은 남는다). **모두 빼기**는 확인 표시가 있는 요청만 받고 그때의 대기 작업 전부를 출력 안 함으로. 출력 중 작업은 뺄 수 없다("출력 중인 라벨은 뺄 수 없어요.").
- 확인: 서버 단위, 적대

### AC-I1-12 [server] 재출력 필요·이력

- **무작위 판매 열 + 출력 결과 열**: 코어 골든 이벤트 생성기류로 판매 열(확정·대기·취소·승계·역전·교체·충돌·번호 변경·품종·가격 변경·합치기)을 만들고 사이사이에 출력 기기의 받기·결과(출력함·끊김·오류·늦은 결과·재전송)·재출력·빼기·출력 기기 바꾸기를 섞는다. 매 단계 불변식:
  1. 출력 중 작업은 판매자마다 많아야 하나.
  2. 작업은 사라지지 않는다 — 모든 작업이 대기·출력 중·출력함·출력 안 함 중 하나이고 기록이 줄지 않는다.
  3. 1등이 아닌 라벨 키의 출력함 작업은 모두 폐기(버릴 라벨) 표시가 있다. 새로 받는 작업의 라벨 키는 늘 지금 1등이다.
  4. 실제 범위의 자동 작업 수 = 코어 재생의 `PRINT_PRODUCT_LABEL` 효과 수. 리허설 범위 작업 0.
  5. 엔진 이벤트 기록의 `effect.labelPrinted` 수 = 출력함이 된 서로 다른 자동 효과 수(효과마다 1 이하).
  6. 출력함 작업의 라벨 데이터 = 그 시점 상태로 L-9를 손으로 계산한 값(구매자 규칙 포함). 재출력 필요 = L-10.
  7. 판매자 격리 — 다른 판매자로 받기·결과·조치·조회가 아무것도 바꾸지 않는다.

- **트랜잭션 경계**: 효과 기록 중 실패 → 작업도 없음, 출력함 기록과 엔진 보고 사이의 실패·재시작 → 한쪽만 남지 않음.

## HG-2 확인 목록 (최종 보고에서 판매자가 실제 B1으로)

자동 시험으로 대신할 수 없는 "실제 B1·실제 기기에서 되나"를 본다. 약 30분. 준비: NIIMBOT B1, 50×30mm 정품 라벨, PC(크롬) 또는 안드로이드 폰(크롬). 결과는 사용자가 DECISIONS 표의 해당 결정을 확정(`ACCEPTED`)하거나 바꾼다(`CHANGED`).

1. **연결**: 라벨 화면 → "블루투스로 연결" → 브라우저 창에서 B1 고르기(한 번 눌러 창이 뜨는지). PC면 "USB 선으로 연결"도 한 번. B1이 아닌 NIIMBOT이 있으면 "지금은 NIIMBOT B1만 연결할 수 있어요."가 나오는지.
2. **테스트 인쇄**: 테스트 라벨의 네 변 테두리(특히 **맨 아래 테두리** — 마지막 줄 미출력 대응), 한글 `가나다 똠햏 ㄱㄴㄷ`, 숫자가 또렷한지. 농도 3이 적당한지(아니면 몇이 좋은지).
3. **라벨 위치·크기**: 기본 상품 라벨(가게 이름을 적고)이 라벨 안에 잘림 없이 찍히는지 — 위아래 여백, 50mm 중 가운데 48mm. 50×20·50×40 라벨이 있으면 한 장씩.
4. **30장 연속**: 리허설이 아닌 시험용 실제 방송에서 상품 30개를 1등으로 만들어 30장이 순서대로 나오는지(빠짐·겹침 없이), 한 장에 걸리는 시간, 20초 시간 초과가 나지 않는지. 중간에 B1 전원을 껐다 켜서 "다시 연결" → 이어서 나오는지.
5. **휴대폰 프린트 스테이션**: 안드로이드 폰을 출력 기기로 하고 PC에서 판매 → 폰에서 나오는지. 폰 화면이 꺼질 때 끊기는지, "출력하는 동안 이 화면을 켜 두세요."가 충분한지.
6. **승계·버릴 라벨**: 1등 취소 → 새 1등 라벨이 나오고 "버릴 라벨"이 눈에 띄는지. Alt+P 재출력.
7. **그림 파일 경로**: 아이폰(또는 출력 기기가 아닌 폰)에서 라벨 PNG를 공유 → NIIMBOT 공식 앱에서 인쇄했을 때 크기가 맞는지. A4 모아찍기 PDF를 실제 크기(100%)로 인쇄했을 때 50×30 칸이 맞는지.
8. **판단**: 출력 기기 하나·쌓인 라벨은 "출력 시작"·버릴 라벨 확인·자동 출력 기본 켜짐(D-I1-01~D-I1-08)과 라벨 형식(D-P1-02·03·05·09) 중 바꾸고 싶은 것. niimbluelib 상업적 사용(D-009)은 유료 출시 전 확인.
