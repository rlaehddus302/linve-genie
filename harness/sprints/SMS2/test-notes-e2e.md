# SMS2 test-notes (test-e2e)

## 띄우는 법
- 시험 화면은 서버가 만드는 HTML이라(D-SMS2-01) 웹 앱 묶음을 쓰지 않는다. `tests/e2e/sms2/support.ts`의 `openSmsBox()`가 연습 모드와 같은 상자(`createSmsTestBox`)·같은 와이파이 http 받는 곳(`createSmsTestHttpServer`)을 시험 안에서 127.0.0.1·포트 0으로 띄우고, 휴대폰 대신 시험이 `X-Try-Token`으로 POST한다. 서버 시계는 시험이 정한다(시간 기다림 없음).
- 모양 시험은 5초 새로고침을 뗀 응답으로 잰다(`holdRefresh` — 재는 도중 화면이 다시 열리지 않게). 새로고침 자체는 flow 시험이 열어 둔 화면에 새 문자가 저절로 나타나는지로 본다.
- 실행: `CI=1 E2E_PORT_OFFSET=4400 pnpm exec playwright test --config apps/web/playwright.config.ts tests/e2e/sms2` (18개, 크로미움 15·WebKit 3).

## 덮은 것
- `flow.spec.ts`: AC-SMS2-31 한 번의 흐름(요약 덩어리 문장 전부·차례, 카드 첫 줄·두 시각·겹침, 원문 번호 없음, 영어 낱말 없음, 표 없음, meta refresh 5), AC-SMS2-14 확인 화면 → 아니요 → 네(303, 토큰 그대로, 같은 문자가 새 1번째, 새로고침으로 저절로 보임, 뒤로 가기는 지우지 않음), AC-SMS2-15 GET do=reset은 지우지 않음, 틀린 토큰 안내, http 받는 곳 다른 경로 404, 받은 글 이스케이프(대화 상자 0), WebKit에서 폼 보내기·303, "네" 두 번 누르기, 51건 안내와 지운 뒤 사라짐.
- `layout.spec.ts`: AC-SMS2-30 크로미움 375×812·412×915·1280×800, WebKit iPhone 15(폭 393 — 보이는 칸 높이는 659) × 뿌리 글자 100%·150%. 빠진 번호 20개 넘는 기기·띄어쓰기 없는 긴 주소 문자·긴 기기 이름·여러 줄 문자를 넣은 화면에서 가로 스크롤 0, 요약 문장 안 잘림, 단추 48px, 글자 18px 이상, PC 내용 폭 720px 이하.

## 찾은 것
- 실패한 제품 버그 없음. 공격은 모두 스펙대로 동작했다.
- (nit, 스펙 확인 필요) 확인 화면을 연 뒤 새 문자가 오면 "네"가 확인 화면에 적힌 건수보다 많이 지운다(물은 것은 3건, 지운 것은 4건). 시험 도구라 사고로 이어지지 않아 시험으로 고정하지 않았다.
