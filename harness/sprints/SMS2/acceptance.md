## 수용 기준

### 휴대폰이 받은 시각 읽기 (D-SMS2-02)

**AC-SMS2-01** [server] 오프셋 있는 ISO 시각
- Given 서버 시계가 `2026-10-26T05:03:08.000Z`(한국 14:03:08)
- When `receivedAt: "2026-10-26T14:03:05+09:00"`(또는 `"2026-10-26T05:03:05Z"`)로 받으면
- Then 카드에 "휴대폰이 받은 시각 10월 26일 14:03:05", "서버가 받은 시각 10월 26일 14:03:08", "늦은 정도 3초" (계산: 08 − 05 = 3000ms → 3초)
- 확인: 단위(가짜 시계)

**AC-SMS2-02** [server] 오프셋 없는 날짜·시각은 한국 시각
- When `receivedAt`이 `"2026-10-26T14:03:05"`, `"2026-10-26 14:03:05"`, `"2026-10-26T14:03:05.250"`, `"2026-10-26 14:03"` 이면
- Then 각각 늦은 정도 "3초", "3초", "3초"(2750ms → 반올림 3), "8초"(14:03:00 → 8000ms). 서버 프로세스 시간대(`TZ=UTC`·`TZ=America/New_York`)를 바꿔도 같은 결과
- 확인: 단위

**AC-SMS2-03** [server] 숫자 시각과 읽을 수 없는 값
- When `receivedAt`이 `1792990985000`(숫자, 밀리초), `"1792990985000"`(글), `1792990985`(초), `"1792990985"`이면 Then 모두 늦은 정도 "3초"
- When `receivedAt`이 없음, `""`, `"어제"`, `true`, `{}`, `"2026-13-40T99:00"`, 서버 시각보다 24시간 넘게 앞이나 뒤인 값(예: `"2026-10-24T14:03:05+09:00"`, 밀리초를 초로 잘못 준 값처럼 1970년대가 되는 값)이면
- Then 받기는 200으로 성공하고, 카드의 "휴대폰이 받은 시각"과 "늦은 정도"는 "-"
- 확인: 단위

### 늦은 정도 (D-SMS2-03)

**AC-SMS2-04** [server] 줄마다 표시
- Given 서버 시각 고정, 지연(서버 − 휴대폰)이 다음과 같게 `receivedAt`을 준다
- Then 400ms → "1초 안", 0ms → "1초 안", −600ms → "1초 안", −1000ms → "1초 안", 1000ms → "1초", 2499ms → "2초", 2500ms → "3초", −1001ms·−1500ms → "시계 차이"
- 확인: 단위

**AC-SMS2-05** [server] 요약의 평균·가장 늦은 것
- Given 같은 기기에서 지연 3000ms, 400ms, 2500ms, −600ms, −1500ms, 그리고 `receivedAt` 없는 것 하나 (모두 다른 내용)
- Then 그 기기 요약에 "늦은 정도: 평균 1.5초 · 가장 늦은 것 3초 (4건으로 쟀어요)", "휴대폰 시계가 맞지 않아 뺀 것 1건", "휴대폰이 받은 시각 없이 온 것 1건"
  - 계산: 잰 것 = 3000·400·2500·0(−600은 0으로) → 합 5900 ÷ 4 = 1475ms → 100ms 단위 반올림 15 → "1.5초". −1500은 시계 차이로 뺌. 가장 늦은 것 3000ms → "3초"
- Given 잰 것이 하나도 없으면 Then "늦은 정도: 휴대폰이 받은 시각이 오지 않아 잴 수 없어요." (뺀 것·없이 온 것 문장은 0건이면 보이지 않는다)
- Given 잰 것의 평균이 1000ms 미만이면 평균은 "1초 안"
- 확인: 단위. 평균은 정수 밀리초 합으로 계산(소수 누적 없음)

### 일련번호 (D-SMS2-04)

**AC-SMS2-06** [server] 본문에서 일련번호 읽기 — 응답 `serial`과 카드 첫 줄
- `시험 3` → 3, `시험3` → 3, `시험   12번` → 12, `시험 3 165번주세요` → 3, `165번 시험 4` → 4, `시험 999` → 999, `[Web발신] 시험 7` → 7
- 번호 없음(`serial: null`, 카드 "번호 없음"): `165번주세요`, `시험`, `시험 일`, `시험 0`, `시험 1000`, `시험 12345`, `시험 ３`(전각), `시험 해요 시험 5`(첫 "시험" 뒤에 숫자가 없음), `테스트 1`
- 일련번호는 200자로 자른 본문에서 읽는다(201번째 글자 뒤의 "시험 1"은 읽지 않는다)
- 확인: 단위(표 시험)

### 겹쳐 온 문자 (D-SMS2-05)

**AC-SMS2-07** [server] 같은 문자는 한 줄
- Given 기기 `iPhone`, 보낸 사람 `010-1234-5678`, 내용 `시험 1`을 받았다
- When 같은 기기·같은 끝 4자리(`+82 10-9999-5678`처럼 번호 원문이 달라도 끝 4자리가 같으면 같음)·같은 내용을 두 번 더 받으면(서로 몇 분 떨어져도)
- Then 줄은 하나, 카드에 "3번 왔어요 (한 번으로 셌어요)", 늦은 정도·두 시각은 처음 온 것 그대로, 두 번째·세 번째 응답은 200 `{ ok: true, seq: 1, last4: "5678", serial: 1, duplicate: true }`
- And 다음 새 문자는 `seq: 2` (겹친 것은 줄 번호를 올리지 않는다)
- 확인: 단위

**AC-SMS2-08** [server] 다른 것으로 보는 경우와 50건
- 기기 이름만 다름(`iPhone`·`Galaxy`), 끝 4자리만 다름, 내용만 다름(`시험 1`·`시험 1 `처럼 끝 띄어쓰기 하나도) → 각각 새 줄. 같은 일련번호인데 내용이 다르면 새 줄이지만 빠진 번호·순서 계산에는 그 번호의 **처음 온 줄**만 쓴다
- 연락처 이름으로 온 두 문자(보낸 사람 종류 "이름")는 내용·기기가 같으면 겹친 것(이름 원문은 비교에도 남기지 않는다)
- 같은 문자를 1000번 받아도 들고 있는 줄은 1개("1000번 왔어요"), 50건 한도·메모리가 늘지 않는다
- 50건이 차서 처음 줄이 밀려난 뒤 같은 문자가 오면 새 줄
- 확인: 단위, [domain] 적대(넘치기·많은 기기)

### 요약 (D-SMS2-06)

**AC-SMS2-09** [server] 기기마다 한 덩어리
- Given `iPhone`과 `Galaxy`에서 섞여 받았다
- Then 화면 맨 위 "요약" 아래 기기마다 제목 "{기기 이름} — 받은 문자 {n}건"(겹친 것 뺀 줄 수), 처음 받은 기기가 먼저. 그 아래 "겹쳐 온 것: 없음" 또는 "겹쳐 온 것: {k}번 (한 번으로 셌어요)"(k = 온 횟수 − 줄 수), 그리고 AC-SMS2-05의 늦은 정도 문장
- 기기 이름이 `<b>x</b>`면 제목에 글자 그대로(태그가 되지 않음)
- 확인: 단위

**AC-SMS2-10** [server] 빠진 번호
- Given 한 기기에서 `시험 1`·`시험 2`·`시험 4`·`시험 6` → Then "시험 1~6: 빠진 번호 3, 5"
- Given `시험 1`~`시험 5` 모두 → Then "시험 1~5: 빠진 번호 없어요"
- Given `시험 30` 하나 → Then "시험 1~30: 빠진 번호 1, 2, …, 20 외 9개"(앞 20개를 쉼표로, 나머지는 개수 — 1~29 중 29개, 20개 보이고 9개)
- Given 번호 있는 문자가 없으면 → Then 빠진 번호 줄 대신 "'시험 1'처럼 번호를 붙여 보내면 빠진 문자와 순서도 볼 수 있어요."
- Given 번호 있는 것과 없는 것이 섞이면 → Then "번호 없는 문자 {z}건"도 보인다
- 늘 붙는 문장(번호 있는 문자가 하나라도 있을 때): "'시험 {가장 큰 번호}' 뒤에 보낸 문자가 안 왔는지는 이 화면이 알 수 없어요. 마지막으로 보낸 번호와 비교해 보세요."
- 확인: 단위

**AC-SMS2-11** [server] 순서가 바뀐 번호
- Given 서버가 받은 차례 `시험 1`, `시험 2`, `시험 4`, `시험 3`, `시험 6`, `시험 5` → Then "순서: 늦게 온 번호 3, 5" (3은 앞선 4보다 작고, 5는 앞선 6보다 작다)
- Given 차례대로 → Then "순서: 보낸 차례대로 왔어요"
- Given `시험 2`, `시험 1`, `시험 2`(내용 같음 — 겹침) → Then "늦게 온 번호 1" 하나(겹친 것은 차례 계산에 다시 들어가지 않는다)
- 21개 넘게 늦으면 앞 20개 + "외 n개"
- 확인: 단위

**AC-SMS2-12** [server] 다음에 보낼 글
- Given 그 기기의 가장 큰 번호가 6 → Then "다음에 보낼 글: 시험 7"
- Given 번호 있는 문자가 없음(또는 받은 것이 없음) → Then "다음에 보낼 글: 시험 1"
- Given 가장 큰 번호가 999 → Then "번호를 999까지 다 썼어요. '처음부터 다시 세기'를 누르세요."
- 확인: 단위

**AC-SMS2-13** [server] 빈 화면·50건 문장
- Given 받은 것이 없음 → Then 요약 자리에 "아직 받은 문자가 없어요. 다른 휴대폰에서 사장님 번호로 '시험 1'을 보내 보세요."
- 늘: "최근 50건 안에서만 세요. 연습 모드를 끄면 모두 사라져요."
- Given 51건째를 받아 처음 줄이 밀려났으면 → Then "50건이 넘어 오래된 문자는 지워졌어요. 빠진 번호가 틀릴 수 있으니 '처음부터 다시 세기'를 누르고 다시 시험하세요."
- 확인: 단위

### 처음부터 다시 세기 (D-SMS2-07)

**AC-SMS2-14** [server] 두 단계로만 지운다
- Given 3건을 받았다
- When 보기 화면의 "처음부터 다시 세기"(링크 `?t=토큰&do=reset-ask`)를 열면 Then 확인 화면에 "받은 시험 문자 3건을 지우고 처음부터 셀까요? 지우면 되돌릴 수 없어요. 결과 사진을 먼저 찍어 두세요.", 단추 "네, 지우고 처음부터 셀게요"(POST 폼 `?t=토큰&do=reset`)와 "아니요, 돌아갈게요"(보기 화면 링크). 확인 화면에는 `meta refresh`가 없다. 이때 3건은 그대로
- When "네, 지우고…"를 보내면 Then 303 → `?t=토큰` 보기 화면, 요약은 빈 화면 문장(AC-SMS2-13), 다음 받은 문자가 `seq: 1`, 겹침 기록도 비었다(전에 받은 `시험 1`을 다시 받으면 새 줄·`duplicate: false`)
- And 토큰은 그대로(같은 `X-Try-Token`으로 계속 받는다)
- 확인: 단위, [e2e]

**AC-SMS2-15** [server] [domain] 지우기 보호
- 토큰 없음·틀림으로 `POST ?do=reset` → 401, 하나도 지우지 않음
- `POST ?do=reset`에 `X-Try-Token` 머리글만 맞고 주소 `t`가 없음 → 지우지 않음(받기로도 처리하지 않음 — 400 또는 401, 줄 수 그대로)
- `GET ?t=토큰&do=reset` → 지우지 않음(보기 화면 또는 405)
- `do`가 다른 값(`?t=토큰&do=xyz`)인 POST → 지우지 않음, 받기도 하지 않음(400)
- 확인: 단위, 적대

### 화면 (D-SMS2-08)

**AC-SMS2-16** [server] 카드 모양과 순서
- 보기 화면에 `<table>`이 없다. 위에서부터 제목 "문자 자동 수신 시험", 요약, 시험 순서 안내(AC-SMS2-18), "처음부터 다시 세기", 받은 문자 카드(새것이 위)
- 카드: 첫 줄 "{seq}번째 · 시험 {번호}"(또는 "{seq}번째 · 번호 없음")과 "늦은 정도 {값}", 이어서 "휴대폰이 받은 시각 …"·"서버가 받은 시각 …"·"보낸 사람 끝 5678"(또는 "번호 대신 이름이 왔어요"·"보낸 사람 없음")·"기기 iPhone", 겹쳤으면 "{k}번 왔어요 (한 번으로 셌어요)", 마지막에 내용(줄바꿈 유지)
- 보기 화면은 5초마다 새로고침(`meta refresh 5`), CSP는 `default-src 'none'; style-src 'unsafe-inline'; form-action 'self'`
- 확인: 단위(HTML 글)

**AC-SMS2-17** [server] 같은 와이파이 http에서도
- http 받는 곳에서 `GET ?t=토큰&do=reset-ask`, `POST ?t=토큰&do=reset`이 https와 같게 동작하고(같은 상자), 303의 `location`은 같은 http 주소의 보기 화면
- 그 밖의 경로는 지금처럼 404
- 확인: 단위(포트 0으로 연 http 서버)

**AC-SMS2-18** [server] 화면 안 시험 안내 (쉬운 한국어)
- 요약 아래 짧은 순서 세 줄: "1. 다른 휴대폰에서 사장님 번호로 '시험 1', '시험 2', '시험 3'… 차례로 보내세요." / "2. 기기마다 '다음에 보낼 글'을 보고 보내면 돼요." / "3. 다 보냈으면 이 화면을 사진으로 찍어 두세요."

**AC-SMS2-31** [e2e] 한 번의 시험 흐름

- When "처음부터 다시 세기" → "네, 지우고 처음부터 셀게요" Then 빈 화면 문장, 주소의 토큰 그대로
- 확인: E2E

### TRY-IT 안내 (D-SMS2-09)

**AC-SMS2-50** [server] 절 차례
- `docs/TRY-IT.md` "문자 자동 수신 시험하기" 절의 소제목이 차례로 "준비", "(가) 아이폰: 단축어 자동화", "(나) 갤럭시: MacroDroid", "(다) 시험 순서", "(라) 결과 읽기", "시험이 끝나면 꼭 끄기"
- 이 도구는 시험용이고 실제 문자찜을 어떻게 자동으로 받을지는 아직 정하지 않았다는 문장 한 줄이 절 첫머리에 있다
- 확인: 수동(문서 읽기) + 단위(소제목 차례 grep 가능)

**AC-SMS2-51** [server] 아이폰 단축어
- 보내는 단축어의 JSON 필드에 `receivedAt` = **현재 날짜**(날짜 형식 ISO 8601, 시간 포함)를 더하는 순서가 있다
- 자동화는 기본 "메시지에 포함: `시험`" 하나로 만드는 순서, 실제 주문 같은 문자까지 보려면 숫자 0~9 열 개(선택)이며 겹쳐 와도 화면이 한 번으로 센다는 문장
- "즉시 실행", "실행 시 알림 끄기", 자체 서명 주소 거절 때 http 주소로 바꾸는 순서는 그대로
- 확인: 수동

**AC-SMS2-52** [server] 갤럭시 MacroDroid
- 본문 예시가 `{"from":"[알림 제목]","body":"[알림 내용]","device":"Galaxy","receivedAt":"[시스템 시간]"}` 모양이고, `[시스템 시간]`은 마법의 글자에서 밀리초 숫자를 고르며 이름이 다르면 비슷한 것, 없으면 그 칸을 빼도 된다는 문장
- 배터리 "제한 없음"·알림 접근 허용 순서는 그대로
- 두 휴대폰과 맥북 모두 "날짜 및 시간 자동 설정"을 켜라는 문장(준비 절)
- 확인: 수동

**AC-SMS2-53** [server] 시험 순서와 결과 읽기
- (다)에 회차 표: ① 하나씩 `시험 1`~`시험 5` ② 10초 안에 몰아 `시험 6`~`시험 10` ③ 잠금 상태 `시험 11` ④ 화면 끄고 30분 뒤 `시험 12` ⑤ `시험 13 165번주세요` ⑥ 연락처에 저장된 번호에서 `시험 14`, 없는 번호에서 `시험 15` ⑦ 보내는 쪽이 일반 문자·채팅+(RCS)·아이메시지 중 무엇이었는지 적기 — 기기마다 결과 화면 사진
- (라)에 요약 문장마다 뜻 한 줄("빠진 번호" = 서버까지 오지 않은 문자, "늦게 온 번호" = 뒤에 보낸 것보다 늦게 도착, "겹쳐 온 것" = 같은 문자가 여러 번 옴, "시계 차이" = 휴대폰 시계와 맥북 시계가 다름)과 "처음부터 다시 세기"(토큰이 바뀌지 않아 단축어·매크로를 고칠 필요 없음)
- 옛 "늦은 정도 '-'" 설명은 `receivedAt`이 없을 때로 맞춘다
- 확인: 수동

- 375·393 WebKit 글자 150%에서 판매자가 요약만 보고 "빠졌는지·순서·몇 초"를 한눈에 읽는지, 확인 화면 문장이 겁주지 않고 분명한지.

## 이번 스프린트에서 하지 않는 것 (범위 밖)

- 운영 기능으로 만들기: 받은 문자를 문자찜·찜·판정·이벤트 저장에 잇기, 로그인한 판매자 화면에 넣기, DB·파일 저장 — **하지 않는다**(사용자 결정 대기).
- 문자 자동 수집 방식 고르기(갤럭시 알림 읽기 앱·아이폰 단축어 등), 가상번호·착신전환·문자 대행업체·새 외부 서비스·유료 앱 — **사용자 결정 필요**로만 적는다(DECISIONS "사용자 확인 필요" 표).
- 실제 아이폰·갤럭시에서의 메뉴 이름·마법의 글자 이름·실제 지연 확인 — 사용자 실물 시험 몫.
- 웹 앱(`apps/web/**`) 변경, 보기 화면의 스크립트·실시간 연결(SSE) — 5초 새로고침 그대로.
- 보낸 개수를 판매자가 적는 칸, 기기별 다시 세기, 결과 내보내기(파일·엑셀) — 넣지 않는다(D-036).
- 유튜브 경로(금지 경로) 일체.
