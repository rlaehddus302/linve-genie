## 실행
- `pnpm --filter @livejjim/web e2e` (깨끗한 서버: `CI=1`). 시험 파일 `tests/e2e/s05/*.spec.ts`, 공용 도우미 `tests/e2e/s05/support.ts`.
- 이 PC 전체 실행: 58개 중 57 통과 · 1 실패(TE-S05-001, 의도한 실패 시험) · 약 4.8분(리허설 끝까지 시험이 약 2.3분).
- 시험끼리 범위가 섞이지 않게(알림 띠는 범위 전체를 센다) 대부분 API로 서로 다른 과거 날짜의 방송을 만들고 그 콘솔을 연다(`openNewBroadcast`).
- 서버는 Origin을 확인하므로 시험이 API로 쓸 때 `Origin` 머리글을 붙인다(`postJson`·`sendViewerChat`).
- `tests/e2e`는 지금 lint·typecheck 대상 밖이다(루트 tsconfig·eslint가 포함하지 않음). 임시 설정으로 tsc 검사는 통과를 확인했다.

## 지적
- **TE-S05-001 (major)** — 앞 줄의 등록 응답이 오기 전에 다음 줄을 Enter하면 그 줄의 판단이 앞 등록 뒤로 미뤄지고 칸의 글자를 골라 두지 않아(`ConsolePage.tsx` `onEnter`의 미룬 경로·`handleDecision` 'register'의 `select()`는 값이 같을 때만), 판매자가 이어 치는 다음 줄이 앞 줄 뒤에 붙는다. 응답이 오면 칸이 그 줄과 달라 비우지 않는다(`clearLine`). 결과: "52 꽃 1만53 꽃 1만54 꽃 1만…" 같은 한 줄이 되고 Enter하면 52번 "고칠까요?"가 열려 품종에 엉뚱한 글자가 들어갈 수 있으며 53~55번은 등록되지 않는다(AC-S05-10 "빠르게 연달아 친 줄이 모두 순서대로 등록되고 빠지거나 두 번 등록되지 않는다"). 재현: 쓰기 응답 500ms 지연 + 짧은 줄을 글자당 40ms로 다섯 줄. 응답이 빠른(로컬) 경우 글자당 25ms에서는 통과한다 — 휴대폰 회선·붐비는 서버에서 난다.

## 통과한 공격(회귀로 남김)
- 로그인·세션 만료 후 같은 콘솔·대기 조치 안 보냄(다시 로그인·로그아웃·새로고침), 방송 목록·끝내기·제목 휴대폰 번호 거절.
- 빠른 입력 네 표기·오류 문장/커서·고치기 칸·번호 찾기(50개 뒤·판매 종료 포함)·고칠까요?(바뀐 칸만·판매 종료 → 다시 판매·가격 적용 범위 UNPAID_CLAIMS)·응답 전 "등록하는 중…"만.
- 채팅 표시(주문·취소·언급·변환 버튼 조건)·XSS 글자 그대로·새 메시지 n개·이전 메시지 보기·번호 칸 변환·이미 바꾼 번호.
- 충돌(변환) → 알림 띠 → 유지/바꾸기(숫자 키·Alt+1)·취소 요청 승인 → 승계·승계 결정(묻기 방송)·직접 배정 교체·차단 확인 문장(리허설)·사유 휴대폰 번호 거절 후 창 다시 열림·적용되지 않았어요·조치 응답 유실/오프라인 재전송 한 번.
- 등록 되돌리기(판매 종료/찜 있음 막힘)·Ctrl+Z 순서·글자 칸 Ctrl+Z·Esc 뒤에도 대기 조치는 감·운영 5초(@prod-delay).
- 두 기기 1초 반영·전체 조회 재요청 없음·끊김 → 다시 붙어 같은 화면·보관 범위(1,000) 넘김 → 전체 다시·동시 같은 번호 등록·오프라인 등록 → 다시 보내기 한 번·응답 유실 등록 한 번.
- 같은 날 리허설/실제 분리(채팅·알림·보드·따라잡기 요청), 같은 날 방송 둘의 보드·채팅 분리.
- 리허설 끝까지: 생성기 1,000건(시드 42) + 1~30번 + 화면 알림 처리 → 서버 상품·정산 = 코어 재생, 보드 낱말·1등·대기 수 = 재생, 같은 메시지 ID 사본 없음, 조치자 수집기, 실제 범위에 없음.
- 채운 범위(상품 500·채팅 1만) PC → 휴대폰 반영 p99 약 107ms(@fill), 375px 넘침 없음·글자 16px·누르는 곳 44px·영어 상태값 없음.

## 관찰(지적 아님)
- "번호 넣기"를 누른 직후(0ms 타이머 전) 친 글자는 칸 앞에 들어갈 수 있다 — 사람이 칠 수 없는 간격이라 지적하지 않았다.

## 수정 라운드 1 다시 공격 (`tests/e2e/s05/attacks-r1.spec.ts`)
- **TE-S05-001 해결** — 같은 시험(500ms 지연·글자당 40ms 다섯 줄)이 세 번 반복해 통과한다. 번호 찾기 줄을 사이에 끼운 변형도 통과(회귀로 남김).
- **TE-S05-002 (major, 새 구멍)** — 미룬 줄의 판단이 "고칠까요?"(같은 번호, AC-S05-13)면 판매자가 다음 줄을 치는 중이어도 창을 띄워 포커스를 가져간다(미룬 찾기·오류는 `typedNext`로 막았지만 `handleDecision` 'edit'와 `runRegistration`의 `first` 확인은 막지 않음). 재현: 500ms 지연에서 `61 꽃 1만`·`61 장미 2만`·`62 꽃 1만`·`63 꽃 1만`을 이어 침 → 62·63 등록 안 됨, 칸에 "63 꽃 1만62 꽃만"이 남고 그걸로 고치기 칸이 열림(가격만 넣으면 63번 품종이 엉뚱하게 등록됨). 세 번 반복 모두 재현.
- 사유 고치기(UX-S05-002): 빠른 입력을 치는 중에 사유 거절 → 창을 띄우지 않고 "15번 홍길동 취소 사유 고치기", 누르면 같은 사유로 다시 열리고 처음 포커스 "닫기", 고쳐 보내면 이력에 한 번·치던 줄 그대로 — 통과(회귀로 남김).

## 수정 라운드 2 다시 공격 (`tests/e2e/s05/attacks-r2.spec.ts`)
- 전체 실행(CI=1): 67개 모두 통과 · 약 5.3분.
- **TE-S05-002 해결** — attacks-r1의 같은 시험이 통과하고, 한 시험 안에서 세 번 반복(500ms 지연·글자당 40ms)해도 62·63이 빠지지 않는다. 창은 뜨지 않고 61 줄은 "고칠까요?" 목록에 남으며 `product.update`는 보내지 않는다.
- 수정으로 생긴 "고칠까요?" 목록 공격(모두 통과, 회귀로 남김):
  - 빈 칸에서 "고치기" → 창 처음 포커스 "아니요" → 아니요면 친 줄이 칸으로 옮겨져 남음(AC-S05-13) → Enter → 예 → 바뀐 칸만 `product.update` 한 번, 목록 비움.
  - 다음 줄을 치는 중 "고치기" → 예 → 고쳐지고 치던 줄 그대로. "그대로 두기" → 아무것도 보내지 않음.
  - 키보드만(NFR-08): 빠른 입력칸에서 Tab으로 "고치기"에 닿고 Enter → 창, Esc → 칸으로 돌아와 친 줄이 남음.
  - 보낸 등록이 다른 기기에 먼저 등록돼 `changed:false`로 돌아오고 판매자는 다음 줄을 치는 중 → 창 없이 목록에 남고 다음 줄은 등록됨, 다른 기기 값은 덮지 않음.
- 서버 라운드 2(메시지 조회 seq) 화면 쪽 확인: 생성기 채팅(400건, 초당 약 100)이 흐르는 동안 콘솔을 두 번 새로고침해도, 끝난 뒤 채팅 패널의 줄이 서버 마지막 메시지들과 빈틈없이 같다(세 번 반복 통과).
- 관찰(지적 아님): 늦은 판단이 판매자가 다음 줄을 치기 직전(칸 글자가 아직 친 줄 그대로)에 나면 창이 뜬다. 창은 처음 포커스가 "아니요"이고 숫자 선택키가 없어 잘못 고쳐지지 않으며, 사람이 보는 창이라 지적하지 않았다.
