## 덮은 것 (모두 통과 — 회귀 시험으로 남김)
- 공급자마다 이 흐름을 끝까지 본다.
  - 처음 연결: 가린 이름·날짜가 보이고, 주소가 지워지며, 새로 고침하면 문장이 다시 나오지 않는다.
  - 로그인: 가게 이름이 보이고 `/api/me`가 같은 판매자다.
  - 새 문맥에서 다시 로그인해도 같은 판매자다.
  - 취소, state 바꾸기, 다른 문맥의 state, 쿠키 없음.
  - 코드 재사용: 성공한 주소를 다시 열면 EXPIRED이고 교환 수가 그대로다. 새 state에 옛 코드를 붙이면 PROVIDER_ERROR다.
  - 돌아오는 주소가 다르면 가짜 화면이 오류를 보이고, 서버가 보낸 `redirect_uri`는 글자까지 같다.
  - 이메일·닉네임이 없으면 "<공> 계정"으로 보인다.
  - 같은 이메일이어도 NOT_LINKED이고 아이디 칸에 커서가 간다.
  - 끊기: 확인 창 문장이 맞고 기본 포커스가 그만두기다. 다른 문맥은 다음 요청에서 "로그인이 풀렸어요"를 보고, 그 뒤 로그인하면 NOT_LINKED다.
- 로그인 화면
  - 순서·색·테두리·명암비가 맞고, 그림·가입 글이 없다.
  - Tab 순서가 맞다.
  - 390 폭에서 폭 가득·44px·16px이고 가로 스크롤이 없다.
  - 누르면 셋 다 잠기고 "이동하는 중…"이 되며, 두 번 눌러도 시작 요청은 하나다.
  - 시작 실패(502 빈 본문·429 서버 문장·오프라인)는 버튼 아래 문장과 잠금 풀림으로 이어진다.
  - 공급자 화면에서 뒤로 가면 잠금이 풀린다.
- 결과 문장
  - 로그인 화면 코드 여섯은 한 번만 보이고 주소에서 지워진다.
  - 모르는 코드·공급자, HTML·스크립트·5000자·대소문자·공백·NUL은 아무것도 보이지 않는다.
  - 설정 코드는 설정 칸에서만 보이고, 로그인한 채 `/?login=`이면 지운다.
- 설정
  - 줄 글·순서·44px.
  - 연결 중 잠금.
  - Esc와 그만두기는 아무것도 바꾸지 않는다.
  - LINKED_ELSEWHERE(B에 관한 글 없음)·ALREADY_LINKED·같은 계정 다시 연결(LINKED).
  - 연결 도중 로그아웃하면 로그인 화면에 SESSION_GONE과 아이디 커서가 보이고, 아무것도 연결되지 않는다.
  - 다른 기기의 연결·끊기가 실시간으로 반영된다. 이미 끊긴 연결을 끊어도 같은 결과다.
  - 휴대폰 확인 창 버튼이 44px 이상이다.
  - 위 칸이 늦게 불러와져도 결과 문장이 화면 안에 보인다.
- 보조자: "로그인 방법" 칸이 없고 `/api/auth/*` 요청도 403도 없다. 간편 로그인은 NOT_LINKED다.
- 깨뜨리기
  - 카카오 세션에서 카카오를 끊으면 지금 세션은 남고, 다른 카카오 세션은 지워지며, 아이디 세션은 그대로다.
  - 끊은 뒤 다른 판매자가 연결하면 그 판매자로 들어간다.
  - 아이디가 잠겨도 구글로는 들어간다.
  - 쿠키
    - `lj_oauth`: `/api/auth`·HttpOnly·Secure·Lax·10분이고, 돌아오면 지워진다.
    - `lj_session`: 아이디 로그인과 같고 30일이다.
  - 연결 중 취소·5xx는 설정 칸 문장으로 끝나고 연결되지 않는다.
  - 사용자 정보 ID 없음·401, invalid_grant, JSON 아님은 PROVIDER_ERROR다.
  - 교환이 12초 걸리면 10초 제한으로 PROVIDER_ERROR가 되고, 그동안 다른 화면은 응답한다.
  - 같은 브라우저 두 탭에서도 다른 판매자로 들어가지 않는다.
  - 카카오 세션에서 네이버를 더 연결해도 세션 쿠키가 그대로다.
  - 연결 중 같은 브라우저에서 B로 바꾸면 A에도 B에도 연결되지 않는다.
  - A의 실시간 알림이 B 화면에 가지 않는다.
- 묶음
  - 구글 하나: 버튼 하나, 다른 공급자 404, 설정 줄 하나.
  - 기본 기동: 버튼·"또는" 없음, `/api/auth/**` 404, `client-config`에 항목 없음, 칸 없음.
  - `/privacy` 줄.

## 찾은 것
- TE-L1-001 (minor, 스펙 확인 필요): 로그인한 채 `/`로 돌아온 연결 결과는 아무 데도 보이지 않는다.
  - 경우 1: 연결 도중 같은 브라우저에서 다른 계정으로 바꿔 로그인하면 SESSION_GONE이 된다.
  - 경우 2: 연결의 돌아옴이 IP 한도에 걸리면 RATE_LIMITED가 된다.
  - 시험(`attacks.spec.ts` "B로 바꿔")은 데이터 안전만 단언한다. 문장을 어디에 보일지는 스펙이 정하지 않았다.
