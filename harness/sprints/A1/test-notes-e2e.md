# A1 test-e2e 노트

## 실행
`CI=1 E2E_PORT_OFFSET=27100 pnpm exec playwright test --config apps/web/playwright.config.ts tests/e2e/a1`
- `no-key.spec.ts` (기본 묶음 `chromium`, 키 없는 서버) 5개 · `screen.spec.ts`·`breaks.spec.ts` (`chromium-assist`, 제목 `@assist`) 19개.
- 결과: 24개 통과. `chromium-assist`는 `--repeat-each 2`로 38/38 통과(흔들림 없음).
- @assist 시험은 시험마다 새 판매자(`/_e2e/sellers`)와 `POST /_fake/reset` — 하루 상한 3이 시험끼리 섞이지 않는다.
- 가짜 AI의 기본 답은 글에 선택지 이름·별칭이 든 경우만 고른다(`엠사이즈`는 `M`이 아님) — AI 제안을 보려는 시험은 `/_fake/answers`로 답을 정해 둔다.

## 다룬 수용 기준
- AC-A1-20: 규칙 제안 글·출처·버튼, 칸 미리 채우지 않음, [이대로 주문] 하나(두 번 눌러도)·값·`source` 안 보냄, [고치기] 요청 없음, 390px·44px·16px, `<b>` 이스케이프.
- AC-A1-21: 화면을 열 때 한 번, 실시간 다시 읽기에 더 부르지 않음, 다시 열면 한 번 더(새 항목만 보냄·보낼 것 없으면 요청 0), 범위 바꾸면 그 범위로 한 번, 읽는 중 문장·느려도 목록 사용, 5xx·끊김 문장, 꺼짐 링크 → 설정 칸.
- AC-A1-02(HOLD·공개·별칭 지우기), 03(같은 글 한 번·규칙으로 풀린 것 안 보냄), 04(상한 문장·요청 안 늘어남·`오늘 3번`), 05(보낸 본문에 닉네임·전화번호·가격·가게 이름·판매자 ID·방송 ID 없음, 온도 0, 출력 ≤1,024), 06(이상한 답 → 제안 없음), 07(기록 안 늘어남), 08(꺼짐·끈 뒤 새 항목도 요청 0, 보조자 403).
- AC-A1-22: 꺼짐·동의 전 잠김·켜짐 문장·확인 창 없는 끄기·다시 동의, 키 없음 "지금은 쓸 수 없어요.", 번호로만 판매자 칸 없음·`/api/assist/*` 안 부름, 옵션 방송 기록만 있어도 칸 보임, 보조자 칸 없음.
- AC-A1-23·24: `/privacy` AI 제안(선택) 문단, 영어 상태값 없음.
- 브라우저 쪽 `api.anthropic.com` 요청 0(서버 쪽은 서버 시험의 가드가 본다 — E2E는 가짜 AI 요청 수로 확인).

## 깨뜨리기에서 본 것
- PC와 휴대폰에서 같은 화면을 동시에 열면 한쪽은 `BUSY` — 그쪽은 AI 답이 1.5초 만에 와도 16초 뒤(고정 타이머)에야 AI 제안을 본다. 스펙 "진행 중인 요청이 끝나면 목록을 다시 읽는다"보다 늦다(최대 16초 지연, 사고는 아님 — minor로 보고, 시험은 25초 안에 보이는지만 회귀로 둔다).
