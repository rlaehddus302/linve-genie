# N4a 수용 기준 — 라벨 끄기 모드

- 스프린트: N4a (5단계, 병렬 트랙 worktree `n4a` · 브랜치 `track/n4a-label-off`, BASE `b25a265`) · spec ID: **RCP-01**, **LBL-09**, **UX-05** (연결: UX-01, UX-02, UX-03, UX-04, NFR-01, NFR-02, NFR-03, NFR-06, NFR-08, SYS-02, LBL-02·06·07·08·10·11, SPEC §7 화면 2·4·7·8) · 규칙: LABEL_RULES v0.1.2 **L-12**(새 절)·L-11 2·3·7, DOMAIN_RULES v0.1.14 설정표 아래 "라벨 기능 켜기/끄기" · 근거 결정: D-036, D-070, D-087, D-102, D-I1-01~D-I1-10, **D-N4a-01~D-N4a-06**
- 개발 영역: **server**, **web** · 테스트: **e2e**(`tests/e2e/n4a/**`) · 사람 확인 지점 없음 · 이 트랙의 E2E는 `E2E_PORT_OFFSET=1300`으로 돈다.
- **dev-core·dev-device가 없다.** 판정 규칙·엔진 효과·`packages/label`·`packages/printer`는 바꾸지 않는다. 엔진은 라벨 기능 켬/끔을 모른다(D-N4a-01) — 꺼져 있어도 엔진은 `print.autoOnConfirm`대로 `PRINT_PRODUCT_LABEL`을 내고, 서버가 그 효과를 출력 작업으로 만들지 않고 화면이 라벨 조작을 숨길 뿐이다.
- 목표(백로그): RCP-01 — 판매자 설정 하나로 라벨 기능 전체를 켜고 끈다(기본 켬). 끄면 라벨 편집·프린터 연결·출력 대기열·자동 출력·재출력·포장 라벨 출력 버튼이 화면에서 사라지고, 엔진의 `PRINT_*`·`VOID_LABEL` 효과는 출력 작업으로 만들지 않는다(판매 판정·감사 메시지는 그대로). 켜고 끄는 변경은 이력에 남고, 방송 중 바꿔도 그 시점 이후에만 적용. 끈 상태에서는 라벨 PNG/PDF 내려받기도 "라벨 쓰지 않음" 안내와 함께 숨긴다. 시작 마법사·설정 화면의 프린터 단계도 끈 상태면 건너뛴다.
- carryOver·질문 → 결정 → 수용 기준

  | 항목 | 결정 | 수용 기준 |

  | 켬/끔은 어떤 설정이고 "그 시점"은 무엇인가, 끈 동안의 효과 | D-N4a-01 (L-12 1~3) | AC-N4a-01·02·03 |

- 공통 전제: S00~S06b·P1·P2·I1·I4 결과(`pnpm verify` 7단계 — typecheck·lint·test·golden·adversarial·coverage·e2e, 골든 589, 라벨 골든, 서버 출력 기록·출력 기기·시험용 프린터, 라벨 화면·콘솔·정산 화면)가 그대로 유지된다. **라벨 기능이 켜진 상태(기본)의 동작은 I1과 하나도 달라지지 않는다**(AC-N4a-40). 외부 계정·실기기·도커는 필요 없다. E2E는 Playwright(크로미움)·PGlite·시험용 계정·시험용 프린터(AC-I1-50)로 돈다.

- 태그: `[server]` = dev-server(`apps/server/**`), `[web]` = dev-web(`apps/web/**`). 의존 순서는 server → web. dev-server는 바뀐 계약(켬/끔 조회·바꾸기 API, 이력 형식, 실시간 알림 종류, 거절 코드 `LABELS_OFF`)을 `harness/sprints/N4a/dev-notes.md`에 먼저 적는다. E2E는 tester가 `tests/e2e/n4a/**`에 쓴다(확인 방법에 "E2E"라고 적은 기준).
- **합칠 때 겹치지 않게**: 켬/끔·이력은 새 표(또는 새 칸)를 마이그레이션 **새 파일**로 더한다. 판매자 판매 규칙 설정(`sellers.settings` JSON — 엔진 스냅샷 재료)에는 넣지 않는다(넣으면 `broadcast.start` 스냅샷이 엔진 입력 오류가 된다). 발송함(`outbox`) 표의 칸은 바꾸지 않는다. 설정 화면 `/settings`·위 줄 "설정" 링크는 다른 병렬 트랙(N5 요금제 등)도 쓸 수 있는 자리라, 화면은 "라벨" 절 하나를 독립 컴포넌트로 두어 합칠 때 절을 더하기 쉽게 한다.
- 화면 문장 중 이 문서·LABEL_RULES가 따옴표로 정한 것은 그대로 쓴다(E2E가 글자로 찾는다). 바꿔야 하면 dev-notes에 이유를 남기고 spec-keeper가 판정한다. 시각은 KST(NFR-07).

## A. 서버 — 설정과 이력 (RCP-01, L-12 1·2, D-N4a-01)

### AC-N4a-01 [server] 라벨 기능 설정: 기본 켬, 엔진 밖, 격리, 재시작
- 근거: RCP-01 "기본 켬", L-12 1·2, DOMAIN_RULES 설정표 아래 문장, SYS-02, D-N4a-01
- Given 이번 스프린트 전의 데이터(I1 출력 기록이 있는 판매자)와 새로 만든 판매자
- Then 둘 다 라벨 기능이 **켬**으로 조회되고(기록이 없으면 켬) 이력은 비어 있다. 켬인 판매자의 출력 동작은 I1과 같다(AC-N4a-40).
- Then 켬/끔은 판매 규칙 설정이 아니다: `/api/settings`의 응답에 그 키가 없고, `/api/settings`로 그 키를 보내면 지금처럼 모르는 키로 거절된다. 방송을 시작할 때 엔진에 넘기는 설정 스냅샷(`broadcast.start`)에도 들어가지 않는다 — 꺼 둔 판매자가 방송을 시작해도 `broadcast.start` 이벤트 내용은 켠 판매자와 같은 키만 가진다.
- Then 켬/끔과 이력은 서버를 다시 켜도 그대로다. 다른 판매자의 켬/끔·이력은 조회·실시간 알림 어디로도 보이지 않고, 한 판매자가 꺼도 다른 판매자의 자동 작업은 그대로 생긴다.
- 확인: 서버 단위

### AC-N4a-02 [server] 켜고 끄기·이력·실시간
- 근거: RCP-01 "켜고 끄는 변경은 이력에 남고", L-12 2, NFR-01, NFR-03, D-N4a-01
- When 로그인한 판매자가 켬/끔 값(예/아니오 하나)을 보낸다
- Then 값이 실제로 바뀌면 이력 한 줄(바뀐 값, 시각 — UTC 저장, 바꾼 계정)이 같은 트랜잭션에서 남고, 응답은 저장된 뒤에만 성공이다(NFR-03). 지금과 같은 값이면 아무것도 바뀌지 않고 이력도 없다(같은 요청을 다시 보내도 이력은 한 줄). 이력은 지우는 API가 없다.
- Then 조회는 지금 값과 이력 최근 20줄(새것 먼저, 줄마다 바뀐 값·시각·바꾼 계정의 로그인 아이디)을 돌려준다.
- Then 본문은 켬/끔 값 하나만 받는다: 불리언이 아니면 `INVALID_INPUT`, 다른 칸이 있으면 `UNKNOWN_FIELD`(I1 출력 API와 같은 오류 형식). 로그인·`Origin`·JSON 검사는 `/api` 공통 그대로다.
- Then 끔↔켬이 동시에 여러 번 와도(두 기기) 판매자마다 한 줄씩 차례로 처리돼, 이력 줄 수 = 실제로 값이 바뀐 횟수이고 마지막 줄의 값 = 지금 값이다.
- Then 값이 바뀌면 그 판매자의 모든 기기에 실시간으로 알려 1초 안(p99)에 화면이 바뀔 수 있게 한다(알림에 바뀐 값을 담거나, 화면이 받는 출력 개요에 켬/끔이 들어간다 — 계약은 dev-notes). 처음 화면을 열 때 한 번의 조회로 켬/끔을 알 수 있다.
- Then 서버 로그에 요청 본문·로그인 아이디를 남기지 않는다(NFR-06, L-11 16과 같은 결).
- 확인: 서버 단위, E2E(AC-N4a-12·18)

## B. 서버 — 효과 → 작업, 폐기, 요청 거절 (LBL-09, L-11 2·3·5·7, L-12 3~8)

### AC-N4a-03 [server] 꺼져 있으면 자동 작업이 없다 — 판정·감사는 그대로
- 근거: RCP-01 "엔진의 PRINT_*·VOID_LABEL 효과는 출력 작업으로 만들지 않는다(판매 판정·감사 메시지는 그대로)", "방송 중 바꿔도 그 시점 이후에만", L-11 2, L-12 3, NFR-02, D-N4a-01, 골든 G-ENG-301·303
- Given 실제 방송(설정 `print.autoOnConfirm: 예`), 라벨 기능 끔
- When 채팅·문자찜·방송자 조치로 1등이 여럿 확정된다(첫 판정·승계·직접 배정·재고 늘림 포함)
- Then 출력 작업이 하나도 생기지 않는다(대기열·이력·출력 기기가 받을 작업 어디에도 없다). 실시간 출력 알림도 작업 때문에 나가지 않는다.
- Then 엔진 쪽은 켬일 때와 같다: 같은 이벤트 순서를 켬인 판매자와 끔인 판매자에게 넣으면 두 판매자의 엔진 상태(찜 상태·1등·대기·정산)·효과 목록(`PRINT_PRODUCT_LABEL`·`POST_THANKS`·`VOID_LABEL` 종류·ID·문구)·발송함 행이 같고, 다른 것은 출력 작업의 유무뿐이다. 리허설 범위는 켬/끔과 상관없이 작업이 없다(L-11 14).
- Then **바꾼 때부터**: 끄기에 성공 응답을 받은 뒤 기록된 이벤트의 효과는 작업이 되지 않고, 켜기에 성공 응답을 받은 뒤 기록된 이벤트의 효과는 자동 작업이 된다(같은 방송 안에서 끔 → 켬 → 끔을 오가며 확인 — 자동 작업 수 = 켬이던 동안 기록된 이벤트의 `PRINT_PRODUCT_LABEL` 효과 수). 켬/끔은 그 이벤트 기록 트랜잭션 **안에서** 읽는다(트랜잭션 밖에서 미리 읽은 값을 넘기지 않는다 — 소스 검사 또는 기록 도중에 켬/끔을 바꾸는 시험으로 확인).
- Then 끈 동안 나온 효과는 나중에 켜도 작업이 되지 않는다(켜는 순간 쌓이지 않는다). 그 상품은 켠 뒤 라벨 상태가 "작업 없음"이고 손으로 출력할 수 있다(AC-N4a-07).
- Then 같은 입력의 재전송(같은 요청 번호·메시지 ID·문자찜 `ref`)은 켬/끔이 그사이 바뀌었어도 작업을 새로 만들지 않는다(처음 기록 때 정해진 대로).
- 확인: 서버 단위

### AC-N4a-17 [web] 출력 기기였던 기기
- 근거: L-12 6, L-11 6, D-N4a-02·03
- Given 이 기기가 출력 기기이고 시험용 프린터로 출력하는 중

- When 다시 켠다
- Then 남은 대기 작업이 있으면 쌓인 라벨 안내와 "출력 시작"이 보이고, 누르기 전에는 출력하지 않는다(AC-N4a-06). 프린터가 그대로 연결돼 있으면 "출력 시작" 뒤 이어서 출력한다.
- 확인: E2E(AC-N4a-30)

### AC-N4a-18 [web] 모르는 동안에도 숨기고, 바뀌면 1초 안

- Then 다른 기기에서 켬/끔을 바꾸면 열려 있는 모든 화면(콘솔·상품 자세히 창·정산 자세히·라벨 화면·설정 화면)이 1초 안에 그 상태로 바뀐다. 상품 자세히 창이 열린 채 꺼지면 창은 열린 채로 라벨 부분만 안내로 바뀐다(포커스를 빼앗지 않는다).
- 확인: E2E(두 기기)

### AC-N4a-19 [web] 다시 켜면 그대로 돌아온다

### AC-N4a-20 [web] 오래된 화면이 보낸 라벨 요청의 거절

## E. 화면 — 라벨 화면의 주 버튼 하나 (I1 통합 지적, UX-01, D-N4a-06)

### AC-N4a-21 [web] 라벨 화면 주 버튼은 지금 할 일 하나
- 근거: UX-01 "화면마다 주 버튼(채운 색)은 많아야 하나이고 지금 할 일이다"(D-102), AC-S06b-24, I1 통합 지적, D-N4a-06
- Given 라벨 기능 켬, 라벨 화면
- Then 창 밖에 동시에 보이는 주 버튼(AC-S06b-24에서 dev-web이 정한 표시 — 클래스 `button-primary`)은 많아야 하나다. 우선순위:
  1. 이 기기에서 누를 수 있는 출력 멈춤 띠의 조치("다시 연결"·"다시 시작"·"출력 시작")가 보이면 그것.
  2. 아니면 프린터 단계의 다음 할 일 — 연결 전: 첫 번째 연결 방법 버튼, 연결 뒤 테스트 결과에 "예"를 고르기 전: "테스트 인쇄", "예"를 고른 뒤: "이 기기에서 출력". 이 기기가 이미 출력 기기면 프린터 단계에 주 버튼이 없다.
- Then (1)이 보이면 "테스트 인쇄"·"이 기기에서 출력"·연결 방법 버튼은 모두 보통 버튼이다. "버렸어요"와 "라벨 설정 저장"은 라벨 화면에서는 늘 보통 버튼이다(창 안의 보내기·숫자 키 버튼 — 알림 창의 "버렸어요", 출력 기기 바꾸기 창의 "1 바꾸기" — 는 그대로).
- Then 사례: (가) 프린터 연결 직후 → 주 버튼 "테스트 인쇄" 하나 (나) 테스트 결과 "예" → 주 버튼 "이 기기에서 출력" 하나, "테스트 인쇄"는 보통 (다) 출력 기기가 된 뒤 끊김 멈춤 → 주 버튼 "다시 연결" 하나 (라) 버릴 라벨이 있고 라벨 설정을 고친 중 → 프린터 단계 밖 주 버튼 없음.
- 확인: E2E(시험용 프린터로 (가)~(라) 상태마다 주 버튼 수 세기)

## F. E2E 시나리오 (tester — `tests/e2e/n4a/**`)

### AC-N4a-30 [server] [web] 방송 중 끄고 켜기 (두 기기)
- 근거: RCP-01, L-12 3·6·7·8, D-N4a-01·02·04·05
- Given 같은 계정으로 연 PC(1440×900)와 휴대폰(375×812) 두 컨텍스트, 실제 방송 하나(`print.autoOnConfirm: 예`), 휴대폰이 시험용 프린터에 연결된 출력 기기
- When PC에서 상품 1~3이 차례로 1등이 된다 → 휴대폰이 3장을 출력한다
- And PC 설정 화면에서 "라벨 끄기" → 확인 창 → 끈다
- Then 1초 안에 두 기기 모두 메뉴 "라벨"·프린터 상태가 사라지고, PC 콘솔 보드에 라벨 상태가 없다.
- When 상품 4~6이 1등이 된다(채팅·문자찜)
- Then 시험용 프린터가 받은 그림은 여전히 3장이고 출력 작업은 3개뿐이다. 감사 메시지 효과는 4~6에도 생긴다(발송함/효과 조회로 확인).
- When PC에서 "라벨 켜기"
- Then 켜기 안내 문장이 보이고, 두 기기에 라벨 메뉴·프린터 상태가 돌아온다. 상품 4~6은 저절로 출력되지 않는다(프린터 그림 3장 그대로, 쌓인 라벨 안내도 없다 — 대기 작업이 없으므로).
- When 상품 7이 1등이 된다
- Then 휴대폰이 바로 7을 출력한다(4장째).
- When PC 콘솔에서 상품 5의 "라벨 출력"
- Then 휴대폰이 5를 출력하고(5장째) 엔진 이벤트 기록에 5의 `effect.labelPrinted`가 하나 생긴다(AC-N4a-07).
- 확인: E2E

### AC-N4a-31 [server] [web] 끈 동안의 대기 라벨·버릴 라벨
- 근거: L-12 4·6·7, D-N4a-02
- Given 휴대폰 출력 기기가 시험용 프린터에 연결돼 있지만 판매자가 "출력 멈추기"를 눌러 대기열이 판매자 멈춤, 상품 1의 라벨은 앞서 출력함, 상품 2·3의 자동 작업이 대기
- When 라벨 기능을 끈다(확인 창에 "출력 대기 중인 라벨 2장은 출력하지 않고 남겨 둬요. 다시 켜면 '출력 시작'을 눌러 이어서 출력할 수 있어요.") → 상품 1의 1등을 취소한다
- Then 두 기기 알림 띠에 "버릴 라벨 1"이 보이고 "출력 멈춤"은 보이지 않는다. `/labels`는 "라벨 쓰지 않음" 안내와 버릴 라벨 절만 보인다. 휴대폰에서 "버렸어요" → 두 기기에서 사라진다.
- When 라벨 기능을 켠다
- Then 판매자 멈춤이었으므로 그 멈춤 그대로("다시 시작")이고, 대기 2장은 그대로 있다. "다시 시작"을 누르면 2·3이 순서대로 출력된다(프린터 그림 = 상품 1(앞서)·2·3).
- Then 변형: 멈추지 않은 대기열에서 끈 경우(출력 기기가 끊겨 대기 2장이 남은 상태)는 켤 때 쌓인 라벨 안내 "대기 중인 라벨 2장이 있어요. 출력 시작을 누르면 먼저 들어온 것부터 출력해요."와 "출력 시작"이 보이고, 누르기 전에는 출력하지 않는다.
- 확인: E2E

### AC-N4a-32 [web] 꺼진 판매자의 화면 둘러보기 (휴대폰·PC)
