## A. 개인정보 — 전화번호 키 (DAT-06, BUY-02, ORD-08 AC4, R-1, R-11, D-061)

### AC-S03b-01 [core] `sms` 이벤트 모양과 입력 오류
- 근거: R-1 `sms` 행·"문자찜 `ref`와 전화번호"·"입력 오류와 맞지 않는 명령", D-050, D-061
- Then 엔진 `sms` 이벤트 타입은 `phone`이 없고 선택 필드 `phoneKey`·`phoneLast4`를 갖는다. 코어는 `normalizePhone`을 계속 내보내고(서버·화면·골든 러너 공용), 서버가 쓸 뒤 4자리 도우미도 내보낸다.
- Given 선언된 방송이 있는 상태
- When `applyEvent`·`checkEvent`에 다음 `sms`를 넣는다
  - `phone` 필드가 있음(값이 무엇이든, `phoneKey`와 함께여도)
  - `phoneKey`만 있음 / `phoneLast4`만 있음
  - `phoneKey`가 15자·129자·빈 문자열, 영문·숫자·`_`·`-` 밖의 글자(공백·`+`·`=`·`/`·한글)를 포함, 문자열이 아님
  - `phoneLast4`가 `"567"`·`"56789"`·`"５６７８"`(전각)·`"12a4"`·수 `5678`
  - `ref`가 빈 문자열·65자·영문·숫자·`_`·`-` 밖의 글자 포함(`"김영희"`·`"s 1"`·`"s:1"`·`"010-1234-5678 "`)
- Then 입력 오류(`InvalidEventError`)를 던지고 넘긴 상태는 바뀌지 않는다. `checkEvent`는 같은 경우에만, 문제 필드 이름과 함께 문제를 돌려준다.
- Then 받는 경계: `phoneKey` 16자·128자, `phoneLast4` `"0000"`, `ref` 1자·64자·`"a-b_C9"`. 숫자만으로 된 `ref`(서버 일련번호)도 받는다.
- 확인: 단위 테스트, 속성 테스트(AC-S03-02의 "검사 함수 = 입력 오류 판정"에 새 필드 포함)

### AC-S03b-02 [core] 전화번호 키로 잇기와 뒤 4자리
- 근거: R-11 "문자찜 구매자 정하기" 1·2·3, BUY-02, ORD-08 AC4, D-051, D-061
- Then 구매자 정하기 순서는 지정 구매자 → 전화번호 키 → 새 문자 구매자다. 같은 `phoneKey`면 같은 문자 구매자이고, 뒤 4자리만 같고 키가 다르면 다른 구매자다(G-ENG-150의 `010-7777-5678`).
- Then 새 문자 구매자의 뒤 4자리 = 그 구매자를 만든 문자찜의 `phoneLast4`. 키 없이 만든 문자 구매자와 유튜브 구매자는 `null`. 같은 키에 다른 `phoneLast4`가 와도 그 구매자의 뒤 4자리는 바뀌지 않는다(단위 테스트).
- Then 지정 구매자가 있으면 `phoneKey`를 보지도 기록하지도 않는다 — 나중에 같은 키로 온 문자찜은 지정 구매자와 이어지지 않고 새 문자 구매자가 된다(G-ENG-150의 s4·s5).
- Then 구매자 보기의 전화번호 정보는 뒤 4자리(`phoneLast4`)뿐이다.
- 확인: 골든(G-ENG-150·151, 기존 G-ENG-055·100·102 그대로 통과), 단위 테스트(키를 직접 넣은 이벤트)

### AC-S03b-03 [core] 엔진 상태·효과에 전화번호가 없다
- 근거: DAT-06, R-11 개인정보 문장, R-13, YT-04 AC1, D-061
- Given 무작위 휴대폰 번호(여러 형식)를 서버처럼 정규화·키로 바꿔 넣은 로그(테스트 안에서 HMAC 등으로 키를 만든다)
- Then 매 이벤트 뒤 상태를 JSON으로 직렬화한 문자열, 모든 효과(필드 전부)·효과 ID·찜 ID·구매자 ID 어디에도 입력한 번호 원문과 정규화한 번호(숫자 10~11자리)가 없다.
- Then 효과·효과 ID·찜 ID·구매자 ID에 `phoneKey`·메모가 없다. 감사 문구는 R-13 공식 그대로다(문자찜 이름은 `문자찜`).
- Then 상태 형식(번호)은 dev-core가 정한다. 저장된 엔진 상태가 아직 없으므로(S04 전) 이전 형식을 읽는 길은 만들지 않는다.
- 확인: 속성 테스트, 단위 테스트

### AC-S03b-04 [core] 골든 어댑터 — 서버 흉내
- 근거: README "규칙"의 문자찜 문단·`sms` 행, D-061
- Then 어댑터는 골든 `sms`의 `phone`을 코어 `normalizePhone`으로 정규화해, 결과가 없으면 전화번호 없이, 있으면 `phoneKey`(정규화한 번호마다 다르고 같은 번호면 같은 결정적 키, 16~128자 영문·숫자·`_`·`-`, 번호 숫자를 그대로 담지 않음 — 예: 테스트 전용 비밀 키의 HMAC-SHA256 base64url)와 `phoneLast4`(정규화한 번호의 뒤 4자리)를 넘긴다. `phone`은 엔진에 넘기지 않는다.
- Then 어댑터는 판정·합계를 다시 계산하지 않는다(AC-S03-91 그대로).
- 확인: 코드 검사, 러너 자체 테스트(G-ENG-150을 돌린 뒤 상태에 `01012345678`·`01099990000`·`01077775678`이 없음)
