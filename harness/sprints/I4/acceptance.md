- 스프린트: I4 (4단계) · spec ID: **VOC-01**, **VOC-02**, **VOC-03**, **VOC-04**, **VOC-05**, **PRD-06** (연결: PRD-01 AC3·AC4, PRD-03 AC3, UX-01, UX-03, UX-04, UX-05, UX-06, NFR-03, NFR-05, NFR-06, NFR-08, DAT-06, SPEC §8 4단계 완료 기준, §9 HG-4) · 규칙: DOMAIN_RULES v0.1.14 R-14, R-15, **R-17 3·4 보강**(끊어 말한 번호) · 근거 결정: **D-I4-01~D-I4-09**(AUTO), D-202~D-205, D-083, D-084, D-087, D-094

- 공통 전제: S00~S06·P2까지의 결과(`pnpm verify` 7단계 — typecheck·lint·test·golden·adversarial·coverage·e2e, 골든 러너, 코어 순수성 린트, 코어 커버리지 95%, 판정 엔진, 서버·라이브 콘솔·문자찜·구매자·정산 화면, 음성·문서 패키지)가 그대로 유지된다. 외부 계정·실기기·마이크·네트워크·도커는 필요 없다. E2E는 Playwright(크로미움)로 돌고, 이 작업 폴더의 E2E가 도는 명령엔 `E2E_PORT_OFFSET=600`을 붙인다.
- 가짜 음성 인식(시험 계약): 시험은 페이지를 열기 전에 `page.addInitScript`로 `window.SpeechRecognition`·`window.webkitSpeechRecognition`을 가짜 생성자로 바꾸거나 지운다. 화면은 "음성 켜기"를 누를 때 `window`에서 생성자를 찾는다(P2 `WebSpeechEngine` 기본 동작) — **화면 코드에 시험용 갈림길·전역 훅을 두지 않는다.** 화면의 시각은 `Date.now`와 브라우저 타이머로 잰다(시험이 `page.clock`으로 당길 수 있게).
- 정답의 우선순위: 골든 → DOMAIN_RULES·SPEC 규칙 문장 → DECISIONS → 이 문서. 규칙 문장으로도 정해지지 않는 경우를 찾으면 구현으로 정하지 말고 dev-notes·결과의 `disputesWithSpec`으로 올린다(dev-common).
- 태그: `[device]` = dev-device(`packages/voice/**`, 그리고 AC-I4-95의 코어 러너 합계 교체), `[web]` = dev-web(`apps/web/**`). 의존 순서는 device → web(추출기 보강·경계 시험 변경을 먼저). dev-device는 바뀐 것(끊어 말한 번호, 스크립트 명령)을 `harness/sprints/I4/dev-notes.md`에 먼저 적는다.
- 화면 문장 중 이 문서가 따옴표로 정한 것은 그대로 쓴다(E2E가 글자로 찾는다). 바꿔야 하면 dev-notes에 이유를 남기고 spec-keeper가 판정한다. 금액은 늘 "15,000원"처럼 코어 `formatWon` 모양이다.

## A. 음성 패키지 보강 (VOC-02·04, R-17, D-I4-01·02·08·09)

### AC-I4-01 [device] 끊어 말한 번호 (TD-P2-002)
- 근거: R-17 3·4, D-I4-01, D-202
- Given 사전 `[핑크프릴, 라울, 블루엘프]`, `claim.maxNumber` 999
- When `extractVoice`를 부른다
- Then 번호 표시마다 `X` 바로 앞 토큰(붙여 쓴 꼴은 표시 토큰의 앞 토큰, 띄어 쓴 꼴은 `X` 토큰의 앞 토큰 — 끝 문장 부호를 지운 토큰 그대로, 끝말을 떼지 않는다)을 `X` 앞에 공백 없이 붙인 글을 코어 `parseKoreanNumber`(R-15)로 읽는다. 수가 되면 끊어 말한 번호다. 하나라도 있으면 결과의 `no`·`price`는 `null`, `confidence`는 `LOW`. 품종은 평소대로(번호 표시 토큰·가격 묶음 토큰은 가격을 비웠어도 품종 창에서 빠진다).
- Then 예(골든): `1 5번 핑크프릴 만오천 원`·`1, 5번 라울 만원`·`1 5 번 라울 만원`·`십 오번 라울 오천 원`·`이 십 번 블루엘프 칠천 원`·`이 십오번 핑크프릴 만원`·`백 오번 라울`·`2 15번 핑크프릴 만원`·`백 이십 삼번 라울 만원`·`15번 1 5번 핑크프릴 만원` → 품종만, `LOW`. `이 15번 핑크프릴 만원` → 15번·핑크프릴·10,000원 `HIGH`, `네 15번 라울 오천 원` → 15번·라울·5,000원 `HIGH`.
- Then 그래서 이런 문장엔 카드가 생기지 않는다(번호도, 품종·가격 짝도 없다 — D-204). 기존 69사례의 결과는 하나도 바뀌지 않는다.
- 확인: 골든(`voice-extract.yaml` 81사례 전부), 단위 테스트, 속성 테스트(임의 문장·사전 → 끊어 말한 표시가 있으면 `no`·`price`가 `null`이고 `LOW`, `HIGH`인 결과의 문장엔 끊어 말한 표시가 없다)

### AC-I4-02 [device] 열린 카드 3장 예외 (SA-P2-004)
- 근거: D-204, D-I4-02, SPEC VOC-04
- Then `addCard`: 새 카드는 맨 앞이고 언제나 열린 채로 들어간다. 손댄 열린 카드는 `addCard`가 닫지 않는다. 열린 카드가 3장을 넘으면 손대지 않은 가장 오래된 열린 카드부터 닫는다. 결과의 열린 카드 수 ≤ max(3, 손댄 열린 카드 수 + 1). 동작은 P2 그대로이고(코드 변경 없음), 함수 설명이 D-I4-02를 가리킨다.
- 확인: 단위 테스트(손댄 카드 3장 + 새 카드 → 4장, 이어서 새 카드 → 4장이고 앞의 손대지 않은 새 카드가 닫힘), 속성 테스트(만들기·손대기·확정·닫기·넣기를 임의 순서로 → 위 상한, 손댄 카드는 넣기로 닫히지 않음, 넣은 카드는 열림)

### AC-I4-03 [device] 정확도 측정 스크립트 (SPEC §8 4단계, HG-4)
- 근거: D-I4-08, R-17
- Given 표본 파일: UTF-8 CSV(맨 앞 BOM 허용, 줄 끝 CRLF·LF 허용, 큰따옴표로 감싼 칸 안의 쉼표·큰따옴표(`""`)·줄바꿈 허용), 첫 줄 열 이름 정확히 `표본,기대 번호,기대 가격,기대 품종,인식 문장`
- When `packages/voice`의 package.json 스크립트 `accuracy`로 연다(예: `pnpm --filter @livejjim/voice accuracy <표본 파일>` — 정확한 명령은 스크립트 머리말과 dev-notes에 적는다). 선택: `--dictionary <파일>`(UTF-8, 한 줄에 이름 하나, 빈 줄 무시 — 판매 이력처럼 기본 사전 앞에 붙인다), `--max-number <1~9999>`(기본 999), `--out <파일>`(보고서를 파일로도 쓴다)
- Then 칸 뜻: `기대 번호` = 1~9999 정수 또는 빈칸("번호를 말하지 않음"), `기대 가격` = 100 이상 정수 원(숫자만 또는 천 단위 쉼표) 또는 빈칸("가격을 말하지 않음"), `기대 품종` = 글 또는 빈칸(빈칸이면 품종은 채점하지 않음), `인식 문장` = 글(빈칸이면 빈 문장).
- Then 표본마다 `extractVoice(인식 문장, { maxNumber, dictionary: 이력 이름 + DEFAULT_DICTIONARY })`(골든과 같은 함수)로 뽑고 칸마다: **맞음** = 뽑은 값이 기대와 같음(기대가 빈칸이면 뽑은 값도 없음, 품종은 공백을 뺀 모양으로 비교), **빈칸** = 기대가 있는데 뽑은 값 없음, **틀림** = 뽑은 값이 있는데 기대와 다름(기대가 빈칸인데 뽑은 것 포함).

## L. 테스트 관점

개발자 보고를 믿지 말고 위 기준을 공격한다. 기대값은 구현을 보고 정하지 않는다 — R-17·골든·D-I4-*로 손 계산한다. 검증 파이프라인 자체는 공격 대상이 아니다(D-027). **비례 원칙(D-036)**: 기본 설정과 실제 방송에서 나올 법한 말·조작을 먼저 본다. 심각도는 "판매 사고(방송자 확인 없이 엉뚱한 번호·가격의 상품 등록, 같은 상품 두 번 등록, 판매 기록 손실, 말·개인정보가 서버·저장소로 나감, 음성 때문에 콘솔이 멈춤)로 이어지는가"로 매긴다.

## HG-4 확인 목록 (최종 보고에서 판매자가 직접)

자동 시험으로 대신할 수 없는 "실제 목소리·마이크·방송 소리에서 쓸 수 있나"를 본다. 약 40분. 결과는 사용자가 DECISIONS 표의 해당 결정을 확정(`ACCEPTED`)하거나 바꾼다(`CHANGED`).

1. **표본 만들기**: 실제 방송처럼 말한 녹음 20개(휴대폰 녹음 가능). 번호·품종·가격을 다 말한 것 12개 이상, 가격이나 번호를 빼먹은 것, `이번엔`·`한 번 더` 같은 말버릇, 잡담을 섞는다. `packages/voice/samples/accuracy-example.csv`를 복사해 표본마다 `기대 번호`·`기대 가격`·`기대 품종`을 적는다.
2. **켜기**: PC 크롬에서 리허설 방송 콘솔 → "음성 켜기" → 안내 창의 문장을 읽고 "음성 켜기" → 크롬의 마이크 질문에 "허용"(D-I4-04).
3. **인식 문장 모으기**: 표본을 스피커로 하나씩 들려주고(또는 직접 그대로 말하고) 음성 칸 "들린 말 기록"의 문장을 CSV `인식 문장` 칸에 옮긴다. 이때 카드가 어떻게 나왔는지도 본다.
4. **측정·기록**: 측정 명령(AC-I4-03)을 돌리고 보고서를 `harness/sprints/I4/hg4-accuracy.md`로 남긴다. "틀린 값을 채움"·"확실한데 틀림" 문장은 spec-keeper에게 넘겨 골든에 넣는다. "확실한데 틀림"이 하나라도 있으면 자동 확정은 꺼진 기본값 그대로 쓴다(D-I4-08).
5. **조작**: 실제 마이크로 상품 5개 등록 — Enter(1초 뒤 "Enter 등록")·"등록" 누르기·고치기·닫기, 이미 있는 번호, 자동 확정 켜 보기와 "자동 등록 멈추기", Ctrl+Z. 배경 음악·손님 응대 말 속에서 카드가 쏟아지지 않는지, 1초 기다림이 답답한지(D-I4-03·05).
6. **끄기**: "음성 끄기" 뒤 같은 방송에서 빠른 입력·충돌 처리·되돌리기 — 음성 없이도 그대로인지(VOC-05).
7. **판단**: 끊어 말한 번호를 비우는 규칙(D-I4-01), 판매 이력 범위(최근 10일, D-I4-06), 외부 전송 안내 방식(D-I4-04), 크롬 인식이 모자라 클라우드 음성이 필요한지(D-I4-07 — 계정·요금은 사용자 결정).
