### TD-I4-001 자동 확정 시각이 지난 두 번째 카드에 타이머가 없다

- 원인: `apps/web/src/voice/controller.ts` `#autoConfirm`은 한 번에 카드 하나만 등록하고(`decideAutoConfirm`의 설계 — "나머지는 그 등록 뒤에 다시 본다"), 다시 보는 것은 `#schedule` → `nextWake`인데 `nextWake`는 자동 확정 시각이 이미 지난(`at <= now`) 카드를 건너뛴다. 맨 앞 카드가 바뀌어 "Enter 등록" 타이머가 생기면 1초 늦게, 맨 앞이 그대로면 아예 다시 보지 않는다.
- 나오는 경우: 한 `onresult`에 최종 결과 둘(같은 밀리초), 기다림을 바꾼 뒤 두 카드의 시각이 같음, **창이 열린 동안 기다림이 지난 카드가 둘 이상인데 창을 닫음**(가장 흔하다), 타이머가 몇 ms 늦게 돌아 두 카드가 함께 익음.
- 결과: 카드가 "1초 뒤 자동 등록"을 보인 채 멈추고, 나중에 아무 타이머(다른 카드의 "Enter 등록" 등)가 돌 때 뒤늦게 자동 등록된다.

### 스펙 확인 필요 (시험 없음)

- 섞어 쓴 끊어 말한 번호: `1 오번`·`일 5번`·`오 오번`·`십이 오번` → 앞 토큰 + X가 R-15로 읽히지 않아(섞기·숫자 하나씩 읽기 실패) 5번 `HIGH`. 규칙 문장대로다.
- 가격의 끊어 말함: `15번 라울 1 5천원` → 5,000원 `HIGH`. R-17 4 금액 조각은 R-16 D-048보다 좁아 앞 토큰 `1`을 보지 않는다. 규칙 문장대로다.

## 라운드 1

- TD-I4-001 다시 공격: 고친 `#autoConfirm`(익은 카드를 모두 차례로)·`#schedule`(익은 카드가 있으면 바로) — 해결.
  - 판정 GATE-I4-VERIFY에 따라 `voice-controller-auto.test.ts` 두 번째 시험을 고쳤다: 맨 앞이 `LOW` 카드여도 T0 + 5초에 [15, 16] 둘 다(이전엔 "T0 + 5초에 1장"을 먼저 확인했다).
- 고침이 만든 새 길 회귀(통과, 같은 파일 `TD-I4-001 회귀` describe):
  - 같은 순간 셋 중 가운데 번호가 이미 있음 → 나머지 둘 등록, 가운데는 "고칠까요?"·자동 확정 끔·창 없음.
  - 첫 자동 등록이 창을 엶 → 남은 카드는 미루고 창을 닫으면 그때 등록(한 카드 한 번).
  - 등록 경로가 그 자리에서 카드를 되돌림(차례에서 같은 번호) → 다시 자동 등록하지 않음.
  - 기다리는 동안 번호 상한이 줄어 등록할 수 없는 카드 → 바쁜 반복(0ms 타이머 되풀이) 없이 자동 확정만 끔.
- 음성 조각 다시 받기(빌드 확인): 운영용 빌드에서 자리 글자가 `./src-<hash>.js`로 채워지고, 음성 조각은 진입 조각만 정적 import한다(이미 받은 조각) — `?retry=N` 주소로 다시 받으면 다른 조각을 다시 받을 일이 없다. 서비스 워커 목록에 음성 조각 없음.
- TD-I4-002·003(스펙 확인 필요)은 판정이 없어 그대로 둔다. 추출 결과도 그대로다(`일 5번 라울 만원` → 5번 HIGH, `15번 라울 1 5천원` → 5,000원 HIGH).
