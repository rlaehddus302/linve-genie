## 지적
- **TE-QS1-001** (minor, spec — 스펙 확인 필요): AC-QS1-44 "화면은 끊김과 '다시 연결'" — 출력 기기가 아닌 기기에서 프린터 쪽 끊김이면 지금 화면(라벨 화면 프린터 칸)에는 "이 기기의 프린터: 끊김"과 연결 방법 단추만 있고 "다시 연결"이 없다(멈춤 띠·윗줄의 "다시 연결"은 출력 기기에서만, 프린터 칸의 "다시 연결"은 연결 오류 상자가 있을 때만). QS1 앞에도 같았고 화면 파일은 금지 경로라, 시험은 끊김과 시도 0만 본다.
- **TE-QS1-002** (major, spec/오케스트레이터): 기존 E2E `tests/e2e/i1/station.spec.ts` AC-I1-70이 QS1 web 커밋 뒤 실패한다(직접 돌려 재현 — 시험용 프린터가 1초 만에 저절로 이어져 "출력 멈춤 · 프린터 연결이 끊겼어요." 알림을 기다리다 끝남). D-QS1-02대로 만든 결과라 제품 버그가 아니라 앞 시험의 전제가 바뀐 것. 금지 경로 3이라 QS1에서 고칠 수 없다 — 그 시험의 끊기 앞에 `setAutoReconnect(false)`를 넣도록 허락하거나(dev-notes "앞 E2E와 부딪힘"), 합치기 전 결정이 필요하다. 이대로면 `pnpm verify`의 E2E가 막힌다.
- **TE-QS1-003** (minor, web `apps/web/src/components/LabelsPage.tsx`): 프린터 칸 연결 오류 상자의 "다시 연결"은 `station.connect(lastMethod)`라 기억한 기기가 있어도 늘 고르기 창이다(D-QS1-01 (2) "다시 연결 = 기억한 기기"와 다름. 예: B1을 한 번 이은 뒤 "블루투스로 연결"에서 고르기 창을 닫음 → 상자의 "다시 연결"이 다시 고르기 창). 화면 파일이 금지 경로 1이라 MOB1 뒤 후속(dev-notes에 이미 적힘) — 실패 시험은 만들지 않았다.
- 참고: TD-QS1-001(출력할 때마다 60초 타이머가 다시 걸림)은 test-domain이 실패 시험으로 남겨 E2E로 겹쳐 만들지 않았다.
