## A. 화면 이동·휴대폰 (UX-04, NFR-08, SPEC §7, D-094)

### AC-S06-01 [web] 메뉴와 주소
- 근거: SPEC §7 화면 1·2·4·6, UX-04, D-094
- Given 로그인한 판매자
- Then 모든 화면에 메뉴 "방송"·"문자찜 입력"·"구매자"·"정산"이 있다(휴대폰은 위 또는 아래 고정 막대). 지금 화면의 메뉴는 `aria-current="page"`로 표시된다. 콘솔에서도 메뉴로 다른 화면에 갈 수 있다(5초 대기 중인 방송자 조치가 있으면 떠나기 전에 "보내기 전인 조치가 있어요. 떠나면 보내지 않아요."를 묻는다 — D-083).
- Then 주소: `/` 방송 목록, `/broadcasts/<방송 ID>` 콘솔, `/sms` 문자찜 입력, `/buyers` 구매자(고른 날짜·리허설·구매자는 검색값, 예 `/buyers?date=2026-10-18&buyer=UC_A`), `/settlements` 정산(같은 검색값). 주소를 새로고침·북마크해도 같은 화면이다. 전화번호·메모·사유는 주소에 넣지 않는다.
- Then 세션이 끝나 다시 로그인하면 보던 주소(검색값 포함)로 돌아간다(AC-S05-01과 같다).
- 확인: E2E

### AC-S06-02 [web] 휴대폰 화면 공통
- 근거: UX-04, NFR-05, NFR-08, UX-01, D-094
- Given 375×812(휴대폰) 화면
- Then 문자찜 입력·구매자 목록·구매자 자세히·정산 목록·정산 자세히·합치기 창·입력 창 모두: 가로 스크롤 없음(`document.documentElement.scrollWidth ≤ 375`), 본문 글자 16px 이상, 누르는 곳 44×44px 이상, 칸마다 보이는 이름(label), 마우스를 올려야만 보이는 조작 없음.
- Then 번호·금액·수신 시각 칸은 숫자 키패드가 뜬다(`inputmode="numeric"` — 수신 시각은 `inputmode="numeric"` 또는 `decimal`이어도 `오후 8:01`을 칠 수 있게 글자 입력이 막히지 않는다).
- Then PC(1440×900)에서도 같은 화면이 쓸 만하다(가로 스크롤 없음, 표는 PC에서 표, 휴대폰에서 줄 카드여도 된다).
- 확인: E2E(두 크기)

### AC-S06-10 [web] 방송 고르기
- 근거: R-0 5 "문자찜은 입력할 때 방송을 고른다(기본: 진행 중 방송)", D-081, D-089
- Given 끝나지 않은 실제 방송이 하나 이상 있다
- When `/sms`를 연다
- Then 그중 가장 최근 방송(날짜가 늦은 것, 같은 날이면 나중에 만든 것)이 골라져 있고 화면 맨 위에 "1부 · 10/18(토)"처럼 크게 보인다. 번호 칸에 포커스가 있다.
- Given 끝나지 않은 실제 방송이 없다
- Then 고른 방송이 없고 "문자찜을 넣을 방송을 골라 주세요."가 보이며 보내기 버튼을 누를 수 없다.
- When "방송 바꾸기"
- Then 방송 목록(날짜 최근 순, 제목·날짜·"진행 중"/"끝남", 리허설은 "리허설")에서 고른다. 끝난 방송도 고를 수 있다(R-1 — 늦게 넣은 문자찜도 평소대로 처리, G-ENG-170). 리허설 방송을 고르면 맨 위에 "리허설 방송이에요 — 실제 판매에 들어가지 않아요"가 늘 보인다.

### AC-S06-12 [web] 수신 시각
- 근거: ORD-08 AC1, R-6 "문자 수신 시각의 날짜"(D-023), D-089, G-ENG-169
- Then 칸 이름 "받은 시각", 비워 둘 수 있고 안내 "비우면 지금 시각(초까지)으로 넣어요". 비우면 `received`를 보내지 않는다 — 서버가 도착 시각(KST)을 `HH:MM:SS`로 적는다(AC-S06-16).
- Then 받는 형식과 읽는 값(지금 = 20:05라면):

  | 친 글자 | 읽은 값 |
  |---|---|
  | `20:01` / `2001` | 20:01 (분까지) |
  | `20:01:05` / `200105` | 20:01:05 |
  | `8:01` / `801` (오전·오후 없음, 앞자리 0 없음, 시 1~12) | 오전·오후 두 읽기를 각각 D-023으로 날짜를 정해 지금과의 거리가 짧은 쪽(같으면 이른 쪽) → 20:01. (`12:30`이면 00:30·12:30 중 가까운 쪽 — 늦으면 아래 확인이 묻는다) |
  | `오후 8:01` / `오전 8:01` | 20:01 / 08:01 |
  | `08:01` (앞자리 0) / `00:30` / `13:05` | 그대로 24시간 표기 |
  | `25:00`, `20:61`, `2:5`, 빈칸 아닌 그 밖 | 읽지 못함 → "받은 시각을 20:01처럼 적어 주세요." 보내지 않음 |

- Then 읽은 값을 칸 옆에 24시간 표기와 날짜로 바로 보인다: "오늘 20:01에 받은 문자"(날짜는 지금 시각을 입력 시각으로 보고 코어 `resolveReceivedTime`으로 정한 것 — "어제"·"오늘"·"내일"). 보내는 값은 `HH:MM` 또는 `HH:MM:SS`다.
- When 읽은 수신 시각(분까지면 그 분의 시작)이 지금보다 늦다(예: 20:05에 `20:07`, 휴대폰 시계가 빠름, `오전`을 잘못 붙임)
- Then 보내기 전에 확인 창: "받은 시각(내일 08:01)이 지금보다 늦어요. 이대로 넣을까요?" 버튼 "고치기"(처음 포커스, 아무것도 보내지 않고 시각 칸으로) / "이대로 넣기".
- 확인: E2E, 화면 단위 시험(읽기 표 전부, 자정 근처)

## HG-1 확인 목록 (최종 보고에서 판매자가 직접)

자동 시험으로 대신할 수 없는 "판매자가 실제로 쓸 수 있나"를 본다. 약 30분. 결과는 사용자가 DECISIONS 표의 해당 결정을 확정(`ACCEPTED`)하거나 바꾼다(`CHANGED`).

1. **PC 리허설**: 홈 → "리허설 해 보기" → 가짜 채팅 300건 시작 → 빠른 입력으로 상품 10개 등록(`15 핑크프릴 10`, `15번 핑크프릴 만원` 같은 평소 말투) → 충돌·취소 요청·보류 찜 알림을 한 번씩 처리 → 등록 하나를 Ctrl+Z로 되돌리기 → 찜 하나를 취소(사유 숫자 키). 헷갈린 낱말·버튼·5초 대기가 방해되는지 적는다(D-083·D-084·D-087).
2. **휴대폰 설치**: 같은 계정으로 휴대폰 크롬(또는 아이폰 사파리)에서 로그인 → "앱으로 설치"(또는 홈 화면에 추가) → 홈 화면 아이콘으로 다시 열기(D-093).
3. **휴대폰 문자찜**: 리허설 방송을 골라 문자찜 5건 — 전화번호 있는 것, 메모만, 구매자 고르기, "같은 사람 하나 더", 휴대폰에 보이는 대로 받은 시각 적기(`오후 8:01`). 한 손으로 넣을 만한지, 결과 문장이 이해되는지(D-089).
4. **구매자**: 문자 구매자 하나를 유튜브 시청자와 합치기 → 미리 보기 문장 → 떼어 내기(D-090·D-091).
5. **정산**: 입금 2건(하나는 남은 금액과 다르게 → 확인 창), 직접 수령 1건, 할인 1건, 입금 하나를 일부러 잘못 적고 환불로 바로잡기. 요약 합계가 손 계산과 맞는지(D-092).
6. **판단**: 글자 크기·버튼 크기·화면 이동, 리허설과 실제 방송 구분, 판매 규칙 기본값(D-003~D-018)과 AUTO 결정(D-081~D-096) 중 바꾸고 싶은 것.
