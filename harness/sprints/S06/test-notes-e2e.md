  - standalone 흉내는 CDP `Emulation.setEmulatedMedia`가 Playwright 자체 미디어 흉내에 덮여 init script로 `matchMedia`를 바꾼다.
  - AC-S06-90 재생의 `phoneKey`는 코어 형식(16~128자)이라 `test-phonekey-<뒤 4자리>`를 쓴다(dev-notes 예 `test-<뒤 4자리>`는 짧아 코어가 거절).

## 새 시험 (`tests/e2e/s06/attacks-r1.spec.ts`, 모두 통과 — 회귀로 남김)
- RA-S06-001: 브라우저 뒤로 가기 → "보내지 않고 떠나기"면 보내지 않음 / 창을 연 채 4.5초(대기 2초보다 길게) 보내지 않음 → "닫기"면 보던 주소로 돌아가 한 번 보냄 / 창이 열린 채 뒤로 두 번 → "닫기" 한 번에 남고 한 번만 보냄 / 콘솔에서 뒤로(방송 목록).
  - 주의: `page.goto`로 만든 기록 사이의 뒤로 가기는 문서 이동이라 앱 창이 아닌 beforeunload가 뜬다. 앱 창을 보려면 앱 안 이동(링크·버튼)으로 기록을 만든다.
- 새로고침: `beforeunload` 확인이 뜨고 새로고침 뒤 차단이 기록되지 않음.
- 문자찜 화면에서 찜 취소 대기 중 "방송 바꾸기": 취소가 한 번 기록되고 "보내지 못했어요"·"저장하지 못했어요"가 뜨지 않음.
- UX-S06-002: 보낸 뒤 "넣은 결과"와 번호 칸이 화면 안(375×812·1440×900).
- AC-S06-82(SA-S06-005 남은 몫): 입금 503 SAVE_FAILED(저절로 다시 보내도 같은 요청 번호 → "다시 보내기" → 한 번 기록), 합치기 500 PROCESSING_FAILED "확인 필요"·다시 보내지 않음, 할인 401 → 로그인 → 같은 정산 주소.
- AC-S06-40(SA-S06-005 남은 몫): 휴대폰 합치기 → PC 구매자 목록 1초(5번).
- AC-S06-20·30 `@fill`(chromium-fill): 자료를 받은 뒤 구매자 목록 94ms·정산 목록 105ms·"찜 없는 구매자도 보기" 27ms, 50ms 넘는 긴 작업 없음(이 PC).
- 연타: 입금·환불 dblclick, 문자찜 Enter 두 번·버튼 dblclick → 각각 한 번만 기록.
- AC-S06-41·61: 375×812 문자찜 입력에서 410 뒤 전체 다시 받기 실패 안내가 끝까지 내려도 화면 안, 회복되면 사라지고 그사이 문자찜이 보임.
