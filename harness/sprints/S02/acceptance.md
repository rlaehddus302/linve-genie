### AC-S02-01 [core] 엔진 공개 API
- 근거: R-0.1, R-1, D-024, S00 API(`initEngine`·`applyEvent`)
- Given `@livejjim/core`
- Then 다음을 export하고, 어느 것도 S02 범위 입력에서 `NotImplementedError`를 던지지 않는다.

  | 이름 | 하는 일 |
  |---|---|
  | `initEngine({ broadcasts, settings })` | 새 엔진 상태. `settings`는 DOMAIN_RULES 기본값 위에 덮어쓴다(`resolveSettings` 재사용, 기본값을 따로 적지 않는다) |
  | `applyEvent(state, event)` | `{ state, effects }`. `effects` = 이 이벤트로 **새로 나온** 효과(각각 효과 ID·종류·대상·상품·구매자·문구·확정버전). 효과의 취소·완료는 상태에 남고 조회 함수로 본다 |
  | 조회 함수(이름은 dev-core가 정한다) | 상품(상태·1등·대기·가격), 찜 전체(생성 순서, 상태·사유), 보류 찜(번호별, 판정 순위 순), 구매자(표시 이름·닉네임 이력·확정 품목·합계·방송별), 정산 묶음(구매자·날짜별, AC-S02-81), 효과 전체(상태 포함), 처리 대기 취소 요청 |
  | `checkInvariants(state)` | 한 상태만 보고 확인할 수 있는 불변식(INV-1·2·5·6·7·9) 위반 목록. 서버 재생 무결성 검사(S04)가 다시 쓴다 |

- S00 단위 테스트 "코어 API는 미구현을 알린다"의 `initEngine`·`applyEvent` 항목은 이 기준의 테스트로 바꾼다. 스펙이 바뀌어서 하는 교체이지 테스트 약화가 아니다.

### AC-S02-02 [core] 순수·결정성·직렬화
- 근거: R-0.1·R-0.2, NFR-02, INV-4, D-024, D-026, RA-S00-001
- Then `applyEvent`는 넘긴 상태·이벤트를 바꾸지 않는다(깊게 얼린 입력으로 호출해도 예외 없이 같은 결과).
- Then 같은 설정·같은 이벤트 로그를 처음부터 두 번 적용하면 각 단계의 상태·효과가 직렬화 수준에서 같다. 실행 환경의 시간대(`TZ`)·언어 설정과 무관하다.
- Then 상태는 JSON으로 직렬화할 수 있는 순수 데이터다(객체·배열·문자열·유한한 수·불리언·`null`. 함수·`Map`·`Set`·클래스 인스턴스·`undefined` 값 없음). 어느 시점의 상태를 `JSON.parse(JSON.stringify(state))`로 왕복한 뒤 나머지 로그를 이어서 적용해도 결과가 같다(S04 스냅샷·재생 대비).
- Then 효과 ID(`{찜ID}:{효과종류}:{대상}:{확정버전}`, R-13)와 찜ID는 같은 로그면 항상 같고, 한 상태 안에서 서로 겹치지 않는다.
- Then 코어 순수성 린트(AC-S00-05)를 그대로 통과한다. `@livejjim/core`에 런타임 의존성을 추가하지 않는다.
- 확인: 속성 테스트(fast-check), 단위 테스트
