# INV1 수용 기준 — 초대받은 유튜버 방송 (사장님 계정으로 잇기·읽기·감사)

- 스프린트: INV1 · spec ID: **YT-02**(새 "초대받은 방송"), 연결: YT-04·YT-05·YT-06·YT-10(AC12·AC13)·NFR-10·DAT-05 · 근거 결정: **D-PHN-17~D-PHN-21·D-PHN-24**(사용자 결정 2026-10-30 + AUTO), 개정한 기존 결정: D-Y03(채널 조건)
- 사용자 결정(2026-10-30, 말 그대로): "사장이 왜 채팅을 쳐. 유튜버랑 한 공간에 같이 있고 말로 할텐데. 그리고 감사 채팅은 사장 계정으로 남기면 되겠지."
- 개발 영역: **server**(`apps/server/**` 유튜브 잇기·이은 기록·발송함·확장 회차 채널), **web**(`apps/web/**` 잇기 확인 줄·콘솔 한 줄, `apps/extension/**`·확장 문구) · 테스트: **e2e**(`tests/e2e/inv1/**`), **domain**(적대 — 남의 채널 잇기 확인 우회) · **core 없음** — 판정·정산 규칙·엔진·골든은 바꾸지 않는다(엔진은 `owner` 값만 받는다).
- 골든: 없음(판정·정산·파서 규칙 변경 없음).
- 낱말: "내 채널" = 사장님이 YT-01로 연결한 채널. "방송 채널" = 붙여 넣은 영상의 채널(`snippet.channelId`). "초대 방송" = 방송 채널 ≠ 내 채널인 이은 방송. "글 올리는 계정" = 잇는 때 연결돼 있던 사장님 채널(지금 이은 기록의 `channelId`).
- **실제 유튜브에서 사장님 계정만으로 남의 공개 라이브를 읽고 쓸 수 있는지는 확인하지 못했다.** 시험은 가짜 구글 서버(남의 채널 영상 추가)로 하고, 실물은 HG-INV.
