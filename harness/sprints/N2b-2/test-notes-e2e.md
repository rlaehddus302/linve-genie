## 실패 시험으로 남긴 지적

- **TE-N2b-2-001** (`layout.spec.ts`) — 375×812 콘솔에서 틱톡 알림 줄(58px)·인스타그램 알림(138px — 긴 문장 + 닫기)·붙여넣기 결과(57px)가 고정 영역(`.console-sticky`)에 쌓여 기존 알림 띠·빠른 입력·되돌리기(201px) + 메뉴(53px)와 합쳐 **541px(화면의 67%)**. AC-N2b-2-60 "고정 영역은 화면 높이의 35% 이하(UX-04 — 기존 시험의 284px)". 틱톡 알림 줄 하나만 더해도 254 + 58 = 312px로 넘는다. dev-notes(화면) 1의 "고정 영역에는 한 줄만 더한다"와도 다르다(셋까지 쌓인다).
- **TE-N2b-2-002** (`dm.spec.ts`) — 감사 DM 자동 발송을 켜지 않은 판매자가 인스타 댓글 판매를 하면 감사 행이 `FAILED(NO_CONSENT)`로 생기고, 콘솔 인스타그램 칸이 "감사 DM 1건을 보내지 못했어요. 인스타그램 앱에서 직접 보내 주세요."를 보인다. AC-N2b-2-63의 셀 목록은 `FAILED`·`GAVE_UP`·`EXPIRED`·`UNCONFIRMED`·라이브 끝남 — 동의하지 않음은 없다(SPEC YT-06 화면: "동의하지 않음·방송을 잇지 않음은 세지 않는다"). 원인: `apps/web/src/lib/platforms.ts` `failedDmCount`가 `status === 'FAILED'`이면 이유를 보지 않고 센다(dev-notes "화면에게" 3의 "이유 무엇이든"도 같은 셈).
- **TE-N2b-2-003** (`attacks.spec.ts`) — 틱톡 잇기 응답(`{ link }`, 상태 `CONNECTING`)이 실시간 알림(`tiktok LINK`, `CONNECTED`)보다 늦게 오면 콘솔 틱톡 칸이 늦은 응답으로 덮여 "틱톡에 연결하는 중이에요."에 머문다(서버는 `CONNECTED`, 다른 화면은 "받고 있어요"). 다음 상태 알림이 올 때까지 — 가짜 웹캐스트에서는 끝까지 — 그대로다. 원인: `ConsolePlatforms.tsx` `TikTokPanel`의 `link`·`unlink`·`reconnect`가 응답을 `setTtLink`로 그대로 넣는다(버전 확인 없음 — 같은 일이 인스타그램 `setIgLink`에도 있다). 이 문제로 다른 시험의 "받고 있어요" 확인이 들쭉날쭉해서, 잇기 도우미는 서버 조회로 연결을 확인한다.

## 시험 환경 메모

- 가짜 웹캐스트의 실패 대기열(`/fail`·`/block`)은 서버 전체 하나다 — 막힘을 쓴 시험은 그 판매자의 다시 시도가 막힘을 다 쓸 때까지(문장으로) 기다린다.
- 이어 둔 연결은 가짜 웹캐스트가 자료를 보내지 않아 120초마다 멈춘 연결로 보고 다시 붙는다(AC-40) — 서버 전체 시도 한도(60초에 30번, AC-42)를 나눠 쓰므로 시험마다 끝에서 틱톡을 끊는다. 잇기는 한도에 밀릴 수 있어 90초까지 기다린다.

## 스펙 확인 필요 (시험 없음)

- 끊겼다 저절로 다시 붙은 뒤(`CONNECTED` + `missed`) 알림 줄 "틱톡 댓글이 들어오지 않아요. 댓글을 직접 붙여 넣어 주세요."가 계속 보이는데, "다시 연결"은 `CONNECTED`에서 보이지 않아 `missed`를 끌 방법이 없다(AC-35 "다시 연결을 누르면 missed가 꺼진다"와 AC-62 표시 조건이 맞물리지 않음). 댓글이 실제로 들어오는데 붙여 넣으라고 하면 이미 들어온 댓글을 다시 넣어 같은 사람이 둘(틱톡·문자)로 찜하게 된다.
