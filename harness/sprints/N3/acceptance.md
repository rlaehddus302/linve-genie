# N3 수용 기준 — 입금 확인(계좌 연동): 입금 내역 수집·자동 매칭·확인 대기열

- 스프린트: N3 (5단계, 병렬 트랙 worktree `n3` · 브랜치 `track/n3-deposit`) · spec ID: **PAY-01**, **STL-07**, **STL-09**, **DAT-06** (연결: STL-01, STL-03, R-7 3, R-11, R-12, BUY-01, UX-01, UX-03, UX-04, NFR-01, NFR-02, NFR-06, NFR-07, SYS-02, DAT-02, DAT-05, YT-09) · 규칙: **DEPOSIT_RULES v0.1.0 DP-0~DP-8·DP-INV-1~5**(새 규칙서), DOMAIN_RULES v0.1.13 R-0 6·R-1·R-7 3·R-11·R-12(변경 없음) · 근거 결정: D-036, D-058, D-061, D-069, D-073, D-074, D-081, D-085, D-092, D-098, D-101, D-903, **D-N3-01~D-N3-12**
- 개발 영역: **server**, **web** · 테스트: **domain**(`tests/adversarial/n3/**`), **e2e**(`tests/e2e/n3/**`) · 사람 확인 지점 없음(실제 팝빌 계약·연동 키·은행 빠른조회 등록·실계좌 확인은 사용자 몫 — DECISIONS "사용자 확인 필요"의 "팝빌 계좌조회 실계약", 막지 않음)
- **dev-core·dev-device가 없다.** 판정·정산 규칙과 엔진(`packages/core/src`)은 바꾸지 않는다. 입금 확인이 엔진에 남기는 것은 손으로 적는 입금과 같은 `settlement.payment`, 되돌리기는 `settlement.refund`뿐이다. 예외는 AC-N3-04의 골든 러너 ID 형식·자체 시험 합계 교체(dev-server, I1 AC-I1-80과 같은 방식).
- 목표(백로그): 정산 묶음의 입금을 자동으로 확인한다(STL-07 확장). 입금 내역 원천은 어댑터 — 계좌조회 API(팝빌 EasyFinBank 형식, 빠른조회 등록 계좌, 1~5분 주기), 입금 내역 붙여넣기/CSV(빠른조회 미지원 은행 대비), 가짜 원천(시험). 매칭: 금액 정확히 같음 + 입금자명 정규화와 구매자 닉네임·메모·실명 후보 비교. 확실한 1:1만 자동으로 `settlement.payment` 기록, 동명·같은 금액 여럿·이름 불일치는 "확인 필요" 대기열에서 판매자가 한 번에 확정/다른 묶음 지정/무시. 같은 입금이 두 번 반영되지 않게(입금 ID 멱등), 판매 기록 이전 입금은 매칭하지 않음. 계좌 비밀번호 등 비밀값은 암호화 저장·로그 금지. 실제 팝빌 계약·은행 빠른조회 등록은 사용자 몫(가짜 원천으로 시험).

## API 뜻 (dev-server가 dev-notes에서 경로 이름을 확정한다)

모든 경로는 기존 `/api` 규칙(D-074: 세션, 상태를 바꾸는 요청의 `Origin`·JSON·64KB, 요청 번호 `requestId`, 다른 판매자 자원은 404, `Cache-Control: no-store`, 받은 값을 오류에 되돌려 보내지 않음, 모르는 항목은 400 `UNKNOWN_FIELD`)을 따른다.

| 뜻 | 요청 | 응답·동작 |
|---|---|---|
| 입금 목록 | 상태(확인 필요·자동 확인됨·확인함·무시함) + 이어 받기(입금 번호 앞) + 개수(1~200) | 입금 번호 내림차순. 입금마다 번호·원천 표시 이름·거래 시각과 정밀도·금액·입금자명·상태·반영한 묶음(날짜·구매자·구매자 표시 이름)·처리 시각. 확인 필요 입금엔 볼 때 다시 계산한 사유·쌍둥이 번호·제안 묶음(5개까지)·미리 고른 묶음(AC-N3-23) |
| 확인 필요 수 | — | `{ review: 수 }` (메뉴 표시) |

### AC-N3-11 [server] 같은 입금은 한 번 (DP-INV-4)

### AC-N3-14 [server] 받아 오기 주기·지금 받아 오기·원천 상태

- 확인: 서버 단위(주입 시계·가짜 전송), 적대

### AC-N3-15 [server] 계좌조회(팝빌 EasyFinBank 형식) 어댑터

- Then "계좌 관리 주소"는 어댑터가 팝빌에서 받은 주소를 그대로 돌려준다(저장하지 않는다, 가짜 전송은 시험용 주소).

- **맞추기 속성**(fast-check, 순수 함수): 무작위 묶음·입금 열에서 (1) 자동 확인은 M이 정확히 하나이고 S ≤ 1이고 쌍둥이가 없을 때뿐, (2) 자동 확인된 묶음은 그 순간 남은 금액 = 입금 금액, (3) 같은 묶음이 한 열에서 두 번 자동으로 채워지지 않는다(남은 금액이 음수가 되지 않는다), (4) 판매 시각보다 이른 입금·30일 밖·빈 이름은 자동 확인되지 않는다, (5) 제안은 5개 이하·중복 없음·미리 고른 묶음은 제안 안, (6) 같은 입력 두 번 = 같은 출력.
- **붙여넣기 퍼징**: 무작위 글(제어 문자·긴 줄·따옴표 짝 안 맞음·이모지·수식 모양 `=`·`+`·`@`·전각 숫자)에서 함수가 예외를 던지지 않고, 읽은 줄은 금액 1~100,000,000·`at` 형식·이름 40자 이하, 출금 모양 줄(입금액 0·구분 "출금"·`-` 금액)은 절대 `rows`에 없다.
- **무작위 처리 열** (서버): 받아 오기·붙여넣기(겹침·재붙여넣기)·확정·무시·다시·되돌리기·한꺼번에·재전송·동시 요청·손 입금·배송비 예외·1등 취소·합치기·떼어 내기·서버 재시작을 섞고 매 단계 DP-INV-1~5와: 입금 확인이 적은 기록은 실제 범위에만, 자동 확인됨 입금마다 그 기록 시점 남은 금액 = 입금 금액, (판매자, 원천, 외부 키) 유일.
- **격리·비밀값·로그**(AC-N3-10·16): 다른 판매자 번호·원천·기억한 이름으로 모든 경로, 비밀번호 모양 항목, 데이터베이스 평문 검사, 로그 모으기. **시험 모드 경로**(AC-N3-17)가 운영 구성에 없음. **원천 실패**(AC-N3-14·15): 전송이 느림·끊김·이상한 응답·쪽 무한 반복이어도 판매 쓰기가 멈추지 않고 입금이 지어지지 않는다.

### test-e2e (`tests/e2e/n3/**`, Playwright 크로미움 + 시험 모드 가짜 원천)
- 기다림은 상태로(`waitForTimeout` 금지). 기대값은 스펙·골든·코어 재생으로 계산한다(구현을 보고 정하지 않는다).
