## 찾은 것
- **TE-TTX-001 (major, web — `apps/extension/src/tiktok-outbox.ts`)**: TD-TTX-001을 실제 확장·실제 서버로 재현. 확장 틱톡 묶음이 500을 받아 다시 보내기를 기다리는 동안 남의 방송으로 잠깐 갔다 돌아오면(대기열이 빔), 돌아온 뒤 붙은 "16"은 30초가 지나도 기록되지 않는다. 그동안 콘솔은 "확장으로 받는 중"(상태는 계속 감), 팝업은 "잠시 뒤 다시 시도해 주세요."에 멈춰 있고 붙여넣기 알림 띠도 없다 — 판매자가 모르는 채 댓글을 잃는다. 원인은 `flush()`가 대기열이 비면 `#waitUntilRetry`를 풀기 전에 돌아가는 것.
- **TE-TTX-002 (minor, 스펙 확인 필요 — web `ConsolePlatforms.tsx`)**: "확장으로 받는 중"인 동안에도 틱톡 칸 굵은 상태 문장은 직접 연결 문장 그대로 "…다시 시도하는 중이에요. 그동안 댓글을 직접 넣어 주세요."(SIGN_FAILED·BLOCKED)다. 띠·주 단추는 없어졌지만 이 문장이 붙여넣기를 시켜 같은 찜이 두 번 생길 수 있다. 화면 문구 표에 이 경우가 없어 시험은 만들지 않았다.

## 확인하지 못한 것
- 탭 뒤로 감(`HIDDEN`)·1분 읽지 못함(`UNREADABLE`) 경고: headless 크로미움에서 확장 쪽 `document.hidden`을 바꿀 수 없고, 읽지 못함은 서버 시계 1분 실제 대기라 단위 시험(서버·웹)에 맡겼다. 실물은 HG-TTX (4).
- 서비스 워커 다시 뜨기(AC-TTX-10(6))는 단위 시험 몫.
