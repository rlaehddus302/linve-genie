# TTX 수용 기준 — 크롬 확장으로 틱톡 라이브 댓글 읽기 (서버 직접 연결의 대비책, 읽기만)

- 스프린트: TTX · spec ID: **PLT-02**(세부 "확장 대비책" 새로), 연결: PLT-03·YT-10(AC4·AC5·AC9·AC10)·DAT-02 · 근거 결정: **D-TTX-01~D-TTX-22**(AUTO) · 기존 결정 확인: D-904(판정은 서버 도착순·글 올리기 없음·쿠키 없음), D-N2b-2-02(틱톡 회차는 접수순, 실제 시각순 회차엔 잇지 않음), D-N2b-2-03(`chat` 모양), D-N2b-2-05(판매자마다 틱톡 연결 하나), D-N2b-2-15(붙여넣기 알림 조건) · 사람 확인: **HG-TTX**
- 개발 영역: **web**(`apps/extension/**` 확장 — X1 확장에 더함, `apps/web/**` 콘솔 틱톡 칸), **server**(`apps/server/**` 확장 틱톡 받는 경로·틱톡 기록 연결) · 테스트: **domain**(`tests/adversarial/ttx/**`), **e2e**(`tests/e2e/ttx/**`) · **core 없음** — 판정·정산 규칙·엔진은 바꾸지 않는다.
- 금지 경로: `apps/server/src/youtube/**`, 이름에 `youtube`가 든 웹 파일, `tests/e2e/y1/**`. 확장의 유튜브 선택자 파일 `apps/extension/src/selectors.ts`와 유튜브 읽기·감사 올리기 동작은 바꾸지 않는다(틱톡은 새 파일).
- 골든: `tests/golden/tiktok/extension.json`(G-TTK-TTX-01~13, 새 `kind: extension`) — 확장 묶음 항목 → 공통 댓글 레코드/버림. 레코드 → `chat`은 기존 `chat.json` 그대로. 엔진 골든 변경 없음.
- **실제 틱톡 웹 화면 구조는 확인하지 못했다.** 선택자·데이터 이름은 우리가 만든 가짜 페이지 기준이고, 실제 구조를 지어내지 않는다. 실물 확인은 HG-TTX.
- 낱말: "직접 연결" = 서버가 틱톡 웹캐스트에 붙는 지금 방식(N2b). "받는 중" = 직접 연결 상태 `CONNECTED`. "연결 회차" = 그 판매자의 끊지 않은 틱톡 연결이 있는 끝나지 않은 실제 회차(판매자마다 많아야 하나 — D-N2b-2-05). "기록 조건" = 연결 회차가 있음 + 운영자 스위치 켜짐(`TIKTOK.ready`) + 판매자 동의가 지금 판(D-TTX-06).

## 사람 확인 (HG-TTX)

PC 크롬·실제 틱톡 라이브(판매자 본인 방송, 남의 방송엔 댓글 쓰지 않음): (1) 댓글 요소·댓글 ID·숫자 사용자 ID·쓴 사람 아이디를 읽을 수 있는지 — 못 읽으면 선택자 파일만 고치거나(값이 있을 때), 새 결정(값이 없을 때) (2) 확장 댓글 ID = 웹캐스트 댓글 ID인지 (3) 선물·입장 알림이 댓글로 읽히지 않는지 (4) 탭을 뒤로 보냈을 때 댓글이 계속 그려지는지 (5) 크롬이 새 권한(`www.tiktok.com`)을 묻는 화면. (6) 댓글 요소를 붙인 뒤 속성·글자를 나중에 채우는지, 목록 요소를 재사용하는지(RA-TTX-05).
