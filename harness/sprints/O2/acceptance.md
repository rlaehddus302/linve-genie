## A. 판매 방식 (OPT-04, D-O-02, D-O2-01·02)

### AC-O2-01 [web] 설정 화면의 "판매 방식"
- 근거: OPT-04, D-O2-01, UX-01
- Given 기본 설정의 판매자가 `/settings` 판매 규칙을 연다
- When 화면을 본다
- Then 판매 규칙 기본 칸 맨 위에 "판매 방식"이 있고 선택지는 "번호로만 받기 (다육 등 — 기본)"·"상품명·옵션도 받기 (의류·식품·케이스 등)" 둘이며 "번호로만 받기"가 골라져 있다. 엄격/느슨 칸("주문 인식 방식")은 "더 보기" 안에 지금처럼 있다. 화면 어디에도 `STRICT`·`LOOSE`·`OPTIONS`·`ARRIVAL` 글자가 없다
- 확인: E2E · 단위(웹)

### AC-O2-02 [web][server] 옵션 방식 고르기와 겨루기 고정
- 근거: R-19 "판매 방식"(옵션 + 실제 시각순은 입력 오류), D-O2-01
- Given 설정의 겨루기(`contention.policy`)가 "실제 시각순"인 판매자
- When "상품명·옵션도 받기"를 고른다
- Then 엄격/느슨 칸이 보이지 않고, 겨루기 칸은 고를 수 없는 글 "먼저 들어온 순서(접수순)"로 바뀌며 "상품명·옵션도 받기는 먼저 들어온 순서로만 판정해요."가 보인다. 저장하면 서버 설정이 `claim.parseMode=OPTIONS`·`contention.policy=ARRIVAL`이고 저장 오류가 나지 않는다. 다시 "번호로만 받기"로 저장하면 `claim.parseMode=STRICT`다
- 확인: E2E · 단위(웹)

### AC-O2-03 [server] 설정 API가 함께 둘 수 없는 값을 막는다
- 근거: R-19 "판매 방식", 설정값 범위
- Given 로그인한 판매자
- When 설정 저장 API에 `claim.parseMode=OPTIONS`와 `contention.policy=RECEIVED_TIME`을 함께, 또는 `claim.maxQuantity`에 0·100·1.5를 보낸다
- Then 400 쉬운 한국어 오류이고 설정이 바뀌지 않는다. `claim.maxQuantity` 1~99 정수와 `OPTIONS`+`ARRIVAL`은 받는다
- 확인: 단위(서버) · 적대

### AC-O2-04 [web] 시작 마법사의 판매 방식
- 근거: UX-02, OPT-04, D-O2-01
- Given 시작 마법사 "판매 규칙 확인" 단계
- When 단계를 연다
- Then AC-O2-01과 같은 "판매 방식" 칸이 있고 기본은 "번호로만 받기"이며, "상품명·옵션도 받기"를 고르고 "다음"을 누르면 설정에 저장된다(AC-O2-02와 같은 겨루기 고정)
- 확인: E2E

### AC-O2-05 [server][web] 방송 시작 창에서 그 방송만
- 근거: OPT-04 "방송마다", D-070, D-O2-02, G-ENG-O2-02
- Given 설정이 "번호로만 받기"인 판매자
- When 새 방송 시작 창(실제·리허설 모두)에서 "판매 방식"을 "상품명·옵션도 받기"로 바꿔 시작한다
- Then 그 방송의 설정 스냅샷은 `claim.parseMode=OPTIONS`·`contention.policy=ARRIVAL`이고, 판매자 설정은 "번호로만 받기" 그대로다. 다음 방송 시작 창의 처음 값은 다시 설정 값("번호로만 받기")이다. 반대로 설정이 옵션 방식일 때 "번호로만 받기"로 시작한 방송은 `STRICT`다. `POST /api/broadcasts`의 `saleMode`에 `NUMBERS`·`OPTIONS` 밖의 값은 400
- 확인: 단위(서버) · E2E · 적대(`saleMode` 값)

### AC-O2-06 [web] 옵션 방송의 표시
- 근거: D-O2-02, D-O2-03
- Given 옵션 방송과 번호 방송이 하나씩
- When 각 콘솔을 연다
- Then 옵션 방송 콘솔 머리에 "상품명·옵션도 받기"가 보이고, 방송 중에 판매 방식을 바꾸는 칸은 없다. 번호 방송 콘솔에는 판매 방식 글이 없다(지금 화면 그대로)
- 확인: E2E

## B. 상품 옵션 등록 (OPT-01, OPT-05, D-O-04·05·14·16, D-O2-04~06·11)

### AC-O2-10 [web] 옵션 추가 창은 옵션 방송에서만
- 근거: CMT-07, D-O2-03, D-O2-05
- Given 옵션 방송 콘솔과 번호 방송 콘솔
- When 빠른 입력 줄 둘레를 본다
- Then 옵션 방송에만 "옵션 추가" 버튼이 있다. 번호 방송의 빠른 입력·상품 상세에는 옵션·별칭 칸이 없다
- 확인: E2E

### AC-O2-11 [web] 옵션을 붙여 한 번에 등록
- 근거: OPT-01, D-O2-05
- Given 옵션 방송, 빠른 입력 줄에 `21 반바지 15000`
- When "옵션 추가" 창에서 항목 `사이즈`(S·M·L)를 만들고 닫은 뒤 Enter를 누른다
- Then 빠른 입력 줄 아래에 붙은 옵션 요약("옵션: 사이즈 S/M/L · 변형 3개")이 등록 전에 보이고, Enter 한 번에 상품 21(옵션 사이즈 S/M/L, 변형 재고 각 1)이 등록된다 — 서버 이벤트 로그에 `product.register` 하나(옵션 포함)이고 옵션 없는 `product.register` 뒤의 `product.update`가 아니다. 등록 뒤 붙은 옵션은 비워져 다음 `22 티셔츠 9000` Enter는 옵션 없는 상품이다. 빠른 입력 한 줄의 문법·되돌리기(UX-06)는 지금과 같다
- 확인: E2E · 단위(웹)

### AC-O2-12 [web] 업종 템플릿 — 항목 하나씩
- 근거: OPT-05, D-O-16, D-O2-04
- Given "옵션 추가" 창
- When "템플릿에서 고르기"를 연다
- Then 업종 묶음(의류·휴대폰 케이스·식품·화분) 아래 항목 템플릿이 보이고(D-O2-04 표의 이름), 하나를 고르면 항목 하나가 그 선택지·별칭으로 채워진다(예: "화분 — 호수" → `호수` 1호~10호, "휴대폰 케이스 — 기종" → `아이폰 17 프로`의 별칭 `17프로` 포함). 채운 선택지·별칭·가격 차이를 고치거나 지울 수 있고, 항목이 3개면 더 고를 수 없다(이유가 보인다). 템플릿 데이터는 웹 안의 데이터 파일 하나이고 서버·엔진 요청에는 템플릿 이름이 없다(상품에 저장된 옵션만)
- 확인: 단위(웹 — 데이터가 R-19 모양 검사를 통과하고 템플릿 안에 비교 글자 겹침이 없음) · E2E

### AC-O2-13 [web] 바로 알림 — 겹침·한도·모양
- 근거: OPT-01, R-19 "옵션 모델"·"비교 글자", D-O2-06
