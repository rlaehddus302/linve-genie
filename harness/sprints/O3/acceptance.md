## A. 상품 라벨 (LBL-01, OPT-06, LABEL_RULES L-3·L-5·L-10, D-O3-01·02·09)

### AC-O3-01 [device] 라벨 골든 전부 통과 — 새 파일 포함
- 근거: L-3·L-4, README "라벨 골든", D-O3-01~04
- Given `tests/golden/label/*.json` 6파일(기존 4 + `product-options.json`·`packing-options.json`)
- When `packages/label` 골든 테스트가 모든 사례를 글 계산 순수 함수(`computeProductText`·`computePackingText`)로 돌린다
- Then 154사례가 모두 `out`과 깊은 같음이다(오류 사례는 그 오류이고 글·그림이 없다). 테스트는 파일 6 · 사례 154를 고정값으로 단언하고, 사례 ID 형식은 `G-LBL-<세 자리>` 또는 `G-LBL-<스프린트>-<두 자리>`(N1·O3 등)를 받는다. 성공 사례는 렌더한 배치 결과의 글이 글 계산 값과 같다(지금 검사 그대로)
- 확인: 골든 · 단위

### AC-O3-02 [device] 옵션 없는 수량 1 라벨은 그림 바이트까지 그대로
- 근거: CMT-07, L-3 "옵션이 아니거나…", D-O3-01
- Given 기존 라벨 골든의 상품·포장 데이터 전부(그리고 같은 데이터에 `qty: 1`·`variant: null`을 더한 것)
- When 기본 템플릿(모든 크기)으로 그림을 그린다
- Then O3 전 BASE 커밋의 렌더 결과와 1비트 그림이 점 하나까지 같고, `qty: 1`·`variant: null`을 더한 데이터도 같은 그림이다. 포장 데이터의 정수 번호를 `{ no }`로 바꾼 것도 같은 그림이다
- 확인: 단위(BASE 렌더 결과를 시험 고정값으로 — 해시 등) · 적대

### AC-O3-03 [device] 옵션 글은 품종 자리, 수량은 가격 자리
- 근거: L-3 표·"옵션 글·수량의 자리", D-O3-02
- Given 기본 50×30 템플릿, 데이터 `{ no: 22, name: "반팔티", price: 34000, variant: "105/검정색", qty: 2 }`
- When 라벨을 그린다
- Then 배치 결과의 품종 항목 글은 `품종: 반팔티 105/검정색`(줄이면 두 줄·`…` — L-5 2 그대로), 가격 항목 글은 `가격: 2개 34 천원`이고 가격 항목은 `truncated`가 아니다. `qty`가 1이거나 없으면 가격 항목에 `개`가 없다
- 확인: 골든(G-LBL-O3-01~15) · 단위

### AC-O3-04 [device] 수량 붙은 가격의 보장값
- 근거: L-5 "기본 템플릿이 보장하는 값"(O3 문장), D-O3-02, D-O3-11
- Given 50×20·50×30·50×40·50×50 기본 상품 템플릿, 작은 템플릿(50×15·테이프 세 가지)
- When 가격 항목에 수량이 붙은 최악값으로 그린다 — 큰 크기: `9개 99,999원`(WON)·`99개 9,999원`(D-O3-11 — 원래 `9개 999,999원`·`99개 99,999원`)·`9개 9,999 천원`·`99개 999 천원`, 작은 크기: `99개 99,999,999원`·`99개 99,999 천원`
- 숫자 모양: 각 값은 같은 글자 수에서 자리마다 0~9 어느 숫자로 채운 값까지 확인한다(첫 자리는 1~9, 수량은 2 이상 — D-O3-11)
- Then 모두 `DOES_NOT_FIT` 없이 20점 이상으로 찍힌다(번호 9999·닉네임은 지금 보장 그대로). 그보다 긴 값(예 50×30 `10개 120,000원`, 큰 크기 원 표기 `3개 300,000원`·`40개 40,000원`)은 잘린 글 없이 `DOES_NOT_FIT`(항목 `price`)이다
- 확인: 단위(그리기) · 적대

### AC-O3-05 [device] 라벨 데이터 검사
- 근거: L-3 데이터 표, L-0 4, D-O3-01
- Given `checkProductData`·`computeProductText`
- When `variant`에 `""`·공백과 보이지 않는 글자만·수·배열을, `qty`에 0·100·1.5·`"2"`·`null`·`NaN`을 넣는다. 그리고 표 밖의 칸(`options`·`memo`)을 넣는다
- Then 모두 `INVALID_DATA`이고 라벨(글·그림)을 만들지 않는다. `variant` 없음·`null`, `qty` 없음·1~99 정수는 받는다. 통과한 데이터에는 표의 칸만 있다(받은 객체를 바꾸지 않는다)
- 확인: 골든(G-LBL-O3-16~23) · 단위 · 적대

### AC-O3-06 [device] 내용 키 — 다육 라벨은 키가 그대로
- 근거: L-10(O3 문장), D-O3-09
- Given `labelContentKey`
- When 옵션 없는 수량 1 상품·포장 데이터(정수 번호, `qty: 1`, `variant: null`, `{ no }` 포함)의 키를 만든다. 그리고 옵션 글·수량만 다른 데이터 두 개의 키를 만든다
- Then 옵션 없는 수량 1 데이터의 키는 BASE 커밋의 `labelContentKey` 결과와 글자까지 같다. 옵션 글이나 수량이 다르면 키가 다르고("재출력 필요"), 다듬으면 같은 옵션 글(`" M"`·`"M"`)이면 키가 같다
- 확인: 단위 · 적대

## B. 포장 라벨 (LBL-02, STL-08, L-4·L-5 4, D-O3-03·04)

### AC-O3-07 [device] 옵션 항목·같음·상품 수
- 근거: L-4 데이터·항목 표, D-O3-03
- Given 포장 데이터의 `numbers`에 정수와 `{ no, variant?, qty? }`가 섞여 있다
- When 글을 계산한다
- Then 옵션 없는 수량 1 항목은 정수 번호, 옵션 항목은 `{번호}[ {옵션 글}][ ×{수량}]` 글이다. 같은 (번호, 다듬은 옵션 글)이 한 방송에 둘이면 `INVALID_DATA`. 한 방송 안은 번호 순, 같은 번호는 받은 순서. `count` = 수량 합(G-LBL-O3-51 = 8)
- 확인: 골든(G-LBL-O3-51~67) · 단위 · 적대(무작위 항목: 같음·정렬·수량 합 성질)

### AC-O3-08 [device] 옵션 방송의 쪽 절반
- 근거: L-4 쪽 나누기 2(O3 문장), D-O3-04
- Given 옵션 항목이 있는 방송과 없는 방송이 섞인 묶음, `perPage` 1~40
- When 쪽을 나눈다
- Then 옵션 항목이 하나라도 있는 방송의 쪽은 많아야 `max(1, ⌊perPage ÷ 2⌋)`개, 그 밖의 방송은 `perPage`개다. 쪽 `k/n`의 n은 모든 쪽의 수다
- 확인: 골든(G-LBL-O3-53~57) · 적대(속성)

- Then 첫 묶음은 `add`에 11(`variant: null`, `qty: 3`), `remove`에 11(`variant: null`, `qty: 2`). 둘째는 `remove`에 21(`variant: "M"`, `qty: 1`). 이전 기록의 뺄 것은 `variant: null`·`qty: 1`. 뺄 것 항목의 다른 칸(`id`·`key`·`broadcast`·`title`·`no`·`name`)은 지금과 같다
- 확인: 단위(서버) · 기존 E2E 그대로

### AC-O3-29 [server] 찜 금액이 없으면 단가 × 수량으로 채우지 않는다 (감사 라운드 1)
- 근거: DOMAIN_RULES R-19 "표시" "찜 금액은 코어 값만", D-206, D-O3-15 (SA-O3-007)
- Given 확정 찜의 `amount`를 `null`로 바꾼 상태(시험용 주입 — 코어로는 만들 수 없다): 옵션 찜 하나(수량 2)와 다육 찜 하나(수량 1)
- When 방송 후 요약 줄·상품 라벨 데이터·포장 품목·포장 라벨 데이터를 만든다
- Then 요약은 그 방송의 댓글을 만들지 않는다(발송함 행 없음). 상품 라벨 데이터·출력 작업이 없다. 포장 품목·포장 라벨 데이터를 만들지 않는다(오류). 어느 경우에도 단가 × 수량이나 가격 스냅샷으로 채운 금액이 결과·응답에 없고, 오류 로그에 닉네임·금액·전화번호가 없다. `amount`가 있는 지금 상태의 결과는 AC-O3-20~22·27과 같다
- 확인: 단위(서버)

## E. 시험 (domain)

### AC-O3-30 [domain] 다육 회귀와 옵션 표시 성질
- 근거: CMT-07, D-O3-01~10
- Given 무작위 옵션 방송·다육 방송 이벤트(코어 실제 엔진)
- When 라벨 데이터·포장 데이터·확인서·대장을 만든다
- Then (1) 옵션 없는 수량 1만 있는 상태의 라벨 데이터·내용 키·포장 데이터·확인서 데이터·대장 행이 BASE 커밋의 결과와 같다. (2) 확인서 줄 금액 합 = 코어 상품 합계, 상품 수 = 수량 합. (3) 포장 라벨 `count` = 수량 합, 항목에 같은 (번호, 옵션 글)이 없다. (4) 상품 라벨 가격 글에 수량이 있으면 그 찜의 수량과 같다. (5) 대장의 확정 행 수 = 확정 찜 수, 가격 = 단가 × 수량. (6) 닉네임·품종·옵션 글의 HTML·수식 모양 글(`=1+1`, `<b>`)은 문서·엑셀에서 글 그대로다
- 확인: 적대(`tests/adversarial/o3/`)
