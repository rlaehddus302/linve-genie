# PL1A test-domain 메모 (AC-PL1A-91)

시험: `tests/adversarial/pl1a/backup-tamper.test.ts` — 실제 봉인 작업으로 A를 봉인한 판매자의 전체 기록 파일(형식 3)을 고쳐, 검사·바꾸기 복구·빈 판매자 가져오기가 예외 없이 거절하고 두 서버의 모든 표·백업 목록이 그대로인지 본다. 고친 파일은 `backupDigest`로 파일 요약값을 다시 맞춘다. 묶음마다 바른 파일이 통과하는지도 본다.

## 통과한 공격 (회귀로 남김)
- 봉인 칸 모양: `{}`·`"x"`·숫자·참거짓·목록·`ledger: null`·`ledgerDigest: null`·`sealedAt: null`·칸 더함/빠짐·봉인 시각 숫자/날짜만·장부가 객체·봉인 칸 안 `__proto__` → 봉인 칸 형식 문장
- 봉인 안 한 범위 B에 A의 봉인 칸·날짜만 B로 고친 장부, 리허설 범위에 봉인 칸
- 같은 범위 `sealed` 키 두 번(세 가지 차례) → "범위의 형식이 올바르지 않아요."
- 형식 번호 4·"3"(글), 형식 3인데 sealed 칸 없음, 형식 2인데 sealed 칸 있음, 봉인 시각 한 글자(파일 요약값 그대로)
- 봉인 범위 이벤트 seq 0·-1·1.5·두 번·뒤집음·뒤집고 다시 매김·맞바꿈, 범위 seq +1·0, 이벤트 0개
- 다른 날짜 장부 바꿔치기(파일 요약값만 / 장부 요약값까지), 요약값 대문자, JSON 아닌 장부·빈 글·`null`
- 속성(fast-check, 고정 시드): 장부 아무 한 글자 → 장부 요약값 문장, 봉인 범위 이벤트 본문 아무 한 글자 → 그 이벤트 요약값 문장
- 64Mi 글자 넘는 장부 → JSON 스트림 상한 문장으로 거절(한 번 읽는 데 20초 넘게 걸려 복구 하나만 본다)

## 실패로 남긴 것
- TD-PL1A-001: 장부 `broadcasts`에 `null`·숫자 → `SealedScopeCheck` 생성자에서 TypeError가 그대로 던져진다(복구 명령은 "데이터베이스를 확인해 주세요"로 잘못 안내)
- TD-PL1A-002: 장부에 `__proto__` 칸(맨 위·판매 행) → 검사·복구 통과. `readLedger`가 모르는 칸을 받아 주기 때문(그 파일은 금지 경로라 `backup.ts` 쪽 검사로 막아야 한다)

## 지적만 (스펙 확인 필요)
- 장부 요약값까지 다시 맞춘 장부에서 판매 금액 ≠ 단가 × 수량 → 검사·가져오기 통과, 가져온 뒤 `GET /api/days/A`는 그 틀린 금액을 그대로 보이고 포장 목록은 500 `LEDGER_UNREADABLE`. 파일 검사가 문서 쪽(`stateFromLedger`)과 같은 기준으로 장부를 읽어야 하는지 AC-PL1A-03 (e)에 적혀 있지 않다.
