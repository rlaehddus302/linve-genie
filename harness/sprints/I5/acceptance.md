# I5 수용 기준 — 아이폰(사파리)에서도 음성 등록 (비용 최소)

- 스프린트: I5 (6단계) · spec ID: **VOC-01**, **VOC-05** (연결: VOC-04 자동 확정, UX-01 쉬운 문장, NFR-05 기기, §9 HG-4) · 규칙: DOMAIN_RULES 변경 없음(R-17 그대로) · 근거 결정: **D-I5-01~D-I5-08**(AUTO), D-205, D-I4-03~D-I4-07, D-I4-09, D-036
- 개발 영역: **device**(`packages/voice/**`), **web**(`apps/web/**`) · 테스트: **e2e** · 사람 확인 지점 **HG-4**(맨 아래 "HG-4 아이폰 확인 목록" — 최종 보고에서 사용자 확인)
- **dev-core·dev-server가 없다.** 판정·정산 규칙·서버 API는 바꾸지 않는다. 음성으로 등록한 상품은 I4 그대로 빠른 입력과 같은 `product.register`다. 서버를 고쳐야 할 것 같으면 고치지 말고 dev-notes·`disputesWithSpec`으로 올린다.
- 목표(백로그, 비용 최소 순서): (1) 사파리 `webkitSpeechRecognition`으로 동작 — 기능 감지, 끊기면 자동 다시 시작, 권한 거절·Siri 꺼짐 안내, 홈 화면 앱 제약 안내 (2) 안 되는 기기는 "이 기기에서는 음성이 어려워요" 안내 + 손 입력 그대로 (3) 유료 클라우드 음성은 숨김·기본 꺼짐 → **I5에선 만들지 않음**(D-I5-07). 실제 아이폰은 HG-4라 사파리 흉내 가짜 인식 + Playwright WebKit으로 확인.
- 원칙(D-036): 기기 이름(UA 문자열)으로 갈라 처리하지 않는다. 기능 감지(`SpeechRecognition`/`webkitSpeechRecognition`, `navigator.standalone`)와 모든 기기에 맞는 문장 하나로 푼다. **UA를 읽는 코드를 새로 넣지 않는다.**

## 공통 전제

- S00~I4·이후 합쳐진 모든 결과(`pnpm verify`)가 그대로 유지된다. 외부 계정·실기기·마이크·네트워크 없이 돈다.
- 이 작업 폴더의 E2E가 도는 명령엔 `E2E_PORT_OFFSET=27900`을 붙인다.
- 가짜 음성 인식 계약은 I4 그대로(`page.addInitScript`로 `window.SpeechRecognition`·`window.webkitSpeechRecognition`을 바꾸거나 지움, 화면 코드에 시험용 갈림길·전역 훅 없음, 시각은 `Date.now`·브라우저 타이머 — `page.clock`). 사파리 흉내 가짜(I5)는 아래 AC-I5-20의 모양을 따른다.
- 화면 문장 중 이 문서·DECISIONS가 따옴표로 정한 것은 그대로 쓴다(E2E가 글자로 찾는다).
- 태그: `[device]` = dev-device(`packages/voice/**`), `[web]` = dev-web(`apps/web/**` — `playwright.config.ts` 포함), `[e2e]` = test-e2e(`tests/e2e/**`). 의존 순서 device → web. dev-device는 바뀐 공개 모양(새 오류 종류 `SERVICE_OFF`·`RESTART_BLOCKED`, `SpeechResult`의 끝에서 넘김 표시 이름, 한도 상수)을 `harness/sprints/I5/dev-notes.md`에 먼저 적는다.
- 기존 시험의 기대값 교체는 이 스프린트에서 스펙이 바꾼 문장·한도(D-I5-01·03·06)에 한한다 — `packages/voice/test`(dev-device), `tests/e2e/i4/**`(test-e2e). 그 밖의 기존 시험은 바꾸지 않는다.

## 수용 기준

### 음성 엔진 (device)

**AC-I5-01** [device] · VOC-01 · D-I5-01 — 빨리 끝남만 센다
- Given 시계 함수를 넣은 `WebSpeechEngine`과 가짜 인식 생성자, 판매자가 `start()`를 불렀다
- When 각 인식 객체가 열린 뒤 1,999ms에 결과 없이 `onend`가 오는 일이 연달아 생긴다(모두 60초 안)
- Then 1~5번째 끝남 뒤에는 새 인식 객체를 열고(상태 `RESTARTING` → `LISTENING`), **6번째** 끝남에서 새 객체를 열지 않고 오류 `KEEPS_STOPPING`과 상태 `HALTED`. 같은 시나리오에서 6번째 끝남 직전에 최종 결과가 하나 오면 센 것이 비워져 멈추지 않는다. 시계가 `NaN`을 내거나 뒤로 가면 그 끝남은 빨리 끝남으로 센다
- 확인: 단위(`packages/voice/test`)

**AC-I5-02** [device] · VOC-01 · D-I5-01 — 조용함으로 끝난 것은 세지 않는다
- Given AC-I5-01과 같은 엔진
- When 각 인식 객체가 열린 뒤 정확히 2,000ms(그리고 따로 3,000ms)에 결과 없이 `onend`가 100번 연달아 온다
- Then 100번 모두 새 인식 객체를 열고 오류는 한 번도 없으며 상태는 `HALTED`가 아니다. 그 뒤 판매자가 `stop()`하면 상태 `OFF`, 새 객체를 열지 않는다
- 확인: 단위

**AC-I5-03** [device] · VOC-01 · D-I5-02 — 끝날 때 남은 중간 결과를 한 번 넘긴다
- Given 엔진이 듣는 중
- When (a) 위치 0에 중간 결과 `15번 핑크프릴 만오천원`(isFinal false)이 온 뒤 저절로 `onend` (b) 위치 0이 최종으로 온 뒤 `onend` (c) 중간 결과 뒤 판매자가 `stop()` (d) 중간 결과 뒤 다시 시작하지 않는 오류(`not-allowed`) (e) 중간 결과가 공백뿐인 채 `onend`
- Then (a) 그 글이 `final: true`이고 "끝에서 넘김" 표시가 참인 결과로 정확히 한 번 나가고 그 뒤 다시 시작한다 (b) 추가 결과 없음(최종은 한 번만, 표시는 거짓) (c)·(d)·(e) 넘기는 결과 없음. 지난 인식 객체의 늦은 이벤트는 여전히 무시한다
- 확인: 단위

**AC-I5-04** [device][web] · VOC-04 · D-I5-02 — 넘긴 문장 카드는 자동 확정하지 않는다
- Given 자동 확정 켬(5초), 사전에 `핑크프릴`, 그 방송에 15번 없음
- When 끝에서 넘긴 결과 `15번 핑크프릴 만오천원`(추출 신뢰도 `HIGH`)으로 카드가 생기고 30초가 지난다
- Then 카드는 등록되지 않고 열린 채로 남으며 "N초 뒤 자동 등록" 표시가 없다. 카드의 "등록"을 누르면 15번 핑크프릴 15,000원이 등록된다. 같은 문장이 보통 최종 결과로 오면 I4대로 5초 뒤 자동 등록된다
- 확인: 단위(카드·자동 확정 판단) + E2E(AC-I5-22)

**AC-I5-05** [device] · VOC-01 · D-I5-03 — 오류 종류 나누기
- Given 엔진
- When (a) 판매자의 `start()`가 연 인식 객체에서 `not-allowed` (b) 같은 객체에서 `service-not-allowed` (c) 저절로 끝난 뒤 엔진이 연 인식 객체에서 `not-allowed` (d) 같은 경우 `service-not-allowed` (e) `audio-capture` (f) 생성자가 없음
- Then 오류 종류가 (a) `PERMISSION_DENIED` (b) `SERVICE_OFF` (c)·(d) `RESTART_BLOCKED` (e) `NO_MICROPHONE` (f) `UNSUPPORTED`. 모두 새 인식 객체를 열지 않고 상태 `HALTED`. 판매자가 그 뒤 다시 `start()`하면 그 객체는 다시 "처음 켤 때"로 본다
- 확인: 단위

**AC-I5-06** [device] · VOC-01 · D-I5-03 — 오류 문장 표
- Then `SPEECH_ERROR_MESSAGES`가 정확히 다음과 같다(글자 그대로):
  - `UNSUPPORTED`: "이 기기에서는 음성이 어려워요. PC 크롬이나 안드로이드 크롬에서 켜 주세요. 상품은 빠른 입력으로 그대로 등록할 수 있어요."
  - `PERMISSION_DENIED`: "마이크 사용이 막혀 있어요. PC·안드로이드 크롬은 주소창 왼쪽 자물쇠에서, 아이폰은 설정 > 사파리 > 마이크에서 허용해 주세요."
  - `SERVICE_OFF`: "이 기기에서 음성 인식이 꺼져 있어요. 아이폰은 설정에서 Siri와 받아쓰기를 켜 주세요. 그래도 안 되면 PC 크롬이나 안드로이드에서 켜 주세요."
  - `RESTART_BLOCKED`: "이 기기는 음성이 저절로 다시 켜지지 않아요. 말하기 전에 '음성 켜기'를 다시 눌러 주세요."
  - `KEEPS_STOPPING`: "음성 인식이 자꾸 끊겨요. 마이크를 확인하고 다시 켜 주세요. 계속 끊기면 PC 크롬이나 안드로이드에서 켜 주세요."
  - `NO_MICROPHONE`·`CONNECTION_FAILED`·`OTHER`: I4 그대로
- 그리고 `packages/voice/src`에 `navigator.userAgent`·`userAgentData`를 읽는 코드가 없다(원칙 D-036)
- 확인: 단위

### 화면 (web)

**AC-I5-10** [web] · VOC-05 · D-I5-04 — 지원 안 하는 기기는 안내 창 없이 손 입력 안내
- Given 그 기기에 확인 기록이 없고 `SpeechRecognition`·`webkitSpeechRecognition`이 둘 다 없다(크로미움과 WebKit 두 묶음에서)
- When 콘솔에서 "음성 켜기"를 누른다
- Then 첫 안내 창이 열리지 않고, 저장소에 확인 기록(`livejjim.voiceConsent`)이 생기지 않고, `getUserMedia`·인식 생성자 호출과 판매 이력 조회(`/api/days`)가 0번이다. 음성 칸에 AC-I5-06의 `UNSUPPORTED` 문장이 알림으로 보이고 버튼은 "음성 켜기" 그대로. 그 뒤 빠른 입력 `15 핑크프릴 10`으로 15번이 등록된다
- 확인: E2E

**AC-I5-11** [web] · VOC-01 · D-I5-05 — 홈 화면 앱 한 줄
- Given 사파리 흉내 가짜 인식, 확인 기록 있음
- When (a) `navigator.standalone`을 `true`로 둔 페이지에서 음성을 켠다 (b) (a)에서 `not-allowed`로 멈춘다 (c) `navigator.standalone`이 없거나 `false`인 페이지에서 음성을 켠다
- Then (a)·(b) 음성 칸에 "홈 화면 앱에서는 음성이 자주 끊길 수 있어요. 안 되면 사파리에서 열어 주세요."가 보이고 음성은 막히지 않는다(a는 듣는 중) (c) 그 문장이 없다
- 확인: E2E(`@webkit`)

**AC-I5-12** [web] · VOC-01 · D-I5-06 — 외부 전송 고지
- Given 확인 기록 없음
- When "음성 켜기"를 눌러 첫 안내 창을 보고 켠다
- Then 창에 "음성은 인식을 위해 브라우저의 음성 인식 서버(크롬은 구글, 아이폰은 애플)로 보내져요."가 있고, 켜진 동안 음성 칸에 "음성은 인식을 위해 크롬은 구글로, 아이폰은 애플로 보내져요."가 늘 보인다. 옛 문장 "음성은 인식을 위해 구글로 보내져요."는 화면 어디에도 없다. 확인 기록이 이미 있는 기기는 창 없이 바로 켜진다(I4 그대로)
- 확인: E2E(크로미움·`@webkit` 둘 다), I4 E2E 기대 문장 교체

**AC-I5-13** [web] · VOC-01 · D-I5-07 — 클라우드 음성은 화면에 없다
- When 설정 화면과 콘솔(음성 켬)을 연다
- Then "Deepgram"·"리턴제로"·"클라우드 음성"·"유료 음성" 글자와 음성 키 입력 칸이 없다. 화면 코드는 `@livejjim/voice`의 클라우드 어댑터를 부르지 않는다
- 확인: E2E + 코드 검사(dev-web 단위 또는 경계 시험)

**AC-I5-14** [web] · VOC-01 · D-I5-03 — 다시 시작이 막혀 멈춘 뒤 다시 켜기
- Given 음성이 켜져 있고 오류 `RESTART_BLOCKED`로 멈췄다
- When "음성 켜기"를 다시 누른다
- Then 안내 창 없이(확인 기록 있음) 새 인식 객체로 듣는 중이 되고 오류 문장이 사라진다. 열린 카드는 남아 있다(D-I4-04 그대로)
- 확인: E2E(`@webkit`)

### WebKit(아이폰 크기) 확인 (web + e2e)

**AC-I5-20** [web][e2e] · VOC-01 · D-I5-01·D-I5-08 — 사파리 흉내 흐름: 조용할 때 끊겨도 계속 듣는다
- Given `webkit-iphone` 묶음, 사파리 흉내 가짜(`webkitSpeechRecognition`만 있고 `SpeechRecognition`은 `undefined`, `interimResults`를 무시하고 중간 결과를 보내지 않음, 최종 결과 하나 뒤 곧 `onend`, 말이 없으면 연 지 3초 뒤 `onend`), 확인 기록 있음, `page.clock`
- When 음성을 켜고 말 없이 시계를 120초 당긴다, 그 뒤 최종 결과 `15번 핑크프릴 만오천원`을 보낸다
- Then 120초 동안 오류 문장이 없고 상태 글자는 "듣는 중"·"다시 시작 중"만 보이며 인식 생성자가 40번 넘게 불린다(멈추지 않음). 최종 결과로 15번 핑크프릴 15,000원 카드가 나오고 "등록"을 누르면 15번이 등록된다
- 확인: E2E(`@webkit`)

**AC-I5-21** [web][e2e] · VOC-01 · D-I5-03 — 사파리 오류 문장
- Given `webkit-iphone` 묶음, 사파리 흉내 가짜
- When (a) 처음 `start()` 뒤 `not-allowed` (b) 처음 `start()` 뒤 `service-not-allowed` (c) 한 번 저절로 끝나 다시 연 객체에서 `not-allowed` (d) 연 지 0초에 끝나기를 6번
- Then 음성 칸 알림이 각각 AC-I5-06의 (a) `PERMISSION_DENIED` (b) `SERVICE_OFF` (c) `RESTART_BLOCKED` (d) `KEEPS_STOPPING` 문장이고, 꺼진 상태로 돌아가 "음성 켜기"를 다시 누를 수 있다. 빠른 입력은 그대로 등록된다

**AC-I5-22** [web][e2e] · VOC-04 · D-I5-02 — 끝에서 넘긴 문장 카드

**AC-I5-23** [web][e2e] · VOC-01·VOC-04·VOC-05 · D-I5-08 — 아이폰 크기에서 화면이 깨지지 않는다

## HG-4 아이폰 확인 목록 (사용자 몫 — 최종 보고)

실제 기기에서 한 번씩, 결과(된다/안 된다/보인 문장)를 적어 주면 D-I5-01~05를 맞춘다.

1. 아이폰 사파리: "음성 켜기" → 마이크·음성 인식 권한을 묻는가, 허용 뒤 "15번 핑크프릴 만오천원" 카드가 나오는가
2. 아이폰 사파리: 30초 동안 말하지 않고 기다린 뒤 다시 말해도 듣는가(멈춤·"자꾸 끊겨요"·"저절로 다시 켜지지 않아요"가 나오는가)
3. 아이폰 설정에서 Siri·받아쓰기를 끈 상태로 켜면 어떤 문장이 나오는가
4. 권한을 "허용 안 함"으로 누르면 어떤 문장이 나오는가, 설정 > 사파리 > 마이크로 되돌릴 수 있는가
5. 홈 화면에 추가한 앱에서 1·2를 다시 — 켤 때마다 마이크를 묻는가, "홈 화면 앱에서는…" 줄이 보이는가
6. 아이폰 크롬·카카오톡 안 브라우저에서 "음성 켜기" → 되는가, 아니면 "이 기기에서는 음성이 어려워요"가 나오는가

9. 위에서 아이폰이 끝내 안 되면: 유료 클라우드 음성(월 비용 발생)을 쓸지 — D-I5-07
