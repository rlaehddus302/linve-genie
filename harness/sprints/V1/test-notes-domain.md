## 찾은 것 (실패 시험 없음 — 모두 스펙 판정이 필요한 것)
- TD-V1-001 (spec, major 후보): R-21에 부정·질문·고쳐 말하기 규칙이 없다. "165번은 문자찜 아니에요", "165번 문자찜 되나요?", "165번은 문자찜 안 돼요", "165번 문자찜 아니에요 댓글로 해주세요"가 모두 `{ orders: [165], problem: null }` → 기본 설정에서 3초 뒤 "문자찜(확인 필요)" 구매자로 1등. "165번 문자찜 끝자리 1234 아니 5678"은 1234로 저절로 들어간다.
- TD-V1-002 (spec, minor): 옵션 방식(R-21 8)은 R-20 결과를 그대로 써서 `orders.no`가 `claim.maxNumber` 밖일 수 있다(상품 목록에 1500번이 있고 maxNumber 999). AC-V1-01 속성 문장 "orders의 no는 늘 1..maxNumber"와 R-21 8이 다르다.
- TD-V1-003 (spec, minor): 같은 말 막기(D-V1-06)가 닫은 카드·이유 카드에도 걸린다. "넣지 않기"를 잘못 누르고 다시 말하거나, "판매 중이 아니에요" 이유 카드를 보고 상품을 연 뒤 10초 안에 다시 말하면 아무것도 넣지 않는다. 닫은 카드는 화면에 없어 "같은 말을 한 번 더 들었어요"도 보이지 않는다.
- TD-V1-004 (spec, nit): "끝 자리 1234"(띄어 씀)는 끝자리로 읽지 않는데 `LAST4_UNCLEAR`도 아니어서 1234는 버려지고 "손님 확인 필요"로 저절로 들어간다.
