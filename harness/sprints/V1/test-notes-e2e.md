## 지적
- **TE-V1-001 (web, minor)** 같은 표시 이름의 문자 구매자가 둘 이상이면(음성 문자찜 구매자는 모두 "문자찜") 결과 줄이 `165번 · 문자찜 · 뒤 4자리 1234 · 1등 · … · 뒤 4자리 1234`처럼 뒤 4자리를 두 번 보인다. 이름의 구분 글자(D-098)와 `SmsResultRow`가 붙이는 글이 겹침. 손 입력 결과 카드(`SmsPage.tsx` 788줄)도 같은 구조.
- **TE-V1-002 (web, major)** 정산 안내 링크 → 확인 필요 구매자 자세히 → "다른 구매자와 합치기"의 기본 방향이 "남는 이름: 문자찜(확인 필요)"라, 그대로 합치면 알던 손님(끝자리 1234)이 확인 필요 구매자에 합쳐지고 안내가 사라지지 않는다(알던 손님의 이름도 "문자찜(확인 필요)"로 바뀐다). AC-V1-29·60 "합치면 그 줄이 사라진다".
- 스펙 확인 필요(시험 없음): 두 기기가 같이 들으면 구매자 말 없는 문장은 찜 둘, 끝자리 같은 후보가 메모 없으면 "문자찜 · 뒤 4자리 1234"·"… · 2"로만 구분, 기다림 10초에서 빠른 연속 문장은 가장 오래된 카드가 조용히 닫혀 넣지 않음, 주문이 빈 다른 문제 문장이 10초 안이면 앞 카드의 이유로 합쳐짐.
